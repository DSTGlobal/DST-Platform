# 40. Производительность и кэширование

Данный документ описывает инфраструктуру кэширования и оптимизации производительности в DST Platform. Кэширование является критически важным механизмом, снижающим нагрузку на базу данных и ускоряющим обработку запросов.

Для информации о производительности запланированных задач см. раздел *«Создание запланированных задач»*. Стратегии оптимизации базы данных описаны в разделе *«Основная архитектура»*.

---

## 40.1. Архитектурный обзор

### Многоуровневая стратегия кэширования

DST Platform реализует многоуровневую архитектуру кэширования с использованием библиотеки **PHPFastCache**, которая обеспечивает абстракцию от множества драйверов бэкендов. Кэширование позиционируется между бизнес-логикой приложения и базой данных, перехватывая запросы к данным и возвращая кэшированные результаты при их наличии.

**Этапы обработки:**

## 40.2. Библиотека PHPFastCache

### Обзор и возможности

DST Platform использует **PHPFastCache v7.1.2** — комплексную библиотеку кэширования, обеспечивающую:

| Функция | Описание | Стандарт |
|---------|----------|----------|
| **Поддержка PSR-6** | Сложный интерфейс кэширования с пулами элементов | `psr/cache ~1.0.0` |
| **Поддержка PSR-16** | Простой интерфейс key-value | `psr/simple-cache ~1.0.0` |
| **Многобэкендная архитектура** | Поддержка Redis, Memcached, Files, APCu и 15+ других | — |
| **Уровень абстракции** | Переключение бэкендов без изменения кода | — |
| **Автоматическая сериализация** | Обработка сложных структур данных | — |

**Зависимость в `composer.json`:**
```json
{
  "require": {
    "phpfastcache/phpfastcache": "^7.1"
  }
}
```

### Поддерживаемые бэкенды

| Бэкенд | Вариант использования | Производительность | Зависимости |
|--------|----------------------|-------------------|-------------|
| **Redis** | Production, высокая нагрузка | Отличная | Сервер Redis, расширение `redis` |
| **Memcached** | Production, распределённое кэширование | Отличная | Сервер Memcached, расширение `memcached` |
| **Files** | Разработка, общий хостинг | Умеренная | Нет (встроенный) |
| **APCu** | Production, односерверное решение | Хорошая | Расширение `apcu` |
| **SQLite** | Встраиваемое решение | Умеренная | Расширение `pdo_sqlite` |

## 40.3. Инициализация и конфигурация

### Последовательность бутстрапа

Инициализация кэша происходит на раннем этапе загрузки приложения, сразу после подключения к базе данных и до запуска системы событий:

```
1. Загрузка конфигурации (cmsConfig)
   ↓
2. Инициализация базы данных
   ↓
3. Создание синглтона кэша (cmsCache::getInstance())
   ↓
4. Запуск системы событий
   ↓
5. Загрузка компонентов
   ↓
6. Обработка запроса
```

<img src="https://github.com/DSTGlobal/DST-Platform/blob/main/images/243.png" alt="Последовательность бутстрапа">

Кэш создаётся как синглтон в файле начальной загрузки, что гарантирует доступность кэша для всех последующих компонентов.

### Конфигурация класса cmsCache

Конфигурация осуществляется через синглтон `cmsConfig`:

```php
// /system/config/config.php
return [
    // ... другие настройки ...
    'cache' => [
        'driver' => 'redis',        // redis, memcached, files, apcu
        'host' => '127.0.0.1',      // для сетевых драйверов
        'port' => 6379,             // порт (Redis: 6379, Memcached: 11211)
        'password' => null,         // опционально
        'database' => 0,            // номер БД (для Redis)
        'ttl' => 3600,              // время жизни кэша по умолчанию (сек)
        'prefix' => 'dst_',         // префикс для ключей кэша
        'path' => PATH . '/cache'   // путь для файлового кэша
    ]
];
```

### Конфигурация для разных сред

| Среда | Драйвер | Параметры | TTL |
|-------|---------|-----------|-----|
| **Разработка** | Files | `path: /cache` | 60 сек (короткий для тестирования) |
| **Общий хостинг** | Files | `path: /cache` (доступен для записи) | 5-30 минут |
| **Production** | Redis/Memcached | `host: localhost`, `port: 6379/11211` | Оптимизирован под тип данных |

**Пример для Redis в продакшене:**
```php
'cache' => [
    'driver' => 'redis',
    'host' => 'cache-server.example.com',
    'port' => 6379,
    'password' => getenv('REDIS_PASSWORD'),
    'database' => 1,
    'ttl' => 3600,
    'prefix' => 'dst_prod_',
    'options' => [
        'timeout' => 2.5,
        'persistent' => true
    ]
]
```

## 40.4. Стратегии кэширования

### Двухуровневая архитектура

Платформа использует двухуровневый подход к кэшированию:

| Уровень | Расположение | Скорость | Емкость | Назначение |
|---------|--------------|----------|---------|------------|
| **L1: Память** | PHPFastCache (Redis/Memcached) | Микросекунды | Ограничено ОЗУ | Быстрый доступ к часто используемым данным |
| **L2: База данных** | Кэш-запросы/индексы MySQL | Миллисекунды | Большой | Резервный уровень, денормализация |

<img src="https://github.com/DSTGlobal/DST-Platform/blob/main/images/249.png" alt="Двухуровневая стратегия кэширования">

### Кэширование на уровне модели

Модели, расширяющие `cmsModel`, используют синглтон кэша для сокращения количества запросов к БД:

```php
// /system/controllers/shop/model.php
class modelShop extends cmsModel {
    
    /**
     * Получение товаров с кэшированием
     */
    public function getProducts($category_id, $limit = 20) {
        // Генерация уникального ключа кэша
        $cache_key = 'shop_products_' . $category_id . '_' . $limit;
        
        // Попытка получить из кэша
        $cached = cmsCache::getInstance()->get($cache_key);
        if ($cached !== false) {
            return $cached;
        }
        
        // Запрос к БД
        $products = $this->select('shop_products')
            ->filterEqual('category_id', $category_id)
            ->filterEqual('is_published', 1)
            ->orderBy('date_pub', 'DESC')
            ->limit($limit)
            ->getItems();
        
        // Сохранение в кэш (60 минут)
        cmsCache::getInstance()->set($cache_key, $products, 3600);
        
        return $products;
    }
}
```

#### 2. Кэширование GeoIP2

Платформа использует GeoIP2 для определения местоположения по IP-адресу. База данных GeoLite2-City (более 64 МБ) значительно выигрывает от кэширования:

```php
class GeoIpCache {
    private $cache;
    
    public function __construct($cache) {
        $this->cache = $cache;
    }
    
    /**
     * Получение данных о местоположении с кэшированием
     */
    public function getLocation($ip) {
        $cache_key = 'geoip_' . md5($ip);
        
        // Попытка получить из кэша
        $cached = $this->cache->get($cache_key);
        if ($cached !== false) {
            return $cached;
        }
        
        // Запрос к базе GeoIP2
        $reader = new \GeoIp2\Database\Reader('/path/to/GeoLite2-City.mmdb');
        $location = $reader->city($ip);
        
        // Сохранение в кэш (24 часа)
        $this->cache->set($cache_key, $location, 86400);
        
        return $location;
    }
}
```

## 40.5. Управление временем жизни (TTL) и аннулирование

### Стратегия TTL по типам данных

Основная стратегия аннулирования использует значения времени жизни (TTL):

| Тип данных | Типичный TTL | Обоснование |
|------------|--------------|-------------|
| **Статическая конфигурация** | 1 час - 24 часа | Изменения происходят редко |
| **Данные о продукте** | 5-15 минут | Периодически обновляются |
| **Пользовательские сессии** | Срок действия сессии | Привязано к аутентификации |
| **Поиск по геолокации (GeoIP)** | 24 часа | IP-адреса меняются нечасто |
| **Результаты вычислений** | 1-60 минут | Баланс свежести и эффективности |
| **Страницы (полный HTML)** | 5-15 минут | Для анонимных пользователей |

### Аннулирование кэша при изменении данных

Компоненты, изменяющие данные, должны аннулировать соответствующие записи кэша:

```php
// /system/controllers/shop/hooks.php
class shop extends cmsAction {
    
    /**
     * Аннулирование кэша после обновления товара
     */
    public function hookShopAfterUpdateProduct($product) {
        $cache = cmsCache::getInstance();
        
        // Удаление кэша конкретного товара
        $cache->delete('shop_product_' . $product['id']);
        
        // Удаление кэша списка товаров категории
        $cache->delete('shop_products_category_' . $product['category_id']);
        
        // Удаление по шаблону (все списки товаров)
        $cache->deleteByPattern('shop_products_*');
        
        // Удаление по тегу
        $cache->deleteByTag('product_' . $product['id']);
        $cache->deleteByTag('category_' . $product['category_id']);
        
        return $product;
    }
}
```

### Использование подстановочных символов

Для аннулирования нескольких связанных ключей полезно использовать удаление по шаблону:

| Шаблон | Описание | Пример использования |
|--------|----------|---------------------|
| `shop_products_*` | Все товарные списки | После массового обновления цен |
| `user_{user_id}_*` | Все данные пользователя | После изменения профиля |
| `category_{cat_id}_*` | Кэши, специфичные для категории | После изменения категории |
| `content_{ctype}_*` | Все кэши типа контента | После настройки типа контента |

## 40.6. Мониторинг и метрики эффективности

### Ключевые метрики

Эффективное кэширование должно обеспечивать:

| Метрика | Целевое значение | Действия при отклонении |
|---------|------------------|-------------------------|
| **Коэффициент попадания в кэш** | > 80% | Проверить настройки TTL и ключи кэша |
| **Среднее время получения кэша** | < 5 мс | Проверить производительность бэкенда |
| **Использование кэш-памяти** | < 80% | Внедрить политику вытеснения |
| **Штраф за промах кэша** | < 100 мс | Оптимизировать запросы к БД |

**Типичные показатели:**
- При интенсивной нагрузке на чтение: коэффициент попадания 80-95%
- При интенсивной записи: коэффициент попадания 50-70%

### Инструменты мониторинга

```php
// Пример класса для сбора метрик кэширования
class CacheMetrics {
    private static $stats = [
        'hits' => 0,
        'misses' => 0,
        'sets' => 0,
        'deletes' => 0
    ];
    
    public static function recordHit() {
        self::$stats['hits']++;
    }
    
    public static function recordMiss() {
        self::$stats['misses']++;
    }
    
    public static function recordSet() {
        self::$stats['sets']++;
    }
    
    public static function recordDelete() {
        self::$stats['deletes']++;
    }
    
    public static function getStats() {
        $total = self::$stats['hits'] + self::$stats['misses'];
        $hit_rate = $total > 0 ? (self::$stats['hits'] / $total) * 100 : 0;
        
        return [
            'hits' => self::$stats['hits'],
            'misses' => self::$stats['misses'],
            'sets' => self::$stats['sets'],
            'deletes' => self::$stats['deletes'],
            'hit_rate' => round($hit_rate, 2),
            'total' => $total
        ];
    }
    
    public static function logStats() {
        $stats = self::getStats();
        error_log(sprintf(
            '[CACHE] Hits: %d, Misses: %d, Hit Rate: %.2f%%, Sets: %d, Deletes: %d',
            $stats['hits'],
            $stats['misses'],
            $stats['hit_rate'],
            $stats['sets'],
            $stats['deletes']
        ));
    }
}

// Интеграция в обёртку кэша
class CacheWrapper {
    private $cache;
    
    public function __construct($cache) {
        $this->cache = $cache;
    }
    
    public function get($key) {
        $value = $this->cache->get($key);
        if ($value !== false) {
            CacheMetrics::recordHit();
        } else {
            CacheMetrics::recordMiss();
        }
        return $value;
    }
    
    public function set($key, $value, $ttl = 3600) {
        CacheMetrics::recordSet();
        return $this->cache->set($key, $value, $ttl);
    }
    
    public function delete($key) {
        CacheMetrics::recordDelete();
        return $this->cache->delete($key);
    }
}
```

### Логирование операций кэширования

```php
class CacheLogger {
    public static function logOperation($operation, $key, $duration) {
        error_log(sprintf(
            '[CACHE] %s: %s (duration: %.4f sec)',
            strtoupper($operation),
            $key,
            $duration
        ));
    }
}

// Пример использования
$start = microtime(true);
$value = cmsCache::getInstance()->get('key');
CacheLogger::logOperation('get', 'key', microtime(true) - $start);
```

## 40.7. Интеграция с компонентами

### Кэширование в компоненте доставки (CDEK)

Для оптимизации расчётов стоимости доставки используется многоуровневое кэширование:

```php
class DeliveryCalculator {
    private $cache;
    private $cdek;
    
    public function calculateShipping($params) {
        // Генерация ключа кэша на основе параметров
        $cache_key = $this->generateCacheKey($params);
        
        // Проверка кэша
        $cached = $this->cache->get($cache_key);
        if ($cached !== false) {
            error_log('[DELIVERY] Cache hit for key: ' . $cache_key);
            return $cached;
        }
        
        error_log('[DELIVERY] Cache miss for key: ' . $cache_key);
        
        // Расчёт через API CDEK
        $result = $this->cdek->calculateShipping($params);
        
        // Сохранение в кэш (1 час)
        $ttl = cmsConfig::get('delivery.cdek.cache_ttl', 3600);
        $this->cache->set($cache_key, $result, $ttl);
        
        // Сохранение в БД для долгосрочного хранения
        $this->saveToDatabaseCache($cache_key, $result, $ttl);
        
        return $result;
    }
    
    private function generateCacheKey($params) {
        $key_parts = [
            'method' => $params['tariff_id'] ?? 'default',
            'city' => md5($params['receiver_city_id']),
            'weight' => $params['weight'],
            'dimensions' => md5($params['length'] . $params['width'] . $params['height'])
        ];
        
        return 'shipping_calc_' . implode('_', $key_parts);
    }
}
```

### Кэширование в компоненте платежей (ЮKassa)

```php
class PaymentService {
    
    /**
     * Получение информации о платеже с кэшированием
     */
    public function getPaymentInfoCached($payment_id) {
        $cache_key = 'payment_info_' . $payment_id;
        
        // Попытка получить из кэша
        $cached = cmsCache::getInstance()->get($cache_key);
        if ($cached !== false) {
            return $cached;
        }
        
        // Запрос к API ЮKassa
        $client = $this->initYooKassaClient();
        $payment = $client->getPaymentInfo($payment_id);
        
        // Сохранение в кэш (5 минут)
        $data = [
            'id' => $payment->getId(),
            'status' => $payment->getStatus(),
            'paid' => $payment->getPaid(),
            'amount' => $payment->getAmount()->getValue(),
            'currency' => $payment->getAmount()->getCurrency(),
            'created_at' => $payment->getCreatedAt()
        ];
        
        cmsCache::getInstance()->set($cache_key, $data, 300);
        
        return $data;
    }
}
```

### Кэширование в компоненте импорта/экспорта

```php
class ExportService {
    
    /**
     * Экспорт с кэшированием результатов
     */
    public function exportWithCache($filters) {
        $cache_key = 'export_products_' . md5(serialize($filters));
        
        // Проверка кэша
        $cached = cmsCache::getInstance()->get($cache_key);
        if ($cached !== false) {
            return $cached;
        }
        
        // Генерация нового экспорта
        $export_file = $this->generateExport($filters);
        
        // Сохранение в кэш на 1 час
        cmsCache::getInstance()->set($cache_key, $export_file, 3600);
        
        return $export_file;
    }
}
```

## 40.8. Блокировки и согласованность

### Файловые блокировки для запланированных задач

Хотя платформа не является строго кэширующей системой, она использует блокировки на основе файлов для предотвращения одновременного выполнения запланированных задач, что связано с обеспечением согласованности кэша:

```php
// В скрипте cron.php или аналогичном
$lock_file = cmsConfig::get('cache_path') . 'cron_lock';
$lockfp = fopen($lock_file, 'w');

if (!$lockfp || !flock($lockfp, LOCK_EX | LOCK_NB)) {
    error_log('[CRON] Another instance is already running. Exiting.');
    exit(1);
}

// Гарантированная очистка блокировки при завершении
register_shutdown_function(function() use ($lockfp, $lock_file) {
    if ($lockfp) {
        flock($lockfp, LOCK_UN);
        fclose($lockfp);
        @unlink($lock_file);
    }
});
```

Это предотвращает:
- Состояние гонки во время обновления кэша
- Аннулирование дублирующихся данных в кэше
- Одновременную запись в одни и те же ключи кэша

<img src="https://github.com/DSTGlobal/DST-Platform/blob/main/images/251.png" alt="Файловые блокировки для запланированных задач">

### Путь кэша на основе файлов

При использовании файлового драйвера данные кэша хранятся в файловой системе. Платформа определяет каталог кэша:

```php
// Конфигурация файлового кэша
'cache' => [
    'driver' => 'files',
    'path' => PATH . '/cache/phpfastcache',
    'htaccess' => true,  // Создание .htaccess для защиты
    'securityKey' => 'dst_platform_cache'
]
```

Файлы блокировки, на которые ссылаются скрипты cron, указывают на то, что операции с файлами, связанные с кэшем, выполняются в корне проекта или в указанном каталоге кэша.

## 40.9. Расширенные возможности

### Кэширование с использованием тегов

PHPFastCache поддерживает тегирование элементов кэша для группового аннулирования:

```php
// Пример 1: Кэширование с тегами
$item = cmsCache::getInstance()->getItem('user_profile_' . $user_id);

if (!$item->isHit()) {
    $profile = $this->getUserProfile($user_id);
    $item->set($profile);
    $item->expiresAfter(3600); // 1 час
    
    // Добавление тегов
    $item->addTag('user_' . $user_id);
    $item->addTag('profiles');
    
    cmsCache::getInstance()->save($item);
}

$profile = $item->get();

// Пример 2: Аннулирование по тегу
cmsCache::getInstance()->deleteByTag('user_' . $user_id);
cmsCache::getInstance()->deleteByTag('profiles');

// Пример 3: Пакетное кэширование
$keys = ['key1', 'key2', 'key3'];
$items = cmsCache::getInstance()->getMultiple($keys);

foreach ($items as $key => $value) {
    if ($value === null) {
        // Кэш промахнулся, нужно загрузить данные
        $data = $this->loadData($key);
        cmsCache::getInstance()->set($key, $data, 3600);
    }
}
```

### Условное кэширование

```php
// Пример: Кэширование с проверкой условия
if (!cmsCache::getInstance()->has('expensive_calculation')) {
    $result = $this->performExpensiveCalculation();
    cmsCache::getInstance()->set('expensive_calculation', $result, 86400); // 24 часа
} else {
    $result = cmsCache::getInstance()->get('expensive_calculation');
}

// Пример: Условная инвалидация
if ($force_refresh) {
    cmsCache::getInstance()->delete('critical_data');
}
$cached = cmsCache::getInstance()->get('critical_data');
```

## 40.10. Интеграция со стандартами PSR

PHPFastCache реализует стандарты PSR-6 (кэш) и PSR-16 (простой кэш), предоставляя стандартные интерфейсы:

<img src="https://github.com/DSTGlobal/DST-Platform/blob/main/images/252.png" alt="DST Platform">

Соответствие стандартам:

- PSR-6 ( psr/cache ~1.0.0) - Сложное кэширование с использованием пулов элементов
- PSR-16 ( psr/simple-cache ~1.0.0) - Простые операции получения/установки/удаления

Эта стандартизация позволяет:

- Упрощенное тестирование с использованием фиктивных реализаций кэша.
- Возможна миграция на другие библиотеки кэша, совместимые с PSR.
- Взаимодействие с программными пакетами сторонних разработчиков.

| Практика | Обоснование |
|----------|-------------|
| **Использовать осмысленные ключи** | `shop_product_123` вместо `key1` |
| **Устанавливать адекватный TTL** | Баланс между свежестью и производительностью |
| **Аннулировать кэш при изменении данных** | Предотвращение устаревших данных |
| **Использовать теги для группового удаления** | Упрощение управления кэшем |

| **Использовать подстановочные символы** | Для массового аннулирования |

### ❌ Избегайте

| Антипаттерн | Риск |
|-------------|------|
| **Отсутствие аннулирования** | Устаревшие данные в кэше |
| **Слишком короткий TTL** | Частые промахи, нагрузка на БД |
| **Слишком длинный TTL** | Данные не обновляются своевременно |
| **Жёсткое кодирование путей** | Проблемы при развёртывании |
| **Отключение кэширования в продакшене** | Резкое падение производительности |
| **Игнорирование мониторинга** | Невозможность диагностики проблем |
