## 1.2. Идентичность платформы

DST Platform — это гибридная система на основе PHP, объединяющая:

Возможности CMS (система управления контентом) для контент-ориентированных веб-сайтов
CMF (Content Management Framework) , предоставляющий низкоуровневые API для пользовательской разработки.
Платформа обеспечивает поддержку проектов от блогов и защищенных сайтов до высоконагруженных социальных сетей, маркетплейсов, B2B-порталов и цифровых экосистем.

Основная философия: Платформа отказывается от дихотомии «простая CMS против сложного фреймворка», вместо этого учитывается многоуровневая модель разработки:

### Уровни разработки в DST Platform

| Уровень               | Подход                              | Сценарий использования                                |
|----------------------|-------------------------------------|--------------------------------------------------------|
| **Конфигурация**     | Настройка через админ-панель без кода | Создание стандартных сущностей: статьи, каталоги, страницы |
| **Расширение**       | Хуки, переопределение классов       | Модификация поведения существующих компонентов         |
| **Разработка**       | Полная реализация контроллеров и моделей | Реализация сложной бизнес-логики: платежи, доставка, интеграции |

## 1.3. Двойная архитектура: Социальная платформа + Бизнес-экосистема

DST Platform реализует архитектуру с двумя доменами, интегрирующую две разные парадигмы в одном ядре:

### Сравнение архитектуры

| Аспект                     | Социальный домен                                      | Бизнес-домен                                          |
|---------------------------|-------------------------------------------------------|-------------------------------------------------------|
| **Философия**             | Расширение Drupal-подобной модели сообщества          | Ориентация на коммерческие транзакции и процессы      |
| **Основная цель**         | Взаимодействие пользователей, UGC, вовлечение         | Автоматизация продаж, логистики, B2B-операций         |
| **Ключевые компоненты**   | `groups`, `forum`, `wall`, `photos`, `comments`, `activity` | `shop`, `partner`, `orders`, `delivery`, `payment`, `tenders` |
| **Типовые приложения**    | Соцсети, новостные порталы, образовательные платформы | Маркетплейсы, B2B-порталы, e-commerce, сервисные системы |
| **Модель данных**         | Пользовательский контент, активность, связи           | Товары, заказы, инвентарь, рабочие процессы           |

### Унифицированные базовые сервисы

## 1.4. Точки входа в систему

Платформа DST обрабатывает запросы через несколько точек входа, каждая из которых инициализирует ядро через общий загрузчик `bootstrap.php`.

<img src="https://dstglobal.ru/img/git/2.png" alt="DST Platform">

Диаграмма: Точки входа в систему, соответствующие файлам кода

### Точки входа

| Тип входа                     | Файл                      | Назначение                                              |
|------------------------------|---------------------------|---------------------------------------------------------|
| HTTP-запросы                 | `index.php`               | Фронт-контроллер для всех веб-запросов                  |
| Запланированные задачи       | `cron.php`                | Выполнение регулярных задач из очереди в БД             |
| Экспорт данных               | `cron_export.php`         | Автоматизированный экспорт данных в табличные форматы   |
| Генерация YML-фида (магазин) | `cron_yml_create.php`     | Формирование фида для Яндекс.Маркета (режим «магазин»)  |
| Генерация YML-фида (маркет)  | `cron_yml_market_create.php` | Формирование фида для Яндекс.Маркета (режим «маркет») |
| Импорт партнёрских данных    | `cron_partner_import.php` | Синхронизация данных от внешних поставщиков             |

> **Примечание.** Все точки входа загружают общий инициализационный скрипт `bootstrap.php`.

### Маршрутизация URL

Файл `.htaccess` в корне проекта перенаправляет все динамические запросы на `index.php`, при этом статические ресурсы обслуживаются напрямую:

- **Статические ресурсы** (`*.css`, `*.js`, изображения и т.п.) → отдаются веб-сервером без участия PHP.
- **Динамические запросы** → переписываются на `index.php` для обработки маршрутизатором платформы.

## 1.5. Слой базовых сервисов

Ядро платформы (`/system/core/`) реализует набор синглтон-классов, предоставляющих фундаментальные сервисы. Все классы следуют соглашению об именовании:

- **Имя файла**: `{classname}.php` (в нижнем регистре)
- **Имя класса**: `cms{ClassName}` (PascalCase)

### Базовые синглтон-сервисы 

<img src="https://dstglobal.ru/img/git/3.png" alt="DST Platform">

### Базовые сервисы

| Файл                      | Класс                | Ответственность                                                                 |
|--------------------------|----------------------|----------------------------------------------------------------------------------|
| `action.php`             | `cmsAction`          | Диспетчеризация действий контроллеров                                            |
| `backend.php`            | `cmsBackend`         | Базовый класс для контроллеров административной части                            |
| `cache.php`              | `cmsCache`           | Абстракция кэширования (поддержка файлового, in-memory и других драйверов)      |
| `config.php`             | `cmsConfig`          | Загрузка и управление глобальной конфигурацией (`/system/config/config.php`)     |
| `controller.php`         | `cmsController`      | Абстрактный базовый класс для всех контроллеров                                  |
| `core.php`               | `cmsCore`            | Центральный локатор сервисов и точка инициализации системы                       |
| `database.php`           | `cmsDatabase`        | Низкоуровневый интерфейс для работы с MySQL                                      |
| `eventsmanager.php`      | `cmsEventsManager`   | Система событий и хуков для межкомпонентного взаимодействия                      |
| `form.php`               | `cmsForm`            | Генерация, валидация и обработка HTML-форм                                       |
| `frontend.php`           | `cmsFrontend`        | Базовый класс для публичных (фронтенд) контроллеров                              |
| `mailer.php`             | `cmsMailer`          | Интеграция с PHPMailer для отправки электронной почты                            |
| `model.php`              | `cmsModel`           | Базовый класс моделей с поддержкой query builder и ORM-подобного доступа к данным|
| `permissions.php`        | `cmsPermissions`     | Система управления доступом на основе ролей (RBAC)                               |
| `request.php`            | `cmsRequest`         | Парсинг, фильтрация и санитизация входящих HTTP-данных                           |
| `template.php`           | `cmsTemplate`        | Рендеринг шаблонов, компоновка макетов, управление блоками                       |
| `uploader.php`           | `cmsUploader`        | Обработка загрузки файлов с валидацией по типу, размеру и безопасности           |
| `user.php`               | `cmsUser`            | Управление сессией, аутентификацией и данными текущего пользователя              |

> **Соглашение об автозагрузке.**  
> Классы из `/system/core/` загружаются автоматически по шаблону:  
> файл `{classname}.php` → класс `cms{ClassName}`.
