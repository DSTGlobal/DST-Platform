# 30. Frontend и ресурсы

В данном разделе описана архитектура уровня представления и система управления ресурсами в DST Platform: механизм рендеринга шаблонов, загрузка и обработка CSS/JavaScript, типографика, шрифты и оптимизация фронтенда.

**Область применения**: Данный раздел посвящён организации и доставке клиентских ресурсов (HTML, CSS, JS, шрифты). Подробнее о механизме рендеринга шаблонов — в разделе *«Система шаблонов»*. Полный жизненный цикл MVC-запроса описан в *«Паттерн MVC и жизненный цикл запроса»*.

## 30.1. Обзор архитектуры управления ресурсами

DST Platform реализует централизованную систему управления фронтенд-ресурсами через синглтон `cmsTemplate`. Все CSS, JavaScript и шрифты подключаются через специализированные методы, обеспечивающие:
- Корректное разрешение путей с учётом наследования тем
- Управление порядком загрузки
- Автоматическое кэширование и минификацию в production-режиме
- Предотвращение дублирования ресурсов

## 30.2. Организация ресурсов в структуре тем

Ресурсы распределены по каталогам тем с поддержкой наследования. Дочерние темы могут переопределять отдельные файлы, сохраняя остальные от родительской темы.

### Структура каталогов тем

```
/templates/
├── default/               # Базовая тема
│   ├── css/
│   ├── js/
│   ├── fonts/
│   ├── controllers/       # Ресурсы компонентов
│   │   └── shop/
│   │       ├── styles.css
│   │       └── scripts.js
│   └── widgets/           # Ресурсы виджетов
└── dark/                  # Дочерняя тема
    ├── inherit.php        # return 'default';
    └── css/
        └── style.css      # Переопределение только этого файла
```

## 30.3. Методы подключения ресурсов

Класс `cmsTemplate` предоставляет унифицированный API для безопасного подключения ресурсов. Все методы автоматически обрабатывают наследование тем и предотвращают дублирование.

### Справочник методов
| Метод | Назначение | Позиция в документе | Участвует в объединении |
|-------|------------|---------------------|--------------------------|
| `getTplFilePath($path)` | Разрешает путь с учётом наследования тем | — | Н/Д |
| `addMainCSS($path)` | Критические стили (рендеринг выше сгиба) | В `<head>`, начало стека | Да |
| `addCSS($path)` | Дополнительные стили | В `<head>`, конец стека | Опционально |
| `addControllerCSS($file, $component)` | Автозагрузка CSS компонента | В `<head>` | Да |
| `addMainJS($path)` | Критические скрипты (инициализация) | В `<head>` | Да |
| `addJS($path)` | Скрипты с отложенной загрузкой | Перед `</body>` | Да |
| `getLangJS($keys)` | Экспорт языковых констант в JS | Встроенный `<script>` в `<head>` | Нет |

### Пример использования в контроллере
```php
// В методе действия контроллера
$this->template->addCSS('templates/default/css/custom-page.css');
$this->template->addControllerCSS('styles.css', 'shop'); // Авто: /templates/{theme}/controllers/shop/styles.css
$this->template->addJS('templates/default/js/gallery.js');
$this->template->getLangJS(['LANG_SAVE', 'LANG_CANCEL', 'LANG_CONFIRM_DELETE']);
```

**Ключевые особенности:**
- `getTplFilePath()` проверяет текущую тему → родительскую тему (указанную в `inherit.php`)
- `addControllerCSS()` автоматически формирует путь к ресурсам компонента
- Все пути указываются относительно корня проекта
- Дубликаты автоматически фильтруются

## 30.4. CSS-фреймворк: кастомизация Bootstrap

DST Platform использует модифицированную версию **Bootstrap 4** с адаптацией под корпоративный стиль и требования проектов.

### Структура кастомизации

```
Базовый Bootstrap 4
    ↓
Кастомные переменные (цвета, шрифты, отступы)
    ↓
Переопределение компонентов (кнопки, формы, таблицы)
    ↓
Специфичные стили компонентов (shop, partner и др.)
```

<img src="https://github.com/DSTGlobal/DST-Platform/blob/main/images/176.png" alt="Архитектура CSS-фреймворка">

### Ключевые изменения
- **Цветовая схема**: `--primary: #5b88bd;`
- **Точки останова**: `xl` изменён с 1200px на **1400px** для поддержки широкоформатных десктопных макетов
- **Сетка**: 12-колоночная, адаптивная
- **Контейнеры**:
  - `.container` — фиксированная ширина по брейкпоинтам
  - `.container2` — полная ширина на всех разрешениях
  - `.container-fluid` — 100% ширина

## 30.5. Типографика и шрифтовая система

Платформа использует профессиональные веб-шрифты с полной поддержкой кроссбраузерности.

### Используемые шрифты
| Шрифт | Назначение | Варианты |
|-------|------------|----------|
| **GT Eesti Pro** | Основной текст, заголовки | Regular (400), Bold (700) |
| **Styrene A Web** | Таблицы, специальные элементы | 100–900 (6 весов × обычный/курсив = 12 вариантов) |

### Поддерживаемые форматы
- `.woff2` — основной формат (современные браузеры)
- `.woff` — fallback для старых браузеров
- `.ttf` — дополнительный fallback
- `.eot` — поддержка Internet Explorer (только Styrene A Web)

### Пример применения
```css
/* Основной текст */
body {
    font-family: "GT Eesti Pro", -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, sans-serif;
    color: #0b1f35;
}

/* Заголовки таблиц */
.table .thead-dark th {
    font-family: "Styrene A Web", sans-serif;
    font-size: 18px;
}
```

## 30.6. Оптимизация и обработка ресурсов

### Наследование тем и разрешение путей

Система автоматически ищет ресурс в текущей теме → родительской теме → базовой теме.  

<img src="https://github.com/DSTGlobal/DST-Platform/blob/main/images/178.png" alt="Процесс разрешения ресурсов">

### Стратегии оптимизации
| Механизм | Описание | Условия применения |
|----------|----------|---------------------|
| **Версионирование** | Добавление `?v={timestamp}` к URL | При изменении файла в production |
| **Объединение** | Сборка всех `addMainCSS()` в один файл | Production-режим, включено в настройках |
| **Минификация** | Удаление пробелов, комментариев | Production-режим |
| **Кэширование** | Сохранение объединённых файлов в `/cache/` | Автоматически после сборки |

## 30.8. Интернационализация в JavaScript

Механизм передачи языковых констант из PHP в клиентский JavaScript без дублирования файлов.

### Пример
```php
// В контроллере
$this->template->getLangJS(['LANG_DELETE', 'LANG_CONFIRM_DELETE']);
```
Генерирует:
```html
<script>
var LANG = {
    'LANG_DELETE': 'Удалить',
    'LANG_CONFIRM_DELETE': 'Вы уверены, что хотите удалить этот элемент?'
};
</script>
```
```javascript
// В клиентском скрипте
if (confirm(LANG.LANG_CONFIRM_DELETE)) {
    deleteItem();
}
```

**Рекомендация:** Передавайте только необходимые ключи для минимизации размера встроенного скрипта.

## 30.9. Статическая доставка ресурсов

### Каталоги и назначение
| Каталог | Содержимое | Обслуживание |
|---------|------------|--------------|
| `/css/` | Глобальные библиотеки (Bootstrap, шрифты) | Веб-сервер (статика) |
| `/fonts/` | Файлы шрифтов (woff2, woff, ttf, eot) | Веб-сервер (статика) |
| `/upload/` | Загруженные пользователем файлы | Веб-сервер (статика) |
| `/templates/{theme}/` | Ресурсы темы | `cmsTemplate` + наследование |
| `/cache/` | Объединённые/минифицированные файлы | Веб-сервер (с кэширующими заголовками) |

**Важно:** Все статические ресурсы обслуживаются напрямую веб-сервером (Apache/Nginx) без участия PHP, что критично для производительности. Правила настройки описаны в разделе *«Маршрутизация URL-адресов и настройка веб-сервера»*.

## 30.11. Рекомендации и лучшие практики

✅ **Используйте методы `cmsTemplate`**  
```php
// Вместо прямого тега в шаблоне:
$this->template->addCSS('templates/default/css/style.css');
```
*Почему:* Автоматическая обработка наследования, предотвращение дублей, поддержка минификации.

✅ **Размещайте ресурсы компонента в его каталоге**  
Файлы `styles.css` и `scripts.js` в `/templates/{theme}/controllers/{component}/` будут автоматически загружены через `addControllerCSS()`.

✅ **Управляйте порядком загрузки**  
- Критические стили → `addMainCSS()`
- Стили компонентов → `addControllerCSS()`
- Скрипты с отложенной загрузкой → `addJS()`

✅ **Минимизируйте объём `getLangJS()`**  
Передавайте только используемые в скрипте ключи.

✅ **Используйте наследование тем**  
Создайте `inherit.php` с `return 'default';` и переопределяйте только изменённые файлы.

## 30.12. Заключение

Архитектура фронтенда DST Platform обеспечивает:
1. **Централизованное управление** через `cmsTemplate` с защитой от ошибок
2. **Гибкое наследование тем** без дублирования кода
3. **Профессиональную типографику** с кроссбраузерной поддержкой шрифтов
4. **Изоляцию компонентов** через автозагрузку ресурсов
5. **Эффективную интернационализацию** JavaScript
6. **Готовность к оптимизации** (объединение, минификация, кэширование)

**Рекомендация для разработчиков:** При создании кастомных тем или расширении компонентов всегда используйте методы `cmsTemplate` и структуру каталогов, описанную в данном разделе. Это гарантирует совместимость с механизмами кэширования, обновлениями платформы и упростит поддержку проекта. Для углублённого изучения изучите реализацию базовой темы `/templates/default/` в исходном коде платформы.
