# 5. Маршрутизация URL-адресов и настройка веб-сервера

Этот документ описывает, как DST Platform обрабатывает входящие HTTP-запросы на уровне веб-сервера. Он охватывает конфигурацию Apache, правила перезаписи URL через `.htaccess`, механизм фронт-контроллера и разграничение между статической и динамической обработкой запросов.

Информацию о последующей инициализации приложения см. в разделе **«Загрузка и инициализация системы»**.  
О жизненном цикле запроса на уровне PHP — в **«Шаблон MVC и жизненный цикл запроса»**.  
О компонентной маршрутизации — в **«Система компонентов»**.

---

## 5.1. Общая архитектура маршрутизации

DST Platform использует **единый фронт-контроллер** (`index.php`) для обработки всех динамических запросов. Статические ресурсы (CSS, JS, изображения) обслуживаются напрямую веб-сервером без участия PHP.

Архитектура обеспечивает:
- Чёткое разделение ответственности: веб-сервер — маршрутизация и безопасность; приложение — бизнес-логика.
- SEO-дружественные URL без расширений.
- Централизованную инициализацию и безопасность.
- Высокую производительность за счёт прямой отдачи статики.

## 5.2. Требования к веб-серверу

### Поддерживаемый сервер
- **Apache HTTP Server** с включённым модулем `mod_rewrite`.

### Обязательные модули
| Модуль | Назначение | Статус |
|--------|------------|--------|
| `mod_rewrite` | Перезапись URL и маршрутизация | Обязательный |
| `mod_headers` | Управление HTTP-заголовками | Рекомендуется |
| `mod_deflate` | Сжатие ответов (gzip) | Рекомендуется |
| `mod_expires` | Кэширование статических ресурсов | Рекомендуется |

Проверка наличия модуля:

```bash
apache2ctl -M | grep rewrite
```

### Конфигурация виртуального хоста
Директива `AllowOverride` должна быть установлена в `All`:

```apache
<Directory "/var/www/your-site">
    AllowOverride All
    Require all granted
</Directory>
```

Без этого `.htaccess` игнорируется.

## 5.3. Файл `.htaccess`: структура и функции

Файл `.htaccess` в корне проекта реализует **каскадную последовательность правил**, выполняемых сверху вниз. Первое совпадающее правило с флагом `[L]` прекращает обработку.

### Основные функции
| Функция | Реализация |
|--------|------------|
| Кодировка по умолчанию | `AddDefaultCharset utf-8` |
| Отключение листинга каталогов | `Options -Indexes` |
| Канонизация домена | Перенаправление `www` → без `www` |
| Безопасность | Блокировка доступа к конфиденциальным файлам |
| Нормализация URL | Удаление завершающего `/` |
| Обслуживание карт сайта | Прямая отдача из кэша |
| Фронт-контроллер | Перенаправление динамических запросов на `index.php` |

## 5.4. Правила перезаписи

DST Platform реализует каскадную последовательность правил перезаписи URL-адресов, которые обрабатывают запросы в определенном порядке. Каждое правило оценивается последовательно, и как только обнаруживается совпадение с [L] флагом (Последний), обработка прекращается.

Схема обработки правил

<img src="https://github.com/DSTGlobal/DST-Platform/blob/main/images/21.png" alt="DST Platform">

### 1. Канонизация домена (без `www`)
```apache
RewriteCond %{HTTP_HOST} ^www\.(.+)$ [NC]
RewriteRule ^ https://%1%{REQUEST_URI} [R=301,L]
```
- **Цель**: единый канонический домен для SEO.
- **Код ответа**: `301 Permanent Redirect`.

### 2. Принудительное HTTPS (опционально)
```apache
# RewriteCond %{HTTPS} !=on
# RewriteRule ^ https://%{HTTP_HOST}%{REQUEST_URI} [R=301,L]
```
- По умолчанию закомментировано (для поддержки dev-сред).
- Раскомментируйте в production.

### 3. Безопасность: блокировка конфиденциальных файлов
```apache
RewriteRule ^(?:\.htaccess|credits\.txt|readme\.txt|license\..*\.txt)$ - [F]
```
- Возвращает статус `403 Forbidden`.
- Защищает: `.htaccess`, `credits.txt`, `readme.txt`, `license.*.txt`.

### 4. Нормализация URL (удаление завершающего `/`)
```apache
RewriteCond %{REQUEST_FILENAME} !-d
RewriteRule ^(.+)/$ /$1 [R=301,L]
```
- Применяется только если путь **не является физическим каталогом**.
- Пример: `/shop/` → `/shop`.

### 5. Обслуживание карт сайта из кэша
```apache
RewriteRule ^sitemap(.*).xml$ ./cache/static/sitemaps/sitemap$1.xml [L]
```
- Обходит PHP и фронт-контроллер.
- Поддерживает: `sitemap.xml`, `sitemap-products.xml`, `sitemap-news.xml` и др.
- Требует предварительной генерации файлов в `/cache/static/sitemaps/`.

### 6. Фронт-контроллер
```apache
RewriteCond %{REQUEST_FILENAME} !-f
RewriteCond %{REQUEST_FILENAME} !-d
RewriteRule ^ index.php [QSA,L]
```
- Условия: запрос не к файлу (`!-f`) и не к каталогу (`!-d`).
- Все остальные запросы передаются в `index.php`.
- Исходный URI сохраняется в `$_SERVER['REQUEST_URI']`.

## 5.5. Шаблон фронт-контроллера

Все динамические запросы обрабатываются через **единую точку входа** — `index.php`.

### Преимущества
| Преимущество | Реализация |
|-------------|------------|
| Централизованная инициализация | Единый `bootstrap.php` |
| Единая точка аутентификации | Проверка сессии в одном месте |
| Независимость URL от структуры кода | ЧПУ без привязки к файлам |
| Упрощённое тестирование | Интеграционные тесты через один вход |
| Централизованное логирование | Все запросы проходят через `index.php` |

### Передача данных в PHP
После перезаписи в `index.php` доступны:
- `$_SERVER['REQUEST_URI']` — исходный путь (например, `/shop/item/123`)
- `$_SERVER['QUERY_STRING']` — параметры после `?`
- `$_SERVER['HTTP_HOST']` — домен

Эти данные используются маршрутизатором приложения для определения компонента и действия.

### Запрос переменных

## 5.6. Статическая vs динамическая обработка

Система маршрутизации различает статические и динамические запросы для оптимизации производительности:

### Обработка статических ресурсов

<img src="https://github.com/DSTGlobal/DST-Platform/blob/main/images/23.png" alt="DST Platform">

Статические ресурсы полностью обходят PHP:

- CSS-файлы (например, /template/css/bootstrap.css)
- Файлы JavaScript (например, /template/js/app.js)
- Изображения (например, /upload/images/product.jpg)
- Шрифты (например, /template/fonts/GTEestiProDisplay-Regular.woff2)
- Загруженные файлы (например, /upload/attachments/document.pdf)

Влияние на производительность:

- Отсутствие накладных расходов на выполнение PHP.
- Запросы к базе данных не требуются.
- Инициализация сессии не выполняется
- Файловая система напрямую считывается Apache.
- Поддерживает заголовки кэширования браузера.

### Динамическая обработка запросов

<img src="https://github.com/DSTGlobal/DST-Platform/blob/main/images/24.png" alt="DST Platform">

Динамические запросы выполняют весь стек приложения:

1. Apache переписывает в index.php .htaccess
2. index.php загрузка bootstrap.php (см. Загрузка и инициализация системы )
3. Bootstrap инициализирует основные сервисы. bootstrap.php
4. Приложение анализирует URL-адрес и перенаправляет его на контроллер компонента.

| Характеристика | Статические ресурсы | Динамические запросы |
|----------------|---------------------|----------------------|
| Примеры | `/css/style.css`, `/upload/images/logo.png` | `/shop`, `/user/profile` |
| Обработка | Напрямую Apache | Через `index.php` |
| Инициализация PHP | Нет | Полная загрузка ядра |
| Доступ к БД | Нет | Да |
| Сессия | Нет | Да (если `SESSION_START`) |
| Производительность | Высокая (без накладных расходов) | Зависит от логики |
| Кэширование | Через `Cache-Control`, `Expires` | Через `cmsCache` |

## 5.8. Требования к конфигурации

### Модули Apache

Для работы платформы DST требуются следующие модули Apache:

Модуль | Цель | Необходимый

mod_deflate | Сжатие ответа | Рекомендуется
mod_expires | Заголовки управления кэшем | Рекомендуется

Проверка:

```

```

## 5.9. Права доступа к файловой системе

| Путь | Права | Назначение |
|------|-------|------------|
| `.htaccess` | `644` | Чтение Apache |
| `index.php` | `644` | Выполнение фронт-контроллера |
| `cache/` | `775` | Запись карт сайта, кэш-файлов |
| `upload/` | `775` | Загрузка пользовательских файлов |

> **Примечание**: права `775` требуют, чтобы владелец каталога совпадал с пользователем веб-сервера или находился в той же группе.

## 5.10. Типичные сценарии настройки

### Включение HTTPS
Раскомментируйте в `.htaccess`:

```apache
RewriteCond %{HTTPS} !=on
RewriteRule ^ https://%{HTTP_HOST}%{REQUEST_URI} [R=301,L]
```

Разместите правило **после** канонизации домена, но **до** правил безопасности.

### Блокировка дополнительных файлов
Добавьте после строки с `.htaccess`:

```apache
RewriteRule ^config\.php$ - [F]
```

### Поддержка кастомных карт сайта
Добавьте правило:

```apache
RewriteRule ^sitemap-([a-z]+)\.xml$ ./cache/static/sitemaps/sitemap-$1.xml [L]
```
Поддерживает: `sitemap-products.xml`, `sitemap-blog.xml` и т.д.

## 5.11. Интеграция с процессом инициализации

После перенаправления на `index.php` происходит:

1. `index.php` определяет `SESSION_START = true`
2. Подключает `bootstrap.php`
3. `bootstrap.php` инициализирует:
   - автозагрузку,
   - конфигурацию,
   - БД,
   - кэш,
   - сессию (если требуется)
4. Управление возвращается в `index.php` для маршрутизации на уровне приложения

Таким образом, `.htaccess` отвечает за **транспортный уровень**, а `bootstrap.php` — за **инициализацию среды выполнения**.

Ключевые моменты передачи информации:

1. .htaccess сохраняет REQUEST_URI в $_SERVER сверхглобальном масштабе
2. index.php включает bootstrap.php в себя инициализацию системы
3. Bootstrap устанавливает среду выполнения (кодировку, часовой пояс, автозагрузку).
4. Bootstrap инициализирует основные сервисы (конфигурацию, базу данных, кэш).
5. Управление возвращается index.php для маршрутизации на уровне приложения.

## 5.13. Диагностика и устранение неполадок

### Распространённые проблемы

| Проблема | Симптом | Причина | Решение |
|---------|--------|--------|--------|
| Все страницы — 404 | Работают только `/` и статика | `mod_rewrite` не включён | `a2enmod rewrite && systemctl restart apache2` |
| `.htaccess` игнорируется | Правила не применяются | `AllowOverride None` | Установить `AllowOverride All` в виртуальном хосте |
| Циклические редиректы | Бесконечный редирект на `/` | Отсутствует условие `!-d` | Проверить правило нормализации URL |
| CSS/JS не загружаются | Ошибки 404 на статику | Неверные пути или права | Убедиться, что файлы существуют и доступны |

### Методы диагностики

1. **Проверка синтаксиса `.htaccess`**:
   ```bash
   apachectl configtest
   ```

2. **Логирование перезаписи** (временно):
   ```apache
   LogLevel alert rewrite:trace3
   ```
   Логи: `tail -f /var/log/apache2/error.log`

3. **Проверка `REQUEST_URI` в `index.php`**:
   ```php
   // Временно добавить в начало index.php
   error_log('URI: ' . $_SERVER['REQUEST_URI']);
   ```

## 5.12. Заключение

Архитектура маршрутизации DST Platform:
- Использует **Apache + mod_rewrite** как основу.
- Реализует **каскадные правила** в `.htaccess` с чётким порядком.
- Обеспечивает **SEO-оптимизацию** (канонизация, нормализация).
- Повышает **безопасность** (блокировка конфиденциальных файлов).
- Максимизирует **производительность** (прямая отдача статики, кэширование карт сайта).
- Интегрируется с **процессом инициализации** через единый фронт-контроллер.

Эта модель разделяет задачи веб-сервера и приложения, обеспечивая масштабируемость, безопасность и удобство сопровождения.
