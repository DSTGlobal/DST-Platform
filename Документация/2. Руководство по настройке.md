# 2. Руководство по настройке

Этот документ описывает процесс развёртывания и первоначальной настройки DST Platform. Он включает системные требования, этапы установки, инициализацию ядра, управление конфигурацией и диагностику типичных проблем. Для углублённого изучения отдельных подсистем см.:
- Управление зависимостями
- Инициализация и настройка системы
- Маршрутизация URL и настройка веб-сервера

---

## 2.1. Системные требования

Для корректной работы платформы требуется следующая среда:

| Требование        | Спецификация                     | Примечание |
|-------------------|----------------------------------|------------|
| PHP               | 7.0 или выше                     | Требуется для `phpfastcache` и других зависимостей |
| Веб-сервер        | Apache с включённым `mod_rewrite`| Необходим для обработки ЧПУ через `.htaccess` |
| База данных       | MySQL 5.0+ или MariaDB           | Основное хранилище реляционных данных |
| Composer          | Последняя стабильная версия      | Управление сторонними пакетами |

### Обязательные расширения PHP

| Расширение     | Назначение                          | Используется в |
|----------------|-------------------------------------|----------------|
| `mbstring`     | Работа с многобайтовыми строками    | Ядро, `phpfastcache` |
| `json`         | Кодирование/декодирование JSON      | Все SDK, API |
| `curl`         | HTTP-запросы                        | Guzzle, CDEK, ЮKassa |
| `openssl`      | SSL/TLS для безопасных соединений   | Composer, внешние API |
| `libxml`       | Парсинг XML                         | CDEK SDK |
| `simplexml`    | Работа с XML                        | CDEK SDK, YML-фиды |

### Опциональные расширения (для производительности)

| Расширение     | Назначение                          | Выгода |
|----------------|-------------------------------------|--------|
| `redis`        | Драйвер кэша Redis                  | Высокопроизводительное кэширование |
| `memcached`    | Драйвер кэша Memcached              | Распределённое кэширование |
| `maxminddb`    | Геолокация по IP (GeoIP)            | Ускорение определения региона |

## 2.2. Этапы установки

### Шаг 1. Распаковка архива
Распакуйте предоставленный архив в рабочую директорию веб-сервера.

### Шаг 2. Установка зависимостей через Composer
Выполните в корне проекта:

```bash
# Если используется глобальный Composer
composer install

# Или, если используется локальный composer.phar
php composer.phar install
```

Это создаст каталог `vendor/` и сгенерирует автозагрузчик `vendor/autoload.php`.

#### Установленные зависимости

| Пакет                          | Версия    | Назначение |
|-------------------------------|-----------|------------|
| `box/spout`                   | ^3.3      | Экспорт/импорт Excel, CSV |
| `sanmai/cdek-sdk`             | ^0.6.22   | Интеграция с CDEK |
| `guzzlehttp/guzzle`           | ~6.0      | HTTP-клиент для API |
| `geoip2/geoip2`               | ~2.0      | Геолокация по IP |
| `phpfastcache/phpfastcache`   | ^7.1      | Абстракция кэширования |
| `yoomoney/yookassa-sdk-php`   | ^2.1      | Платежи через ЮKassa |

### Шаг 3. Настройка подключения к базе данных
Отредактируйте основной конфигурационный файл:

```
/system/config/config.php
```

Укажите параметры подключения:

```php
return [
    'database' => [
        'host'     => 'localhost',
        'name'     => 'your_db_name',
        'user'     => 'your_db_user',
        'pass'     => 'your_db_password',
        'charset'  => 'utf8mb4',
    ],
    // остальные параметры...
];
```

> **Важно**: Файл `database.php` не используется. Вся конфигурация — в `config.php`.

### Шаг 4. Настройка прав доступа
Убедитесь, что веб-сервер может записывать в следующие каталоги:

```bash
chmod -R 775 cache/ upload/ exports/
```

Если владелец файлов отличается от пользователя веб-сервера, также выполните:

```bash
chown -R www-data:www-data cache/ upload/ exports/
```

(Замените `www-data` на актуального пользователя, например `nginx` или `apache`.)

### Шаг 5. Настройка веб-сервера
Убедитесь, что:
- Включён модуль `mod_rewrite`.
- Разрешено чтение `.htaccess` (директива `AllowOverride All` в виртуальном хосте).

Файл `.htaccess` уже содержит правила для маршрутизации динамических запросов на `index.php`.

### Шаг 6. Запуск веб-установщика
Если система не установлена, первый запрос к корню сайта автоматически перенаправит на `/install/`.  
Следуйте инструкциям установщика для:
- Создания таблиц в БД
- Настройки учётной записи администратора
- Конфигурирования начальных параметров

После завершения **удалите каталог `install/`**.

## 2.3. Процесс инициализации

Диаграмма последовательности

<img src="https://dstglobal.ru/img/git/11.png" alt="DST Platform">

Каждый запрос (HTTP или CLI) проходит через единый бутстрап-процесс:

1. Загрузка автозагрузчика Composer (`vendor/autoload.php`)
2. Инициализация `cmsConfig` → чтение `config.php`
3. Создание экземпляра `cmsCore` (service locator)
4. Подключение к БД через `cmsDatabase`
5. Инициализация кэша (`cmsCache`)
6. Запуск системы событий (`cmsEventsManager::hook('core_start')`)
7. (Для HTTP) Инициализация сессии через `cmsUser`

## 2.4. Управление конфигурацией

Ключевые параметры конфигурации, доступные во время загрузки системы:

<img src="https://dstglobal.ru/img/git/9.png" alt="DST Platform">

Основной конфигурационный файл:  
`/system/config/config.php`

Ключевые параметры:

| Параметр      | Тип    | Описание |
|---------------|--------|----------|
| `debug`       | bool   | Включает режим отладки: отображение ошибок, логирование |
| `time_zone`   | string | Часовой пояс приложения (например, `'Europe/Moscow'`) |
| `is_installed`| bool   | Флаг завершённой установки (устанавливается автоматически) |

Если `debug = false`, ошибки PHP подавляются (`error_reporting(0)`).  
Если система не установлена (`is_installed = false`), все запросы перенаправляются на `/install/`.

## 2.5. Архитектура автозагрузки

Иерархия автозагрузчика

<img src="https://dstglobal.ru/img/git/10.png" alt="DST Platform">

Платформа использует **два уровня автозагрузки**:

| Уровень                | Источник                     | Отвечает за |
|------------------------|------------------------------|-------------|
| Composer (PSR-4)       | `vendor/autoload.php`        | Сторонние пакеты и пользовательские namespace (например, `shopUtils\`) |
| Пользовательский loader| `system/config/autoload.php` | Core-классы (`cms*`) из `/system/core/` |

Пример PSR-4-отображения в `composer.json`:

```json
"autoload": {
    "psr-4": {
        "shopUtils\\": "system/utils/shop/"
    }
}
```

Core-классы загружаются по соглашению:  
файл `/system/core/action.php` → класс `cmsAction`.

## 2.7. Подключение к базе данных и кэширование

После инициализации `cmsConfig` создаётся соединение с БД через `cmsDatabase`.

Поток подключения к базе данных

<img src="https://dstglobal.ru/img/git/12.png" alt="DST Platform">
  
При ошибке подключения:
- Загружаются языковые файлы
- Отображается сообщение об ошибке
- Выполнение прерывается

### Кэширование

Инициализируется после подключения к БД:

```php
cmsCache::getInstance()->start();
```

Поддерживаемые драйверы (в порядке приоритета):
- Redis (`ext-redis`)
- Memcached (`ext-memcached`)
- APCu (`ext-apcu`)
- Файлы (по умолчанию, каталог `cache/`)

Конфигурация кэша — в `config.php` (секция `'cache'`).

## 2.8. Инициализация системы событий

На раннем этапе вызывается:

```php
cmsEventsManager::hook('core_start');
```

Это позволяет компонентам:
- Регистрировать дополнительные автозагрузчики
- Инициализировать внешние сервисы
- Настраивать обработчики ошибок

Обработчики определяются в файлах `hooks.php` внутри компонентов.

## 2.10. Структура каталогов

Основные каталоги

<img src="https://dstglobal.ru/img/git/14.png" alt="DST Platform">

| Каталог           | Назначение                          | Требуются права на запись |
|--------------------|-------------------------------------|----------------------------|
| `/system/`         | Ядро платформы                      | Нет |
| `/system/controllers/` | Компоненты (MVC)                | Нет |
| `/system/config/`  | Конфигурационные файлы              | Только для генерируемых файлов |
| `/vendor/`         | Зависимости Composer                | Нет |
| `/upload/`         | Файлы, загруженные пользователями   | Да |
| `/cache/`          | Кэш и временные файлы               | Да |
| `/exports/`        | Сгенерированные файлы (CSV, YML)    | Да |
| `/install/`        | Веб-установщик                      | Удалить после установки |

Каталоги `cache/`, `upload/`, `exports/`, `vendor/` должны быть исключены из Git.

## 2.11. Константы и пути

В `bootstrap.php` определяются:

| Константа       | Значение                     | Использование |
|-----------------|------------------------------|---------------|
| `PATH`          | Абсолютный путь к корню      | Все `include` и `require` |
| `SESSION_START` | Определяется в точках входа  | Управление инициализацией сессии |

Пример в `index.php`:

```php
define('SESSION_START', true);
require_once 'bootstrap.php';
```

В CLI-скриптах (`cron_*.php`) эта константа **не определяется**.

## 2.12. Управление сессиями

Сессия инициализируется только если определена `SESSION_START`:

```php
if (defined('SESSION_START')) {
    cmsUser::sessionStart();
}
```

Особенности:
- Поддержка кастомного домена cookie
- Сохранение часового пояса пользователя в сессии
- Не используется в фоновых задачах

## 2.13. Диагностика после установки

### Проверка работоспособности
1. Откройте главную страницу — должен отобразиться сайт.
2. Убедитесь, что нет «белого экрана».

### Проверка зависимостей
```bash
ls -la vendor/
```
Ожидаемые каталоги: `box/`, `guzzlehttp/`, `geoip2/`, `phpfastcache/`, `sanmai/`, `yoomoney/`.

### Проверка подключения к БД
- Убедитесь, что MySQL запущена
- Проверьте логин/пароль в `config.php`
- Убедитесь, что пользователь имеет права на БД

### Проверка прав доступа
```bash
ls -la cache/ upload/ exports/
```
Каталоги должны быть доступны для записи веб-серверу.

## 2.14. Устранение распространённых проблем

| Проблема                              | Причина возможная                          | Решение |
|---------------------------------------|--------------------------------------------|---------|
| Пустая страница («белый экран»)       | Подавлены ошибки PHP                       | Включите `debug = true` в `config.php` |
| Ошибка подключения к БД               | Неверные данные в `config.php`             | Проверьте параметры подключения |
| `Class not found`                     | Отсутствует `vendor/` или автозагрузчик   | Выполните `composer install` |
| Ошибки записи в `cache/` или `upload/`| Недостаточные права                        | `chmod -R 775` + `chown` при необходимости |
| Предупреждения о часовом поясе        | Не задан `date.timezone` в PHP или `time_zone` в конфиге | Укажите `'time_zone' => 'UTC'` в `config.php` |
