# 39. Система типов контента

Система типов контента (Content Type System) — это декларативная подсистема управления контентом DST Platform, позволяющая администраторам создавать структурированные сущности без написания PHP-кода. Через веб-интерфейс определяются схемы данных, формы ввода и шаблоны отображения, что обеспечивает быстрое развёртывание контент-ориентированных функций.

Для создания пользовательских компонентов с императивным кодом см. раздел *«Создание компонентов»*. Для расширения типов контента через хуки см. раздел *«Работа с хуками»*.

---

## 39.1. Декларативная и императивная разработка

DST Platform поддерживает два взаимодополняющих подхода к разработке:

| Аспект | Декларативный (типы контента) | Императивный (компоненты) |
|--------|-------------------------------|---------------------------|
| **Точка входа** | Админка → Генератор типов контента | PHP-код в `/system/controllers/{name}/` |
| **Схема данных** | Визуальный конструктор полей | Ручное создание таблиц + методы модели |
| **Формы** | Автогенерация на основе схемы | `cmsForm` подклассы или ручной HTML |
| **Шаблоны** | Выбор из доступных вариантов | Пользовательские `.tpl.php` файлы |
| **Бизнес-логика** | CRUD-операции | Произвольный PHP-код |
| **Время прототипирования** | Минуты | От часов до дней |
| **Гибкость** | Ограничена моделью контента | Без ограничений |
| **Идеальное применение** | Статьи, каталоги, справочники | Электронная коммерция, форумы, сложные рабочие процессы |

**Ключевой принцип:** Подходы не конкурируют, а дополняют друг друга. Можно начать с типа контента для быстрого MVP, затем добавить пользовательский компонент для сложных функций и связать их через хуки.

## 39.3. Метаданные типов контента

Каждый тип контента определяется записью в таблице `content_types`:

| Поле | Тип | Описание | Пример |
|------|-----|----------|--------|
| `name` | VARCHAR(50) | Системное имя (латиница, нижний регистр) | `news`, `articles`, `products` |
| `title` | VARCHAR(255) | Отображаемое название | "Новостные статьи" |
| `description` | TEXT | Описание типа контента | "Публикации новостей компании" |
| `is_date_appended` | TINYINT(1) | Добавлять дату к URL | 1 |
| `is_cats` | TINYINT(1) | Включить категории | 1 |
| `is_tags` | TINYINT(1) | Включить теги | 1 |
| `is_comments` | TINYINT(1) | Включить комментарии | 1 |
| `is_rating` | TINYINT(1) | Включить рейтинг | 0 |
| `is_trash` | TINYINT(1) | Включить корзину | 1 |
| `item_append_html` | VARCHAR(50) | Суффикс шаблона элемента | `_view` |
| `options` | TEXT (JSON) | Сериализованные настройки | `{"cache_ttl": 3600}` |

### Динамическая генерация таблиц

При создании типа контента `articles` система автоматически создаёт:

| Таблица | Назначение | Ключевые столбцы |
|---------|------------|------------------|
| `content_articles` | Основное хранилище | `id`, `user_id`, `date_pub`, `title`, `slug`, `content`, `is_published`, `is_deleted` |
| `content_articles_cats` | Привязка категорий | `item_id`, `category_id` |
| `content_articles_props` | Расширенные свойства | `item_id`, `field_name`, `field_value` |

**Стандартные системные столбцы:**
- `id` — первичный ключ
- `user_id` — автор контента
- `date_pub` — дата публикации
- `date_last_modified` — дата последнего изменения
- `title` — заголовок
- `slug` — человекочитаемый URL
- `content` — основной текст (для текстовых типов)
- `is_published` — статус публикации
- `is_deleted` — флаг удаления (мягкое удаление)
- `rating` — рейтинг элемента
- `hits` — счётчик просмотров

### Интерфейс класса поля

Все классы полей в `/system/fields/` должны реализовывать:

| Метод | Назначение |
|-------|------------|
| `render()` | Генерация HTML для формы ввода |
| `parse($value)` | Обработка данных из формы |
| `store($value)` | Подготовка данных для сохранения в БД |
| `load($value)` | Загрузка данных из БД |
| `validate($value)` | Применение правил валидации |
| `getFilterInput()` | Создание UI фильтра для списков |
| `applyFilter($query, $value)` | Применение фильтра к запросу |

### Пример пользовательского типа поля

```php
// Файл: /system/fields/geolocation.php
class fieldGeolocation extends cmsFormField {
    
    public $title = 'Geographic Location';
    public $sql = 'VARCHAR(255) DEFAULT NULL'; // Тип столбца в БД
    
    /**
     * Валидация формата: "широта,долгота"
     */
    public function parse($value) {
        if (empty($value)) {
            return null;
        }
        
        // Проверка формата "55.7558,37.6173"
        if (!preg_match('/^-?\d+\.\d+,-?\d+\.\d+$/', $value)) {
            $this->addError('Неверный формат координат. Используйте: широта,долгота');
            return null;
        }
        
        return $value;
    }
    
    /**
     * Генерация интерфейса выбора на карте
     */
    public function render($options = []) {
        $value = $this->value;
        
        // Загрузка шаблона поля
        return $this->renderTemplate('field_geolocation', [
            'field' => $this,
            'value' => $value,
            'name' => $this->name,
            'id' => $this->id
        ]);
    }
    
    /**
     * Применение фильтра по радиусу
     */
    public function applyFilter($model, $value) {
        if (empty($value['radius']) || empty($value['center'])) {
            return $model;
        }
        
        // Расчёт координат для прямоугольной области
        list($lat, $lng) = explode(',', $value['center']);
        $radius_km = $value['radius'];
        
        // Приблизительный расчёт (1 градус ≈ 111 км)
        $lat_delta = $radius_km / 111;
        $lng_delta = $radius_km / (111 * cos(deg2rad($lat)));
        
        $model->filterGte('latitude', $lat - $lat_delta);
        $model->filterLte('latitude', $lat + $lat_delta);
        $model->filterGte('longitude', $lng - $lng_delta);
        $model->filterLte('longitude', $lng + $lng_delta);
        
        return $model;
    }
}
```

Диаграмма: Обработка запросов по типам контента

### Этапы обработки

1. **Загрузка схемы**: Контроллер считывает определение типа контента из `content_types`
2. **Увлажнение полей**: Модель использует определения из `content_fields` для интерпретации столбцов БД
3. **Стратегия кэширования**: Списки и элементы кэшируются по типам и категориям
4. **Генерация форм**: `cmsForm` динамически создаёт формы на основе схемы полей
5. **Конвейер валидации**: Каждый тип поля проверяется по своим правилам
6. **Сохранение данных**: Модель сохраняет обработанные данные в `content_{type}` таблицах
7. **Вызов хуков**: Система событий уведомляет зарегистрированные обработчики

## 39.8. Шаблоны типов контента

### Иерархия поиска шаблонов

Система ищет шаблоны по следующему пути (в порядке приоритета):

```
1. /templates/{theme}/content/{ctype_name}/       ← Специфичные для типа контента
2. /templates/{theme}/controllers/content/        ← Общие для компонента контента
3. /templates/default/content/{ctype_name}/       ← Базовая тема, специфичная для типа
4. /templates/default/controllers/content/        ← Резервные универсальные шаблоны
```

### Стандартные шаблоны

| Шаблон | Назначение | Переменные |
|--------|------------|------------|
| `list.tpl.php` | Список категорий (страница категории) | `$items`, `$category`, `$pagination` |
| `list_simple.tpl.php` | Упрощённый список (виджеты) | `$items`, `$ctype` |
| `item.tpl.php` | Детальный просмотр (страница элемента) | `$item`, `$ctype`, `$user` |
| `item_edit.tpl.php` | Форма редактирования | `$form`, `$item`, `$ctype` |

## 39.10. Система хуков для типов контента

### Доступные точки расширения

Компонент `content` генерирует события в ключевых точках жизненного цикла:

| Хук | Время вызова | Параметры | Назначение |
|-----|--------------|-----------|------------|
| `content_before_add` | Перед INSERT | `$item`, `$ctype_name` | Модификация данных перед сохранением |
| `content_after_add` | После INSERT | `$item`, `$ctype_name` | Действия после создания |
| `content_before_update` | Перед UPDATE | `$item`, `$old_item`, `$ctype_name` | Предварительная проверка обновления |
| `content_after_update` | После UPDATE | `$item`, `$old_item`, `$ctype_name` | Синхронизация связанных данных |
| `content_before_delete` | Перед удалением | `$item_id`, `$ctype_name` | Каскадные операции |
| `content_after_delete` | После удаления | `$item_id`, `$ctype_name` | Задачи по уборке |
| `content_list_filter` | При построении запроса списка | `$model`, `$ctype_name` | Модификация запросов к спискам |
| `content_item_html` | Перед рендерингом шаблона | `$html`, `$item`, `$ctype_name` | Преобразование вывода HTML |

### Примеры использования хуков

#### Пример 1: Уведомление редакторов о публикации статьи

```php
// Файл: /system/controllers/article_notifier/hooks.php
class article_notifier extends cmsAction {
    
    /**
     * Уведомление редакторов при публикации статьи
     */
    public function hookContentAfterAdd($item, $ctype_name) {
        // Обрабатываем только тип "articles"
        if ($ctype_name !== 'articles') {
            return $item;
        }
        
        // Отправляем уведомление только при публикации
        if ($item['is_published']) {
            $this->notifyEditors($item);
        }
        
        return $item;
    }
    
    /**
     * Логирование изменений заголовка
     */
    public function hookContentBeforeUpdate($item, $old_item, $ctype_name) {
        if ($ctype_name === 'articles' && 
            $item['title'] !== $old_item['title']) {
            
            $this->logTitleChange(
                $old_item['id'],
                $old_item['title'], 
                $item['title']
            );
        }
        
        return $item;
    }
    
    /**
     * Отправка уведомлений редакторам
     */
    private function notifyEditors($article) {
        // Получение списка редакторов
        $editors = $this->model->getUsersByGroup('editors');
        
        foreach ($editors as $editor) {
            $this->sendNotification($editor['id'], [
                'type' => 'new_article',
                'article_id' => $article['id'],
                'article_title' => $article['title'],
                'author' => $article['user']['nickname']
            ]);
        }
    }
    
    /**
     * Логирование изменений заголовка
     */
    private function logTitleChange($article_id, $old_title, $new_title) {
        $this->model->insert('article_title_changes', [
            'article_id' => $article_id,
            'old_title' => $old_title,
            'new_title' => $new_title,
            'changed_by' => $this->cms_user->id,
            'changed_at' => date('Y-m-d H:i:s')
        ]);
    }
}
```

#### Пример 2: Интеграция с внешним API при создании контента

```php
// Файл: /system/controllers/external_sync/hooks.php
class external_sync extends cmsAction {
    
    /**
     * Синхронизация с внешним API после создания
     */
    public function hookContentAfterAdd($item, $ctype_name) {
        // Синхронизируем только определённые типы
        $sync_types = ['products', 'news'];
        
        if (!in_array($ctype_name, $sync_types)) {
            return $item;
        }
        
        try {
            // Отправка данных во внешнюю систему
            $response = $this->sendToExternalAPI($ctype_name, $item);
            
            // Логирование успешной синхронизации
            $this->logSync($ctype_name, $item['id'], 'created', $response);
            
        } catch (Exception $e) {
            // Логирование ошибки (не прерываем выполнение)
            $this->logSyncError($ctype_name, $item['id'], $e->getMessage());
        }
        
        return $item;
    }
    
    /**
     * Обновление во внешней системе при изменении
     */
    public function hookContentAfterUpdate($item, $old_item, $ctype_name) {
        $sync_types = ['products', 'news'];
        
        if (!in_array($ctype_name, $sync_types)) {
            return $item;
        }
        
        try {
            $response = $this->updateInExternalAPI($ctype_name, $item);
            $this->logSync($ctype_name, $item['id'], 'updated', $response);
            
        } catch (Exception $e) {
            $this->logSyncError($ctype_name, $item['id'], $e->getMessage());
        }
        
        return $item;
    }
    
    /**
     * Отправка данных во внешнюю систему
     */
    private function sendToExternalAPI($ctype, $item) {
        $client = $this->getExternalAPIClient();
        
        $data = [
            'external_id' => $item['id'],
            'type' => $ctype,
            'title' => $item['title'],
            'content' => $item['content'] ?? '',
            'published_at' => $item['date_pub'],
            'url' => $this->getExternalUrl($ctype, $item['id'])
        ];
        
        // Добавление специфичных полей для разных типов
        if ($ctype === 'products') {
            $data['price'] = $item['price'] ?? 0;
            $data['sku'] = $item['sku'] ?? '';
        }
        
        return $client->createItem($data);
    }
}
```

## 39.12. Когда использовать типы контента

### ✅ Используйте типы контента, когда:

| Критерий | Обоснование | Примеры |
|----------|-------------|---------|
| **Модель данных соответствует CRUD** | Создание, чтение, обновление, удаление | Статьи, новости, блоги |
| **Достаточно стандартных полей** | Текст, изображения, даты, связи | Портфолио, каталоги |
| **Не требуется сложная бизнес-логика** | Простые правила валидации | Часто задаваемые вопросы |
| **Требуется быстрое прототипирование** | Минуты вместо дней | Лендинг-страницы |
| **Стандартные режимы отображения** | Список/детальная страница | Библиотеки файлов |
| **Требуются встроенные функции** | SEO, кэширование, права доступа | Энциклопедии, справочники |

**Типичные сценарии:**
- Новостные статьи
- Записи в блогах
- Портфолио работ
- Объявления о вакансиях
- Календари мероприятий
- Страницы с часто задаваемыми вопросами
- Каталоги контента
- Энциклопедии
- Библиотеки файлов

### ❌ Создайте пользовательский компонент, когда:

| Критерий | Обоснование | Примеры |
|----------|-------------|---------|
| **Сложные многоэтапные рабочие процессы** | Конечные автоматы, состояния | Интернет-магазин |
| **Пользовательские бизнес-правила** | Сложная валидация, расчёты | Финансовые системы |
| **Интеграция с внешними API** | Платежные шлюзы, доставка | Системы бронирования |
| **Функции в реальном времени** | Чат, уведомления, обновления | Социальные сети |
| **Сложные взаимосвязи в БД** | Многие-ко-многим, графы | Форумы с темами |
| **Индивидуальные требования к UI/UX** | Drag & drop, кастомные интерфейсы | Конструкторы |

**Типичные сценарии:**
- Интернет-магазин (корзина, заказы, оплата)
- Социальная сеть (стена, друзья, лента)
- Видео-каналы (стриминг, плейлисты)
- Форум с модерацией
- Система обработки платежей
- Системы бронирования
- Панели управления

### 💡 Гибридный подход

Вы можете комбинировать оба подхода:

1. **Начните с типа контента** для быстрого создания MVP
2. **Создайте вспомогательный компонент** для сложных функций
3. **Используйте хуки** для связи типа контента с пользовательской логикой
4. **Переопределите шаблоны** для создания пользовательского оформления

**Пример гибридной архитектуры:**
- `products` тип контента → базовый каталог товаров (CRUD)
- `shop` компонент → корзина, оформление заказа, обработка платежей
- Хук `content_after_add` → синхронизация товара с товарными запасами маркетплейса
- Переопределённый шаблон → страница с подробным описанием товара и кнопкой покупки

## 39.13. Расширение системы типов контента

### Создание пользовательских типов полей

Для добавления нового типа поля (например, геолокация с выбором на карте):

```php
// Файл: /system/fields/geolocation.php
class fieldGeolocation extends cmsFormField {
    
    public $title = 'Geographic Location';
    public $sql = 'VARCHAR(255) DEFAULT NULL'; // Тип столбца в БД
    
    /**
     * Валидация и парсинг значения
     */
    public function parse($value) {
        if (empty($value)) {
            return null;
        }
        
        // Проверка формата "широта,долгота"
        if (!preg_match('/^-?\d+\.\d+,-?\d+\.\d+$/', $value)) {
            $this->addError('Неверный формат координат. Используйте: 55.7558,37.6173');
            return null;
        }
        
        return $value;
    }
    
    /**
     * Генерация HTML для формы
     */
    public function render($options = []) {
        $value = $this->value;
        $coordinates = $value ? explode(',', $value) : [55.7558, 37.6173];
        
        return $this->renderTemplate('field_geolocation', [
            'field' => $this,
            'value' => $value,
            'lat' => $coordinates[0],
            'lng' => $coordinates[1],
            'name' => $this->name,
            'id' => $this->id,
            'required' => $this->is_required
        ]);
    }
    
    /**
     * Применение фильтра по радиусу
     */
    public function applyFilter($model, $value) {
        if (empty($value['radius']) || empty($value['center'])) {
            return $model;
        }
        
        // Расчёт координат для прямоугольной области поиска
        list($center_lat, $center_lng) = explode(',', $value['center']);
        $radius_km = (float)$value['radius'];
        
        // Приблизительный расчёт (1 градус широты ≈ 111 км)
        $lat_delta = $radius_km / 111;
        $lng_delta = $radius_km / (111 * cos(deg2rad($center_lat)));
        
        // Фильтрация по прямоугольной области
        $model->filterGte('latitude', $center_lat - $lat_delta);
        $model->filterLte('latitude', $center_lat + $lat_delta);
        $model->filterGte('longitude', $center_lng - $lng_delta);
        $model->filterLte('longitude', $center_lng + $lng_delta);
        
        return $model;
    }
    
    /**
     * Генерация интерфейса фильтра
     */
    public function getFilterInput($value = null) {
        return $this->renderTemplate('field_geolocation_filter', [
            'field' => $this,
            'value' => $value
        ]);
    }
}
```

## 39.14. Миграция от типов контента к компонентам

### Сценарий: переход от типа контента к полноценному компоненту

Если требования выросли за рамки возможностей типов контента:

1. **Экспорт данных контента**
   ```bash
   # Через существующий экспорт
   php cron_export.php articles
   
   # Или напрямую из БД
   mysqldump -u user -p database content_articles > articles_backup.sql
   ```

2. **Создание нового компонента**
   ```bash
   mkdir /system/controllers/articles_pro/
   ```

3. **Создание пользовательских таблиц**
   ```sql
   CREATE TABLE articles_pro (
       id INT AUTO_INCREMENT PRIMARY KEY,
       user_id INT NOT NULL,
       title VARCHAR(255) NOT NULL,
       content LONGTEXT,
       -- Дополнительные специфичные поля
       views_count INT DEFAULT 0,
       featured BOOLEAN DEFAULT 0,
       -- Стандартные поля
       date_pub DATETIME,
       is_published TINYINT(1) DEFAULT 1,
       INDEX idx_user (user_id),
       INDEX idx_date (date_pub)
   );
   ```

4. **Импорт данных с помощью миграционного скрипта**
   ```php
   // migration_articles.php
   require_once 'bootstrap.php';
   
   $old_model = cmsCore::getModel('content');
   $new_model = cmsCore::getModel('articles_pro');
   
   $old_articles = $old_model->getContentItems('articles', [
       'limit' => false
   ]);
   
   foreach ($old_articles as $article) {
       $new_model->insert('articles_pro', [
           'id' => $article['id'],
           'user_id' => $article['user_id'],
           'title' => $article['title'],
           'content' => $article['content'],
           'date_pub' => $article['date_pub'],
           'is_published' => $article['is_published'],
           // Миграция пользовательских полей
           'custom_field' => $article['custom_field_name'] ?? null
       ]);
   }
   
   echo "Миграция завершена: " . count($old_articles) . " статей\n";
   ```

5. **Перенаправление старых URL**
   ```php
   // В .htaccess или через роутинг
   RewriteRule ^articles/(.*)$ /articles_pro/$1 [R=301,L]
   ```

6. **Сохранение типа контента для архивных данных**
   - Оставить старый тип контента в режиме "только чтение"
   - Использовать для исторических данных
   - Новые данные создавать только в новом компоненте

## 39.16. Модель безопасности

### Уровни доступа

Типы контента интегрируются с системой разрешений платформы (`cmsPermissions`):

| Разрешение | Название правила | Элементы управления |
|------------|------------------|---------------------|
| Просмотр содержимого | `content_{ctype}_view` | Доступ к опубликованным материалам |
| Просмотр неопубликованного | `content_{ctype}_view_all` | Доступ к черновикам и скрытым материалам |
| Добавление контента | `content_{ctype}_add` | Создание новых элементов |
| Редактирование своего | `content_{ctype}_edit_own` | Редактирование авторских элементов |
| Редактирование любого | `content_{ctype}_edit` | Редактирование любых элементов |
| Удаление своего | `content_{ctype}_delete_own` | Удаление авторских элементов |
| Удаление любого | `content_{ctype}_delete` | Удаление любых элементов |
| Модерация | `content_{ctype}_moderate` | Одобрение/отклонение материалов |

### Безопасность на уровне поля

Каждое определение поля включает параметры контроля доступа:

| Параметр | Описание |
|----------|----------|
| `groups_read` | Массив ID групп, которые могут просматривать поле. |
| `groups_edit` | Массив ID групп, которые могут редактировать поле. |

**Пример:** поле "цена" видно всем, но редактировать его могут только администраторы.

### Санитизация входных данных

Для всех типов полей автоматическая очистка реализована в методе `parse()`:

| Тип поля | Меры защиты |
|----------|-------------|
| **Строковые поля** | Кодирование HTML-сущностей через `htmlspecialchars()`. |
| **HTML-поля** | Фильтрация XSS с использованием настроенного белого списка. |
| **Числовые поля** | Приведение к типу `int` или `float`. |
| **Загрузка файлов** | Проверка расширения и MIME-типа. |
| **SQL-инъекции** | Предотвращение с помощью подготовленных выражений в `cmsModel`. |

## 39.17. Ограничения системы типов контента

### Не подходит для

Декларативная система типов контента имеет преднамеренные ограничения:

| Сценарий | Причина |
|----------|---------|
| **Сложные бизнес-процессы** | Многоэтапные процессы, конечные автоматы (state machines). |
| **Функции реального времени** | WebSocket-соединения, мгновенные обновления. |
| **Сложные вычисления** | Динамическое ценообразование, управление запасами. |
| **Интеграция с внешними API** | Платежные шлюзы, расчет стоимости доставки. |
| **Пользовательские схемы БД** | Связи "многие-ко-многим", графовые структуры. |
| **Сложный UI/UX** | Конструкторы с drag-and-drop, совместное редактирование. |

### Обходные пути

Для функций, выходящих за рамки возможностей типов контента:

| Решение | Описание |
|---------|----------|
| **Использование хуков** | Внедрение кастомной логики в события жизненного цикла. |
| **Создание компонента-помощника** | Отдельный компонент для работы с данными контента. |
| **Расширение модели** | Добавление пользовательских методов через наследование от `modelContent`. |
| **Кастомизация шаблонов** | Переопределение шаблонов для добавления своего JavaScript/UI. |
| **Полноценный компонент** | Реализация сложной логики в отдельном компоненте, а типы контента — для простых сущностей. |

### Миграционный путь

Для перехода от типа контента к пользовательскому компоненту:

1.  **Экспорт данных:** сделайте дамп данных через `cron_export.php` или прямой экспорт БД.
2.  **Создание компонента:** разработайте новый компонент с собственной структурой таблиц.
3.  **Импорт данных:** перенесите данные с помощью кастомного скрипта миграции.
4.  **Редирект URL:** настройте перенаправление со старых URL на новые маршруты компонента.
5.  **Архивация:** при необходимости оставьте старый тип контента для доступа к архивным данным.

## 39.19. Заключение

Система типов контента DST Platform предоставляет мощный механизм для быстрого создания структурированного контента без написания кода. Ключевые преимущества:

- **Декларативный подход**: Создание типов контента через веб-интерфейс
- **Автоматическая генерация**: Таблиц БД, CRUD-операций, форм и шаблонов
- **Встроенная интеграция**: SEO, кэширование, поиск, комментарии, права доступа
- **Гибкость расширения**: Хуки для внедрения пользовательской логики
- **Масштабируемость**: От простых статей до сложных каталогов

**Когда использовать:**
- Для контент-ориентированных функций с простой бизнес-логикой
- Когда требуется быстрое прототипирование
- Для стандартных сущностей: статьи, новости, каталоги, портфолио

**Когда создавать компонент:**
- Для сложных рабочих процессов
- При необходимости интеграции с внешними API
- Для функций реального времени
- При сложных взаимосвязях данных

**Дальнейшее изучение:**
- *«Создание компонентов»* — императивная разработка
- *«Работа с хуками»* — расширение функциональности
- *«Создание запланированных задач»* — автоматизация процессов
- *«Производительность и кэширование»* — оптимизация работы с контентом
