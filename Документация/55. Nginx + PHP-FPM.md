# Часть I. Архитектура и основы

## 55.1. Роль Nginx + PHP-FPM в DST Platform

DST Platform — PHP-приложение, работающее по классической схеме:

```
Клиент ──HTTP/HTTPS──▶ Nginx ──FastCGI──▶ PHP-FPM ──▶ DST Platform
                                              │
                                              ├──▶ MySQL / MariaDB
                                              ├──▶ Redis
                                              └──▶ Внешние API
```

| Компонент | Ответственность | Не отвечает за |
|---|---|---|
| **Nginx** | TLS, статика, gzip/brotli, rate limiting, кэширование ответов, reverse proxy | Исполнение PHP |
| **PHP-FPM** | Пул воркеров, исполнение PHP, таймауты, slowlog, status | Роутинг, TLS, статика |
| **DST Platform** | Роутинг (`index.php`), MVC, БД, кэш, бизнес-логика | Всё вышеперечисленное |

**Разделение труда — ключ к производительности:**

- Nginx отдаёт статику **в 100–1000 раз быстрее** PHP.
- PHP-FPM держит пул процессов «горячими» — нет накладных расходов на `fork()` при каждом запросе.
- OPcache хранит скомпилированный байткод — нет парсинга файлов.

> 💡 **Правило DST.** Любой файл, который можно отдать статикой (`/upload/`, `/templates/*/css/`, `/templates/*/js/`, `/favicon.ico`), **должен** отдаваться Nginx напрямую, без участия PHP.

## 55.2. Поток запроса

```
┌────────────────────────────────────────────────────────────────────┐
│                     ПОТОК ЗАПРОСА В DST                            │
├────────────────────────────────────────────────────────────────────┤
│                                                                    │
│  1. Клиент отправляет HTTP-запрос                                  │
│     GET /shop/category/15?page=2 HTTP/1.1                          │
│     Host: example.com                                              │
│                                                                    │
│  2. Nginx принимает соединение                                     │
│     • TLS handshake (если HTTPS)                                   │
│     • Читает заголовки                                             │
│     • Определяет server_name → выбирает server block               │
│                                                                    │
│  3. Nginx применяет правила                                        │
│     • Rate limiting (limit_req)                                    │
│     • Проверка IP (allow/deny)                                     │
│     • Проверка HTTP-метода (limit_except)                          │
│                                                                    │
│  4. Nginx роутинг:                                                 │
│     • /upload/...  → try_files $uri =404 (статика)                 │
│     • /css/*.css   → try_files $uri =404 (статика)                 │
│     • /favicon.ico → try_files $uri =404                           │
│     • /shop/...    → /index.php?$query_string (PHP)                │
│                                                                    │
│  5. Nginx передаёт запрос PHP-FPM через FastCGI                    │
│     • SCRIPT_FILENAME = /var/www/dst/index.php                     │
│     • QUERY_STRING = page=2                                        │
│     • REQUEST_URI = /shop/category/15?page=2                       │
│                                                                    │
│  6. PHP-FPM берёт воркер из пула                                   │
│     • Если свободных нет — запрос в очередь (backlog)              │
│     • Воркер загружает index.php                                   │
│                                                                    │
│  7. DST Platform обрабатывает запрос                               │
│     • cmsCore::init() → подключение к БД, Redis                    │
│     • cmsRequest → разбор URL                                      │
│     • Router → компонент / действие                                │
│     • Controller → бизнес-логика                                   │
│     • Model → SQL-запросы                                          │
│     • Template → HTML                                              │
│                                                                    │
│  8. PHP-FPM возвращает результат Nginx                             │
│     • Status: 200                                                  │
│     • Headers: Content-Type, Set-Cookie, ...                       │
│     • Body: HTML                                                   │
│                                                                    │
│  9. Nginx отдаёт клиенту                                           │
│     • Сжатие (gzip/brotli, если ещё не сжато)                      │
│     • Кэширование (Cache-Control, ETag)                            │
│     • Логирование (access.log)                                     │
└────────────────────────────────────────────────────────────────────┘
```

## 55.3. Варианты топологии

### 55.3.1. Один сервер

```
Интернет ──▶ Nginx ──▶ PHP-FPM ──▶ MySQL / Redis
              │
              └── статика (/upload, /css, /js)
```

**Когда:** до 100 000 посещений/сутки, один сервер, простота.

### 55.3.2. Два сервера (web + DB)

```
Интернет ──▶ [Web1: Nginx + PHP-FPM] ──▶ [DB: MySQL / Redis]
```

**Когда:** 100 000–500 000 посещений/сутки, разделение нагрузки.

### 55.3.3. Кластер (несколько web-серверов)

```
                   ┌──▶ [Web1: Nginx + PHP-FPM]
Интернет ──▶ LB ──┼──▶ [Web2: Nginx + PHP-FPM] ──▶ [DB: MySQL / Redis]
                   └──▶ [Web3: Nginx + PHP-FPM]
```

**Когда:** > 500 000 посещений/сутки, high availability, горизонтальное масштабирование.

**LB (Load Balancer):**

- Nginx / HAProxy / Traefik.
- Или облачный (Yandex NLB, AWS ALB).

**Sticky sessions** — не нужны, если сессии в Redis (см. раздел 50.5.2 — `session.save_handler = redis`).

### 55.3.4. Docker Compose

```
                   ┌──▶ [dst-app (PHP-FPM)]
Интернет ──▶ [Nginx]┤
                   └──▶ [dst-app (PHP-FPM)] ──▶ [mysql / redis]
```

Подробно — в разделе 50.7.

## 55.6. Пользователи и права

| Пользователь | Назначение | Домашняя директория |
|---|---|---|
| `nginx` (или `www-data`) | Веб-сервер | `/var/lib/nginx` |
| `dst` | PHP-FPM (исполнение PHP) | `/home/dst` или `/nonexistent` |
| `deploy` | CI/CD (SSH, деплой) | `/home/deploy` |
| `root` | Управление сервером | `/root` |

**Ключевые правила:**

1. **PHP-FPM работает не от root.** `user = dst`, `group = dst`.
2. **Nginx читает статику, но не пишет.** `chmod 644` на файлы.
3. **`/upload/`, `/cache/`, `/exports/` — writable для `dst`.**
4. **`config.php` — `chmod 640`, владелец `dst:dst`.**
5. **`.env` — `chmod 600`, владелец `dst:dst`.**

**Установка прав:**

```bash
APP_DIR=/var/www/dst
APP_USER=dst
APP_GROUP=dst

# Код — root:dst, 755/644
sudo chown -R root:"$APP_GROUP" "$APP_DIR"
sudo find "$APP_DIR" -type d -exec chmod 755 {} \;
sudo find "$APP_DIR" -type f -exec chmod 644 {} \;

# Writable-директории
for d in cache upload exports; do
    sudo chown -R "$APP_USER":"$APP_GROUP" "$APP_DIR/$d"
    sudo chmod -R 775 "$APP_DIR/$d"
done

# Конфиг
sudo chown "$APP_USER":"$APP_GROUP" "$APP_DIR/system/config/config.php"
sudo chmod 640 "$APP_DIR/system/config/config.php"
```

# Часть III. Nginx — базовая конфигурация

## 55.7. Структура `nginx.conf`

**Файл:** `/etc/nginx/nginx.conf`

```nginx
# Пользователь, от которого работает Nginx (не root!)
user nginx;  # или www-data для Debian/Ubuntu

# Количество worker-процессов: auto = число ядер CPU
worker_processes auto;

# Максимальное число открытых файлов на процесс
worker_rlimit_nofile 65535;

# Куда писать PID
pid /run/nginx.pid;

# Ошибки
error_log /var/log/nginx/error.log warn;

# Подключение модулей (для RHEL/AlmaLinux)
include /etc/nginx/modules-enabled/*.conf;

events {
    use epoll;               # Linux: epoll, FreeBSD: kqueue
    worker_connections 8192; # соединений на worker
    multi_accept on;         # принимать несколько соединений за раз
}

http {
    include /etc/nginx/mime.types;
    default_type application/octet-stream;

    # Логи
    log_format main '$remote_addr - $remote_user [$time_local] "$request" '
                    '$status $body_bytes_sent "$http_referer" '
                    '"$http_user_agent" rt=$request_time urt=$upstream_response_time '
                    'rid=$http_x_request_id';

    access_log /var/log/nginx/access.log main;
    error_log /var/log/nginx/error.log warn;

    # Производительность
    sendfile on;
    tcp_nopush on;
    tcp_nodelay on;
    keepalive_timeout 65;
    keepalive_requests 1000;
    types_hash_max_size 2048;
    server_tokens off;       # скрыть версию Nginx

    # Размеры
    client_max_body_size 32M;
    client_body_buffer_size 128k;
    client_header_buffer_size 4k;
    large_client_header_buffers 4 16k;

    # Таймауты
    client_body_timeout 30s;
    client_header_timeout 30s;
    send_timeout 60s;
    reset_timedout_connection on;

    # Gzip
    gzip on;
    gzip_vary on;
    gzip_min_length 1024;
    gzip_comp_level 6;
    gzip_types text/plain text/css text/xml application/json
               application/javascript application/xml+rss
               application/atom+xml image/svg+xml;

    # Включаем сайты
    include /etc/nginx/conf.d/*.conf;
}
```

## 55.8. Блок `http`

Уже показан выше. Ключевые директивы:

| Директива | Значение | Зачем |
|---|---|---|
| `worker_processes auto` | Число CPU | Оптимально по умолчанию |
| `worker_rlimit_nofile 65535` | Макс. FD | Nginx может держать много соединений |
| `worker_connections 8192` | На worker | Максимум соединений: `worker × connections` |
| `sendfile on` | — | Zero-copy отдача файлов |
| `tcp_nopush on` | — | Отправка заголовков и файла вместе |
| `tcp_nodelay on` | — | Отключение Nagle для keepalive |
| `keepalive_timeout 65` | 65 сек | Keepalive для клиента |
| `keepalive_requests 1000` | 1000 | Макс. запросов на соединение |
| `server_tokens off` | — | Скрыть версию Nginx |
| `client_max_body_size 32M` | 32 МБ | Загрузка файлов (см. 53.38) |

## 55.9. Блок `server`

**Файл:** `/etc/nginx/conf.d/dst.conf`

```nginx
upstream dst_php {
    # Unix socket — быстрее, чем TCP
    server unix:/run/php/php8.1-fpm-dst.sock;

    # Или TCP (если PHP-FPM на другом сервере)
    # server 127.0.0.1:9000;

    keepalive 32;  # пул keepalive-соединений к PHP-FPM
}

# HTTP → HTTPS редирект
server {
    listen 80;
    listen [::]:80;
    server_name example.com www.example.com;

    # ACME-challenge для Let's Encrypt (см. 55.18)
    location /.well-known/acme-challenge/ {
        root /var/www/certbot;
    }

    # Всё остальное — редирект
    location / {
        return 301 https://$host$request_uri;
    }
}

# Основной HTTPS-сервер
server {
    listen 443 ssl http2;
    listen [::]:443 ssl http2;
    server_name example.com;

    root /var/www/dst;
    index index.php;

    # TLS (см. 55.18)
    ssl_certificate     /etc/letsencrypt/live/example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/example.com/privkey.pem;
    include /etc/nginx/snippets/ssl-params.conf;

    # Заголовки безопасности (см. 55.39)
    include /etc/nginx/snippets/security-headers.conf;

    # Размеры
    client_max_body_size 32M;

    # Скрытие чувствительных файлов (см. 55.35)
    include /etc/nginx/snippets/hide-sensitive.conf;

    # ===== СТАТИКА =====
    include /etc/nginx/snippets/static.conf;

    # ===== UPLOAD =====
    location /upload/ {
        alias /var/www/dst/upload/;
        try_files $uri =404;

        # Запрет PHP в upload (см. 53.39)
        location ~ \.(php|phtml|php3|php4|php5|phar)$ {
            deny all;
        }

        # Кэширование
        expires 7d;
        add_header Cache-Control "public";
        access_log off;
    }

    # ===== API =====
    location /api/ {
        limit_req zone=api burst=20 nodelay;

        try_files $uri @php;
    }

    # ===== ОСНОВНОЙ РОУТИНГ =====
    location / {
        limit_req zone=general burst=50 nodelay;
        try_files $uri @php;
    }

    # ===== PHP =====
    location @php {
        fastcgi_pass dst_php;
        fastcgi_index index.php;
        fastcgi_param SCRIPT_FILENAME $document_root/index.php;
        fastcgi_param SCRIPT_NAME /index.php;
        include fastcgi_params;

        # Таймауты
        fastcgi_connect_timeout 10s;
        fastcgi_send_timeout 60s;
        fastcgi_read_timeout 120s;

        # Буферы
        fastcgi_buffer_size 128k;
        fastcgi_buffers 4 256k;
        fastcgi_busy_buffers_size 256k;

        # Не скрывать ошибки
        fastcgi_intercept_errors off;
    }

    # ===== HEALTH CHECK =====
    location = /healthz {
        access_log off;
        return 200 "ok\n";
        add_header Content-Type text/plain;
    }

    location = /readyz {
        access_log off;
        try_files /nonexistent @php_readyz;
    }
}
```

## 55.10. Роутинг на `index.php`

### 55.10.1. Классический `try_files`

```nginx
location / {
    try_files $uri $uri/ @php;
}

location @php {
    fastcgi_pass dst_php;
    fastcgi_param SCRIPT_FILENAME $document_root/index.php;
    include fastcgi_params;
}
```

**Логика:**

1. `$uri` — файл существует? Отдать.
2. `$uri/` — директория существует? Отдать (обычно 403/404).
3. `@php` — передать в PHP.

**Почему `@php`, а не `index index.php`:**

- Безопасность: `/index.php/foo` не сработает как PHP.
- Явный контроль: только `index.php` — точка входа.

### 55.10.2. Прямой `fastcgi_pass` (без `@php`)

Альтернатива — прямая передача:

```nginx
location / {
    try_files $uri $uri/ /index.php?$query_string;
}

location ~ \.php$ {
    fastcgi_pass dst_php;
    fastcgi_index index.php;
    fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
    include fastcgi_params;
}
```

**Минус:** `location ~ \.php$` открывает прямой доступ к `*.php` в `/upload/` (если не защищено отдельно). **Плюс:** работает для `index.php/foo` (path info).

**Для DST Platform рекомендуется первый вариант** (`@php`), так как:

- Единая точка входа — только `index.php`.
- Нет прямого доступа к PHP-файлам в `/upload/`.
- Проще отладка.

### 55.11.1. Сниппет `static.conf`

## 55.13. Gzip и Brotli

### 55.13.1. Gzip

Уже включён в `http` (см. 55.7). Рекомендации:

| Параметр | Значение | Комментарий |
|---|---|---|
| `gzip on` | — | Включить |
| `gzip_vary on` | — | `Vary: Accept-Encoding` для CDN |
| `gzip_comp_level 6` | 1–9 | 6 — баланс CPU/размер |
| `gzip_min_length 1024` | 1 КБ | Меньше — не сжимать (оверхед) |
| `gzip_types` | Список MIME | Не сжимать изображения/видео |
| `gzip_proxied any` | — | Сжимать за прокси |

### 55.13.2. Brotli (лучше Gzip)

**Требует модуля `ngx_brotli`** (в стандартных пакетах — нет).

**Ubuntu (PPA):**

```bash
sudo add-apt-repository ppa:ondrej/nginx
sudo apt update
sudo apt install nginx-extras
```

**Проверка:**

```bash
nginx -V 2>&1 | grep -o with-http_brotli
```

**Конфигурация:**

```nginx
brotli on;
brotli_comp_level 6;
brotli_static on;             # отдавать .br, если есть
brotli_types text/plain text/css text/xml application/json
            application/javascript application/xml+rss
            image/svg+xml;
```

**Экономия:** Brotli сжимает на 15–25 % лучше Gzip.

### 55.13.3. Предварительное сжатие (static)

Для статики можно генерировать `.gz` и `.br` заранее:

```bash
# В CI/CD после сборки
find /var/www/dst/templates -name "*.css" -o -name "*.js" | while read f; do
    gzip -9 -k "$f"
    brotli -9 -k "$f"
done
```

```nginx
location ~* \.(css|js)$ {
    gzip_static on;
    brotli_static on;
    expires 1y;
    add_header Cache-Control "public, immutable";
}
```

### 55.14.1. HTTP-заголовки

```nginx
# Статика — навсегда
location ~* \.(css|js|woff2?)$ {
    expires 1y;
    add_header Cache-Control "public, immutable";
}

# Upload — 7 дней

}

# HTML — не кэшировать
location @php {
    add_header Cache-Control "no-cache, no-store, must-revalidate";
    add_header Pragma "no-cache";
    add_header Expires "0";
    # ...
}
```

### 55.14.2. `fastcgi_cache` (кэш ответов PHP)

**Проблема:** DST Platform кэширует данные (Redis), но каждая страница всё равно рендерится PHP.

**Решение:** Nginx кэширует **готовый HTML**.

**Конфигурация в `http`:**

```nginx
# Зона кэша: 100 МБ, ключ — схема+метод+host+uri+куки сессии
fastcgi_cache_path /var/cache/nginx/dst
    levels=1:2
    keys_zone=dst_cache:100m
    inactive=60m
    max_size=1g;

fastcgi_cache_key "$scheme$request_method$host$request_uri";

# Кэшировать только 200, 301, 302
fastcgi_cache_valid 200 301 302 5m;
fastcgi_cache_valid 404 1m;

# Не кэшировать при Cookie (авторизованные пользователи)
fastcgi_cache_bypass $cookie_PHPSESSID $cookie_dst_session;
fastcgi_no_cache $cookie_PHPSESSID $cookie_dst_session;

# Заголовок для отладки
add_header X-Cache-Status $upstream_cache_status;
```

**В `location @php`:**

```nginx
fastcgi_cache dst_cache;
fastcgi_cache_valid 200 5m;
fastcgi_cache_use_stale error timeout updating http_500 http_503;
fastcgi_cache_background_update on;
fastcgi_cache_lock on;
```

**Что кэшируется:**

- Главная (`/`).
- Списки товаров (`/shop/category/15`).
- Карточки товаров (`/shop/item/456`).
- Статьи (`/news/123`).

**Что НЕ кэшируется:**

- `/admin/*` (авторизация).
- `/api/*` (своя логика).
- `/cart`, `/checkout` (зависят от пользователя).
- Любые страницы с `Set-Cookie`.

**Инвалидация:**

```bash
# При деплое
rm -rf /var/cache/nginx/dst/*

# Или через PURGE (требует ngx_cache_purge)
curl -X PURGE https://example.com/shop/item/456
```

> ⚠️ **Осторожно.** `fastcgi_cache` может кэшировать персонализированные страницы, если неправильно настроен `bypass`. Всегда тестируйте на staging.

## 55.15. Rate limiting

### 55.15.1. Зоны

**В `http`:**

```nginx
# Лимит по IP для API: 100 запросов/минуту
limit_req_zone $binary_remote_addr zone=api:10m rate=100r/m;

# Общий лимит: 30 запросов/секунду
limit_req_zone $binary_remote_addr zone=general:10m rate=30r/s;

# Лимит по логину (если нужно)
limit_req_zone $binary_remote_user zone=per_user:10m rate=10r/s;

# Лимит соединений (защита от slowloris)
limit_conn_zone $binary_remote_addr zone=addr:10m;
```

### 55.15.2. Применение

```nginx
location /api/ {
    limit_req zone=api burst=20 nodelay;
    limit_conn addr 10;
    # ...
}

location / {
    limit_req zone=general burst=50 nodelay;
    limit_conn addr 20;
    # ...
}

# Страница ошибки
limit_req_status 429;
error_page 429 /429.html;

location = /429.html {
    internal;
    return 429 "Too Many Requests\n";
    add_header Content-Type text/plain;
    add_header Retry-After 60;
}
```

### 55.15.3. Параметры

| Параметр | Значение | Комментарий |
|---|---|---|
| `rate` | `100r/m`, `30r/s` | Скорость |
| `burst` | `20` | Очередь (запросы сверх лимита) |
| `nodelay` | — | Не откладывать burst-запросы (сразу 429 после) |

**Без `nodelay`** — запросы в burst **ждут** (замедляют ответ). **С `nodelay`** — сразу выполняются, потом 429.

### 55.15.4. Мониторинг

```bash
# Количество 429 за час
grep ' 429 ' /var/log/nginx/access.log | wc -l

# Топ IP с 429
grep ' 429 ' /var/log/nginx/access.log | \
    awk '{print $1}' | sort | uniq -c | sort -rn | head -20
```

## 55.20. Конфигурация пула

| Директива | Значение | Комментарий |
|---|---|---|
| `user` / `group` | `dst` / `dst` | Не `root`! |
| `listen` | Unix socket | Быстрее TCP |
| `listen.owner` | `nginx` | Владелец сокета |
| `listen.mode` | `0660` | Только Nginx и PHP-FPM |
| `pm` | `dynamic` | См. 55.21 |
| `pm.max_children` | 50 | См. 55.22 |
| `pm.max_requests` | 1000 | Перезапуск воркера (защита от утечек) |
| `request_slowlog_timeout` | 3s | Логировать медленные |
| `request_terminate_timeout` | 120s | Жёсткий лимит |
| `security.limit_extensions` | `.php` | Только `.php` исполняется |

## 55.21. Режимы `pm`

| Режим | Поведение | Когда |
|---|---|---|
| **`static`** | Фиксированное число воркеров | Максимальная нагрузка (всегда занято) |
| **`dynamic`** | Воркеры добавляются/удаляются в диапазоне | Большинство случаев |
| **`ondemand`** | Воркеры создаются по запросу | Низкая нагрузка, экономия RAM |

**`dynamic` (рекомендуется):**

```ini
pm = dynamic
pm.max_children = 50
pm.start_servers = 10       ; при старте
pm.min_spare_servers = 5    ; минимум свободных
pm.max_spare_servers = 15   ; максимум свободных
```

**Логика:**

- При старте — `start_servers`.
- Если свободных < `min_spare_servers` — добавляет воркеры (до `max_children`).
- Если свободных > `max_spare_servers` — убивает лишние.

**`ondemand`:**

```ini
pm = ondemand
pm.max_children = 50
pm.process_idle_timeout = 10s  ; убить через 10 сек простоя
```

**Плюс:** RAM не тратится на простаивающие воркеры. **Минус:** latency первого запроса (~50–200 мс на `fork`).

**Для DST Platform:**

- Prod с нагрузкой — `dynamic`.
- Dev / staging — `ondemand` (экономия RAM).
- Максимальная нагрузка (маркетплейс 400k+) — `static`.

## 55.22. Расчёт `pm.max_children`

### 55.22.1. Формула

```
pm.max_children = (RAM_total × 0.7) / memory_per_worker
```

Где:

- `RAM_total` — общая память сервера.
- `0.7` — оставляем 30 % для ОС, MySQL (если на том же сервере), Redis, Nginx.
- `memory_per_worker` — среднее потребление одного PHP-воркера.

### 55.22.2. Замер `memory_per_worker`

```bash
# Средний RSS воркеров
ps --no-headers -o rss -C php-fpm8.1 | \
    awk '{sum+=$1; n++} END {print sum/n/1024 " MB"}'

# Или через pm.status
curl http://localhost/fpm-status | grep memory
```

**Типичные значения для DST Platform:**

| Сценарий | memory_per_worker |
|---|---|
| Лёгкий сайт (блог, портал) | 60–80 МБ |
| Интернет-магазин | 100–150 МБ |
| Маркетплейс (тяжёлые запросы) | 150–250 МБ |
| С AI-генерацией | 200–300 МБ |

### 55.22.3. Пример расчёта

**Сервер:** 8 vCPU, 16 ГБ RAM. MySQL + Redis на том же сервере.

```
RAM доступно для PHP-FPM = 16 × 0.7 = 11.2 ГБ
memory_per_worker = 120 МБ
pm.max_children = 11200 / 120 ≈ 93
```

**Округляем до 90.**

**Ограничение по CPU:** 8 vCPU. Если `max_children > 8 × 2 = 16`, воркеры будут конкурировать за CPU. Но это нормально — они ждут I/O (MySQL, Redis), не CPU.

**Реальный лимит** — `max_children × ~2–3` на vCPU при I/O-bound нагрузке.

### 55.22.4. Мониторинг


## 55.25. Таймауты

### 55.25.1. Цепочка таймаутов

```
Nginx: fastcgi_read_timeout (120s)

    │
```

| `client_body_timeout` (Nginx) | 30 сек |
| `client_header_timeout` (Nginx) | 30 сек |

- Используйте **CLI** (`php -f scripts/export.php`), не HTTP.

## 55.27. Буферы

**Проблема:** PHP генерирует HTML > 4 КБ (по умолчанию `fastcgi_buffer_size`). Nginx пишет во временный файл → медленно.

**Решение:**

```nginx
fastcgi_buffer_size 128k;
fastcgi_buffers 8 128k;
fastcgi_busy_buffers_size 256k;
fastcgi_temp_file_write_size 256k;
```

**Расчёт:**

```
fastcgi_buffer_size = 128k         # первый буфер (заголовки)
fastcgi_buffers = 8 × 128k = 1M    # для тела
fastcgi_busy_buffers_size = 256k   # максимум «занятых» буферов
```

**Если страница > 1 МБ** — увеличьте `fastcgi_buffers` до `16 × 128k`.

## 55.28. Keepalive

### 55.28.1. Nginx ↔ клиент

```nginx
keepalive_timeout 65;
keepalive_requests 1000;
```

- `65s` — держать соединение 65 секунд.
- `1000` — до 1000 запросов на соединение.

### 55.28.2. Nginx ↔ PHP-FPM

```nginx
upstream dst_php {
    server unix:/run/php/php8.1-fpm-dst.sock;
    keepalive 32;
}

location @php {
    fastcgi_keep_conn on;  # ← обязательно для keepalive
    fastcgi_pass dst_php;
    # ...
}
```

**Плюс:** не открывать новое соединение к PHP-FPM на каждый запрос (~0.5 мс экономии).

## 55.29. Unix socket vs TCP

| Параметр | Unix socket | TCP |
|---|---|---|
| **Скорость** | Быстрее (~10–20 %) | Медленнее |
| **Безопасность** | Только локально | Нужно ограничивать `allow` |
| **Разнесение** | Только на одном сервере | Можно на разных |
| **Отладка** | `socat` / `nc` | Проще (`tcpdump`) |

**Для DST Platform:**

- **Один сервер** → Unix socket.
- **Кластер** → TCP (или Unix socket + Nginx на том же сервере).

## 55.42. Типичные ошибки

| Ошибка | Причина | Решение |
|---|---|---|
| **`502 Bad Gateway`** | PHP-FPM не запущен / сокет не найден | `systemctl status php8.1-fpm`, проверить `listen` |
| **`504 Gateway Timeout`** | PHP дольше `fastcgi_read_timeout` | Увеличить таймауты или оптимизировать код |
| **`413 Request Entity Too Large`** | `client_max_body_size` | Увеличить (см. 53.38) |
| **`403 Forbidden`** | `deny all` / права на файлы | Проверить `location` и права |
| **`404 Not Found`** | `try_files` не нашёл файл | Проверить `root`/`alias` |
| **`500 Internal Server Error`** | Ошибка PHP | `/var/log/php-fpm/*.log` |
| **`Permission denied`** (в логе) | PHP-FPM не может читать/писать | Проверить права (см. 55.6) |
| **`upstream timed out`** | PHP-FPM не отвечает | Slowlog, оптимизация |
| **`worker_connections exceeded`** | Мало `worker_connections` | Увеличить (см. 55.30) |
| **`max children reached`** | Мало `pm.max_children` | Увеличить (см. 55.22) |

```nginx
    include /etc/nginx/snippets/ssl-params.conf;

    include /etc/nginx/snippets/security-headers.conf;
    include /etc/nginx/snippets/hide-sensitive.conf;

    client_max_body_size 32M;

    # Gzip (уже в http, но дублируем для ясности)
    gzip on;

    # Rate limiting
    limit_req zone=general burst=50 nodelay;

    # ===== HEALTH =====
    location = /healthz {
        access_log off;
        return 200 "ok\n";
        add_header Content-Type text/plain;
    }

    location = /nginx-status {
        stub_status on;
        access_log off;
        allow 127.0.0.1;
        deny all;
    }

    location = /fpm-status {
        access_log off;
        allow 127.0.0.1;
        deny all;
        fastcgi_pass dst_php;
        fastcgi_param SCRIPT_FILENAME $document_root/index.php;
        include fastcgi_params;
    }

    # ===== STATIC =====
    location ~* \.(css|js|woff2?|ttf|eot|otf)$ {
        expires 1y;
        add_header Cache-Control "public, immutable";
        access_log off;
        try_files $uri =404;
    }

    location ~* ^/templates/.*\.(jpg|jpeg|png|gif|webp|avif|svg|ico)$ {
        expires 30d;
        add_header Cache-Control "public";
        access_log off;
        try_files $uri =404;
    }

    # ===== UPLOAD =====
    location /upload/ {
        alias /var/www/dst/upload/;
        try_files $uri =404;
        expires 7d;
        add_header Cache-Control "public";

        location ~ \.(php|phtml|phar)$ {
            deny all;
        }
    }

    # ===== API =====
    location /api/ {
        limit_req zone=api burst=20 nodelay;
        try_files $uri @php;
    }

    # ===== FAVICON =====
    location = /favicon.ico {
        access_log off;
        expires 30d;
        try_files $uri =404;
    }

    # ===== ROBOTS =====
    location = /robots.txt {
        access_log off;
        try_files $uri =404;
    }

    # ===== ОСНОВНОЙ РОУТИНГ =====
    location / {
        try_files $uri @php;
    }

    # ===== PHP =====
    location @php {
        fastcgi_pass dst_php;
        fastcgi_keep_conn on;
        fastcgi_index index.php;
        fastcgi_param SCRIPT_FILENAME $document_root/index.php;
        fastcgi_param SCRIPT_NAME /index.php;
        include fastcgi_params;

        fastcgi_connect_timeout 10s;
        fastcgi_send_timeout 60s;
        fastcgi_read_timeout 120s;

        fastcgi_buffer_size 128k;
        fastcgi_buffers 8 128k;
        fastcgi_busy_buffers_size 256k;
        fastcgi_temp_file_write_size 256k;

        fastcgi_intercept_errors off;
    }
}
```

## 55.47. Заключение

Nginx + PHP-FPM в DST Platform — это **разделённая ответственность**:

- **Nginx** — быстрый фронт: TLS, статика, сжатие, кэш, rate limiting.
- **PHP-FPM** — исполнение PHP с пулом «горячих» воркеров.
- **DST Platform** — бизнес-логика.

**Три принципа конфигурации:**

1. **Безопасность.** Скрытие чувствительных файлов, `deny all` для `/cache/`, `/system/`, `/vendor/`, `deny all` для PHP в `/upload/`, TLS 1.2+, заголовки безопасности.
2. **Производительность.** OPcache + JIT, `fastcgi_cache`, `open_file_cache`, `fastcgi_keep_conn`, правильный `pm.max_children`.
3. **Наблюдаемость.** `stub_status`, `pm.status_path`, `slowlog`, health checks, метрики.

**Ключевые файлы:**

| Файл | Назначение |
|---|---|
| `/etc/nginx/nginx.conf` | Главный конфиг Nginx |
| `/etc/nginx/conf.d/dst.conf` | Конфиг DST Platform |
| `/etc/nginx/snippets/*.conf` | Переиспользуемые фрагменты |
| `/etc/php/8.1/fpm/php-fpm.conf` | Главный конфиг FPM |
| `/etc/php/8.1/fpm/pool.d/dst.conf` | Пул DST Platform |
| `/etc/php/8.1/fpm/conf.d/10-opcache.ini` | OPcache |
| `/etc/php/8.1/fpm/conf.d/99-dst.ini` | Настройки PHP для DST |
