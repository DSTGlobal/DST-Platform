# Часть I. Основы

## 56.1. Зачем нужны бэкапы

DST Platform используется для критичных бизнес-проектов:

- **Маркетплейс** — заказы, транзакции, комиссии. Потеря = финансовые потери.
- **Мед Центр** — карты пациентов, расписания. Потеря = нарушение 152-ФЗ + уголовная ответственность.
- **LMS** — курсы, прогресс. Потеря = недовольные клиенты.
- **CRM** — клиентская база. Потеря = потеря бизнеса.

**Типичные инциденты:**

| Инцидент | Частота | Последствия без бэкапа |
|---|---|---|
| Случайное удаление (`DELETE` без `WHERE`) | 1–2 раза в год | Потеря данных |
| Ошибка в миграции | 1 раз в год | Схема сломана |
| Ransomware | 1 раз в 3–5 лет | Всё зашифровано |
| Сбой диска | 1 раз в 3–5 лет | Данные потеряны |
| Corrupt InnoDB | 1 раз в 5 лет | БД не открывается |
| Ошибочный деплой | 1–2 раза в квартал | Откат через бэкап |
| «Злой» админ | 1 раз в 10 лет | Всё удалено |

**Бэкапы — это не «на всякий случай», а обязательный элемент инфраструктуры.**

> ⚠️ **Правило DST.** Бэкапа не существует, пока не проверено восстановление. Резервная копия, которую никто не восстанавливал — это просто «файлы на диске».

## 56.2. Терминология (RPO, RTO, 3-2-1)

### 56.2.1. Ключевые метрики

| Метрика | Расшифровка | Что значит | Пример |
|---|---|---|---|
| **RPO** (Recovery Point Objective) | Целевая точка восстановления | **Сколько данных можно потерять** | «RPO = 1 час» → потеряем не более 1 часа данных |
| **RTO** (Recovery Time Objective) | Целевое время восстановления | **Как быстро восстановимся** | «RTO = 30 мин» → сервис вернётся за 30 мин |
| **MTTR** (Mean Time To Recover) | Среднее время восстановления | **Реальное** время | — |
| **MTBF** (Mean Time Between Failures) | Среднее время между сбоями | Надёжность | — |

**RPO и RTO — это SLA**, которые бизнес (или заказчик) определяет **до** проектирования бэкапов.

### 56.2.2. Пример по типам проектов

| Проект | RPO | RTO | Частота бэкапов | Хранение |
|---|---|---|---|---|
| **Блог / портал** | 24 часа | 4 часа | Ежедневно | 7 дней |
| **Интернет-магазин** | 1 час | 2 часа | Каждый час + бинарные логи | 30 дней |
| **Маркетплейс** | 15 минут | 30 минут | Каждые 15 мин + binlog | 90 дней |
| **Мед Центр** | 15 минут | 1 час | Каждые 15 мин + binlog | 5 лет (152-ФЗ) |
| **CRM** | 1 час | 4 часа | Ежечасно | 90 дней |

### 56.2.3. Правило 3-2-1

```
┌────────────────────────────────────────────────────────────┐
│                      ПРАВИЛО 3-2-1                         │
├────────────────────────────────────────────────────────────┤
│                                                            │
│  3  копии данных                                           │
│     • Оригинал (prod)                                      │
│     • Локальный бэкап (другой диск)                        │
│     • Offsite-бэкап (S3 / другой ДЦ)                       │
│                                                            │
│  2  разных носителя                                        │
│     • SSD/HDD prod                                         │
│     • S3 / ленточная библиотека                            │
│                                                            │
│  1  offsite-копия                                          │
│     • Другой ДЦ / регион                                   │
│     • Защита от: пожара, затопления, ransomware            │
└────────────────────────────────────────────────────────────┘
```

**Расширение 3-2-1-1-0:**

- **3** копии.
- **2** носителя.
- **1** offsite.
- **1** immutable (неизменяемая — защита от ransomware).
- **0** ошибок (проверенное восстановление).

## 56.5. Стратегии (full, incremental, differential)

### 56.5.1. Типы

| Тип | Что копирует | Размер | Время | Восстановление |
|---|---|---|---|---|
| **Full** | Всё | 100 % | Долго | Один файл — быстро |
| **Incremental** | Изменения с последнего бэкапа (любого типа) | Мало | Быстро | Все инкременты по порядку — долго |
| **Differential** | Изменения с последнего **full** | Средне | Средне | Full + последний diff — быстро |

### 56.5.2. Пример (неделя)

```
Пн (full) ── Вт (inc) ── Ср (inc) ── Чт (inc) ── Пт (inc) ── Сб (inc) ── Вс (full)
```

| Восстановление на… | Нужно |
|---|---|
| Вторник | Full (Пн) + Inc (Вт) |
| Четверг | Full (Пн) + Inc (Вт) + Inc (Ср) + Inc (Чт) |
| Суббота | Full (Пн) + все 5 инкрементов |
| Воскресенье | Full (Вс) |

**Differential** — проще: Full (Пн) + Diff (Сб) = восстановление на Сб.

### 56.5.3. Что использовать в DST Platform

| Сценарий | Стратегия |
|---|---|
| **БД (MySQL)** | Full ежедневно + binlog (PITR) |
| **Файлы (`upload/`)** | Full еженедельно + incremental ежедневно (rsync/restic) |
| **Конфиги** | Full при изменении (git + бэкап) |

> 💡 **PITR (Point-in-Time Recovery)** — восстановление на конкретный момент (например, «14:35, до ошибочного DELETE»). Требует **бинарных логов** (см. 56.12).

## 56.6. Стратегии хранения (GFS)

### 56.6.1. GFS (Grandfather-Father-Son)

```
┌──────────────────────────────────────────────────────────┐
│                  GFS ROTATION                            │
├──────────────────────────────────────────────────────────┤
│                                                          │
│  Son (ежедневно, 7 дней)                                 │
│  ├─ Пн, Вт, Ср, Чт, Пт, Сб, Вс                           │
│  └─ Удаляются через 7 дней                               │
│                                                          │
│  Father (еженедельно, 4 недели)                          │
│  ├─ Неделя 1, 2, 3, 4                                    │
│  └─ Удаляются через 4 недели                             │
│                                                          │
│  Grandfather (ежемесячно, 12 месяцев)                    │
│  ├─ Янв, Фев, ..., Дек                                   │
│  └─ Удаляются через 12 месяцев                           │
│                                                          │
│  + Годовые (7 лет)                                       │
│  └─ Для 152-ФЗ, налоговой                                │
└──────────────────────────────────────────────────────────┘
```

### 56.6.2. Реализация

```bash
# Ежедневный (Son) — 7 дней
0 3 * * * /opt/backup/backup.sh --type=daily --retention=7

# Еженедельный (Father) — 4 недели
0 4 * * 0 /opt/backup/backup.sh --type=weekly --retention=4

# Ежемесячный (Grandfather) — 12 месяцев
0 5 1 * * /opt/backup/backup.sh --type=monthly --retention=12

# Годовой — 7 лет
0 6 1 1 * /opt/backup/backup.sh --type=yearly --retention=7
```

### 56.6.3. Retention для DST Platform

| Тип данных | Retention | Причина |
|---|---|---|
| **БД (общая)** | 30 дней | Типичная практика |
| **БД (финансы)** | 5 лет | Налоговая |
| **БД (мед)** | 5 лет | 152-ФЗ (медданные) |
| **Файлы** | 30 дней | — |
| **Логи** | 1 год | Аудит |
| **Годовые бэкапы** | 7 лет | 152-ФЗ, налоговая |

## 56.7. Logical backup — `mysqldump` (полный листинг)

### 56.7.1. Базовый вызов

**Файл:** `/opt/backup/backup-mysql.sh`

```bash
#!/usr/bin/env bash
# ─────────────────────────────────────────────────────────────
# Резервное копирование MySQL для DST Platform.
#
# Использование:
#   ./backup-mysql.sh                    # полный бэкап
#   ./backup-mysql.sh --schema-only      # только схема
#   ./backup-mysql.sh --tables=a,b       # только таблицы a,b
# ─────────────────────────────────────────────────────────────

set -euo pipefail

# ─── Конфигурация ─────────────────────────────────────────────
BACKUP_DIR="${BACKUP_DIR:-/backups/mysql}"
DB_HOST="${DB_HOST:-127.0.0.1}"
DB_PORT="${DB_PORT:-3306}"
DB_NAME="${DB_NAME:-dst}"
DB_USER="${DB_USER:-backup}"
DB_PASS="${DB_PASS:-$(cat /etc/dst/backup-password 2>/dev/null || echo '')}"
RETENTION_DAYS="${RETENTION_DAYS:-30}"
COMPRESS="${COMPRESS:-gzip}"  # gzip | zstd | none

# Опции
SCHEMA_ONLY=0
TABLES=""
IGNORE_TABLES=""

# ─── Разбор аргументов ────────────────────────────────────────
while [[ $# -gt 0 ]]; do
    case "$1" in
        --schema-only) SCHEMA_ONLY=1; shift ;;
        --tables=*)    TABLES="${1#*=}"; shift ;;
        --ignore-tables=*) IGNORE_TABLES="${1#*=}"; shift ;;
        --help)        grep '^#' "$0" | sed 's/^# \?//'; exit 0 ;;
        *)             echo "Unknown arg: $1" >&2; exit 1 ;;
    esac
done

# ─── Подготовка ───────────────────────────────────────────────
TIMESTAMP=$(date +%Y%m%d_%H%M%S)
DATE=$(date +%F)
BACKUP_FILE="${BACKUP_DIR}/${DB_NAME}_${TIMESTAMP}.sql"
mkdir -p "$BACKUP_DIR"

echo "[$(date -Iseconds)] Starting MySQL backup: ${DB_NAME}"
echo "  Host: ${DB_HOST}:${DB_PORT}"
echo "  File: ${BACKUP_FILE}"
echo "  Retention: ${RETENTION_DAYS} days"

# ─── Проверка подключения ─────────────────────────────────────
if ! mysql \
    --host="$DB_HOST" \
    --port="$DB_PORT" \
    --user="$DB_USER" \
    --password="$DB_PASS" \
    --silent \
    -e "SELECT 1" > /dev/null 2>&1; then
    echo "ERROR: Cannot connect to MySQL" >&2
    exit 1
fi

# ─── Проверка свободного места (минимум 2× размера БД) ───────
DB_SIZE=$(mysql \
    --host="$DB_HOST" \
    --port="$DB_PORT" \
    --user="$DB_USER" \
    --password="$DB_PASS" \
    --silent \
    -N \
    -e "SELECT ROUND(SUM(data_length + index_length) / 1024 / 1024) 
        FROM information_schema.TABLES 
        WHERE table_schema = '${DB_NAME}'")

FREE_SPACE=$(df -BM "$BACKUP_DIR" | awk 'NR==2 {gsub("M",""); print $4}')
REQUIRED=$((DB_SIZE * 2))

if [[ $FREE_SPACE -lt $REQUIRED ]]; then
    echo "ERROR: Not enough disk space. Need ${REQUIRED}MB, have ${FREE_SPACE}MB" >&2
    exit 1
fi

echo "  DB size: ${DB_SIZE}MB"
echo "  Free space: ${FREE_SPACE}MB"

# ─── Формирование команды mysqldump ──────────────────────────
MYSQLDUMP_ARGS=(
    --host="$DB_HOST"
    --port="$DB_PORT"
    --user="$DB_USER"
    --password="$DB_PASS"

    # Транзакционность и консистентность
    --single-transaction      # InnoDB: без блокировки
    --quick                   # Стриминг (без буферизации)
    --lock-tables=false       # Не блокировать (для --single-transaction)

    # Полнота
    --routines                # Хранимые процедуры
    --triggers                # Триггеры
    --events                  # События
    --hex-blob                # Бинарные данные (BLOB) в hex
    --set-gtid-purged=OFF     # Не включать GTID (для совместимости)

    # Формат
    --default-character-set=utf8mb4
    --extended-insert         # Многострочный INSERT (быстрее)

    # Надёжность
    --skip-comments           # Без комментариев (меньше размер)
    --no-tablespaces          # Не запрашивать tablespace (для RDS)

    # Схема
    --create-options          # ENGINE, CHARSET и т.д.
    --add-drop-table          # DROP TABLE перед CREATE

    # Прочее
    --databases "$DB_NAME"
)

# Только схема
if [[ $SCHEMA_ONLY -eq 1 ]]; then
    MYSQLDUMP_ARGS+=(--no-data)
    BACKUP_FILE="${BACKUP_DIR}/${DB_NAME}_${TIMESTAMP}_schema.sql"
fi

# Конкретные таблицы
if [[ -n "$TABLES" ]]; then
    MYSQLDUMP_ARGS=("${MYSQLDUMP_ARGS[@]}" $(echo "$TABLES" | tr ',' ' '))
fi

# Игнорируемые таблицы
if [[ -n "$IGNORE_TABLES" ]]; then
    for tbl in $(echo "$IGNORE_TABLES" | tr ',' ' '); do
        MYSQLDUMP_ARGS+=("--ignore-table=${DB_NAME}.${tbl}")
    done
fi

# ─── Выполнение дампа ─────────────────────────────────────────
START_TIME=$(date +%s)

case "$COMPRESS" in
    gzip)
        BACKUP_FILE="${BACKUP_FILE}.gz"
        mysqldump "${MYSQLDUMP_ARGS[@]}" | gzip -9 > "$BACKUP_FILE"
        ;;
    zstd)
        BACKUP_FILE="${BACKUP_FILE}.zst"
        mysqldump "${MYSQLDUMP_ARGS[@]}" | zstd -19 -T0 > "$BACKUP_FILE"
        ;;
    none)
        mysqldump "${MYSQLDUMP_ARGS[@]}" > "$BACKUP_FILE"
        ;;
    *)
        echo "ERROR: Unknown compression: $COMPRESS" >&2
        exit 1
        ;;
esac

DUMP_EXIT=$?
if [[ $DUMP_EXIT -ne 0 ]]; then
    echo "ERROR: mysqldump failed with exit code $DUMP_EXIT" >&2
    rm -f "$BACKUP_FILE"
    exit $DUMP_EXIT
fi

END_TIME=$(date +%s)
DURATION=$((END_TIME - START_TIME))
FILE_SIZE=$(stat -f%z "$BACKUP_FILE" 2>/dev/null || stat -c%s "$BACKUP_FILE")
FILE_SIZE_MB=$((FILE_SIZE / 1024 / 1024))

echo "  Backup completed in ${DURATION}s"
echo "  File size: ${FILE_SIZE_MB}MB"

# ─── Проверка целостности ─────────────────────────────────────
echo "[$(date -Iseconds)] Verifying backup..."

case "$COMPRESS" in
    gzip)
        if ! gzip -t "$BACKUP_FILE"; then
            echo "ERROR: gzip integrity check failed" >&2
            exit 1
        fi
        ;;
    zstd)
        if ! zstd -t "$BACKUP_FILE"; then
            echo "ERROR: zstd integrity check failed" >&2
            exit 1
        fi
        ;;
esac

# Проверка, что дамп оканчивается на «Dump completed»
case "$COMPRESS" in
    gzip)
        if ! zcat "$BACKUP_FILE" | tail -5 | grep -q "Dump completed"; then
            echo "ERROR: Backup incomplete (missing 'Dump completed' marker)" >&2
            exit 1
        fi
        ;;
    zstd)
        if ! zstd -dc "$BACKUP_FILE" | tail -5 | grep -q "Dump completed"; then
            echo "ERROR: Backup incomplete (missing 'Dump completed' marker)" >&2
            exit 1
        fi
        ;;
esac

echo "  ✓ Integrity check passed"

# ─── Контрольная сумма ────────────────────────────────────────
CHECKSUM=$(sha256sum "$BACKUP_FILE" | awk '{print $1}')
echo "$CHECKSUM  $(basename "$BACKUP_FILE")" > "${BACKUP_FILE}.sha256"
echo "  SHA-256: $CHECKSUM"

# ─── Метаданные ───────────────────────────────────────────────
cat > "${BACKUP_FILE}.meta.json" <<EOF
{
  "db_name": "${DB_NAME}",
  "db_size_mb": ${DB_SIZE},
  "backup_file": "$(basename "$BACKUP_FILE")",
  "file_size_mb": ${FILE_SIZE_MB},
  "checksum_sha256": "${CHECKSUM}",
  "compression": "${COMPRESS}",
  "duration_seconds": ${DURATION},
  "schema_only": $([[ $SCHEMA_ONLY -eq 1 ]] && echo "true" || echo "false"),
  "created_at": "$(date -u +%Y-%m-%dT%H:%M:%SZ)",
  "host": "$(hostname)",
  "mysql_version": "$(mysql --version | awk '{print $5}' | tr -d ,)"
}
EOF

echo "  Metadata: ${BACKUP_FILE}.meta.json"

# ─── Ротация ──────────────────────────────────────────────────
echo "[$(date -Iseconds)] Rotating old backups (older than ${RETENTION_DAYS} days)..."

DELETED=0
while IFS= read -r old_file; do
    rm -f "$old_file" "${old_file}.sha256" "${old_file}.meta.json"
    DELETED=$((DELETED + 1))
done < <(find "$BACKUP_DIR" -name "${DB_NAME}_*.sql.*" -type f -mtime +"$RETENTION_DAYS")

echo "  Deleted: ${DELETED} old backup(s)"

# ─── Итог ─────────────────────────────────────────────────────
echo ""
echo "=== Backup complete ==="
echo "  File: ${BACKUP_FILE}"
echo "  Size: ${FILE_SIZE_MB}MB"
echo "  Duration: ${DURATION}s"
echo "  SHA-256: ${CHECKSUM}"
echo ""

# Возврат пути — для использования в других скриптах
echo "$BACKUP_FILE"
```

### 56.7.2. Ключевые опции `mysqldump`

| Опция | Зачем |
|---|---|
| `--single-transaction` | InnoDB: консистентный снимок без блокировки таблиц |
| `--quick` | Стриминг строк (не держать всё в памяти) |
| `--lock-tables=false` | Не блокировать таблицы |
| `--routines` | Хранимые процедуры и функции |
| `--triggers` | Триггеры |
| `--events` | События (`CREATE EVENT`) |
| `--hex-blob` | BLOB → hex (бинарная безопасность) |
| `--set-gtid-purged=OFF` | Убрать GTID (для восстановления на другой сервер) |
| `--extended-insert` | `INSERT INTO t VALUES (...), (...), ...` (быстрее) |
| `--add-drop-table` | `DROP TABLE IF EXISTS` перед `CREATE` |
| `--create-options` | `ENGINE=InnoDB`, `CHARSET=utf8mb4` и т.д. |
| `--default-character-set=utf8mb4` | Для эмодзи и иероглифов |
| `--no-tablespaces` | Для RDS / облачных MySQL (не требует PROCESS) |

> ⚠️ **`--single-transaction`** работает **только** с InnoDB. Для MyISAM нужен `--lock-tables`. В DST Platform все таблицы — InnoDB (см. раздел 51.9), так что безопасно.

### 56.7.3. Пользователь `backup`

```sql
-- Минимальные привилегии для бэкапа
CREATE USER 'backup'@'127.0.0.1' IDENTIFIED BY 'strong_password_here';

GRANT SELECT, SHOW VIEW, TRIGGER, LOCK TABLES, EVENT, PROCESS, RELOAD
    ON dst.* TO 'backup'@'127.0.0.1';

GRANT REPLICATION CLIENT, REPLICATION SLAVE
    ON *.* TO 'backup'@'127.0.0.1';  -- для --single-transaction и binlog

FLUSH PRIVILEGES;
```

**Для восстановления** нужен отдельный пользователь:

```sql
CREATE USER 'restore'@'127.0.0.1' IDENTIFIED BY 'strong_password_here';
GRANT ALL PRIVILEGES ON dst.* TO 'restore'@'127.0.0.1';
-- ⚠ Только для восстановления! Не использовать в повседневной работе.
```

## 56.8. `mysqldump` — опции для больших БД

### 56.8.1. Проблемы больших БД (>10 ГБ)

| Проблема | Решение |
|---|---|
| Долго (часы) | `--quick` + параллельный дамп (см. 56.9) |
| Много памяти | `--quick` (стриминг) |
| Блокировка | `--single-transaction` |
| Долгая блокировка `FLUSH TABLES WITH READ LOCK` | `--source-data=2` (не блокировать) |
| Большой файл | Сжатие (`gzip`, `zstd`) |
| Долгое восстановление | `--extended-insert`, `--disable-keys` |

### 56.8.2. Дополнительные опции

```bash
mysqldump \
    --single-transaction \
    --quick \
    --skip-add-locks \       # Не добавлять LOCK TABLES
    --disable-keys \         # ALTER TABLE ... DISABLE KEYS (быстрее импорт)
    --net-buffer-length=1M \ # Больше пакет
    --max-allowed-packet=1G \
    --compress \             # Сжатие трафика (если удалённо)
    dst
```

### 56.8.3. Тайминги

| Размер БД | `mysqldump` (gzip) | Восстановление |
|---|---|---|
| 1 ГБ | ~2 мин | ~5 мин |
| 10 ГБ | ~20 мин | ~1 час |
| 100 ГБ | ~3 часа | ~10 часов |
| 1 ТБ | **Не использовать** | — |

> ⚠️ **Для БД >100 ГБ** — используйте физические бэкапы (Percona XtraBackup, см. 56.10).

## 56.9. `mysqldump` — параллельный дамп

### 56.9.1. `mysqldumper` (Percona)

```bash

```

**Плюсы:**

- Параллельный дамп (по таблицам).
- В 3–8 раз быстрее `mysqldump`.

### 56.9.2. Своя реализация (через `xargs -P`)

```bash
# Список таблиц
TABLES=$(mysql -u backup -p"$DB_PASS" -N -B -e "SHOW TABLES" "$DB_NAME")

# Дамп каждой таблицы параллельно (4 потока)
echo "$TABLES" | xargs -P 4 -I {} sh -c '
```

**Минус:** нет консистентности между таблицами (каждая — свой снимок). **Для DST Platform не подходит**, если есть FK.

```bash

# /opt/backup/backup-xtrabackup.sh

    --backup \
    --user="$DB_USER" \
    --password="$DB_PASS" \
    --host=127.0.0.1 \
    --port=3306 \
    --target-dir="$BACKUP_PATH" \
    --compress \
    --compress-threads=4 \
    --parallel=4 \
```

## 56.11. Физический бэкап через файловую систему (LVM, ZFS)

### 56.11.1. LVM snapshot

**Требует:** MySQL на LVM-разделе.

```bash
# 1. Остановить MySQL (или FLUSH TABLES WITH READ LOCK)
mysql -e "FLUSH TABLES WITH READ LOCK;"

# 2. Создать snapshot (мгновенно)
lvcreate -L 10G -s -n mysql_snap /dev/vg0/mysql

# 3. Снять блокировку
mysql -e "UNLOCK TABLES;"

# 4. Смонтировать snapshot
mkdir -p /mnt/mysql_snap
mount /dev/vg0/mysql_snap /mnt/mysql_snap

# 5. Скопировать данные
rsync -a /mnt/mysql_snap/ /backups/mysql_snap_$(date +%F)/

# 6. Удалить snapshot
umount /mnt/mysql_snap
lvremove -f /dev/vg0/mysql_snap
```

### 56.11.2. ZFS snapshot

```bash
# 1. Snapshot (мгновенно)
zfs snapshot tank/mysql@backup-$(date +%Y%m%d_%H%M%S)

# 2. Отправить на другой сервер
zfs send tank/mysql@backup-20240115_030000 | \
    ssh backup-server "zfs receive backup/mysql"

# 3. Удалить старые
zfs list -t snapshot -o name tank/mysql | \
    grep backup- | head -n -7 | xargs -n 1 zfs destroy
```

**Плюсы:**

- Мгновенно.
- Не блокирует MySQL (на короткое время).

**Минусы:**

- Требует LVM / ZFS.
- Snapshot — не бэкап (диск может умереть вместе с snapshot).

## 56.12. Бинарные логи для PITR

### 56.12.1. Зачем

**PITR (Point-in-Time Recovery)** — восстановление на конкретный момент:

```
Full (03:00) ── binlog (03:00–14:30) ── binlog (14:30–14:35) ── binlog (14:35–...)
                                                    │
                                                    └── Ошибочный DELETE
```

Восстановление: `Full (03:00)` + `binlog (03:00–14:35)` = состояние на 14:35.

### 56.12.2. Включение

**`/etc/mysql/mysql.conf.d/mysqld.cnf`:**

```ini
[mysqld]
log_bin = /var/log/mysql/mysql-bin
binlog_format = ROW              # ROW — точнее, чем STATEMENT
binlog_row_image = FULL          # Полные данные
expire_logs_days = 7             # Хранить 7 дней (или binlog_expire_logs_seconds)
max_binlog_size = 500M           # Ротация по размеру
sync_binlog = 1                  # Синхронизация после каждой транзакции
```

**Проверка:**

```sql
SHOW VARIABLES LIKE 'log_bin';
-- log_bin | ON

SHOW MASTER STATUS;
-- File: mysql-bin.000042
-- Position: 1234
```

### 56.12.3. Бэкап бинарных логов

```bash
# Копировать все binlog-файлы
rsync -av /var/log/mysql/mysql-bin.* /backups/mysql-bin/

# Или через mysqlbinlog (в текст)
mysqlbinlog /var/log/mysql/mysql-bin.000042 > /backups/mysql-bin.000042.sql
```

### 56.12.4. Восстановление с PITR

```bash
# 1. Восстановить Full
gunzip -c /backups/mysql/dst_20240115_030000.sql.gz | mysql -u root -p dst

# 2. Применить binlog до 14:35
mysqlbinlog \
    --start-datetime="2024-01-15 03:00:00" \
    --stop-datetime="2024-01-15 14:35:00" \
    /var/log/mysql/mysql-bin.000042 \
    | mysql -u root -p dst
```

> ⚠️ **`binlog_format = ROW`** — обязательно для PITR. **`STATEMENT`** может дать другой результат при восстановлении (если данные зависят от времени, `RAND()`, `UUID()`).

## 56.13. Бэкап с реплики

### 56.13.1. Зачем

- **Разгрузка мастера** — бэкап не нагружает прод.
- **Безопасность** — если мастер упадёт, бэкап не остановится.
- **Консистентность** — реплика уже консистентна (если lag = 0).

### 56.13.2. Схема

```
Master (prod) ──replication──▶ Replica (backup)
                                    │
                                    └── mysqldump / XtraBackup
```

### 56.13.3. Настройка реплики

**Master (`my.cnf`):**

```ini
[mysqld]
server-id = 1
log_bin = /var/log/mysql/mysql-bin
binlog_format = ROW
```

**Replica (`my.cnf`):**

```ini
[mysqld]
server-id = 2
relay_log = /var/log/mysql/relay-bin
read_only = ON
```

**Запуск репликации:**

```sql
-- На реплике
CHANGE MASTER TO
    MASTER_HOST='master_host',
    MASTER_USER='replication',
    MASTER_PASSWORD='replication_password',
    MASTER_LOG_FILE='mysql-bin.000042',
    MASTER_LOG_POS=1234;

START SLAVE;

SHOW SLAVE STATUS\G
-- Slave_IO_Running: Yes
-- Slave_SQL_Running: Yes
-- Seconds_Behind_Master: 0
```

**Проверка lag:**

```bash
#!/usr/bin/env bash
# check-replication-lag.sh
LAG=$(mysql -u backup -p"$DB_PASS" -e "SHOW SLAVE STATUS\G" | grep "Seconds_Behind_Master" | awk '{print $2}')

if [[ "$LAG" -gt 60 ]]; then
    echo "ALERT: Replication lag = ${LAG}s" >&2
    exit 1
fi

echo "OK: Replication lag = ${LAG}s"
```

## 56.15. `rsync` — полный листинг

### 56.15.1. Базовый `rsync`

**Файл:** `/opt/backup/backup-files-rsync.sh`

```bash
#!/usr/bin/env bash
# ─────────────────────────────────────────────────────────────
# Резервное копирование файлов DST Platform через rsync.
# ─────────────────────────────────────────────────────────────

set -euo pipefail

# ─── Конфигурация ─────────────────────────────────────────────
SOURCE_DIR="${SOURCE_DIR:-/var/www/dst/upload}"
BACKUP_DIR="${BACKUP_DIR:-/backups/files}"
DATE=$(date +%Y%m%d)
RETENTION_DAYS="${RETENTION_DAYS:-30}"
LOG_FILE="${LOG_FILE:-/var/log/backup-files.log}"

# ─── Что бэкапить ─────────────────────────────────────────────
DIRS_TO_BACKUP=(
    "images/original"
    "files"
    "video"
    "audio"
)

# Что НЕ бэкапить
EXCLUDE=(
    "images/thumb"
    "images/product_list"
    "images/product_main"
    "images/product_zoom"
    "images/avatar"
    "images/avatar_large"
    "images/banner"
    "exports"
    "temp"
)

# ─── Логирование ──────────────────────────────────────────────
exec > >(tee -a "$LOG_FILE") 2>&1

echo "[$(date -Iseconds)] Starting file backup"

# ─── Проверка ─────────────────────────────────────────────────
if [[ ! -d "$SOURCE_DIR" ]]; then
    echo "ERROR: Source directory not found: $SOURCE_DIR" >&2
    exit 1
fi

if [[ ! -d "$BACKUP_DIR" ]]; then
    mkdir -p "$BACKUP_DIR"
fi

# ─── Формирование опций ───────────────────────────────────────
RSYNC_OPTS=(
    -avz                       # Архив, verbose, сжатие
    --delete                   # Удалять файлы, удалённые из источника
    --delete-excluded          # Удалять и исключённые
    --numeric-ids              # Не преобразовывать UID/GID
    --partial                  # Докачивать при обрыве
    --progress                 # Прогресс
    --human-readable           # Читаемый вывод
    --stats                    # Статистика в конце
    --exclude-from=-           # Исключения из stdin
)

# ─── Выполнение ───────────────────────────────────────────────
TOTAL_SIZE=0
TOTAL_FILES=0

for dir in "${DIRS_TO_BACKUP[@]}"; do
    SRC="${SOURCE_DIR}/${dir}"
    DST="${BACKUP_DIR}/${dir}"

    if [[ ! -d "$SRC" ]]; then
        echo "SKIP: $SRC (not found)"
        continue
    fi

    echo ""
    echo "--- Backing up: $dir ---"
    mkdir -p "$DST"

    # rsync с исключениями
    printf '%s\n' "${EXCLUDE[@]}" | \
        rsync "${RSYNC_OPTS[@]}" "$SRC/" "$DST/"

    # Статистика
    DIR_SIZE=$(du -sb "$SRC" | awk '{print $1}')
    DIR_FILES=$(find "$SRC" -type f | wc -l)
    TOTAL_SIZE=$((TOTAL_SIZE + DIR_SIZE))
    TOTAL_FILES=$((TOTAL_FILES + DIR_FILES))

    echo "  Size: $(numfmt --to=iec $DIR_SIZE), Files: $DIR_FILES"
done

echo ""
echo "=== Backup summary ==="
echo "  Total size: $(numfmt --to=iec $TOTAL_SIZE)"
echo "  Total files: $TOTAL_FILES"
echo "  Target: $BACKUP_DIR"
echo "  Duration: $(($(date +%s) - START_TIME))s"
```

## 56.16. `tar` — архивация

### 56.16.1. Простая архивация

```bash
#!/usr/bin/env bash
# /opt/backup/backup-files-tar.sh

set -euo pipefail

SOURCE_DIR="/var/www/dst/upload"
BACKUP_DIR="/backups/files"
DATE=$(date +%Y%m%d)
RETENTION_DAYS=30

mkdir -p "$BACKUP_DIR"

ARCHIVE="${BACKUP_DIR}/upload_${DATE}.tar.gz"

echo "[$(date -Iseconds)] Creating archive: $ARCHIVE"

tar -czf "$ARCHIVE" \
    --exclude='images/thumb' \
    --exclude='images/product_list' \
    --exclude='images/product_main' \
    --exclude='images/product_zoom' \
    --exclude='images/avatar' \
    --exclude='images/avatar_large' \
    --exclude='images/banner' \
    --exclude='exports' \
    --exclude='temp' \
    -C "$(dirname "$SOURCE_DIR")" \
    "$(basename "$SOURCE_DIR")"

# Проверка
if ! gzip -t "$ARCHIVE"; then
    echo "ERROR: Archive integrity check failed" >&2
    exit 1
fi

# Контрольная сумма
CHECKSUM=$(sha256sum "$ARCHIVE" | awk '{print $1}')
echo "$CHECKSUM  $(basename "$ARCHIVE")" > "${ARCHIVE}.sha256"

echo "  Size: $(du -h "$ARCHIVE" | awk '{print $1}')"
echo "  SHA-256: $CHECKSUM"

# Ротация
find "$BACKUP_DIR" -name "upload_*.tar.gz*" -mtime +"$RETENTION_DAYS" -delete
```

### 56.16.2. `tar` — опции

| Опция | Значение |
|---|---|
| `-c` | Create |
| `-x` | Extract |
| `-z` | gzip |
| `-j` | bzip2 |
| `-J` | xz |
| `--zstd` | zstd (Linux 5.9+, GNU tar 1.31+) |
| `-f` | File |
| `-v` | Verbose |
| `-C dir` | Change directory |

## 56.18. Инкрементальные бэкапы — `rsnapshot`

### 56.18.1. Что это

`rsnapshot` — обёртка над `rsync` с инкрементальными бэкапами через **hardlinks**.

**Преимущества:**

- Полная копия — но занимает мало места (hardlinks).
- Легко восстанавливать (просто скопировать директорию).

```
cmd_rm          /bin/rm

cmd_ssh         /usr/bin/ssh
cmd_logger      /usr/bin/logger

# Интервалы
retain  daily   7
retain  weekly  4
retain  monthly 12

#verbose        2
loglevel        3
logfile         /var/log/rsnapshot.log

# Точки
```

## 56.20. Полный скрипт бэкапа (листинг)

**Файл:** `/opt/backup/full-backup.sh` — объединяет всё:

```bash
#!/usr/bin/env bash
# ─────────────────────────────────────────────────────────────
# Полный бэкап DST Platform.
#
# Что делает:
#   1. Бэкап MySQL (mysqldump + gzip)
#   2. Бэкап файлов (rsync)
#   3. Бэкап конфигов (config.php, .env)
#   4. Верификация (checksums)
#   5. Загрузка в S3
#   6. Ротация
#   7. Уведомление (Slack/Telegram)
#
# Использование:
#   ./full-backup.sh                    # ежедневный
#   ./full-backup.sh --type=weekly      # еженедельный
#   ./full-backup.sh --type=monthly     # ежемесячный
# ─────────────────────────────────────────────────────────────

set -euo pipefail

# ─── Конфигурация ─────────────────────────────────────────────
BACKUP_ROOT="${BACKUP_ROOT:-/backups/dst}"
DB_NAME="${DB_NAME:-dst}"
DB_USER="${DB_USER:-backup}"
DB_PASS="${DB_PASS:-$(cat /etc/dst/backup-password)}"
APP_DIR="${APP_DIR:-/var/www/dst}"
S3_BUCKET="${S3_BUCKET:-dst-backups}"

# Тип
TYPE="daily"
while [[ $# -gt 0 ]]; do
    case "$1" in
        --type=*) TYPE="${1#*=}"; shift ;;
        *) echo "Unknown arg: $1" >&2; exit 1 ;;
    esac
done

# Retention по типу
case "$TYPE" in
    daily)   RETENTION_DAYS=7 ;;
    weekly)  RETENTION_DAYS=30 ;;
    monthly) RETENTION_DAYS=365 ;;
    yearly)  RETENTION_DAYS=2555 ;;
    *)       echo "Unknown type: $TYPE" >&2; exit 1 ;;
esac

# ─── Подготовка ───────────────────────────────────────────────
TIMESTAMP=$(date +%Y%m%d_%H%M%S)
BACKUP_DIR="${BACKUP_ROOT}/${TYPE}/${TIMESTAMP}"
LOG_FILE="${BACKUP_ROOT}/logs/${TYPE}_${TIMESTAMP}.log"

mkdir -p "$BACKUP_DIR" "$(dirname "$LOG_FILE")"

exec > >(tee -a "$LOG_FILE") 2>&1

START_TIME=$(date +%s)
HOSTNAME=$(hostname)
ERRORS=0

log() {
    echo "[$(date -Iseconds)] $*"
}

fail() {
    log "ERROR: $*"
    ERRORS=$((ERRORS + 1))
}

# ─── Уведомление ──────────────────────────────────────────────
notify() {
    local status="$1"
    local message="$2"

    if [[ -n "${SLACK_WEBHOOK:-}" ]]; then
        curl -sS -X POST "$SLACK_WEBHOOK" \
            -H 'Content-Type: application/json' \
            -d "{\"text\":\"[$status] DST backup on $HOSTNAME: $message\"}" \
            > /dev/null || true
    fi

    if [[ -n "${TELEGRAM_BOT_TOKEN:-}" && -n "${TELEGRAM_CHAT_ID:-}" ]]; then
        curl -sS -X POST "https://api.telegram.org/bot${TELEGRAM_BOT_TOKEN}/sendMessage" \
            -d "chat_id=${TELEGRAM_CHAT_ID}" \
            -d "text=[$status] DST backup on $HOSTNAME: $message" \
            > /dev/null || true
    fi
}

trap 'notify "FAILED" "Unexpected error at line $LINENO"' ERR

# ─── 1. Бэкап MySQL ───────────────────────────────────────────
log "=== 1/6 MySQL backup ==="

MYSQL_FILE="${BACKUP_DIR}/mysql.sql.gz"

if mysqldump \
    --single-transaction \
    --quick \
    --routines \
    --triggers \
    --events \
    --hex-blob \
    --set-gtid-purged=OFF \
    --default-character-set=utf8mb4 \
    --extended-insert \
    --user="$DB_USER" \
    --password="$DB_PASS" \
    --host=127.0.0.1 \
    "$DB_NAME" | gzip -9 > "$MYSQL_FILE"; then

    if gzip -t "$MYSQL_FILE" && zcat "$MYSQL_FILE" | tail -1 | grep -q "Dump completed"; then
        MYSQL_SIZE=$(stat -c%s "$MYSQL_FILE")
        log "  OK: $(numfmt --to=iec $MYSQL_SIZE)"
    else
        fail "MySQL backup integrity check failed"
    fi
else
    fail "MySQL backup failed"
fi

# ─── 2. Бэкап файлов ──────────────────────────────────────────
log "=== 2/6 Files backup ==="

FILES_DIR="${BACKUP_DIR}/files"
mkdir -p "$FILES_DIR"

for dir in images/original files video audio; do
    SRC="${APP_DIR}/upload/${dir}"
    DST="${FILES_DIR}/${dir}"

    if [[ ! -d "$SRC" ]]; then
        log "  SKIP: $dir (not found)"
        continue
    fi

    mkdir -p "$DST"

    if rsync -az --delete "$SRC/" "$DST/"; then
        DIR_SIZE=$(du -sb "$DST" | awk '{print $1}')
        log "  OK: $dir ($(numfmt --to=iec $DIR_SIZE))"
    else
        fail "rsync failed for $dir"
    fi
done

# ─── 3. Бэкап конфигов ────────────────────────────────────────
log "=== 3/6 Config backup ==="

CONFIG_DIR="${BACKUP_DIR}/config"
mkdir -p "$CONFIG_DIR"

# config.php
if [[ -f "${APP_DIR}/system/config/config.php" ]]; then
    cp "${APP_DIR}/system/config/config.php" "${CONFIG_DIR}/"
    log "  OK: config.php"
fi

# .env
if [[ -f "${APP_DIR}/.env" ]]; then
    cp "${APP_DIR}/.env" "${CONFIG_DIR}/"
    log "  OK: .env"
fi

# composer.lock (для воспроизводимости)
if [[ -f "${APP_DIR}/composer.lock" ]]; then
    cp "${APP_DIR}/composer.lock" "${CONFIG_DIR}/"
    log "  OK: composer.lock"
fi

# Список пакетов
if command -v dpkg &> /dev/null; then
    dpkg -l > "${CONFIG_DIR}/packages.txt"
elif command -v rpm &> /dev/null; then
    rpm -qa > "${CONFIG_DIR}/packages.txt"
fi

# Версия PHP
php -v > "${CONFIG_DIR}/php-version.txt" 2>&1
mysql --version > "${CONFIG_DIR}/mysql-version.txt" 2>&1
nginx -v > "${CONFIG_DIR}/nginx-version.txt" 2>&1

# ─── 4. Метаданные ────────────────────────────────────────────
log "=== 4/6 Metadata ==="

cat > "${BACKUP_DIR}/metadata.json" <<EOF
{
  "type": "${TYPE}",
  "hostname": "${HOSTNAME}",
  "timestamp": "$(date -u +%Y-%m-%dT%H:%M:%SZ)",
  "db_name": "${DB_NAME}",
  "db_size_bytes": $(stat -c%s "$MYSQL_FILE" 2>/dev/null || echo 0),
  "files_size_bytes": $(du -sb "$FILES_DIR" 2>/dev/null | awk '{print $1}'),
  "errors": ${ERRORS}
}
EOF

log "  OK: metadata.json"

# ─── 5. Контрольные суммы ─────────────────────────────────────
log "=== 5/6 Checksums ==="

cd "$BACKUP_DIR"
find . -type f ! -name "*.sha256" ! -name "metadata.json" | sort | \
    xargs sha256sum > SHA256SUMS

log "  OK: SHA256SUMS"

# ─── 6. Загрузка в S3 ─────────────────────────────────────────
log "=== 6/6 S3 upload ==="

if command -v aws &> /dev/null && [[ -n "${S3_BUCKET:-}" ]]; then
    S3_PATH="s3://${S3_BUCKET}/${TYPE}/${TIMESTAMP}/"

    if aws s3 sync "$BACKUP_DIR" "$S3_PATH" \
        --storage-class STANDARD_IA \
        --sse AES256 \
        --only-show-errors; then
        log "  OK: $S3_PATH"
    else
        fail "S3 upload failed"
    fi
else
    log "  SKIP: aws-cli not found or S3_BUCKET not set"
fi

# ─── Ротация ──────────────────────────────────────────────────
log "=== Rotation ==="

CUTOFF=$(date -d "-${RETENTION_DAYS} days" +%s)
DELETED=0

while IFS= read -r old_dir; do
    DIR_DATE=$(basename "$old_dir" | cut -d'_' -f1)
    DIR_TS=$(date -d "$DIR_DATE" +%s 2>/dev/null || echo 0)

    if [[ $DIR_TS -lt $CUTOFF ]]; then
        rm -rf "$old_dir"
        DELETED=$((DELETED + 1))
    fi
done < <(find "${BACKUP_ROOT}/${TYPE}" -maxdepth 1 -type d -name "202*")

log "  Deleted: $DELETED dir(s)"

# ─── Итог ─────────────────────────────────────────────────────
END_TIME=$(date +%s)
DURATION=$((END_TIME - START_TIME))
TOTAL_SIZE=$(du -sb "$BACKUP_DIR" | awk '{print $1}')

log ""
log "=== Summary ==="
log "  Type: ${TYPE}"
log "  Path: ${BACKUP_DIR}"
log "  Size: $(numfmt --to=iec $TOTAL_SIZE)"
log "  Duration: ${DURATION}s"
log "  Errors: ${ERRORS}"

if [[ $ERRORS -eq 0 ]]; then
    notify "OK" "Backup completed in ${DURATION}s ($(numfmt --to=iec $TOTAL_SIZE))"
    exit 0
else
    notify "PARTIAL" "${ERRORS} error(s) during backup"
    exit 1
fi
```

```ini
ExecStart=/opt/backup/full-backup.sh --type=daily
User=root

# Ограничения
```

**`/etc/systemd/system/dst-backup.timer`:**

```ini
[Unit]
Description=DST Platform daily backup timer
Requires=dst-backup.service

[Timer]
OnCalendar=*-*-* 03:00:00
Persistent=true
RandomizedDelaySec=300

[Install]
WantedBy=timers.target
```

**Активация:**

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now dst-backup.timer
sudo systemctl list-timers
```

**Логи:**

```bash
journalctl -u dst-backup.service -f
```

**Плюсы systemd timers:**

- `Persistent=true` — если сервер был выключен в 3:00, бэкап выполнится при старте.
- `RandomizedDelaySec` — случайная задержка (избежать thundering herd).
- Логи в journald.
- Зависимости (`After=mysql.service`).

### 56.24.2. Скрипт проверки

**Файл:** `/opt/backup/verify-backup.sh`

```bash
#!/usr/bin/env bash
# ─────────────────────────────────────────────────────────────
# Проверка, что бэкапы выполняются и валидны.
# Запуск: cron 8:00 (после ночного бэкапа).
# ─────────────────────────────────────────────────────────────

set -euo pipefail

BACKUP_ROOT="${BACKUP_ROOT:-/backups/dst}"
MAX_AGE_HOURS=26
MIN_SIZE_MB=10

ERRORS=0

notify() {
    local status="$1"
    local message="$2"

    if [[ -n "${SLACK_WEBHOOK:-}" ]]; then
        curl -sS -X POST "$SLACK_WEBHOOK" \
            -H 'Content-Type: application/json' \
            -d "{\"text\":\"[$status] Backup verification: $message\"}" \
            > /dev/null || true
    fi
}

fail() {
    echo "FAIL: $*"
    ERRORS=$((ERRORS + 1))
}

# ─── 1. Проверка свежести ─────────────────────────────────────
echo "=== 1. Freshness check ==="

LATEST=$(find "${BACKUP_ROOT}/daily" -maxdepth 1 -type d -name "202*" | sort | tail -1)

if [[ -z "$LATEST" ]]; then
    fail "No daily backups found"
else
    BACKUP_TIME=$(stat -c%Y "$LATEST")
    NOW=$(date +%s)
    AGE_HOURS=$(( (NOW - BACKUP_TIME) / 3600 ))

    echo "  Latest: $LATEST (${AGE_HOURS}h ago)"

    if [[ $AGE_HOURS -gt $MAX_AGE_HOURS ]]; then
        fail "Backup too old: ${AGE_HOURS}h > ${MAX_AGE_HOURS}h"
    fi
fi

# ─── 2. Проверка размера ──────────────────────────────────────
echo "=== 2. Size check ==="

if [[ -n "$LATEST" ]]; then
    SIZE_MB=$(du -sm "$LATEST" | awk '{print $1}')
    echo "  Size: ${SIZE_MB}MB"

    if [[ $SIZE_MB -lt $MIN_SIZE_MB ]]; then
        fail "Backup too small: ${SIZE_MB}MB < ${MIN_SIZE_MB}MB"
    fi
fi

# ─── 3. Проверка checksum ─────────────────────────────────────
echo "=== 3. Checksum check ==="

if [[ -f "${LATEST}/SHA256SUMS" ]]; then
    if cd "$LATEST" && sha256sum -c SHA256SUMS --quiet 2>&1; then
        echo "  OK: All files verified"
    else
        fail "Checksum mismatch"
    fi
else
    fail "SHA256SUMS not found"
fi

# ─── 4. Проверка MySQL-дампа ──────────────────────────────────
echo "=== 4. MySQL dump check ==="

MYSQL_FILE="${LATEST}/mysql.sql.gz"

if [[ -f "$MYSQL_FILE" ]]; then
    if gzip -t "$MYSQL_FILE"; then
        echo "  OK: gzip valid"
    else
        fail "MySQL dump gzip corrupt"
    fi

    if zcat "$MYSQL_FILE" | tail -1 | grep -q "Dump completed"; then
        echo "  OK: dump complete"
    else
        fail "MySQL dump incomplete"
    fi
else
    fail "MySQL dump not found"
fi

# ─── 5. Диск ──────────────────────────────────────────────────
echo "=== 5. Disk space ==="

DISK_USAGE=$(df -h "$BACKUP_ROOT" | awk 'NR==2 {gsub("%",""); print $5}')
echo "  Usage: ${DISK_USAGE}%"

if [[ $DISK_USAGE -gt 80 ]]; then
    fail "Disk usage high: ${DISK_USAGE}%"
fi

# ─── Итог ─────────────────────────────────────────────────────
if [[ $ERRORS -eq 0 ]]; then
    echo "=== All checks passed ==="
    exit 0
else
    echo "=== ${ERRORS} check(s) failed ==="
    notify "FAILED" "${ERRORS} check(s) failed"
    exit 1
fi
```

## 56.26. S3 / Object Storage

### 56.26.1. Провайдеры

| Провайдер | Цена (STANDARD) | Особенности |
|---|---|---|
| **AWS S3** | $0.023/ГБ | Эталон, глобальный |
| **Yandex Object Storage** | 1.5–2 ₽/ГБ | В РФ, 152-ФЗ |
| **VK Cloud Storage** | 1.5 ₽/ГБ | В РФ |
| **Selectel** | 1.5 ₽/ГБ | В РФ |
| **MinIO** | self-hosted | Бесплатно, но нужен сервер |

**Для РФ-проектов** — Yandex / VK / Selectel (152-ФЗ — данные в РФ).

### 56.26.2. Immutability (защита от ransomware)

**S3 Object Lock:**

```bash
aws s3api put-object-lock-configuration \
    --bucket dst-backups \
    --object-lock-configuration '{
        "ObjectLockEnabled": "Enabled",
        "Rule": {
            "DefaultRetention": {
                "Mode": "COMPLIANCE",
                "Days": 30
            }
        }
    }'
```

- `COMPLIANCE` — **никто** (включая root) не может удалить файл до истечения.
- `GOVERNANCE` — только пользователи с правом `s3:BypassGovernanceRetention`.

**Yandex Object Lock:** аналогично.

> 💡 **Immutability** — критично для защиты от ransomware. Если злоумышленник получил доступ к серверу, он **не сможет** удалить S3-бэкапы.

## 56.30. Зачем проверять

> 💡 **Правило.** Бэкап без проверки = 0 бэкапов.

**Типичные проблемы:**

| Проблема | Как обнаружить |
|---|---|
| Файл не создался | `ls` — нет файла |
| Файл пустой | `stat` — 0 байт |
| Файл повреждён | `gzip -t` — ошибка |
| Дамп неполный | Нет `Dump completed` в конце |
| Checksum не совпадает | `sha256sum -c` |
| Не восстанавливается | Тестовое восстановление |

## 56.31. Checksums

### 56.31.1. При создании

Уже реализовано в скриптах (см. 56.7, 56.20):

```bash

```

### 56.31.2. При проверке

```bash
cd /backups/dst/daily/20240115_030000/
```

## 56.32. Тестовое восстановление

### 56.32.1. Почему

> 💡 **Единственный способ узнать, что бэкап работает — восстановить его.**

**Регулярность:**

| Критичность | Частота теста |
|---|---|
| Критично (мед, маркетплейс) | Еженедельно |
| Важно (магазин) | Ежемесячно |
| Стандартно (портал) | Ежеквартально |

### 56.32.2. Скрипт тестового восстановления

**Файл:** `/opt/backup/test-restore.sh`

```bash
#!/usr/bin/env bash
# ─────────────────────────────────────────────────────────────
# Тестовое восстановление бэкапа в изолированную БД.
# Не трогает prod!
# ─────────────────────────────────────────────────────────────

set -euo pipefail

LATEST_BACKUP="${1:-$(find /backups/dst/daily -maxdepth 1 -type d -name "202*" | sort | tail -1)}"
TEST_DB="dst_restore_test_$(date +%s)"
MYSQL_FILE="${LATEST_BACKUP}/mysql.sql.gz"

echo "=== Restore test ==="
echo "  Backup: $LATEST_BACKUP"
echo "  Test DB: $TEST_DB"

# 1. Проверка checksum
echo "[1/5] Verifying checksum..."
cd "$LATEST_BACKUP"
if ! sha256sum -c SHA256SUMS --quiet 2>&1; then
    echo "FAIL: Checksum mismatch"
    exit 1
fi
echo "  OK"

# 2. Создание тестовой БД
echo "[2/5] Creating test database..."
mysql -u root -p"${MYSQL_ROOT_PASS}" \
    -e "DROP DATABASE IF EXISTS ${TEST_DB}; CREATE DATABASE ${TEST_DB} CHARACTER SET utf8mb4;"
echo "  OK"

# 3. Восстановление
echo "[3/5] Restoring..."
START=$(date +%s)

if ! gunzip -c "$MYSQL_FILE" | mysql -u root -p"${MYSQL_ROOT_PASS}" "$TEST_DB"; then
    echo "FAIL: Restore failed"
    mysql -u root -p"${MYSQL_ROOT_PASS}" -e "DROP DATABASE IF EXISTS ${TEST_DB};"
    exit 1
fi

DURATION=$(($(date +%s) - START))
echo "  OK (${DURATION}s)"

# 4. Проверка данных
echo "[4/5] Verifying data..."

TABLES=$(mysql -u root -p"${MYSQL_ROOT_PASS}" -N -B -e \
    "SELECT COUNT(*) FROM information_schema.TABLES WHERE table_schema='${TEST_DB}'")
echo "  Tables: $TABLES"

if [[ $TABLES -lt 10 ]]; then
    echo "FAIL: Too few tables ($TABLES < 10)"
    exit 1
fi

# Проверка ключевых таблиц
for tbl in cms_users cms_content cms_shop_products; do
    COUNT=$(mysql -u root -p"${MYSQL_ROOT_PASS}" -N -B -e \
        "SELECT COUNT(*) FROM ${TEST_DB}.${tbl}" 2>/dev/null || echo "MISSING")
    echo "  $tbl: $COUNT rows"
done

# 5. Удаление
echo "[5/5] Cleanup..."
mysql -u root -p"${MYSQL_ROOT_PASS}" -e "DROP DATABASE ${TEST_DB};"
echo "  OK"

echo ""
echo "=== Restore test PASSED (${DURATION}s) ==="
```

## 56.35. Восстановление БД из `mysqldump`

### 56.35.1. Полное восстановление

```bash
#!/usr/bin/env bash
# /opt/backup/restore-mysql.sh

set -euo pipefail

BACKUP_FILE="${1:?Usage: $0 <backup.sql.gz>}"
DB_NAME="${2:-dst}"
DB_HOST="${DB_HOST:-127.0.0.1}"
DB_USER="${DB_USER:-root}"
DB_PASS="${DB_PASS:?DB_PASS required}"

echo "=== MySQL restore ==="
echo "  Backup: $BACKUP_FILE"
echo "  Target DB: $DB_NAME"
echo "  Host: $DB_HOST"

# 1. Проверка
if [[ ! -f "$BACKUP_FILE" ]]; then
    echo "ERROR: File not found: $BACKUP_FILE" >&2
    exit 1
fi

# 2. Checksum
if [[ -f "${BACKUP_FILE}.sha256" ]]; then
    echo "[1/5] Verifying checksum..."
    if ! sha256sum -c "${BACKUP_FILE}.sha256" --quiet; then
        echo "ERROR: Checksum mismatch" >&2
        exit 1
    fi
    echo "  OK"
fi

# 3. Тест gzip
echo "[2/5] Testing archive..."
if ! gzip -t "$BACKUP_FILE"; then
    echo "ERROR: gzip corrupt" >&2
    exit 1
fi
echo "  OK"

# 4. Подтверждение
echo "[3/5] Confirmation..."
echo ""
echo "⚠ WARNING: This will DROP and recreate database '${DB_NAME}'!"
echo ""
read -r -p "Type 'YES' to continue: " confirm
if [[ "$confirm" != "YES" ]]; then
    echo "Aborted"
    exit 1
fi

# 5. Восстановление
echo "[4/5] Restoring (this may take a while)..."

START=$(date +%s)

mysql \
    --host="$DB_HOST" \
    --user="$DB_USER" \
    --password="$DB_PASS" \
    -e "DROP DATABASE IF EXISTS \`${DB_NAME}\`; CREATE DATABASE \`${DB_NAME}\` CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"

gunzip -c "$BACKUP_FILE" | \
    mysql \
        --host="$DB_HOST" \
        --user="$DB_USER" \
        --password="$DB_PASS" \
        "$DB_NAME"

DURATION=$(($(date +%s) - START))

# 6. Проверка
echo "[5/5] Verifying..."

TABLE_COUNT=$(mysql \
    --host="$DB_HOST" \
    --user="$DB_USER" \
    --password="$DB_PASS" \
    -N -B \
    -e "SELECT COUNT(*) FROM information_schema.TABLES WHERE table_schema = '${DB_NAME}'")

echo "  Tables: $TABLE_COUNT"

if [[ $TABLE_COUNT -lt 10 ]]; then
    echo "ERROR: Too few tables ($TABLE_COUNT)" >&2
    exit 1
fi

echo ""
echo "=== Restore complete (${DURATION}s) ==="
```

### 56.35.2. Ускорение восстановления

| Опция | Эффект |
|---|---|
| `--disable-keys` при `mysqldump` | Быстрее импорт |
| `--extended-insert` | Быстрее (многострочные INSERT) |
| `innodb_flush_log_at_trx_commit = 2` | Быстрее (риск потери 1 сек) |
| `innodb_flush_method = O_DIRECT` | Быстрее |
| `--init-command="SET sql_log_bin=0"` | Не писать в binlog |
| `--max-allowed-packet=1G` | Большие BLOB |

**Пример:**

```bash
gunzip -c backup.sql.gz | mysql \
    --init-command="SET sql_log_bin=0" \
    --max-allowed-packet=1G \
    --user=root --password=xxx \
    dst
```

> ⚠️ **`sql_log_bin=0`** — только для восстановления. В обычной работе — не отключайте.

## 56.36. PITR (Point-in-Time Recovery)

### 56.36.1. Сценарий

```
03:00 — Full backup
...
14:30 — OK
14:35 — Ошибочный DELETE (удалили 1000 заказов)
14:36 — Обнаружили
...
Текущее — Хотим восстановить на 14:34
```

### 56.36.2. Процедура

```bash
#!/usr/bin/env bash
# /opt/backup/restore-pitr.sh

set -euo pipefail

FULL_BACKUP="${1:?Usage: $0 <full.sql.gz> <stop_datetime>}"
STOP_DATETIME="${2:?Example: '2024-01-15 14:34:00'}"
DB_NAME="${DB_NAME:-dst}"

# 1. Восстановить Full
echo "[1/4] Restoring full backup..."
gunzip -c "$FULL_BACKUP" | mysql -u root -p"$MYSQL_ROOT_PASS" "$DB_NAME"
echo "  OK"

# 2. Найти binlog-файлы с момента full
echo "[2/4] Finding binlogs..."

BACKUP_TIME=$(stat -c%Y "$FULL_BACKUP")
BACKUP_DATETIME=$(date -d "@$BACKUP_TIME" '+%Y-%m-%d %H:%M:%S')

# Список binlog (по времени)
BINLOGS=$(mysql -u root -p"$MYSQL_ROOT_PASS" -N -B -e "SHOW BINARY LOGS" | awk '{print $1}')

# 3. Применить binlog до STOP_DATETIME
echo "[3/4] Applying binlogs..."
echo "  From: $BACKUP_DATETIME"
echo "  To:   $STOP_DATETIME"

for binlog in $BINLOGS; do
    # Пропустить binlog старше бэкапа
    BINLOG_TIME=$(stat -c%Y "/var/log/mysql/$binlog" 2>/dev/null || echo 0)
    if [[ $BINLOG_TIME -lt $BACKUP_TIME ]]; then
        continue
    fi

    echo "  Processing: $binlog"

    mysqlbinlog \
        --start-datetime="$BACKUP_DATETIME" \
        --stop-datetime="$STOP_DATETIME" \
        "/var/log/mysql/$binlog" | \
        mysql -u root -p"$MYSQL_ROOT_PASS" "$DB_NAME"
done

# 4. Проверка
echo "[4/4] Verifying..."

COUNT=$(mysql -u root -p"$MYSQL_ROOT_PASS" -N -B -e "SELECT COUNT(*) FROM ${DB_NAME}.cms_shop_orders")
echo "  cms_shop_orders: $COUNT rows"

echo ""
echo "=== PITR complete ==="
echo "  Restored to: $STOP_DATETIME"
```

### 56.36.3. Рекомендации

- **`binlog_format = ROW`** — обязательно.
- **`--stop-datetime`** — точное время (не `--stop-position`).
- **Тест на staging** — перед prod.
- **Логи binlog** — хранить ≥ 7 дней.

## 56.37. Восстановление файлов

### 56.37.1. Из `rsync`

```bash
#!/usr/bin/env bash
# /opt/backup/restore-files.sh

set -euo pipefail

BACKUP_DIR="${1:?Usage: $0 <backup_dir>}"
TARGET="${2:-/var/www/dst/upload}"

echo "=== Files restore ==="
echo "  From: $BACKUP_DIR"
echo "  To: $TARGET"

# Подтверждение
read -r -p "Type 'YES' to continue: " confirm
if [[ "$confirm" != "YES" ]]; then
    echo "Aborted"
    exit 1
fi

# rsync
rsync -av --delete "$BACKUP_DIR/files/" "$TARGET/"

# Права
chown -R dst:dst "$TARGET"
find "$TARGET" -type d -exec chmod 775 {} \;
find "$TARGET" -type f -exec chmod 644 {} \;

echo "=== Restore complete ==="
```

## 56.38. Восстановление после ransomware

### 56.38.1. Сценарий

- Злоумышленник получил доступ.
- Зашифровал все данные (БД, файлы).
- Требует выкуп.

### 56.38.2. Что делать

1. **НЕ платить выкуп.** Платеж не гарантирует восстановление.
2. **Изолировать сервер** (отключить от сети).
3. **Не перезагружать** (могут быть ключи в памяти).
4. **Восстановить из immutable-бэкапа.**
5. **Проверить всю инфраструктуру** (мог проникнуть везде).
6. **Сменить все пароли и ключи.**
7. **Уведомить** (если PII — Роскомнадзор, 152-ФЗ).
8. **Post-mortem** — как проникли, что улучшить.

### 56.38.3. Профилактика

| Мера | Зачем |
|---|---|
| **Immutable-бэкапы** (S3 Object Lock) | Нельзя удалить |
| **Offsite** | Не в сети с prod |
| **Разные учётки** для бэкапов | Компромисс prod не даёт доступ к бэкапам |
| **2FA** на S3 / Vault | Сложнее украсть ключи |
| **Мониторинг аномалий** | Быстрее обнаружение |
| **Регулярные бэкапы** | Не потерять много данных |

## 56.39. Восстановление после случайного удаления

### 56.39.1. Сценарий

```sql
-- 14:35 — разработчик случайно выполнил
DELETE FROM cms_shop_orders;  -- без WHERE!
-- Удалил 10 000 заказов
```

### 56.39.2. Что делать

**Вариант 1: PITR (быстро, если есть binlog)**

```bash
# Восстановить на 14:34
./restore-pitr.sh /backups/dst/daily/latest/mysql.sql.gz "2024-01-15 14:34:00"
```

**Вариант 2: Восстановление только таблицы (из бэкапа)**

```bash
# 1. Развернуть бэкап в тестовую БД
mysql -e "CREATE DATABASE dst_restore"
gunzip -c backup.sql.gz | mysql dst_restore

# 2. Скопировать таблицу
mysqldump dst_restore cms_shop_orders | mysql dst

# 3. Восстановить только потерянные строки
# (сравнить ID, вставить недостающие)
```

**Вариант 3: `mysqlbinlog` с фильтром**

```bash
# Отфильтровать DELETE и отменить его
mysqlbinlog --start-datetime="2024-01-15 14:30:00" \
    /var/log/mysql/mysql-bin.000042 > binlog.sql

# Найти DELETE, заменить на INSERT (вручную или скриптом)
```

> 💡 **Лучший способ** — PITR. **Второй** — восстановление таблицы из бэкапа. **Третий** — binlog (сложно).

### 56.39.3. Профилактика

- **`binlog_format = ROW`** — обязательно.
- **`sql_safe_updates = ON`** — запрет `UPDATE`/`DELETE` без `WHERE`.
- **Двухфакторное подтверждение** для опасных операций в админке.
- **Права:** разработчик — не `root`.

## 56.41. Retention (152-ФЗ, GDPR)

### 56.41.1. 152-ФЗ (РФ)

| Данные | Retention | Обоснование |
|---|---|---|
| **Медданные** | 5 лет | Приказ Минздрава |

| **Кадры** | 75 лет | Трудовой кодекс |
| **Заказы** | 5 лет | Налоговая |
| **Логи доступа к PII** | 1 год | 152-ФЗ |
| **Общие логи** | 6 месяцев | — |

### 56.41.2. GDPR (ЕС)

| Данные | Retention |
|---|---|
| Персональные данные | «Не дольше, чем нужно» |
| Финансовые | 7–10 лет (в зависимости от страны) |
| Логи | 6–12 месяцев |

**Правило:** если проект работает с ЕС — retention должен быть **обоснован**.

### 56.41.3. Реализация


**В скрипте:**

```bash
case "$TYPE" in

    weekly)    RETENTION=90 ;;

    financial) RETENTION=1825 ;;

```

## 56.42. BCP / DR план

### 56.42.1. BCP (Business Continuity Plan)

**Документ**, описывающий:

1. **Критичные системы** — что должно работать.

3. **Сценарии** — что делать при инциденте.
4. **Роли** — кто отвечает.
5. **Контакты** — кому звонить.
6. **Процедуры** — пошаговые.

### 56.42.2. DR (Disaster Recovery) план

**Часть BCP**, специфичная для ИТ:

1. **Инвентаризация** — серверы, сервисы, зависимости.
2. **Бэкапы** — что, где, как.
3. **Восстановление** — пошаговые сценарии.
4. **Тестирование** — регулярные учения.
5. **Обновление** — раз в квартал.

### 56.42.4. Учения

**Раз в квартал:**

1. Выбрать сценарий (например, «сбой БД»).
2. Смоделировать инцидент на staging.
3. Восстановить по плану.
4. Замерить RTO.
5. Обновить план (если что-то не сработало).

> 💡 **Правило.** RTO, который не проверен — это фантазия. Учения — единственный способ узнать реальное время восстановления.

## 56.44. Заключение

Резервное копирование в DST Platform строится на трёх принципах:

1. **3-2-1.** Три копии, два носителя, одна offsite. Плюс immutability (защита от ransomware).
2. **Проверенность.** Бэкап без проверки — 0 бэкапов. Регулярное тестовое восстановление — обязательно.
3. **Автоматизация.** Ручные бэкапы — забываются. Cron / systemd timers + мониторинг + алерты.
