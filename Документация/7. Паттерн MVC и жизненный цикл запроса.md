# 7. Паттерн MVC и жизненный цикл запроса

Этот документ описывает реализацию архитектурного паттерна Model-View-Controller (MVC) в DST Platform и детализирует полный жизненный цикл HTTP-запроса — от получения URI до отправки HTML-ответа. Он объясняет, как маршрутизация, контроллеры, модели и шаблоны взаимодействуют в рамках единой архитектуры.

Связанные разделы:
- **«Загрузка и инициализация системы»** — подготовка среды выполнения
- **«Маршрутизация URL-адресов и настройка веб-сервера»** — обработка запроса на уровне Apache
- **«Система компонентов»** — организация логики по модулям
- **«Система шаблонов»** — рендеринг представлений

---

## 7.1. Архитектура MVC

DST Platform реализует классический шаблон MVC с четким разделением задач. В отличие от традиционных ORM-фреймворков, DST использует утилитарный подход к моделированию, где модели представляют собой сервисные классы, предоставляющие методы доступа к данным, а не представления сущностей.

DST Platform реализует **классический MVC с утилитарной моделью**, где:

| Слой | Базовый класс | Ответственность | Расположение |
|------|----------------|------------------|--------------|
| **Модель** | `cmsModel` | Доступ к данным, бизнес-логика, валидация | `/system/controllers/{component}/model.php` |
| **Контроллер** | `cmsFrontend` / `cmsBackend` | Обработка запроса, координация, вызов моделей | `/system/controllers/{component}/controller.php` |
| **Представление** | `.tpl.php`-файлы | HTML-рендеринг, минимальная логика | `/templates/{theme}/controllers/{component}/` |

### Ключевые особенности
- **Нет ORM/Active Record**: модели — это сервисные классы с методами (`getProducts()`, `saveOrder()`), а не объекты сущностей.
- **Два контроллера на компонент**: отдельные классы для фронтенда (`shop`) и админки (`backendShop`).
- **PHP-шаблоны без компиляции**: прямое выполнение `.tpl.php` для максимальной производительности.
- **Service Locator**: все сервисы доступны через `$this->db`, `$this->cache`, `$this->user` и т.д.

## 7.2. Жизненный цикл запроса: обзор

Полный цикл состоит из шести этапов:

1. **Перезапись URL** — Apache → `index.php`
2. **Инициализация** — `bootstrap.php` загружает ядро
3. **Маршрутизация** — определение компонента и действия
4. **Выполнение контроллера** — вызов метода действия
5. **Работа модели** — запрос данных из БД
6. **Рендеринг** — генерация HTML через шаблоны

Диаграмма иллюстрирует весь цикл «запрос-ответ», от получения HTTP-запроса до доставки HTML-вывода.

## 7.3. Этап 1: Перезапись URL и фронт-контроллер

Файл `.htaccess` определяет, как обрабатывать входящий запрос:

| Тип запроса | Условие | Обработка |
|-------------|--------|-----------|
| Статический ресурс | Файл существует (`!-f`) | Отдаётся напрямую Apache |
| Карта сайта | `/sitemap*.xml` | Перенаправляется на `/cache/static/sitemaps/...` |
| Динамический запрос | Иначе | Передаётся в `index.php` |

Примеры:
- `/css/style.css` → статика → Apache
- `/shop/item/123` → динамика → `index.php`
- `/sitemap.xml` → кэшированный XML

Исходный URI сохраняется в `$_SERVER['REQUEST_URI']`.

## 7.4. Этап 2: Инициализация системы

bootstrap.php файл инициализирует все основные подсистемы перед началом обработки запроса. Этот этап выполняется один раз для каждого запроса.

Последовательность bootstrap

<img src="https://github.com/DSTGlobal/DST-Platform/blob/main/images/38.png" alt="DST Platform">

Диаграмма: Процесс инициализации Bootstrap

Файл `index.php` подключает `bootstrap.php`, который выполняет:

1. Определение `PATH`, `ROOT`
2. Установка кодировки: `mb_internal_encoding('UTF-8')`
3. Загрузка автозагрузчика Composer
4. Регистрация пользовательского автозагрузчика
5. Инициализация `cmsConfig`
6. Настройка обработки ошибок (`debug` → `display_errors`)
7. Проверка установки (`is_installed`)
8. Инициализация сессии (`SESSION_START`)
9. Создание `cmsCore`
10. Подключение к БД
11. Запуск кэша
12. Вызов события `core_start`
13. Загрузка локализации

После этого управление возвращается в `index.php`.

## 7.5. Этап 3: Маршрутизация и диспетчеризация

`index.php` парсит `$_SERVER['REQUEST_URI']` по сегментам:

```
/{component}/{action}/{param1}/{param2}/...
```

### Примеры разбора

| URI | Компонент | Действие | Параметры |
|-----|-----------|----------|-----------|
| `/shop` | `shop` | `index` (по умолчанию) | `[]` |
| `/shop/category/electronics` | `shop` | `category` | `['electronics']` |
| `/users/profile/johndoe` | `users` | `profile` | `['johndoe']` |

### Загрузка контроллера
- Создаётся экземпляр класса `{component}` (например, `shop`)
- Класс должен наследоваться от `cmsFrontend` или `cmsBackend`
- Расположение: `/system/controllers/{component}/controller.php`

## 7.6. Этап 4: Выполнение контроллера

Базовые классы контроллеров

<img src="https://github.com/DSTGlobal/DST-Platform/blob/main/images/40.png" alt="DST Platform">

Диаграмма: Иерархия классов контроллеров

Контроллер организует обработку запроса через **методы действий**.

### Соглашение об именовании
- Метод действия: `action{ActionName}` → `/shop/item` → `actionItem()`
- Параметры передаются как аргументы: `actionItem($id)`

### Пример контроллера
```php
class shop extends cmsFrontend {

    public function actionIndex() {
        $items = $this->model->getPublishedItems();
        return $this->render('index', ['items' => $items]);
    }

    public function actionItem($id) {
        if (!$id) { $this->halt('Товар не найден', 404); }
        $item = $this->model->getItemById($id);
        return $this->render('item_view', ['item' => $item]);
    }
}
```

### Доступные методы
| Метод | Назначение |
|-------|-----------|
| `$this->model` | Экземпляр модели компонента |
| `$this->render($template, $data)` | Рендеринг шаблона |
| `$this->redirect($url)` | HTTP-редирект |
| `$this->halt($msg, $code)` | Остановка с ошибкой |
| `$this->request` | Доступ к входным данным (`cmsRequest`) |

## 7.7. Этап 5: Работа модели

Модель наследуется от `cmsModel` и предоставляет **query builder** для безопасного доступа к БД.

<img src="https://github.com/DSTGlobal/DST-Platform/blob/main/images/41.png" alt="DST Platform">

Диаграмма: Архитектура слоев модели

### Query Builder: основные методы

| Метод | Пример | SQL-аналог |
|-------|--------|------------|
| `select($table, $fields)` | `->select('shop_products')` | `SELECT * FROM shop_products` |
| `filterEqual($field, $value)` | `->filterEqual('is_published', 1)` | `WHERE is_published = 1` |
| `filterLike($field, $pattern)` | `->filterLike('title', '%phone%')` | `WHERE title LIKE '%phone%'` |
| `orderBy($field, $dir)` | `->orderBy('date_pub', 'DESC')` | `ORDER BY date_pub DESC` |
| `limit($n)` | `->limit(20)` | `LIMIT 20` |
| `getItem()` / `getItems()` | `->getItem()` | `fetch()` / `fetchAll()` |

### Пример метода модели

```php
public function getPublishedProducts($category_id, $limit = 20) {
    return $this->select('shop_products')
                ->filterEqual('category_id', $category_id)
                ->filterEqual('is_published', 1)
                ->orderBy('date_created', 'DESC')
                ->limit($limit)
                ->getItems();
}
```

Модели **не содержат логики представления** и **не обращаются напрямую к `$_POST`/`$_GET`**.

## 7.8. Этап 6: Рендеринг представления

Представления — это .tpl.php файлы-шаблоны, управляемые классом cmsTemplate. Система шаблонов поддерживает наследование, управление ресурсами и позиционирование виджетов.

### Разрешение шаблонов и наследование

<img src="https://github.com/DSTGlobal/DST-Platform/blob/main/images/42.png" alt="DST Platform">

Диаграмма: Разрешение шаблонов и процесс рендеринга

Шаблоны — это PHP-файлы с расширением `.tpl.php`.

### Расположение шаблонов
```
/templates/{theme}/controllers/{component}/{template}.tpl.php
```

### Приоритет загрузки
1. Текущая тема: `/templates/custom/...`
2. Родительская тема: `/templates/default/...`
3. Компонент по умолчанию: `/system/controllers/{component}/templates/...`

### Пример шаблона
```php
<?php
// Доступные переменные: $item, $images и др. (из render())
$this->addCSS('controllers/shop/item.css');
$this->addJS('controllers/shop/item.js');
?>
<div class="product-detail">
    <h1><?= $item['title'] ?></h1>
    <div class="price"><?= $item['price'] ?> руб.</div>
</div>
```

### Методы в шаблоне (`$this` → `cmsTemplate`)
| Метод | Назначение |
|-------|-----------|
| `$this->addCSS($path)` | Добавить CSS в очередь |
| `$this->addJS($path)` | Добавить JS в очередь |
| `$this->renderWidget($name, $opts)` | Вывести виджет |
| `$this->getLangJS(['KEY'])` | Передать строки локализации в JS |

## 7.9. Применение основного макета

Результат действия встраивается в **главный шаблон** — `main.tpl.php`:

```php
<!DOCTYPE html>
<html>
<head>
    <?= $this->renderHead() ?>
</head>
<body>
    <?= cmsUser::getSessionMessages() ?>
    <?= $this->breadcrumbs() ?>
    <main><?= $this->body() ?></main>
    <?= $this->widgets('footer') ?>
</body>
</html>
```

- `$this->body()` — результат `render()` из контроллера
- `$this->renderHead()` — все CSS, JS, meta-теги
- `$this->widgets('position')` — вывод виджетов в заданную позицию

cmsEventsManager обеспечивает точки подключения на протяжении всего жизненного цикла запроса, позволяя компонентам расширять или изменять поведение без изменения основного кода.

На всех этапах жизненного цикла вызываются **системные события**:

| Событие | Когда вызывается | Пример использования |
|--------|------------------|----------------------|
| `core_start` | После инициализации ядра | Инициализация SDK |
| `{component}_before_{action}` | До выполнения действия | Валидация прав |

## 7.14. Методы действий контроллера

### Шаблон регистрации действий
Контроллеры регистрируют доступные действия в своём конструкторе или посредством соглашений об именовании методов.

**Соглашение об именовании методов:**
- Методы действий обычно начинаются с префикса `action` (например, `actionIndex`, `actionCategory`, `actionItem`).
- Или используются прямые названия методов, соответствующие сегментам URL.

**Пример структуры контроллера:**
```php
class shop extends cmsFrontend {
    
    public function __construct() {
        parent::__construct();
        // Инициализация в конструкторе
    }
    
    // Действие по умолчанию — главная страница магазина
    public function actionIndex() {
        // Логика здесь
    }
    
    // Список категорий — /shop/category/{slug}
    public function actionCategory($slug = null) {
        // Логика здесь
    }
    
    // Детали товара — /shop/item/{id}
    public function actionItem($id = null) {
        // Логика здесь
    }
    
    // Корзина — /shop/cart
    public function actionCart() {
        // Логика здесь
    }
}
```

### Жизненный цикл метода действия
1. **Получение входных данных** — параметры из сегментов URL или `cmsRequest`.
2. **Проверка** — валидация параметров и прав доступа пользователя.
3. **Взаимодействие с моделью** — загрузка данных через методы модели.
4. **Бизнес-логика** — обработка данных, применение преобразований.
5. **Обработчики событий** — вызов событий до/после для расширения функциональности.
6. **Подготовка шаблона** — настройка метаданных страницы, подготовка массива данных.
7. **Рендеринг** — вызов `$this->render()` для вывода представления.

## 7.16. Структура шаблона представления

### Анатомия файла шаблона
Типичный шаблон представления (`.tpl.php`) имеет следующую структуру:

**Пример шаблона компонента:**
```php
<?php
// Файл: /templates/default/controllers/shop/item_view.tpl.php

// Переменные извлекаются из вызова render() контроллера
// Доступны: $item (данные товара), $category, $images и др.

// Можно загрузить специфичные для шаблона CSS/JS
$this->addCSS('controllers/shop/item.css');
$this->addJS('controllers/shop/item.js');
?>

<div class="product-detail">
    <h1><?php echo $item['title']; ?></h1>
    
    <div class="product-images">
        <?php foreach($images as $image): ?>
            <img src="<?php echo $image['url']; ?>" alt="">
        <?php endforeach; ?>
    </div>
    
    <div class="product-price">
        <?php echo $item['price']; ?> руб.
    </div>
    
    <div class="product-description">
        <?php echo $item['description']; ?>
    </div>
    
    <button class="btn-buy" data-id="<?php echo $item['id']; ?>">
        Купить
    </button>
</div>
```

### Область видимости переменных шаблона
- Все переменные, переданные в `render($template, $data)`, извлекаются в область видимости шаблона.
- `$this` ссылается на экземпляр `cmsTemplate`, предоставляя вспомогательные методы.
- Шаблон может получать доступ к глобальным объектам через `cmsCore::getInstance()->getObject()`.

### Распространённые методы работы с шаблонами

| Метод | Назначение |
|-------|------------|
| `$this->addCSS($path)` | Добавить CSS-файл в очередь |
| `$this->addJS($path)` | Добавить JavaScript-файл в очередь |
| `$this->renderWidget($widget, $options)` | Отображение виджета в указанном месте |
| `$this->getSchemeCSS()` | Получение CSS-классов, специфичных для макета |
| `$this->getLangJS($keys)` | Передача языковых строк в JavaScript |

## 7.17. Интеграция основного макета

### Структура основного макета
Файл `main.tpl.php` содержит общую структуру страницы и выводит контент компонентов.

<img src="https://github.com/DSTGlobal/DST-Platform/blob/main/images/45.png" alt="DST Platform">

Диаграмма: Последовательность рендеринга основного макета.

### Основные методы макета

| Метод | Расположение | Назначение |
|-------|--------------|------------|
| `$this->renderHead()` | Секция `<head>` | Выводит все CSS, JS, метатеги и заголовок страницы |
| `$this->body()` | Основная область контента | Вставляет результат работы контроллера/действия |
| `$this->widgets('position')` | Различные позиции | Отображает виджеты в указанной позиции |
| `$this->hasWidgetsOn('position')` | Условные блоки | Проверяет, есть ли активные виджеты в позиции |
| `$this->breadcrumbs()` | Навигационная зона | Выводит «хлебные крошки» |
| `cmsUser::getSessionMessages()` | Перед контентом | Отображает всплывающие сообщения (успех, ошибка) |

## 7.18. Пример: просмотр товара

**URI**: `/shop/item/123`

1. `.htaccess` → `index.php`
2. `bootstrap.php` → инициализация ядра
3. Маршрутизация: компонент=`shop`, действие=`item`, параметр=`123`
4. Вызывается `shop::actionItem(123)`
5. Модель: `$this->model->getItemById(123)`
6. Контроллер: `render('item_view', ['item' => $data])`
7. Шаблон: `/templates/default/controllers/shop/item_view.tpl.php`
8. Макет: встраивание в `main.tpl.php`
9. Отправка HTML клиенту

## 7.19. Заключение

Жизненный цикл запроса в DST Platform:
- **Линейный и предсказуемый**
- **Чётко разделён на слои** (маршрутизация → контроллер → модель → шаблон)
- **Расширяем через события** без модификации ядра
- **Оптимизирован через многоуровневое кэширование**
- **Поддерживает два контекста** — публичный и административный

Эта архитектура обеспечивает баланс между простотой типовых задач и гибкостью для сложных enterprise-сценариев.

### Философия MVC DST Platform

Слой модели:

- Это не ORM : модели представляют собой классы репозиториев/сервисов, а не объекты сущностей.
- Конструктор запросов : Удобный интерфейс для создания SQL-запросов.
- Никакой магии : прямой контроль над операциями базы данных.
- Встроенное кэширование : поддержка кэширования на уровне модели.

Вид слоя:

- Наследование шаблонов : Темы могут расширять родительские темы.
- PHP-шаблоны : .tpl.php файлы со встроенным PHP-кодом.
- Без шаблонизатора : прямое выполнение PHP-кода для максимальной производительности.
- Asset Pipeline : Интегрированное управление CSS/JS с функцией минификации.

Уровень контроллера:

- Двойной интерфейс : отдельные контроллеры для фронтенда и бэкенда.
- На основе действий : сегменты URL-адресов сопоставляются с действиями контроллера.
- Событийно-ориентированный подход : точки подключения для расширяемости.
- Поиск сервисов : доступ к глобальным услугам черезcmsCore

Жизненный цикл запроса:

- Фронт-контроллер : Все запросы проходят через index.php
- Этап начальной загрузки : инициализация системы перед маршрутизацией.
- Маршрутизация : анализ URL-адресов и диспетчеризация контроллеров.
- Выполнение : Вызов метода действия с параметрами.
- Визуализация : обработка шаблонов и применение макета.
- Результат : Итоговая HTML-версия с кэшированием.
