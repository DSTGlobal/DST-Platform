# 33. Конвейер обработки ресурсов

В данном разделе описана система управления фронтенд-ресурсами в DST Platform: регистрация, разрешение путей, оптимизация и доставка CSS/JavaScript. Конвейер обеспечивает централизованное управление через класс `cmsTemplate`, поддержку наследования тем, автоматическую минификацию и изоляцию ресурсов компонентов.

**Связанные разделы:**
- *«Система шаблонов»* — общая архитектура рендеринга
- *«Структура стилей»* — организация и загрузка CSS
- *«Типографика и шрифты»* — загрузка и применение веб-шрифтов
- *«Работа с ресурсами (CSS/JS)»* — методы подключения

---

## 33.1. Обзор архитектуры конвейера

Конвейер обработки ресурсов DST Platform реализует многоуровневый подход к управлению фронтенд-активами, обеспечивая баланс между гибкостью разработки и оптимизацией производительности.

### Ключевые функции
- **Централизованная регистрация** через синглтон `cmsTemplate`
- **Автоматическое разрешение путей** с поддержкой наследования тем
- **Оптимизация доставки**: минификация, объединение, версионирование
- **Изоляция ресурсов** компонентов и виджетов
- **Гибкая стратегия загрузки** (критические/отложенные ресурсы)

## 33.2. Центральный реестр: класс cmsTemplate

Класс `cmsTemplate` служит центральным реестром всех фронтенд-ресурсов. Контроллеры и шаблоны регистрируют активы через его методы, которые обрабатывают разрешение путей, порядок загрузки и генерацию выходных данных.

### Структура класса
```php
class cmsTemplate {
    private $css_stack = [];      // Стек зарегистрированных CSS
    private $js_head_stack = [];  // JavaScript для <head>
    private $js_body_stack = [];  // JavaScript перед </body>
    private $lang_js = [];        // Языковые константы для JS
    
    // Методы регистрации ресурсов
    public function addMainCSS($path) { /* ... */ }
    public function addCSS($path) { /* ... */ }
    public function addControllerCSS($file, $component) { /* ... */ }
    public function addMainJS($path) { /* ... */ }
    public function addJS($path) { /* ... */ }
    public function getLangJS($keys) { /* ... */ }
    
    // Методы разрешения путей
    public function getTplFilePath($relative_path) { /* ... */ }
    
    // Методы вывода
    public function renderHead() { /* ... */ }
    public function head() { /* ... */ }
}
```

### Процесс регистрации ресурсов
```
1. Контроллер вызывает метод регистрации (addMainCSS, addJS и т.д.)
2. cmsTemplate добавляет путь в соответствующий стек
3. Проверяется дублирование (автоматическая фильтрация)
4. При выводе страницы ресурсы обрабатываются в правильном порядке
```

## 33.3. Стратегия загрузки CSS

DST Platform использует двухуровневую стратегию загрузки CSS для баланса между производительностью (объединение) и гибкостью (динамическое добавление).

### Уровни загрузки CSS
| Уровень | Метод | Позиция в документе | Участвует в объединении |
|---------|-------|---------------------|--------------------------|
| **Критический** | `addMainCSS()` | `<head>`, начало стека | Да |
| **Дополнительный** | `addCSS()` | `<head>`, конец стека | Нет (опционально) |
| **Компонентный** | `addControllerCSS()` | `<head>` | Нет |

### Диаграмма загрузки CSS

<img src="https://github.com/DSTGlobal/DST-Platform/blob/main/images/191.png" alt="Стратегия загрузки CSS">

### Автоматическое разрешение стилей компонентов
Метод `addControllerCSS()` автоматически находит таблицы стилей, специфичные для компонента:

```php
// В контроллере компонента
$this->template->addControllerCSS('styles.css', 'shop');
// Автоматически загружает: /templates/{theme}/controllers/shop/styles.css
```

## 33.4. Стратегия загрузки JavaScript

Для оптимизации производительности отрисовки страницы JavaScript-ресурсы загружаются в двух зонах: критические в `<head>`, отложенные перед `</body>`.

### Зоны загрузки JavaScript
| Зона | Метод | Позиция | Назначение |
|------|-------|---------|------------|
| **Критическая** | `addMainJS()` | `<head>` | Инициализация фреймворков, критичный код |
| **Отложенная** | `addJS()` | Перед `</body>` | Интерактив, не критичный для рендеринга |

### Диаграмма загрузки JavaScript

<img src="https://github.com/DSTGlobal/DST-Platform/blob/main/images/193.png" alt="Стратегия загрузки JavaScript">

### Экспорт языковых переменных в JavaScript
Метод `getLangJS()` обеспечивает мост между константами языка PHP и клиентским JavaScript:

```php
// В контроллере
$this->template->getLangJS(['LANG_SAVE', 'LANG_CANCEL', 'LANG_CONFIRM']);

// Генерирует в <head>:
<script>
var LANG = {
    'LANG_SAVE': 'Сохранить',
    'LANG_CANCEL': 'Отмена',
    'LANG_CONFIRM': 'Вы уверены?'
};
</script>
```

## 33.5. Наследование шаблонов и разрешение ресурсов

Механизм наследования позволяет дочерним темам переопределять только необходимые файлы, используя ресурсы родительской темы в случае отсутствия.

### Структура файлов наследования
```
/templates/
├── default/              # Базовая тема
│   ├── css/
│   │   ├── style.css
│   │   └── bootstrap.css
│   ├── js/
│   │   └── main.js
│   └── controllers/
│       └── shop/
│           └── styles.css
└── dark/                 # Дочерняя тема
    ├── inherit.php       # return 'default';
    └── css/
        └── style.css     # Переопределяет только этот файл
```

<img src="https://github.com/DSTGlobal/DST-Platform/blob/main/images/195.png" alt="Структура наследования тем">

### Алгоритм разрешения ресурсов
```
При запросе файла /templates/dark/css/custom.css:
1. Проверить наличие в текущей теме (dark)
2. Если не найден → проверить родительскую тему (default)
3. Если не найден → проверить рекурсивно вверх по цепочке
4. Если не найден → вернуть null или сгенерировать ошибку
```

## 33.6. Статическая доставка через веб-сервер

Веб-сервер Apache/Nginx обрабатывает запросы статических ресурсов напрямую, без вызова PHP, что обеспечивает оптимальную производительность.

### Маршрутизация запросов через .htaccess
```apache
# Правила маршрутизации
RewriteEngine On

# Если запрошенный путь - существующий файл
RewriteCond %{REQUEST_FILENAME} !-f
# Если запрошенный путь - существующий каталог
RewriteCond %{REQUEST_FILENAME} !-d
# Перенаправить на index.php для динамической обработки
RewriteRule ^(.*)$ ./index.php [L]
```

<img src="https://github.com/DSTGlobal/DST-Platform/blob/main/images/197.png" alt="Маршрутизация статических ресурсов">

### Процесс обработки запроса
```
Браузер запрашивает /css/bootstrap.css
    ↓
Apache проверяет существование файла
    ↓
Файл существует → отдаёт напрямую (без PHP)
    ↓
Заголовки кэширования устанавливаются автоматически
```

## 33.7. Оптимизация: минификация и предотвращение кэширования

DST Platform поддерживает объединение ресурсов и стратегическое кэширование для оптимизации доставки.

### Стратегия кэширования
| Тип ресурса | Кэширование | Версионирование | Минификация |
|-------------|-------------|-----------------|-------------|
| **Объединённые CSS/JS** | Долгосрочное (1 год) | Да (`?v={hash}`) | Да |
| **Отдельные файлы** | Краткосрочное (1 час) | Да (`?v={timestamp}`) | Опционально |
| **Динамические ресурсы** | Отключено | Н/Д | Н/Д |

### Диаграмма стратегии кэширования

<img src="https://github.com/DSTGlobal/DST-Platform/blob/main/images/198.png" alt="Стратегия кэширования ресурсов">

### Процесс генерации объединённых пакетов
```
1. Сбор всех файлов из addMainCSS()/addMainJS()
2. Чтение содержимого каждого файла
3. Минификация (удаление пробелов, комментариев)
4. Объединение в один файл
5. Сохранение в /cache/{hash}.css
6. Добавление версионного параметра ?v={timestamp}
7. Отдача браузеру с заголовками кэширования
```

## 33.8. Изоляция ресурсов компонентов

Каждый компонент может содержать собственные CSS и JavaScript, которые конвейер автоматически обнаруживает и включает.

### Структура каталога ресурсов компонентов
```
/templates/{theme}/controllers/{component}/
├── styles.css          # Стили компонента
├── admin_styles.css    # Стили админки компонента
├── scripts.js          # JavaScript компонента
└── assets/             # Дополнительные ресурсы
    ├── images/
    └── fonts/
```

### Шаблон регистрации ресурсов компонента
```php
// В контроллере компонента
public function __construct($request) {
    parent::__construct($request);
    
    // Регистрация стилей компонента
    $this->template->addControllerCSS('styles.css', $this->name);
    
    // Регистрация скриптов компонента
    $this->template->addJS('controllers/' . $this->name . '/scripts.js');
}
```

### Пример: ресурсы компонента "Магазин"
| Файл | Назначение | Использование |
|------|------------|---------------|
| `/templates/default/shop/styles.css` | Основные стили магазина | Карточки товаров, интерфейс корзины |
| `/templates/default/shop/bootstrap.css` | Изолированная сетка Bootstrap | Отдельная система сетки для магазина |

## 33.9. Загрузка ресурсов в жизненном цикле страницы

Понимание последовательности загрузки ресурсов критично для оптимизации производительности.

### Последовательность отрисовки страницы
```
1. Загрузка шаблона (cmsTemplate::getInstance())
2. Регистрация ресурсов контроллером
3. Вызов $this->renderHead() в <head>
   ├─ Вывод мета-тегов
   ├─ Вывод объединённого CSS-пакета (addMainCSS)
   ├─ Вывод дополнительных CSS (addCSS, addControllerCSS)
   ├─ Вывод критического JavaScript (addMainJS)
   └─ Вывод языковых констант (getLangJS)
4. Рендеринг тела страницы ($this->body())
5. Перед закрытием </body>
   └─ Вывод отложенного JavaScript (addJS)
```

## 33.11. Динамическая генерация ресурсов

DST Platform поддерживает динамическую генерацию CSS на основе настроек конфигурации темы.

### Структура динамических ресурсов
```
/templates/{theme}/
├── options.css.php      # Генератор динамического CSS
├── options.form.php     # Форма настроек в админке
└── css/
    └── style.css        # Статические стили
```

### Пример динамического CSS-генератора
```php
<?php
// /templates/my_theme/options.css.php

header('Content-Type: text/css; charset=utf-8');

// Получение настроек темы
$settings = cmsCore::getSettings('theme.' . cmsTemplate::getTemplateName());

// Генерация динамических стилей
?>
:root {
    --primary-color: <?= $settings['primary_color'] ?? '#5b88bd' ?>;
    --secondary-color: <?= $settings['secondary_color'] ?? '#0b1f35' ?>;
    --border-radius: <?= $settings['border_radius'] ?? '4px' ?>;
    --font-family: <?= $settings['font_family'] ?? '"GT Eesti Pro", sans-serif' ?>;
}

body {
    font-family: var(--font-family);
    color: var(--secondary-color);
}

.btn-primary {
    background-color: var(--primary-color);
    border-radius: var(--border-radius);
}

.btn-primary:hover {
    background-color: <?= $this->darkenColor($settings['primary_color'] ?? '#5b88bd', 10) ?>;
}
```

## 33.13. Лучшие практики управления ресурсами

### Время регистрации ресурсов
1. **Конструктор контроллера**: Регистрируйте ресурсы, доступные во всём компоненте
   ```php
   public function __construct($request) {
       parent::__construct($request);
       $this->template->addControllerCSS('styles.css', $this->name);
   }
   ```

2. **Методы действий**: Регистрируйте ресурсы, специфичные для конкретного действия
   ```php
   public function actionItem($id) {
       $this->template->addJS('controllers/shop/gallery.js');
       // ... логика действия
   }
   ```

3. **Файлы шаблонов**: Используйте `getTplFilePath()` для динамического разрешения путей
   ```php
   <img src="<?= $this->getTplFilePath('images/logo.png') ?>" alt="Logo">
   ```

### Оптимизация производительности
| Практика | Реализация | Выгода |
|----------|------------|--------|
| **Критические стили** | Используйте `addMainCSS()` | Обеспечивает объединение и минификацию |
| **Отложенный JavaScript** | Используйте `addJS()` вместо `addMainJS()` | Улучшает время первоначальной загрузки |
| **Минимизация инлайна** | Используйте внешние таблицы стилей | Улучшенное кэширование |
| **Кэширование браузера** | Добавление версионных меток | Оптимальное использование кэша |
| **Изоляция компонентов** | Используйте `addControllerCSS()` | Автоматическое определение области видимости |

### Стратегия наследования тем
```
Принцип: Переопределяйте только те ресурсы, которые требуют настройки.
Пусть наследование позаботится обо всём остальном.
```

## 33.15. Диагностика и решение проблем

### Распространённые проблемы и решения

| Проблема | Возможная причина | Решение |
|----------|------------------|---------|
| **Ресурсы не загружаются** | Неправильный путь к файлу | Используйте `getTplFilePath()` для проверки разрешения пути |
| **Дублирование ресурсов** | Многократная регистрация | Конвейер автоматически фильтрует дубликаты |
| **CSS не применяется** | Неправильный порядок загрузки | Используйте `addMainCSS()` для критических стилей |
| **JavaScript ошибки** | Зависимости загружаются в неправильном порядке | Проверьте порядок вызова `addMainJS()` и `addJS()` |
| **Кэширование старой версии** | Отсутствует версионирование | Убедитесь, что включена опция версионирования |

### Инструменты отладки
```php
// Включение режима отладки
cmsConfig::set('debug_assets', true);

// Проверка разрешения пути
$path = $this->template->getTplFilePath('css/custom.css');
echo "Resolved path: " . $path;

// Просмотр зарегистрированных ресурсов
$css_stack = $this->template->getCSSStack();
print_r($css_stack);
```

## 33.16. Заключение

Конвейер обработки ресурсов DST Platform предоставляет комплексную систему управления фронтенд-активами со следующими характеристиками:

1. **Централизованное управление**: Все ресурсы регистрируются через единый интерфейс `cmsTemplate`
2. **Наследование шаблонов**: Дочерние темы переопределяют только необходимые ресурсы
3. **Оптимизация производительности**: Объединение, минификация и стратегическое кэширование
4. **Изоляция компонентов**: Каждый компонент управляет своими собственными ресурсами
5. **Гибкая загрузка**: Разделение на критические и отложенные ресурсы
6. **PHP-JS мост**: Экспорт языковых переменных через `getLangJS()`
7. **Статическая доставка**: Веб-сервер обходит PHP для обслуживания статических ресурсов

**Рекомендация для разработчиков:** При создании кастомных тем или компонентов всегда используйте методы `cmsTemplate` для регистрации ресурсов. Это гарантирует корректную обработку наследования, оптимизацию и совместимость с механизмами кэширования платформы. Для углублённого изучения системы визуального оформления см. разделы *«Структура стилей»* и *«Типографика и шрифты»*.
