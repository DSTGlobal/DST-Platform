# 4. Загрузка и инициализация системы

Этот документ описывает последовательность инициализации DST Platform при запуске приложения — как через HTTP-запрос (`index.php`), так и через CLI-скрипты (`cron_*.php`). Процесс загрузки гарантирует, что к моменту начала обработки запроса все необходимые сервисы (конфигурация, БД, кэш, сессия, локализация) уже инициализированы и готовы к использованию.

Информацию о зависимостях см. в разделе **«Управление зависимостями»**.  
О маршрутизации входящих запросов — в **«Маршрутизация URL и настройка веб-сервера»**.  
О дальнейших этапах жизненного цикла — в **«Шаблон MVC и жизненный цикл запроса»**.

---

## 4.1. Общая последовательность инициализации

Каждый запуск приложения проходит следующие этапы:

1. Определение корневых путей и констант
2. Настройка кодировки (`mb_internal_encoding`)
3. Загрузка автозагрузчика Composer
4. Регистрация пользовательского автозагрузчика ядра
5. Инициализация `cmsConfig`
6. Настройка обработки ошибок (в зависимости от режима отладки)
7. Проверка состояния установки
8. Условная инициализация сессии
9. Установка часового пояса
10. Загрузка вспомогательных библиотек
11. Инициализация `cmsCore`
12. Подключение к базе данных
13. Инициализация подсистемы кэширования
14. Вызов события `core_start`
15. Загрузка локализации

После этого управление передаётся точке входа (например, `index.php`), которая запускает маршрутизацию и выполнение контроллера.

---

## 4.2. Константы и пути

На старте определяются две ключевые константы:

| Константа | Значение | Назначение |
|----------|---------|------------|
| `PATH`   | `dirname(__FILE__)` | Абсолютный путь к корню приложения |
| `ROOT`   | `rtrim($_SERVER['DOCUMENT_ROOT'], DIRECTORY_SEPARATOR)` | Корень веб-сервера (для обратной совместимости) |

Пример:
```php
// PATH = /var/www/demo.dstglobal.ru
// ROOT = /var/www/demo.dstglobal.ru
```

> **Примечание**: `ROOT` устарел и не используется в ядре. Все пути строятся относительно `PATH`.

Константа `PATH` применяется для всех внутренних `include`/`require`.

---

## 4.3. Кодировка и локаль

Перед любой операцией с текстом устанавливается внутренняя кодировка:

```php
mb_internal_encoding('UTF-8');
```

Это обеспечивает корректную работу:
- функций `mb_*` (`mb_strlen`, `mb_substr`)
- экранирования HTML и SQL
- обработки строк в шаблонах
- локализованных сообщений

## 4.4. Автозагрузка зависимостей

### Composer
Если существует `vendor/autoload.php`, он подключается первым:

```php
if (file_exists(PATH . '/vendor/autoload.php')) {
    require_once PATH . '/vendor/autoload.php';
}
```

Загружаются все сторонние библиотеки: `guzzle`, `phpfastcache`, `yookassa-sdk` и др.

### Ядро платформы
После Composer регистрируется пользовательский автозагрузчик из `/system/config/autoload.php`:

```php
spl_autoload_register('autoLoadCoreClass');
```

Он загружает классы по соглашению:

| Префикс  | Путь шаблона | Пример |
|----------|--------------|--------|
| `cms`    | `/system/core/{name}.php` | `cmsCore` → `core.php` |
| `model`  | `/system/controllers/{component}/model.php` | `modelShop` → `shop/model.php` |
| `field`  | `/system/fields/{name}.php` | `fieldDate` → `date.php` |
| `widget` | `/system/widgets/{name}/widget.php` | `widgetMenu` → `menu/widget.php` |

## 4.5. Инициализация конфигурации

Создаётся синглтон `cmsConfig`:

```php
$config = cmsConfig::getInstance();
```

Он загружает `/system/config/config.php` и предоставляет доступ к:

| Параметр | Тип | Описание |
|---------|-----|----------|
| `database` | array | Хост, имя БД, пользователь, пароль, charset |
| `debug` | bool | Включает/выключает вывод ошибок |
| `time_zone` | string | Часовой пояс по умолчанию (например, `Europe/Moscow`) |
| `cookie_domain` | string | Домен для сессионных cookie |
| `cache` | array | Конфигурация Redis/Memcached/файлов |
| `is_installed` | bool | Флаг завершённой установки |

Объект доступен глобально через `cmsConfig::getInstance()`.

---

## 4.6. Обработка ошибок и режим отладки

Настройка поведения системы обработки ошибок осуществляется на основе debugфлага в конфигурации:

<img src="https://github.com/DSTGlobal/DST-Platform/blob/main/images/18.png" alt="DST Platform">

Поведение зависит от `$config->debug`:

### Режим отладки **отключён** (production):
```php
error_reporting(0);
```
Все ошибки PHP подавляются.

### Режим отладки **включён**:
```php
ini_set('display_errors', 1);
error_reporting(E_ALL);
```
Активируется расширенная диагностика:
- подробные трассировки ошибок
- логирование SQL-запросов
- профилирование памяти и времени выполнения

---

## 4.7. Проверка состояния установки

Если система не установлена (`$config->is_installed === false`), происходит редирект:

```php
if (!$config->isReady()) {
    header('Location: /install/');
    exit;
}
```

Это предотвращает запуск приложения без корректной конфигурации.

---

## 4.8. Управление сессиями

Сессия инициализируется **условно**:

```php
if (defined('SESSION_START')) {
    cmsUser::sessionStart();
}
```

### Где определяется `SESSION_START`:
| Точка входа | Сессия | Пример |
|-------------|--------|--------|
| `index.php` | Да | Веб-запросы |
| `admin/index.php` | Да | Админка |
| `cron_*.php` | Нет | Фоновые задачи |
| API-эндпоинты | Нет | Токен-аутентификация |

Функционал сессии:
- Установка домена cookie из конфигурации
- Сохранение пользовательского часового пояса
- Перезапись системного `time_zone` при наличии в сессии

---

## 4.9. Настройка часового пояса

Часовой пояс устанавливается один раз:

```php
date_default_timezone_set($config->time_zone);
```

Приоритет:
1. Часовой пояс из сессии (если сессия активна)
2. Значение из `config.php`

Влияет на все функции: `date()`, `time()`, `strtotime()`, логирование, временные метки БД.

---

## 4.10. Загрузка вспомогательных библиотек

Перед инициализацией ядра загружаются глобальные утилиты:

```php
cmsCore::loadLib('html.helper');
cmsCore::loadLib('strings.helper');
cmsCore::loadLib('files.helper');
cmsCore::loadLib('spyc.class');
```

| Библиотека | Путь | Назначение |
|-----------|------|------------|
| `html.helper` | `/system/libs/html.helper.php` | Генерация и экранирование HTML |
| `strings.helper` | `/system/libs/strings.helper.php` | Работа со строками (slug, trim и др.) |
| `files.helper` | `/system/libs/files.helper.php` | Операции с файловой системой |
| `spyc.class` | `/system/libs/spyc.class.php` | Парсинг YAML |

Функции этих библиотек доступны глобально без создания объектов.

## 4.11. Инициализация ядра (`cmsCore`)

Создаётся центральный синглтон:

```php
$core = cmsCore::getInstance();
```

Он выступает как **service locator** и предоставляет доступ к:

| Свойство | Тип | Описание |
|---------|-----|----------|
| `$core->db` | `cmsDatabase` | Подключение к БД |
| `$core->template` | `cmsTemplate` | Шаблонный движок |
| `$core->events` | `cmsEventsManager` | Система событий |
| `$core->user` | `cmsUser` | Текущий пользователь |
| `$core->permissions` | `cmsPermissions` | Система прав |

---

## 4.12. Подключение к базе данных

Выполняется через ядро:

```php
$core->connectDB();
```

Процесс:
1. Создаётся экземпляр `cmsDatabase` с параметрами из `cmsConfig`
2. Устанавливается соединение
3. Проверяется статус через `$core->db->ready()`

При ошибке:
- Загружаются языковые файлы
- Отображается локализованная страница ошибки
- Выполнение прерывается

Все операции с БД используют единый экземпляр `$core->db`.

---

## 4.13. Инициализация кэширования

После успешного подключения к БД запускается кэш:

```php
cmsCache::getInstance()->start();
```

Поддерживаемые бэкенды (в порядке приоритета):
- Redis (`ext-redis`)
- Memcached (`ext-memcached`)
- APCu (`ext-apcu`)
- Файлы (`/cache/`)

Конфигурация берётся из `$config->cache`.  
Используется для: кэша запросов, фрагментов шаблонов, сессий, API-ответов.

---

## 4.14. Событие `core_start`

На этом этапе вызывается первый системный хук:

```php
cmsEventsManager::hook('core_start');
```

Компоненты могут подписаться на него через `hooks.php`:

```php
// /system/controllers/search/hooks.php
class search {
    public function onCoreStart() {
        // инициализация индекса, проверка миграций и т.д.
    }
}
```

Типичные сценарии:
- Подогрев кэша
- Проверка версии схемы БД
- Инициализация внешних SDK
- Настройка аналитики

---

## 4.15. Локализация

Завершающий этап инициализации:

```php
cmsCore::loadLanguage();
```

Процесс:
1. Загружаются языковые массивы из `/system/languages/{locale}/`
2. Устанавливается локаль PHP: `setlocale(LC_TIME, ...)`
3. Настраивается локаль MySQL для сообщений об ошибках

Языковые строки доступны через глобальный массив `LANG`:

```php
echo LANG['USER_LOGIN']; // "Войти"
```

Приоритет выбора языка:
1. Настройки пользователя
2. Сессия
3. Значение по умолчанию из `config.php`

## 4.17. Синглтоны, создаваемые при загрузке

В процессе начальной загрузки создается несколько экземпляров-одиночек, которые сохраняются на протяжении всего жизненного цикла запроса:

<img src="https://github.com/DSTGlobal/DST-Platform/blob/main/images/20.png" alt="DST Platform">

| Синглтон | Время инициализации | Тип |
|----------|---------------------|-----|
| `cmsConfig` | Немедленно | Обязательный |
| `cmsDebugging` | Условно (если `debug = true`) | Опциональный |
| `cmsCore` | Немедленно | Обязательный |
| `cmsDatabase` | Через `$core->connectDB()` | Обязательный |
| `cmsCache` | После подключения к БД | Обязательный |
| `cmsUser` | Лениво (при первом обращении) | Условный |
| `cmsTemplate` | Лениво | Условный |
| `cmsEventsManager` | Лениво (при первом вызове `hook()`) | Условный |

Все синглтоны остаются доступными на протяжении всего жизненного цикла запроса.

## 4.18. Контексты запуска

Хотя последовательность инициализации едина, точки входа различаются:

| Точка входа | Сессия | Назначение |
|-------------|--------|-----------|
| `index.php` | Да | Обработка HTTP-запросов |
| `admin/index.php` | Да | Административная панель |
| `cron.php` | Нет | Выполнение фоновых задач из очереди |
| `cron_export.php` | Нет | Экспорт данных (CSV, YML) |
| `cron_yml_create.php` | Нет | Генерация фида для Яндекс.Маркета |

CLI-скрипты определяют `BASEPATH` вместо `PATH` и не инициализируют сессию.

---

## 4.19. Обработка ошибок при загрузке

| Сценарий | Обнаружение | Реакция |
|---------|-------------|--------|
| Отсутствует `config.php` | `$config->isReady() === false` | Редирект на `/install/` |
| Ошибка подключения к БД | `$core->db->ready() === false` | Локализованная страница ошибки + `exit` |
| Отсутствует `vendor/autoload.php` | `file_exists()` → `false` | Fatal error PHP |
| Неверный часовой пояс | `date_default_timezone_set()` → предупреждение | Продолжение работы |

---

## 4.20. Что происходит после инициализации

После завершения загрузки управление возвращается в точку входа.

### Для `index.php`:
1. Анализ URI → определение компонента и действия
2. Создание контроллера (например, `shop`)
3. Вызов метода действия (например, `item_view_action`)
4. Рендеринг шаблона
5. Отправка ответа клиенту

### Для `cron_*.php`:
1. Прямой вызов метода контроллера
2. Выполнение бизнес-логики (экспорт, импорт, генерация)
3. Завершение скрипта

---

## 4.21. Заключение

Процесс загрузки DST Platform:
- **Линейный и детерминированный**
- **Безопасный**: проверяет состояние перед продолжением
- **Гибкий**: поддерживает разные контексты (HTTP/CLI)
- **Расширяемый**: через событие `core_start`
- **Согласованный**: использует единые синглтоны для всех подсистем

После его завершения приложение полностью готово к обработке запроса или выполнению задачи.
