# 35. Структура проекта

Этот документ представляет собой исчерпывающее руководство по организации каталогов, соглашениям об именовании файлов и шаблонам их размещения в DST Platform. Он служит справочником для разработчиков, которым необходимо понять, где найти существующий код или куда поместить новые файлы при расширении платформы.

Информацию о создании новых компонентов с нуля см. в разделе «Создание компонентов». Подробные сведения о процессе начальной загрузки и последовательности инициализации приведены в разделе «Начальная загрузка и инициализация системы». Механику шаблонной системы и наследование см. в разделе «Шаблонная система».

## 35.2. Системный каталог (`/system/`)

В директории `/system/` содержится весь основной код фреймворка и бизнес-логика. Она структурирована в несколько поддиректорий, каждая из которых имеет определенное назначение:

### Структура каталога

| Каталог | Цель | Шаблон именования классов | Пример |
|---|---|---|---|
| `/system/config/` | Файлы конфигурации | Н/Д | `config.php`, `autoload.php`, `remap.php` |
| `/system/core/` | Основные классы фреймворка | `cms*` | `cmsCore`, `cmsModel`, `cmsTemplate` |
| `/system/controllers/` | Контроллеры/модели компонентов | `controller*`, `model*` | `controllerShop`, `modelShop` |
| `/system/fields/` | Типы полей формы | `field*` | `fieldDate`, `fieldImage` |
| `/system/languages/` | Файлы локализации | Н/Д | `en/default.php`, `ru/default.php` |
| `/system/libs/` | Внутренние библиотеки | Различный | Вспомогательные классы, утилиты |
| `/system/widgets/` | Глобальные виджеты | `widget*` | `widgetMenu`, `widgetHTML` |

### Файлы конфигурации (`/system/config/`)

## 35.3. Основные классы (`/system/core/`)

В основной директории находятся классы-одиночки, предоставляющие базовые сервисы. Каждый файл определяет один класс в соответствии с соглашением об именовании `cms*`:

<img src="https://github.com/DSTGlobal/DST-Platform/blob/main/images/214.png" alt="Основные классы фреймворка DST Platform">

*Диаграмма: Основные классы фреймворка и их взаимосвязи.*

Основные характеристики:

*   **Именование файлов:** строчными буквами (например, `core.php`, `model.php`)
*   **Именование классов:** `CamelCase` с префиксом `cms` (например, `cmsCore`, `cmsModel`)
*   **Создание экземпляра:** В большинстве случаев это синглтоны, доступ к которым осуществляется через `cmsCore::getInstance()`
*   **Наследование:** `cmsFrontend` и `cmsBackend` расширяют `cmsController`

## 35.4. Контроллеры и компоненты (`/system/controllers/`)

Компоненты представляют собой самодостаточные функциональные модули. Каждый компонент находится в своей поддиректории внутри `/system/controllers/`. Имя директории должно:

*   Начинаться с буквы (a-z).
*   Содержать только строчные буквы, цифры и символы подчеркивания.
*   Иметь длину не менее 3 символов.
*   Быть уникальным в рамках всей системы.

## 35.5. Соглашения об именовании файлов компонентов

Названия классов строго соответствуют соглашениям, основанным на названии компонента:

| Файл | Шаблон имени класса | Пример (компонент: `shop`) |
|---|---|---|
| `frontend.php` | `controller{Component}` | `controllerShop` |
| `model.php` | `model{Component}` | `modelShop` |
| `backend/backend.php` | `controllerBackend{Component}` | `controllerBackendShop` |
| `backend/model.php` | `modelBackend{Component}` | `modelBackendShop` |
| `hooks.php` | `on{Component}Hooks` | `onShopHooks` |
| `widgets/{name}.php` | `widget{Component}{Name}` | `widgetShopCart` |

**Важно:** в именах компонентов в названиях классов используется `CamelCase` (например, директория `purchase_requisition` → класс `controllerPurchaseRequisition`).

## 35.6. Каталог шаблонов (`/templates/`)

Шаблоны управляют уровнем представления. Каждая тема находится в своей поддиректории внутри `/templates/`. Тема `default` служит основой, от которой наследуются все остальные темы.

### Структура каталогов шаблонов

<img src="https://github.com/DSTGlobal/DST-Platform/blob/main/images/217.png" alt="Структура каталогов шаблонов DST Platform">

*Диаграмма: Структура каталогов шаблонов для темы по умолчанию.*

### Соглашение об именовании файлов шаблонов

Файлы шаблонов используют расширение `.tpl.php`. Шаблон именования зависит от типа:

| Тип шаблона | Расположение | Шаблон именования | Пример |
|---|---|---|---|
| Основной макет | `/templates/{theme}/` | `main.tpl.php` | `main.tpl.php` |
| Макет административной панели | `/templates/{theme}/` | `admin.tpl.php` | `admin.tpl.php` |
| Представление компонента | `/templates/{theme}/controllers/{component}/` | `{action}.tpl.php` | `item_view.tpl.php` |
| Шаблон виджета | `/templates/{theme}/widgets/` | `{widget_name}.tpl.php` | `menu.tpl.php` |
| Виджет компонента | `/templates/{theme}/controllers/{component}/widgets/` | `{widget_name}.tpl.php` | `cart.tpl.php` |
| Представление в бэкенде | `/templates/{theme}/controllers/{component}/backend/` | `{action}.tpl.php` | `form.tpl.php` |
| Элемент интерфейса | `/templates/{theme}/assets/ui/` | `{element}.tpl.php` | `breadcrumbs.tpl.php` |
| Страница ошибки | `/templates/{theme}/assets/errors/` | `{error}.tpl.php` | `404.tpl.php` |

### Механизм наследования шаблонов

<img src="https://github.com/DSTGlobal/DST-Platform/blob/main/images/218.png" alt="Наследование шаблонов DST Platform">

*Диаграмма: Последовательность разрешения наследования шаблонов.*

Для включения наследования создайте файл `/templates/{custom_theme}/inherit.php`:
```php
<?php
return 'default'; // Наследовать от темы default
```

Когда запрашивается файл шаблона:
1.  Система проверяет каталог активной темы.
2.  Если файл не найден, проверяется родительская тема (определенная в `inherit.php`).
3.  Если файл по-прежнему не найден, возвращается ошибка.

Это относится к файлам `.tpl.php`, `.css`, `.js` и при загрузке с помощью методов `cmsTemplate`.

## 35.7. Специальные каталоги

### Каталоги времени выполнения

Эти каталоги содержат сгенерированный или загруженный пользователем контент и должны быть доступны для записи веб-сервером:

<img src="https://github.com/DSTGlobal/DST-Platform/blob/main/images/219.png" alt="Каталоги среды выполнения DST Platform">

*Диаграмма: Каталоги среды выполнения и их содержимое.*

Эти каталоги исключены из системы контроля версий:

| Каталог | Содержимое |
|---|---|
| `/cache/` | Системно сгенерированные файлы кэша, файлы блокировки для задач cron, скомпилированные шаблоны. |
| `/upload/` | Файлы, загруженные пользователями, организованные по компонентам (пользователи, маркетплейс, контент и т.д.). |
| `/exports/` | Сгенерированные файлы для экспорта (фиды товаров, YML-файлы для маркетплейсов). |

### Каталог поставщиков (`/vendor/`)

Содержит сторонние библиотеки, управляемые Composer. Эта директория генерируется автоматически и не должна изменяться напрямую:
```
/vendor/
├── box/spout/              # Spreadsheet I/O
├── sanmai/cdek-sdk/        # CDEK shipping API
├── guzzlehttp/guzzle/      # HTTP client
├── geoip2/geoip2/          # IP geolocation
├── phpfastcache/           # Cache abstraction
├── yoomoney/yookassa-sdk-php/  # Payment gateway
└── autoload.php            # Composer autoloader
```

Каталог `vendor` исключен из системы контроля версий. Зависимости устанавливаются с помощью `composer install`.

---

### Основные зависимости
| Библиотека | Версия | Назначение |
|---|---|---|
| `guzzlehttp/guzzle` | ~6.0 | HTTP-клиент для интеграции API |
| `box/spout` | ^3.3 | Импорт/экспорт электронных таблиц |
| `phpfastcache/phpfastcache` | ^7.1 | Абстракция кэширования |
| `sanmai/cdek-sdk` | ^0.6.22 | Интеграция доставки CDEK |
| `yoomoney/yookassa-sdk-php` | ^2.1 | Обработка платежей |
| `geoip2/geoip2` | ~2.0 | Геолокация по IP-адресу |

## 35.8. Именование файлов и автозагрузка

DST Platform использует автозагрузку на основе соглашений. При обращении к классу автозагрузчик ищет его на основе шаблонов именования:

### Правила автозагрузки

| Шаблон класса | Каталог | Имя файла | Пример |
|---|---|---|---|
| `cms*` | `/system/core/` | Имя класса в нижнем регистре без `cms` | `cmsCore` → `core.php` |
| `field*` | `/system/fields/` | Имя класса в нижнем регистре без `field` | `fieldDate` → `date.php` |
| `controller*` | `/system/controllers/{component}/` | `frontend.php` | `controllerShop` → `shop/frontend.php` |
| `controllerBackend*` | `/system/controllers/{component}/backend/` | `backend.php` | `controllerBackendShop` → `shop/backend/backend.php` |
| `model*` | `/system/controllers/{component}/` | `model.php` | `modelShop` → `shop/model.php` |
| `modelBackend*` | `/system/controllers/{component}/backend/` | `model.php` | `modelBackendShop` → `shop/backend/model.php` |
| `widget*` | `/system/widgets/` или `/system/controllers/{component}/widgets/` | строчные буквы без `widget` | `widgetMenu` → `menu.php` |

### Сопоставление имени компонента с каталогом

В названиях компонентов в каталогах используются строчные буквы с подчеркиваниями, а в названиях классов — `CamelCase`:

*   **Каталог:** `/system/controllers/purchase_requisition/`
*   **Frontend-класс:** `controllerPurchaseRequisition`
*   **Класс модели:** `modelPurchaseRequisition`

Автозагрузчик выполняет это преобразование автоматически.

## 35.10. Практическое руководство по навигации по каталогам

Эта таблица обеспечивает быструю навигацию для распространенных задач разработки:

| Задача | Расположение |
|---|---|
| Добавить новый компонент | Создайте каталог в `/system/controllers/{component_name}/` |
| Создать действие во фронтенде | Добавить метод в `/system/controllers/{component}/frontend.php` |
| Создать административный интерфейс | Создать `/system/controllers/{component}/backend/backend.php` |
| Добавить запросы к базе данных | Расширить `/system/controllers/{component}/model.php` |
| Настроить шаблон компонента | Создать/редактировать `/templates/{theme}/controllers/{component}/{action}.tpl.php` |
| Добавить глобальный виджет | Создать `/system/widgets/{widget_name}.php` и `/templates/{theme}/widgets/{widget_name}.tpl.php` |
| Добавить виджет компонента | Создать в `/system/controllers/{component}/widgets/` и `/templates/{theme}/controllers/{component}/widgets/` |
| Создать пользовательское поле формы | Добавить класс в `/system/fields/field{Type}.php` |
| Добавить языковые строки | Редактировать `/system/controllers/{component}/languages/{lang}/default.php` |
| Подключиться к событиям | Создать `/system/controllers/{component}/hooks.php` |
| Изменить макет страницы | Редактировать `/templates/{theme}/main.tpl.php` |
| Настроить страницы ошибок | Редактировать `/templates/{theme}/assets/errors/{error_code}.tpl.php` |
| Добавить глобальные CSS-стили | Разместить в `/templates/{theme}/css/` и подключить через `$this->addMainCSS()` |
| Добавить CSS-стили компонента | Разместить в `/templates/{theme}/controllers/{component}/styles.css` |
| Настроить базу данных | Редактировать `/system/config/config.php` |
| Настроить правила перезаписи URL | Редактировать `/system/config/remap.php` |

## 35.11. Исключения системы контроля версий

В файле `.gitignore` определены каталоги и файлы, которые не следует отслеживать:

**Исключенные каталоги:**

*   `/cache/` — Сгенерированные файлы кэша.
*   `/upload/` — Контент, загруженный пользователями.
*   `/vendor/` — Зависимости Composer.
*   `/exports/` — Сгенерированные файлы экспорта (кроме `.gitkeep`).
*   `/system/config/config.php` — Содержит конфиденциальные учетные данные.
*   Устаревшие/резервные каталоги (например, `/templates/default/assets_old/`).

**Исключенные шаблоны файлов:**

*   `products*.xlsx` — Экспорт сгенерированной продукции.
*   `*.xls`, `*.xlsx` — Экспортированные электронные таблицы.
*   `market*.xml` — YML-файлы фидов.

При настройке новой среды эти каталоги должны быть созданы и предоставлены веб-серверу для записи. Репозиторий включает файлы `.gitkeep` в критически важные пустые каталоги для сохранения структуры.

## 35.12. Заключение

Структура каталогов DST Platform основана на следующих принципах:

1.  **Разделение ответственности:** Системная логика (`/system/`), представление (`/templates/`) и данные времени выполнения (`/cache/`, `/upload/`) строго разделены.
2.  **Принцип «соглашение важнее конфигурации»:** Именование файлов и классов следует предсказуемым шаблонам, что обеспечивает автозагрузку.
3.  **Модульность компонентов:** Каждый функциональный модуль самодостаточен и расположен в `/system/controllers/{component}/`.
4.  **Наследование шаблонов:** Темы наследуют файлы от родительских тем, что уменьшает дублирование кода.
5.  **Безопасность по умолчанию:** Конфиденциальные файлы (конфигурация, загрузки) защищены от веб-доступа правилами `.htaccess`.

Понимание этой структуры позволяет эффективно ориентироваться в кодовой базе и обеспечивать согласованное размещение нового кода.
