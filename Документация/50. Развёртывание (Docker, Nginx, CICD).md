# Часть I. Обзор

## 50.1. Стратегии развёртывания

DST Platform — модульный монолит на PHP, работающий в связке с MySQL/MariaDB, Redis и веб-сервером (Nginx или Apache). Это определяет три базовые стратегии развёртывания:

| Стратегия | Когда использовать | Плюсы | Минусы |
|---|---|---|---|
| **Bare-metal / VPS + Nginx + PHP-FPM** | Один сервер, до ~400 000 посещений/сутки | Минимум накладных расходов, максимальная производительность | Ручное управление зависимостями, сложнее масштабировать |
| **Docker Compose** | 2–5 серверов, staging, локальная разработка | Повторяемость, изоляция сервисов, простой CI/CD | +5–10 % накладных расходов, требует Docker-экспертизы |
| **Kubernetes / Swarm** | Кластер, горизонтальное масштабирование, многотенантность | Автомасштабирование, self-healing, rolling updates | Высокая операционная сложность, требует отдельной команды |

> 💡 **Прагматичный выбор.** Для 90 % проектов на DST Platform оптимален **Docker Compose на 1–3 серверах**: он даёт воспроизводимость bare-metal и простоту CI/CD, при этом не требует Kubernetes. Миграция на K8s оправдана при измеримых триггерах (нагрузка >70 % CPU на несколько сервисов, >10 000 RPS, много команд).

**Ключевые принципы (единые для всех стратегий):**

1. **Идемпотентность.** Любой деплой можно повторить — результат тот же.
2. **Zero-downtime.** Пользователи не видят паузы (blue-green, rolling).
3. **Воспроизводимость.** Один и тот же артефакт разворачивается на staging и prod.
4. **Откатываемость.** Rollback до предыдущей версии — за < 5 минут.
5. **Наблюдаемость.** После деплоя — health checks и smoke-тесты (см. 57).

## 50.2. Среды (dev / staging / prod)

```
┌────────────────────────────────────────────────────────────────┐
│                   СРЕДЫ DST PLATFORM                           │
├────────────────────────────────────────────────────────────────┤
│                                                                │
│  ┌──────────────┐     ┌──────────────┐     ┌──────────────┐    │
│  │    DEV       │────▶│   STAGING    │────▶│     PROD     │    │
│  │  (локально)  │     │ (зеркало)    │     │  (боевая)    │    │
│  └──────────────┘     └──────────────┘     └──────────────┘    │
│                                                                │
│  • SQLite/MySQL       • MySQL 8              • MySQL 8         │
│  • debug=true         • debug=false          • debug=false     │
│  • Xdebug вкл.        • Xdebug выкл.         • Xdebug выкл.    │
│  • кэш в файлах       • Redis db 1           • Redis db 0      │
│  • реальные email     • mock email           • реальные email  │
│    отключены          • API test-ключи       • API live-ключи  │
│                                                                │
│  Источник:            Источник:              Источник:         │
│  git clone            git tag v1.x.x         git tag v1.x.x    │
│                       + миграции             + миграции        │
│                       + smoke-тесты          + smoke-тесты     │
└────────────────────────────────────────────────────────────────┘
```

| Параметр | dev | staging | prod |
|---|---|---|---|
| Ветка / тег | `develop` | `v*.*.*` (тег) | `v*.*.*` (тег) |
| `debug` | `true` | `false` | `false` |
| Xdebug | Вкл. | Выкл. | Выкл. |
| Redis | Файловый кэш | Отдельный namespace | Боевой |
| Внешние сервисы | Моки | Test-ключи (YooKassa test, CDEK test) | Live-ключи |
| Email | Отключён / Mailhog | Mock transport | SMTP (см. 46) |
| Тестовые данные | Любые | Анонимизированные из prod | Реальные |
| CI/CD | Pre-commit | Авто-деплой по тегу | Ручное подтверждение |
| Backup | Не нужен | Ежедневно | По политике (см. 56) |

> ⚠️ **Правило staging.** Staging должен быть **максимально похож** на prod: та же версия PHP, тот же MySQL, та же конфигурация Nginx. Иначе баги переезжают в prod. Данные в staging — анонимизированная копия prod (с соблюдением 152-ФЗ, см. раздел *«Вопросы безопасности»*).

## 50.3. Архитектура развёртывания

### 50.3.1. Базовая (односерверная)

```
                        ┌──────────────────────┐
        Интернет ──────▶│   Nginx :80/:443     │
                        └──────────┬───────────┘
                                   │
                        ┌──────────▼───────────┐
                        │   PHP-FPM (pool)     │
                        │   php8.1-fpm         │
                        └──┬─────────┬─────────┘
                           │         │
                ┌──────────▼──┐  ┌───▼──────────┐
                │ MySQL/Maria │  │    Redis     │
                │   :3306     │  │   :6379      │
                └─────────────┘  └──────────────┘

                Файлы: /var/www/dst (код + upload + cache)
```

**Производительность:** ~400 000 посещений/сутки, 120–150 RPS при пике, при 8 vCPU / 32 ГБ RAM (см. раздел *«Схема архитектуры»*).

### 50.3.2. Docker Compose (рекомендуется для staging и небольших prod)

```
                        ┌──────────────────────┐
        Интернет ──────▶│  Traefik / Nginx     │  (reverse proxy + TLS)
                        └──────────┬───────────┘
                                   │
                    ┌──────────────┼──────────────┐
                    │              │              │
             ┌──────▼─────┐ ┌──────▼──────┐ ┌─────▼──────┐
             │  dst-app   │ │   dst-app   │ │   dst-app  │  ← PHP-FPM + Nginx
             │  (replica) │ │  (replica)  │ │  (replica) │
             └──────┬─────┘ └──────┬──────┘ └─────┬──────┘
                    │              │              │
                    └──────────────┼──────────────┘
                                   │
                    ┌──────────────┼──────────────┐
                    │              │              │
             ┌──────▼─────┐ ┌──────▼──────┐ ┌─────▼──────┐
             │   MySQL    │ │    Redis    │ │  Volumes   │
             │  :3306     │ │   :6379     │ │ upload/    │
             └────────────┘ └─────────────┘ │ cache/     │
                                             │ exports/   │
                                             └────────────┘
```

**Когда:** несколько серверов, горизонтальное масштабирование, изоляция сервисов, единый артефакт для staging/prod.

### 50.3.3. Кластер (Kubernetes)

Используется при >10 000 RPS и/или многотенантности. Выходит за рамки данного документа; принципы — те же, что в Docker Compose, но с оркестрацией (Deployment, Service, Ingress, HPA).

# Часть II. Docker

## 50.5. Dockerfile для DST Platform

### 50.5.1. Multi-stage Dockerfile (полный листинг)

**Файл:** `/docker/Dockerfile`

```dockerfile
# syntax=docker/dockerfile:1.6
# ─────────────────────────────────────────────────────────────
# DST Platform — production Dockerfile
# Multi-stage: builder → runtime
# ─────────────────────────────────────────────────────────────

# ═════════════════════════════════════════════════════════════
# Stage 1: builder — установка Composer-зависимостей
# ═════════════════════════════════════════════════════════════
FROM php:8.1-cli-alpine AS builder

RUN apk add --no-cache \
        git \
        unzip \
        icu-dev \
        libzip-dev \
        oniguruma-dev \
        $PHPIZE_DEPS

RUN docker-php-ext-install \
        intl \
        zip \
        mbstring \
        opcache

# Composer
COPY --from=composer:2.5 /usr/bin/composer /usr/bin/composer

WORKDIR /app

# Сначала — только composer.json/lock для кэша слоёв
COPY composer.json composer.lock ./

RUN --mount=type=cache,target=/tmp/composer-cache \
    COMPOSER_CACHE_DIR=/tmp/composer-cache \
    composer install \
        --no-dev \
        --no-interaction \
        --no-progress \
        --prefer-dist \
        --optimize-autoloader \
        --classmap-authoritative \
        --no-scripts

# Затем — весь код
COPY . .

RUN composer dump-autoload --optimize --classmap-authoritative --no-dev

# Удаляем всё лишнее
RUN rm -rf \
        tests \
        .git \
        .github \
        .gitlab-ci.yml \
        phpunit.xml \
        phpunit.ci.xml \
        .phpunit.cache \
        coverage \
        node_modules \
        .env.example

# ═════════════════════════════════════════════════════════════
# Stage 2: runtime — минимальный образ с PHP-FPM
# ═════════════════════════════════════════════════════════════
FROM php:8.1-fpm-alpine AS runtime

LABEL maintainer="DST Global <devops@dstglobal.ru>" \
      org.opencontainers.image.title="DST Platform" \
      org.opencontainers.image.vendor="DST Global" \
      org.opencontainers.image.licenses="Proprietary"

# Системные зависимости
RUN apk add --no-cache \
        icu-libs \
        libzip \
        oniguruma \
        curl \
        tini \
        mysql-client

# Расширения PHP
RUN apk add --no-cache --virtual .build-deps \
        $PHPIZE_DEPS \
        icu-dev \
        libzip-dev \
        oniguruma-dev \
        libpng-dev \
        libjpeg-turbo-dev \
        freetype-dev \
        libwebp-dev \
    && docker-php-ext-configure gd \
        --with-freetype \
        --with-jpeg \
        --with-webp \
    && docker-php-ext-install -j$(nproc) \
        pdo_mysql \
        mbstring \
        json \
        intl \
        zip \
        gd \
        opcache \
        bcmath \
        exif \
    && pecl install redis \
    && docker-php-ext-enable redis \
    && apk del .build-deps

# Конфигурация PHP (production)
COPY docker/php/php.ini /usr/local/etc/php/conf.d/99-dst.ini
COPY docker/php/php-fpm.conf /usr/local/etc/php-fpm.d/zz-dst.conf

# Пользователь (не root)
ARG UID=1000
ARG GID=1000
RUN addgroup -g ${GID} dst \
    && adduser -D -u ${UID} -G dst -s /sbin/nologin dst

WORKDIR /var/www/dst

# Копируем готовый код из builder
COPY --from=builder --chown=dst:dst /app /var/www/dst

# Директории с правильными правами
RUN mkdir -p \
        /var/www/dst/cache \
        /var/www/dst/upload \
        /var/www/dst/exports \
        /var/www/dst/system/config \
    && chown -R dst:dst \
        /var/www/dst/cache \
        /var/www/dst/upload \
        /var/www/dst/exports \
        /var/www/dst/system/config \
    && chmod -R 775 \
        /var/www/dst/cache \
        /var/www/dst/upload \
        /var/www/dst/exports \
        /var/www/dst/system/config

# Healthcheck
HEALTHCHECK --interval=30s --timeout=5s --start-period=10s --retries=3 \
    CMD php -r "exit(@fsockopen('127.0.0.1', 9000) ? 0 : 1);"

USER dst

EXPOSE 9000

# tini — корректная обработка сигналов
ENTRYPOINT ["/sbin/tini", "--"]
CMD ["php-fpm", "-F"]
```

### 50.5.3. Конфигурация PHP-FPM

**Файл:** `/docker/php/php-fpm.conf`

```ini
; ─────────────────────────────────────────────
; DST Platform — PHP-FPM pool
; ─────────────────────────────────────────────

[dst]
user = dst
group = dst

listen = 0.0.0.0:9000
listen.backlog = 511

; Dynamic — оптимально для одного сервера
pm = dynamic
pm.max_children = 50
pm.start_servers = 10
pm.min_spare_servers = 5
pm.max_spare_servers = 15
pm.max_requests = 1000

; Логирование медленных запросов (> 3 сек)
request_slowlog_timeout = 3s
slowlog = /proc/self/fd/2

; Таймауты
request_terminate_timeout = 120s

; Буферизация
catch_workers_output = yes
decorate_workers_output = no

; Статус для мониторинга (см. 57)
pm.status_path = /status
ping.path = /ping
ping.response = pong
```

> 💡 **`pm.max_children`.** Формула: `(RAM × 0.7) / memory_per_worker`. Для 8 ГБ RAM и ~120 МБ на воркер — `(8192 × 0.7) / 120 ≈ 47`. Значение `50` — оптимум для 8 ГБ. При большем числе воркеров упрётесь в RAM раньше, чем в CPU.

## 50.6. `docker-compose` для локальной разработки

**Файл:** `/docker-compose.yml` (dev)

```yaml
version: '3.9'

services:
  app:
    build:
      context: .
      dockerfile: docker/Dockerfile.dev
      args:
        UID: ${UID:-1000}
        GID: ${GID:-1000}
    container_name: dst_app_dev
    working_dir: /var/www/dst
    volumes:
      # Монтируем код целиком — правки видны сразу
      - .:/var/www/dst:cached
      # Отдельные volume для кэша/загрузок (чтобы не тормозить на macOS/Windows)
      - dst_cache:/var/www/dst/cache
      - dst_upload:/var/www/dst/upload
      - dst_exports:/var/www/dst/exports
    environment:
      - APP_ENV=dev
      - PHP_IDE_CONFIG=serverName=dst.local
      - XDEBUG_MODE=develop,debug
      - XDEBUG_CONFIG=client_host=host.docker.internal client_port=9003
    extra_hosts:
      - "host.docker.internal:host-gateway"
    depends_on:
      mysql:
        condition: service_healthy
      redis:
        condition: service_healthy
    networks:
      - dst

  nginx:
    image: nginx:1.25-alpine
    container_name: dst_nginx_dev
    ports:
      - "8080:80"
    volumes:
      - .:/var/www/dst:cached
      - ./docker/nginx/dev.conf:/etc/nginx/conf.d/default.conf:ro
    depends_on:
      - app
    networks:
      - dst

  mysql:
    image: mysql:8.0
    container_name: dst_mysql_dev
    ports:
      - "3306:3306"
    environment:
      MYSQL_ROOT_PASSWORD: root
      MYSQL_DATABASE: dst_dev
      MYSQL_USER: dst
      MYSQL_PASSWORD: dst
    volumes:
      - dst_mysql_dev:/var/lib/mysql
      - ./docker/mysql/init.sql:/docker-entrypoint-initdb.d/init.sql:ro
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "localhost", "-uroot", "-proot"]
      interval: 10s
      timeout: 5s
      retries: 5
    networks:
      - dst

  redis:
    image: redis:7-alpine
    container_name: dst_redis_dev
    ports:
      - "6379:6379"
    command: redis-server --appendonly yes
    volumes:
      - dst_redis_dev:/data
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 10s
      timeout: 5s
      retries: 5
    networks:
      - dst

  # Mailhog — перехват писем (см. раздел 46)

    image: mailhog/mailhog:latest
    container_name: dst_mailhog_dev
    ports:
      - "1025:1025"   # SMTP
      - "8025:8025"   # Web UI
    networks:
      - dst

  # Adminer — управление БД через браузер
  adminer:
    image: adminer:latest
    container_name: dst_adminer_dev
    ports:
      - "8081:8080"
    depends_on:
      - mysql
    networks:
      - dst

volumes:
  dst_cache:
  dst_upload:
  dst_exports:
  dst_mysql_dev:
  dst_redis_dev:

networks:
  dst:
    driver: bridge
```

### 50.7.1. Скрипт cron-раннера

**Файл:** `/scripts/cron_runner.sh`

```bash
#!/bin/sh
# ─────────────────────────────────────────────
# Единый cron-воркер для кластера.
# Запускает задачи из планировщика DST (см. раздел 17–19).
# ─────────────────────────────────────────────

set -e

echo "[cron] Started at $(date -Iseconds)"

# Проверка, что БД доступна
until php -r "exit(@fsockopen('mysql', 3306) ? 0 : 1);"; do
    echo "[cron] Waiting for MySQL..."
    sleep 3
done

# Основной цикл: раз в минуту
while :; do
    echo "[cron] Tick at $(date -Iseconds)"
    php /var/www/dst/cron.php || echo "[cron] cron.php exited with $?"
    sleep 60
done
```

## 50.9. Persistent volumes

**Что обязательно монтируется в volume** (иначе потеряется при пересоздании контейнера):

| Директория | Содержимое | Почему volume |
|---|---|---|
| `/var/www/dst/upload` | Пользовательские файлы, изображения | Несменяемые данные |
| `/var/www/dst/exports` | Экспорт товаров, YML, отчёты | Генерируется долго — не терять |
| `/var/www/dst/system/config` | `config.php` (не в образе!) | Секреты, специфичные для сервера |
| `/var/www/dst/cache` | Файловый кэш | Ускоряет холодный старт (опционально) |
| `/var/lib/mysql` | Данные MySQL | Критично |
| `/data` (Redis) | AOF-файл Redis | Опционально (Redis — кэш) |

**Что НЕ монтируется:**

- Код (`/var/www/dst` целиком) — только в dev.
- `vendor/` — часть образа.
- `node_modules/` — часть образа (собранные ассеты).

## 50.11. Роль Nginx + PHP-FPM

```
Клиент ──HTTPS──▶ Nginx :443 ──FastCGI──▶ PHP-FPM (pool dst) ──▶ DST Platform
                    │
                    ├─▶ Статика (/upload, /css, /js) — напрямую с диска
                    ├─▶ Кэш (/cache) — запрещён
                    └─▶ Динамика (/*.php) — через FastCGI
```

| Компонент | Ответственность |
|---|---|
| **Nginx** | TLS, статика, gzip/brotli, rate limiting, reverse proxy, кэширование ответов |
| **PHP-FPM** | Пул воркеров, исполнение PHP, таймауты, slowlog |
| **DST Platform** | Роутинг (`index.php`), MVC, БД, кэш, бизнес-логика |

    ssl_certificate_key /etc/nginx/ssl/privkey.pem;

    add_header X-Content-Type-Options "nosniff" always;
    add_header Referrer-Policy "strict-origin-when-cross-origin" always;
    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;

    client_max_body_size 32M;

    location ~* \.(jpg|jpeg|png|gif|webp|svg|ico|css|js|woff2?)$ {

        add_header Cache-Control "public, immutable";
        access_log off;
        try_files $uri =404;
    }

    # Загруженные пользователем файлы
    location /upload/ {
        expires 7d;
        add_header Cache-Control "public";
        try_files $uri =404;

        try_files $uri /index.php?$query_string;

    location ~ ^/(cache|system|vendor|tests|\.git) {
        deny all;

    # Основной роутинг — на index.php
    location / {
        limit_req zone=general burst=50 nodelay;
        try_files $uri $uri/ /index.php?$query_string;
    }

    location ~ \.php$ {
        fastcgi_pass dst_php;
        fastcgi_index index.php;
        fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;

        access_log off;
        return 200 "ok\n";
        add_header Content-Type text/plain;
    }

## 50.16. GitHub Actions — полный workflow

**Файл:** `/.github/workflows/deploy.yml`

```yaml
name: Build & Deploy

on:
  push:
    branches: [main, develop]
    tags: ['v*.*.*']
  pull_request:
    branches: [main, develop]

env:
  REGISTRY: registry.dstglobal.ru
  IMAGE_NAME: dst-platform
  PHP_VERSION: '8.1'
  NODE_VERSION: '20'

jobs:
  # ══════════════════════════════════════════════════════════
  # 1. Линтеры
  # ══════════════════════════════════════════════════════════
  lint:
    name: Lint & Static analysis
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Setup PHP
        uses: shivammathur/setup-php@v2
        with:
          php-version: ${{ env.PHP_VERSION }}
          extensions: mbstring, pdo_mysql, intl, zip
          tools: composer:v2

      - name: Cache Composer
        uses: actions/cache@v3
        with:
          path: ~/.composer/cache
          key: composer-${{ env.PHP_VERSION }}-${{ hashFiles('composer.lock') }}

      - name: Install dependencies
        run: composer install --prefer-dist --no-progress --no-scripts

      - name: PHPStan
        run: vendor/bin/phpstan analyse --level=6 --no-progress system/core system/controllers

      - name: PHP CS Fixer
        run: vendor/bin/php-cs-fixer fix --dry-run --diff --allow-risky=yes

  # ══════════════════════════════════════════════════════════
  # 2. Unit-тесты
  # ══════════════════════════════════════════════════════════
  unit:
    name: Unit tests
    runs-on: ubuntu-latest
    needs: lint
    services:
      mysql:
        image: mysql:8.0

## 50.18. Артефакты, кэши, оптимизация

| Механизм | Что кэшировать | Экономия |
|---|---|---|
| **Composer cache** | `~/.composer/cache` | 40–60 с на каждом запуске |
| **Docker layer cache** | `buildcache` (registry) | 2–5 мин на сборке |
| **vendor/** | Результат `composer install` | 30–50 с |
| **node_modules/** | Если собираются ассеты | 1–2 мин |
| **Trivy DB** | `~/.cache/trivy` | 30 с |

**Правила:**

1. **Кэш-ключ** должен включать `hashFiles('composer.lock')` — иначе после обновления зависимостей кэш будет невалидным.
2. **Docker layer cache** — использовать `cache-from: type=registry`, чтобы кэш переживал пересоздание runner'а.
3. **Артефакты** (coverage, отчёты Trivy) — обязательно загружать, даже при падении (`if: always()`).

#!/usr/bin/env bash
# ─────────────────────────────────────────────
# Деплой DST Platform на staging/одиночный prod.
# Использует: docker-compose pull + up + миграции + healthcheck.
# ─────────────────────────────────────────────

set -euo pipefail

COMPOSE_FILE="${COMPOSE_FILE:-docker-compose.prod.yml}"
DST_VERSION="${DST_VERSION:-latest}"
ENV_FILE="${ENV_FILE:-.env.prod}"
HEALTH_URL="${HEALTH_URL:-http://localhost/healthz}"

echo "=== DST Deploy ==="
echo "Version: $DST_VERSION"
echo "Compose: $COMPOSE_FILE"
echo "Env:     $ENV_FILE"

# ─────────────────────────────────────────────
# 1. Проверка окружения
# ─────────────────────────────────────────────
if [ ! -f "$COMPOSE_FILE" ]; then
    echo "ERROR: $COMPOSE_FILE not found" >&2
    exit 1
fi
if [ ! -f "$ENV_FILE" ]; then
    echo "ERROR: $ENV_FILE not found" >&2
    exit 1
fi

# ─────────────────────────────────────────────
# 2. Pull нового образа
# ─────────────────────────────────────────────
echo "▶ Pulling image $DST_VERSION..."
DST_VERSION="$DST_VERSION" docker compose -f "$COMPOSE_FILE" --env-file "$ENV_FILE" pull app

# ─────────────────────────────────────────────
# 3. Бэкап БД перед миграциями
# ─────────────────────────────────────────────
echo "▶ Backing up database..."
BACKUP_DIR="./backups/mysql"
mkdir -p "$BACKUP_DIR"
BACKUP_FILE="$BACKUP_DIR/pre-deploy-$(date +%Y%m%d-%H%M%S).sql.gz"
docker compose -f "$COMPOSE_FILE" --env-file "$ENV_FILE" exec -T mysql \
    mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" \
    --single-transaction --quick --routines --triggers \
    "$DB_NAME" | gzip > "$BACKUP_FILE"
echo "  Saved: $BACKUP_FILE"

# ─────────────────────────────────────────────
# 4. Запуск миграций (в отдельном контейнере)
# ─────────────────────────────────────────────
echo "▶ Running migrations..."
DST_VERSION="$DST_VERSION" docker compose -f "$COMPOSE_FILE" --env-file "$ENV_FILE" \
    run --rm --no-deps app php /var/www/dst/scripts/migrate.php

# ─────────────────────────────────────────────
# 5. Очистка кэша (пересоберётся на первом запросе)
# ─────────────────────────────────────────────
echo "▶ Clearing cache..."
docker compose -f "$COMPOSE_FILE" --env-file "$ENV_FILE" exec -T app \
    php -r "require '/var/www/dst/bootstrap.php'; cmsCache::getInstance()->clean();" || true

# ─────────────────────────────────────────────
# 6. Пересоздание контейнеров
# ─────────────────────────────────────────────
echo "▶ Recreating containers..."
DST_VERSION="$DST_VERSION" docker compose -f "$COMPOSE_FILE" --env-file "$ENV_FILE" \
    up -d --no-deps --remove-orphans app cron

# ─────────────────────────────────────────────
# 7. Healthcheck
# ─────────────────────────────────────────────
echo "▶ Waiting for health..."
for i in $(seq 1 $MAX_WAIT); do
    if curl -fsS "$HEALTH_URL" > /dev/null 2>&1; then
        echo "  ✓ Healthy after ${i}s"
        echo "=== Deploy OK ==="
        exit 0
    fi
    sleep 1
done

echo "✗ Health check failed after ${MAX_WAIT}s" >&2
echo "  Logs:" >&2
docker compose -f "$COMPOSE_FILE" logs --tail=50 app >&2
exit 1
```

## 50.21. Blue-green и rolling update

### 50.21.1. Blue-green

```
┌──────────────────────────────────────────────────────────┐
│                    BLUE-GREEN DEPLOY                     │
├──────────────────────────────────────────────────────────┤
│                                                          │
│   ДО деплоя:                                             │
│   ┌──────────────┐                                       │
│   │  Nginx       │──────▶ BLUE (v1.41, активный)        │
│   └──────────────┘        GREEN (v1.42, idle)            │
│                                                          │
│   ДЕПЛОЙ:                                                │
│   1. GREEN поднимается с v1.42                           │
│   2. Миграции (обратно совместимые) — на обе              │
│   3. Smoke-тесты на GREEN                                │
│   4. Переключение Nginx: BLUE → GREEN                    │
│   5. BLUE остаётся тёплым (rollback за секунды)          │
│                                                          │
│   ПОСЛЕ:                                                 │
│   ┌──────────────┐                                       │
│   │  Nginx       │──────▶ GREEN (v1.42, активный)        │
│   └──────────────┘        BLUE (v1.41, backup)           │
└──────────────────────────────────────────────────────────┘
```

**Файл:** `/scripts/deploy-blue-green.sh`

```bash
#!/usr/bin/env bash
# Blue-green деплой для DST Platform.
# Требует: 2 набора контейнеров (blue/green) за Nginx.

set -euo pipefail

COMPOSE_FILE="${COMPOSE_FILE:-docker-compose.prod.yml}"
NEW_VERSION="${DST_VERSION:?DST_VERSION required}"
HEALTH_URL="${HEALTH_URL:-http://localhost/healthz}"

# Определяем, какой цвет сейчас активен
ACTIVE=$(cat /opt/dst/active_color 2>/dev/null || echo "blue")
if [ "$ACTIVE" = "blue" ]; then
    NEW="green"; OLD="blue"
else
    NEW="blue"; OLD="green"
fi

echo "▶ Active: $OLD, deploying: $NEW (version $NEW_VERSION)"

# 1. Поднимаем новый цвет
DST_VERSION="$NEW_VERSION" \
docker compose -f "$COMPOSE_FILE" --env-file .env.prod \
    -p "dst-$NEW" up -d --no-deps app-$NEW

# 2. Ждём healthy
for i in $(seq 1 60); do
    if docker compose -f "$COMPOSE_FILE" -p "dst-$NEW" ps app-$NEW | grep -q healthy; then
        echo "  ✓ $NEW healthy"
        break
    fi
    [ "$i" = "60" ] && { echo "✗ $NEW unhealthy"; exit 1; }
    sleep 2
done

# 3. Переключаем Nginx upstream
sed "s/app-$OLD:9000/app-$NEW:9000/" -i /etc/nginx/conf.d/dst.conf
nginx -t && nginx -s reload
echo "  ✓ Nginx switched to $NEW"

# 4. Smoke-тесты
for i in $(seq 1 30); do
    if curl -fsS "$HEALTH_URL" > /dev/null; then
        echo "  ✓ Smoke OK"
        break
    fi
    [ "$i" = "30" ] && { echo "✗ Smoke failed"; nginx -s reload; exit 1; }
    sleep 1
done

# 5. Фиксируем активный цвет
echo "$NEW" > /opt/dst/active_color

# 6. Старый цвет оставляем тёплым на 30 минут, потом гасим
(sleep 1800 && DST_VERSION="$NEW_VERSION" \
    docker compose -f "$COMPOSE_FILE" -p "dst-$OLD" down) &

echo "=== Deploy OK: $NEW_VERSION ($NEW) ==="
```

### 50.21.2. Rolling update (Docker Swarm / K8s)

```yaml
services:
  app:
    deploy:
      replicas: 3
      update_config:
        parallelism: 1
        delay: 30s
        order: start-first       # new up → old down (zero-downtime)
        failure_action: rollback
      rollback_config:
        parallelism: 1
        delay: 10s
```

## 50.22. Миграции БД при деплое

### 50.22.1. Принцип «N и N+1»

При zero-downtime деплое старая и новая версии работают одновременно. Схема БД должна быть совместима с **обеими** на время раскатки.

| Фаза | Схема | Старая версия | Новая версия |
|---|---|---|---|
| **Expand** | Добавить новые колонки (nullable) | ✅ работает | ✅ работает |
| **Deploy** | Обе версии на проде | ✅ | ✅ |
| **Migrate** | Заполнить новые колонки | ✅ | ✅ |
| **Contract** | Удалить старые колонки (следующий релиз) | ❌ | ✅ |

**Правила:**

1. **Никогда не удалять колонки в том же релизе, что добавляете.**
2. **Новые колонки — nullable** (или с `DEFAULT`).
3. **Переименование = new + copy + drop** (через 2 релиза).
4. **Индексы — `CREATE INDEX CONCURRENTLY`** (MySQL: `ALGORITHM=INPLACE, LOCK=NONE`).

### 50.22.3. Раннер миграций

**Файл:** `/scripts/migrate.php`

```php
<?php
/**
 * Раннер миграций DST Platform.
 *
 * • Читает SQL-файлы из /migrations
 * • Ведёт учёт выполненных в таблице cms_migrations
 * • Выполняет недостающие в лексикографическом порядке
 * • Каждая миграция — в транзакции (если поддерживается)
 */

declare(strict_types=1);

require_once __DIR__ . '/../bootstrap.php';

$db = cmsDatabase::getInstance();
$migrationsDir = __DIR__ . '/../migrations';

// 1. Создаём таблицу учёта
$db->query("
    CREATE TABLE IF NOT EXISTS `cms_migrations` (
        `id` INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
        `name` VARCHAR(255) NOT NULL UNIQUE,
        `applied_at` DATETIME NOT NULL,
        `checksum` CHAR(32) NOT NULL
    ) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4
");

// 2. Уже применённые
$applied = [];
foreach ($db->query("SELECT name, checksum FROM cms_migrations")->getRows() as $row) {
    $applied[$row['name']] = $row['checksum'];
}

// 3. Список файлов
$files = glob($migrationsDir . '/*.sql');
sort($files, SORT_STRING);

$applied_count = 0;
$skipped_count = 0;

foreach ($files as $file) {
    $name = basename($file);
    $checksum = md5_file($file);

    if (isset($applied[$name])) {
        if ($applied[$name] !== $checksum) {
            fwrite(STDERR, "⚠ Checksum mismatch: {$name}\n");
            fwrite(STDERR, "  Applied: {$applied[$name]}\n");
            fwrite(STDERR, "  Current: {$checksum}\n");
            exit(1);
        }
        $skipped_count++;
        continue;
    }

    echo "▶ Applying: {$name}\n";
    $sql = file_get_contents($file);

    try {
        $db->beginTransaction();
        $db->query($sql);
        $db->insert('cms_migrations', [
            'name'       => $name,
            'applied_at' => date('Y-m-d H:i:s'),
            'checksum'   => $checksum,
        ]);
        $db->commit();
        $applied_count++;
    } catch (\Throwable $e) {
        $db->rollback();
        fwrite(STDERR, "✗ Failed: {$name}: {$e->getMessage()}\n");
        exit(1);
    }
}

echo "=== Done. Applied: {$applied_count}, skipped: {$skipped_count} ===\n";
```

**Запуск:**

```bash
docker compose run --rm --no-deps app php /var/www/dst/scripts/migrate.php
```

## 50.23. Rollback

### 50.23.1. Стратегии отката

| Стратегия | Когда | Скорость |
|---|---|---|
| **Вернуть образ** (Docker tag) | Проблема в коде, схема совместима | ~30 сек |
| **Blue-green** (переключить Nginx) | Blue-green деплой | ~5 сек |
| **Откатить миграции** | Проблема в схеме | Зависит от миграции |
| **Полный откат + восстановление из бэкапа** | Катастрофа | 5–30 мин |

### 50.23.2. Скрипт отката (полный листинг)

**Файл:** `/scripts/rollback.sh`

```bash
#!/usr/bin/env bash
# Откат к предыдущей версии.
# Аргументы: [--image=v1.41.0] [--db-backup=path/to/backup.sql.gz] [--migrations]

set -euo pipefail

COMPOSE_FILE="${COMPOSE_FILE:-docker-compose.prod.yml}"
ENV_FILE="${ENV_FILE:-.env.prod}"

# ─────────────────────────────────────────────
# 1. Парсинг аргументов
# ─────────────────────────────────────────────
PREV_VERSION=""
DB_BACKUP=""
RESTORE_DB=0

for arg in "$@"; do
    case "$arg" in
        --image=*)      PREV_VERSION="${arg#*=}" ;;
        --db-backup=*)  DB_BACKUP="${arg#*=}"; RESTORE_DB=1 ;;
        --migrations)   RESTORE_DB=1 ;;
        *)              echo "Unknown arg: $arg"; exit 1 ;;
    esac
done

# ─────────────────────────────────────────────
# 2. Определяем версию для отката
# ─────────────────────────────────────────────
if [ -z "$PREV_VERSION" ]; then
    PREV_VERSION=$(cat /opt/dst/previous_version 2>/dev/null || echo "")
    if [ -z "$PREV_VERSION" ]; then
        echo "✗ No previous version known. Use --image=" >&2
        exit 1
    fi
fi

echo "▶ Rolling back to: $PREV_VERSION"

# ─────────────────────────────────────────────
# 3. (Опционально) Восстановление БД
# ─────────────────────────────────────────────
if [ "$RESTORE_DB" = "1" ]; then
    if [ -z "$DB_BACKUP" ] || [ ! -f "$DB_BACKUP" ]; then
        echo "✗ DB backup not found: $DB_BACKUP" >&2
        exit 1
    fi

    echo "▶ Restoring database from $DB_BACKUP..."
    read -r -p "  ⚠ This will DROP and recreate the database. Continue? [y/N] " confirm
    if [ "$confirm" != "y" ]; then
        echo "Aborted"; exit 1
    fi

    gunzip -c "$DB_BACKUP" | docker compose -f "$COMPOSE_FILE" exec -T mysql \
        mysql -uroot -p"$MYSQL_ROOT_PASSWORD" "$DB_NAME"

    echo "  ✓ Database restored"
fi

# ─────────────────────────────────────────────
# 4. Откатываем образ
# ─────────────────────────────────────────────
echo "▶ Pulling previous image..."
DST_VERSION="$PREV_VERSION" docker compose -f "$COMPOSE_FILE" --env-file "$ENV_FILE" pull app

echo "▶ Recreating containers..."
DST_VERSION="$PREV_VERSION" docker compose -f "$COMPOSE_FILE" --env-file "$ENV_FILE" \
    up -d --no-deps --remove-orphans app cron

# ─────────────────────────────────────────────
# 5. Healthcheck
# ─────────────────────────────────────────────
echo "▶ Waiting for health..."
for i in $(seq 1 60); do
    if curl -fsS http://localhost/healthz > /dev/null 2>&1; then
        echo "  ✓ Healthy after ${i}s"
        echo "=== Rollback OK: $PREV_VERSION ==="
        echo "$PREV_VERSION" > /opt/dst/previous_version
        exit 0
    fi
    sleep 1
done

echo "✗ Health check failed after rollback" >&2
docker compose -f "$COMPOSE_FILE" logs --tail=50 app >&2
exit 1
```

### 50.24.2. Smoke-тесты после деплоя

**Файл:** `/scripts/smoke.sh`

```bash
#!/usr/bin/env bash
# Smoke-тесты после деплоя. Возвращает 0 при успехе.
set -euo pipefail

BASE_URL="${BASE_URL:-https://example.com}"
FAILED=0

check() {
    local name="$1"; local url="$2"; local expected="${3:-200}"
    local code
    code=$(curl -sS -o /dev/null -w '%{http_code}' "$url" || echo "000")
    if [ "$code" != "$expected" ]; then
        echo "✗ $name: $code (expected $expected) — $url"
        FAILED=$((FAILED + 1))
    else
        echo "✓ $name: $code"
    fi
}

# 1. Health
check "healthz"      "$BASE_URL/healthz"
check "readyz"       "$BASE_URL/readyz"

# 2. Главная
check "homepage"     "$BASE_URL/"

# 3. Ключевые страницы
check "news"         "$BASE_URL/news"
check "shop"         "$BASE_URL/shop"
check "login"        "$BASE_URL/auth/login"

# 4. API
check "api-method"   "$BASE_URL/api/method/content.get.news?per_page=1"
check "api-error"    "$BASE_URL/api/method/nonexistent"

# 5. Проверка, что API вернул JSON
CONTENT_TYPE=$(curl -sS -o /dev/null -w '%{content_type}' "$BASE_URL/api/method/content.get.news?per_page=1")
if [[ "$CONTENT_TYPE" != application/json* ]]; then
    echo "✗ api content-type: $CONTENT_TYPE"
    FAILED=$((FAILED + 1))
else
    echo "✓ api content-type: $CONTENT_TYPE"
fi

# 6. Проверка, что статика отдаётся Nginx (не через PHP)
check "static-css"   "$BASE_URL/templates/default/css/style.css"

# 7. Проверка HTTPS (если prod)
if [[ "$BASE_URL" == https://* ]]; then
    check "http-redirect" "http://${BASE_URL#https://}/" 301
fi

if [ "$FAILED" -gt 0 ]; then
    echo "=== $FAILED checks failed ==="
    exit 1
fi

echo "=== All smoke tests passed ==="
```

## 50.27. Оптимизация (opcache, composer)

### 50.27.1. OPcache

Уже настроен в `php.ini` (см. 50.5.2). Ключевое для production:

| Параметр | Значение | Эффект |
|---|---|---|
| `opcache.enable=1` | Вкл. | Ускорение 2–3× |
| `opcache.validate_timestamps=0` | Выкл. | Не проверять изменения файлов (требует reload при деплое!) |
| `opcache.memory_consumption=256` | 256 МБ | Хватает для типичного проекта |
| `opcache.max_accelerated_files=20000` | 20 000 | Больше, чем файлов в проекте |
| `opcache.jit=tracing` | Вкл. | +10–20 % на CPU-bound |
| `opcache.jit_buffer_size=64M` | 64 МБ | Буфер JIT |

> ⚠️ При `validate_timestamps=0` **обязательно** перезагружать PHP-FPM при деплое, иначе изменения не применятся:
> ```bash
> docker compose exec app kill -USR2 1
> # или
> docker compose restart app
> ```

## 50.29. Заключение

Развёртывание DST Platform строится на трёх столпах:

1. **Воспроизводимость.** Один и тот же артефакт (Docker-образ) разворачивается на staging и prod. Bare-metal допускается, но требует дисциплины (Ansible / shell-скрипты + lock-файлы).
2. **Zero-downtime.** Blue-green (для одного сервера) или rolling update (для кластера) + миграции по принципу «N и N+1».
3. **Откатываемость.** Образ предыдущей версии всегда доступен; бэкап БД — перед миграциями; health-check + smoke-тесты — автоматически.

**Ключевые компоненты инфраструктуры:**

| Компонент | Назначение | Расположение |
|---|---|---|
| **`Dockerfile`** | Multi-stage сборка образа | `/docker/Dockerfile` |
| **`docker-compose.yml`** | Локальная разработка | `/docker-compose.yml` |
| **`docker-compose.prod.yml`** | Production | `/docker-compose.prod.yml` |
