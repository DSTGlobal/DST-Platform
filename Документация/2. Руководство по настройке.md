Эта страница содержит руководство по настройке CMS/CMF платформы DST, а также по пониманию её основных зависимостей и процесса инициализации. ## 2.1. Системные требования
Для корректной работы платформы DST требуется следующая среда:

Требование | Спецификация | Примечания
Версия PHP | >= 7.0 | Требуется для работы phpfastcache и других зависимостей.
Веб-сервер | Apache с mod_rewrite | Необходимо для маршрутизации URL-адресов через .htaccess.
База данных | MySQL/MariaDB | Основное хранилище данных
Композитор | Последняя стабильная версия | Инструмент управления зависимостями

### Необходимые расширения PHP

Необходимо включить следующие расширения PHP:

Расширение | Цель | Требуется
ext-mbstring | Обработка многобайтовых строк | Основная система, phpfastcache
ext-json | кодирование/декодирование JSON | Базовая система, все SDK
ext-curl | операции HTTP-клиента | Guzzle, CDEK SDK, YooKassa SDK
ext-openssl | SSL/TLS для безопасных соединений | Пакет Composer CA, внешние API
ext-libxml | XML-анализ | сериализация SDK CDEK
ext-simplexml | Простые операции с XML | CDEK SDK

### Дополнительные расширения PHP для повышения производительности

Расширение | Цель | Выгода
ext-redis | драйвер кэша Redis | Высокопроизводительная система кэширования
ext-memcached | Драйвер кэша Memcached | Распределенное кэширование
ext-maxminddb | Встроенные функции поиска по геолокации (GeoIP). | Более быстрая геолокация по IP-адресу (по сравнению с чистым PHP)

## 2.2. Этапы установки

Шаг 1: Установите платформу из присланного архива.

Шаг 2: Установите зависимости Composer.

Платформа использует Composer для управления сторонними библиотеками. Установите зависимости с помощью:

```
# Using the bundled composer.phar
```

Это установит все необходимые пакеты, указанные в composer.json 7-13

в vendor/каталог и генерирует автозагрузчик Composer по адресу vendor/autoload.php.

Шаг 4: Настройка прав доступа к файлу

Убедитесь, что веб-сервер имеет права на запись для:

```

```

Шаг 5: Настройка веб-сервера

Для Apache убедитесь, .htaccessчто он обрабатывается и mod_rewrite включен. Платформа включает предварительно настроенный .htaccessфайл для маршрутизации URL-адресов. Подробнее см. раздел «Маршрутизация URL-адресов и настройка веб-сервера» .

## 2.4. Управление конфигурацией

### Основная конфигурация: cmsConfig

Этот cmsConfig синглтон загружает системную конфигурацию и обеспечивает доступ ко всей системе приложения.

Ключевые параметры конфигурации, доступные во время загрузки системы:

<img src="https://dstglobal.ru/img/git/9.png" alt="DST Platform">

Процесс настройки:

1. Режим отладки - Система управления отправкой сообщений об ошибках:

- Если $config->debugзначение равно false: error_reporting(0)скрывает все ошибки.

## 2.5. Архитектура автозагрузки

Платформа использует стратегию двойной автозагрузки, сочетая автозагрузчик PSR-4 от Composer с пользовательским загрузчиком основных классов.

Иерархия автозагрузчика

<img src="https://dstglobal.ru/img/git/10.png" alt="DST Platform">

Последовательность регистрации автозагрузчика:

1. Композитор Автозагрузчик:

- Загружено из vendor/autoload.php
- Обрабатывает все зависимости сторонних разработчиков.
- Включает пользовательское сопоставление PSR-4 для shopUtils\пространства имен.

2. Автозагрузчик ядра:

- Загружено изsystem/config/autoload.php
- Зарегистрировано черезspl_autoload_register('autoLoadCoreClass')
- Обрабатывает основные классы платформы (классы cms*).

Конфигурация композитора PSR-4 composer.json:

```
"autoload": {
```

## 2.8. Инициализация системы событий

После запуска кэша система инициирует core_start событие следующим образом cmsEventsManager:

```
cmsEventsManager::hook('core_start');
```

Это событие позволяет компонентам и плагинам выполнять код на ранних этапах процесса инициализации. Типичные варианты использования:

- Регистрация дополнительных автозагрузчиков
- Инициализация сторонних сервисов
- Настройка обработчиков событий базы данных
- Регистрация пользовательских обработчиков ошибок

Для получения более подробной информации о системе событий/крючков см. раздел «Система событий и крючков» .

## 2.12. Управление сессиями

Обработка сессий на платформе осуществляется в зависимости от SESSION_START константы.

Процесс инициализации сессии

```
if(defined('SESSION_START')){
```

Особенности сессии:

- Используется cmsUser::sessionStart() с настраиваемым доменом cookie.
- Поддерживает переопределение часового пояса для каждого пользователя, сохраняемое в сессии.
- Запускается только при SESSION_START наличии соответствующего параметра (не используется заданиями cron).

## 2.13. Этапы проверки

После установки убедитесь, что система работает корректно:

1. Проверьте завершение загрузки.

Перейдите на главную страницу. Сайт должен загрузиться без ошибок. Если вы видите пустую страницу, проверьте:

- Журналы ошибок PHP
- Настройки подключения к базе данных
- Права доступа к файлам cache/upload/

2. Проверьте зависимости Composer.

Убедитесь, что vendor/каталог существует и содержит пакеты:

```
ls -la vendor/
```

Вы должны увидеть следующие каталоги:

box/, guzzlehttp/, geoip2/, phpfastcache/, sanmai/,yoomoney/

3. Проверка подключения к базе данных

Если система выдает ошибки базы данных, проверьте следующее:

- Служба MySQL запущена.
- База данных существует и доступна.
- Пользователь обладает соответствующими правами доступа.
- Настройки system/config/database.phpверны.

4. Проверьте каталог кэша.

Убедитесь, что каталог кэша доступен для записи:

```
ls -la cache/
```

## 2.15. Устранение распространенных проблем

### Проблема: Пустая страница после установки

Симптомы: Белый экран, контент не отображается.

Возможные причины:

1. Ошибки PHP подавляются (режим отладки отключен)
2. Сбой подключения к базе данных
3. Отсутствуют зависимости Composer.

Решение:

1. Включите режим отладки, system/config/config.php чтобы увидеть ошибки.
2. Проверьте журналы ошибок:tail -f /var/log/apache2/error.log
3. Проверьте подключение к базе данных вручную.
4. Выполните команду composer install, чтобы убедиться в установке зависимостей.

### Проблема: ошибки "Класс не найден"

Симптомы: фатальная ошибка, связанная с пропуском занятия.

Возможные причины:

1. Автозагрузчик Composer не загружен.
2. каталог поставщиков отсутствует или неполный.
3. Пользовательский автозагрузчик не зарегистрирован

Решение:

1. Беги composer install или php composer.phar install
2. Проверить vendor/autoload.phpналичие
3. Проверять включает в себя автозагрузчик Composer.

### Проблема: Ошибки кэширования или загрузки в каталог.


Симптомы: ошибки, связанные с невозможностью записи файлов.

Возможные причины:

1. Права доступа к каталогу слишком ограничены.
2. Неверные права доступа к каталогу.

Решение:

```
chmod -R 755 cache/ upload/ exports/
```

### Проблема: Предупреждения о часовых поясах

Симптомы: предупреждения PHP о том, что часовой пояс не установлен.

Возможные причины:

1. Системный часовой пояс не настроен в конфигурации.
2. В файле php.ini отсутствует настройка date.timezone.

Решение:

1. Место действия system/config/config.php:'time_zone' => 'UTC'
2. Или в файле php.ini:date.timezone = UTC
