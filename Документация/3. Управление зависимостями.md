# 3. Управление зависимостями

Этот документ описывает, как DST Platform управляет сторонними PHP-библиотеками с помощью Composer. Он включает список прямых зависимостей, стратегию управления версиями, архитектуру автозагрузки и рекомендации по безопасному обновлению пакетов. Информацию об инициализации зависимостей в runtime см. в разделе *«Инициализация и настройка системы»*.

---

## 3.1. Общие принципы

DST Platform использует **Composer** — стандартный менеджер зависимостей для PHP. Все сторонние библиотеки:
- объявляются в `composer.json`;
- фиксируются по версиям в `composer.lock`;
- устанавливаются в каталог `/vendor/`;
- загружаются через автозагрузчик `vendor/autoload.php`.

Каталог `/vendor/` **не включается в систему контроля версий (VCS)**. Файл `composer.lock` **обязательно включается**, чтобы гарантировать воспроизводимость сборок.

## 3.3. Стратегия управления версиями

### Оператор `^` (caret)
Разрешает обновления **минорных и патч-версий**, но блокирует мажорные (согласно SemVer).

Примеры:
- `^3.3` → `>=3.3.0 <4.0.0`
- `^7.1` → `>=7.1.0 <8.0.0`

**Используется в**:  
`box/spout`, `phpfastcache/phpfastcache`, `yoomoney/yookassa-sdk-php`

### Оператор `~` (tilde)
Разрешает **только патч-обновления**.

Примеры:
- `~6.0` → `>=6.0.0 <6.1.0`
- `~2.0` → `>=2.0.0 <2.1.0`

**Используется в**:  
`guzzlehttp/guzzle`, `geoip2/geoip2`

### Точное ограничение
Для `sanmai/cdek-sdk` используется `^0.6.22` → `>=0.6.22 <0.7.0`, чтобы зафиксировать совместимую минорную серию.

## 3.6. Автозагрузка PSR-4

Помимо сторонних пакетов, платформа определяет **пользовательское пространство имён**:

```json
"autoload": {
    "psr-4": {
        "shopUtils\\": "system/controllers/shop/utils/"
    }
}
```

Это позволяет использовать классы из `system/controllers/shop/utils/` без ручного `require`:

```php
// Файл: system/controllers/shop/utils/ProductHelper.php
namespace shopUtils;

class ProductHelper { /* ... */ }

// Где угодно в коде:
$helper = new \shopUtils\ProductHelper();
```

## 3.8. Подробное описание зависимостей

### `box/spout` (^3.3)
- **Назначение**: потоковая обработка больших таблиц (XLSX, CSV, ODS) с низким потреблением памяти.
- **Особенности**:
  - Не требует расширений `xml` или `zip`.
  - Поддерживает чтение и запись.
- **Использование**: экспорт товаров, генерация YML-фидов, импорт партнёрских прайсов.

> ⚠️ **Примечание**: проект `box/spout` официально заброшен. Рекомендуется миграция на `openspout/openspout` в будущих версиях.

---

### `sanmai/cdek-sdk` (^0.6.22)
- **Назначение**: клиент для API CDEK (расчёт, отслеживание, ПВЗ).
- **Зависимости**: `guzzlehttp/guzzle`, `jms/serializer`.
- **Особенности**:
  - Поддержка XML через JMS Serializer.
  - Совместимость с PSR-3 (логирование).
- **Статус**: пакет помечен как **устаревший**; официальный преемник — `cdek-it/sdk2.0`.

---

### `guzzlehttp/guzzle` (~6.0)
- **Назначение**: надёжный HTTP-клиент с поддержкой middleware, асинхронных запросов и PSR-7.
- **Транзитивные зависимости**:
  - `guzzlehttp/promises`
  - `guzzlehttp/psr7`
  - `psr/http-message`
- **Использование**: все внешние вызовы — от партнёрских API до SMTP-почты.

> ⚠️ **Безопасность**: версия 6.x находится в режиме **только исправления уязвимостей**. Версия 7.x — активно поддерживается.

---

### `geoip2/geoip2` (~2.0)
- **Назначение**: определение страны, региона, города по IP через MaxMind GeoIP2.
- **Требования**: файл базы `GeoLite2-City.mmdb` (≥64 МБ).
- **Использование**: персонализация контента, антифрод, аналитика.

---

### `phpfastcache/phpfastcache` (^7.1)
- **Назначение**: единый интерфейс кэширования с поддержкой множества бэкендов.
- **Поддерживаемые драйверы**:
  - Redis (рекомендуется для production)
  - Memcached
  - APCu
  - Файлы
  - SQLite
- **Соответствие стандартам**: PSR-6 (сложное кэширование), PSR-16 (простое key-value).

---

### `yoomoney/yookassa-sdk-php` (^2.1)
- **Назначение**: официальный SDK для приёма платежей через ЮKassa.
- **Функции**:
  - Создание платежей
  - Обработка вебхуков
  - Формирование чеков (54-ФЗ)
  - Возвраты
- **Поддерживаемые методы**: карты, кошельки, мобильные операторы, рассрочка.

## 3.9. Работа с Composer

### Установка зависимостей

```bash
# Используя глобальный Composer
composer install

# Или локальный composer.phar
php composer.phar install
```

### Полезные команды

| Команда | Назначение |
|--------|------------|
| `composer install` | Устанавливает зависимости **строго по `composer.lock`** |
| `composer update` | Обновляет зависимости до последних разрешённых версий |
| `composer require vendor/package` | Добавляет новую зависимость |
| `composer dump-autoload --optimize` | Генерирует оптимизированный автозагрузчик (для production) |

> ✅ **Рекомендация**: в production всегда используйте `composer install`, а не `update`.

## 3.10. Разрешение файлов и версий блокировок

Этот composer.lock файл представляет собой снимок точных версий установленных пакетов

### Гарантии файла блокировки

1. Воспроизводимые сборки — на всех машинах установлены одни и те же версии.
2. Стабильность транзитивных зависимостей — блокирует и косвенные зависимости.
3. Проверка хеша — content-hashобнаруживает изменения, внесенные вручную.

### Рекомендации по использованию файлов блокировки

| Сценарий | Действие |
|--------|------------|
| Добавление нового сервера | Запуск composer install (не update) |
| Обновление отдельного пакета | composer update vendor/package |
| Обновление всех пакетов | Запустите composer update |
| Конфликты слияния в файле блокировки | Повторите запуск composer update --lock после устранения проблемы |

## 3.11. Интеграция автозагрузчика

Автозагрузчик Composer включается на этапе инициализации каждого запроса:

```
// bootstrap.php includes the autoloader
```

Эта единственная строка позволяет:

1. Автоматическая загрузка PSR-4 для всех пакетов от поставщиков.
2. Автоматическая загрузка PSR-0 для устаревших пакетов
3. Автоматическая загрузка Classmap для оптимизации поиска классов.
4. Автоматическая загрузка файлов для библиотек функций
5. Пользовательское пространство имен PSR-4 (shopUtils)

### Производительность автозагрузчика

Для производственных сред создайте оптимизированный автозагрузчик:

```
php composer.phar dump-autoload --optimize
```

Это позволяет создать карту классов для более быстрого поиска классов, что сокращает количество операций с файловой системой.

## 3.13. Заключение

DST Platform следует современным практикам управления зависимостями:
- Все внешние библиотеки — через Composer.
- Версии зафиксированы в `composer.lock` для воспроизводимости.
- Используются стандарты PSR (6, 16, 7).
- Предусмотрена расширяемость через пользовательскую автозагрузку PSR-4.
