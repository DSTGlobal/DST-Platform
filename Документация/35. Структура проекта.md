# 35. Структура проекта

В данном разделе описана организация файловой системы, каталогов и конфигурации проекта на базе DST Platform. Понимание структуры проекта критично для эффективной разработки, настройки окружения и сопровождения системы.

**Связанные разделы:**
- *«Руководство по разработке»* — основные подходы к созданию функциональности
- *«Создание компонентов»* — разработка пользовательских модулей
- *«Инициализация и настройка системы»* — загрузка зависимостей и конфигурация
- *«Шаблонная система»* — механика шаблонов и наследование

---

## 35.1. Обзор архитектуры и принципы организации

DST Platform следует принципу разделения ответственности между ядром, компонентами, темами и пользовательскими данными. Платформа обеспечивает четкое разделение между:

1. **Системной логикой** (`/system/`) — ядро фреймворка и бизнес-логика
2. **Уровнем представления** (`/templates/`) — темы оформления и шаблоны
3. **Пользовательским контентом** (`/upload/`, `/cache/`, `/exports/`) — данные времени выполнения

**Основные принципы:**
- **Соглашение важнее конфигурации** — именование файлов и классов следует предсказуемым шаблонам
- **Модульность компонентов** — каждый функциональный модуль самодостаточен
- **Наследование шаблонов** — темы наследуют файлы от родительских тем
- **Безопасность по умолчанию** — конфиденциальные файлы защищены от веб-доступа

## 35.4. Ядро платформы (`/system/`)

Каталог `/system/` содержит ядро платформы и все компоненты приложения.

### 35.4.1. Основные классы (`/system/core/`)

Содержит базовые классы, от которых наследуются все компоненты. Каждый файл определяет один класс в соответствии с соглашением об именовании `cms*`:

<img src="https://github.com/DSTGlobal/DST-Platform/blob/main/images/214.png" alt="Основные классы фреймворка DST Platform">

*Диаграмма: Основные классы фреймворка и их взаимосвязи.*

| Файл | Класс | Назначение | Синглтон | Соглашение именования |
|------|-------|------------|----------|---------------------|
| `cmsCore.php` | `cmsCore` | Главный класс ядра, точка входа | Да | `cms*` |
| `cmsConfig.php` | `cmsConfig` | Управление конфигурацией | Да | `cms*` |
| `cmsTemplate.php` | `cmsTemplate` | Система шаблонов и ресурсов | Да | `cms*` |
| `cmsModel.php` | `cmsModel` | Базовый класс моделей данных | Нет | `cms*` |
| `cmsFrontend.php` | `cmsFrontend` | Базовый класс публичных контроллеров | Нет | `cms*` |
| `cmsBackend.php` | `cmsBackend` | Базовый класс админ-контроллеров | Нет | `cms*` |
| `cmsEventsManager.php` | `cmsEventsManager` | Система событий и хуков | Да | `cms*` |
| `cmsCache.php` | `cmsCache` | Абстракция кэширования | Да | `cms*` |
| `cmsUser.php` | `cmsUser` | Управление пользователями и сессией | Да | `cms*` |
| `cmsRequest.php` | `cmsRequest` | Обработка входящих запросов | Да | `cms*` |

**Основные характеристики:**
- **Именование файлов:** строчными буквами (например, `core.php`, `model.php`)
- **Именование классов:** `CamelCase` с префиксом `cms` (например, `cmsCore`, `cmsModel`)
- **Создание экземпляра:** В большинстве случаев это синглтоны, доступ к которым осуществляется через `cmsCore::getInstance()`
- **Наследование:** `cmsFrontend` и `cmsBackend` расширяют `cmsController`

### 35.4.3. Контроллеры и компоненты (`/system/controllers/`)

Содержит все компоненты приложения. Каждый компонент — автономный модуль, расположенный в своей поддиректории. Имя директории должно:
- Начинаться с буквы (a-z)
- Содержать только строчные буквы, цифры и символы подчеркивания
- Иметь длину не менее 3 символов
- Быть уникальным в рамках всей системы

#### Соглашения об именовании файлов компонентов

| Файл | Шаблон имени класса | Пример (компонент: `shop`) |
|------|---------------------|----------------------------|
| `frontend.php` | `controller{Component}` | `controllerShop` |
| `model.php` | `model{Component}` | `modelShop` |
| `backend/backend.php` | `controllerBackend{Component}` | `controllerBackendShop` |
| `backend/model.php` | `modelBackend{Component}` | `modelBackendShop` |
| `hooks.php` | `on{Component}Hooks` | `onShopHooks` |
| `widgets/{name}.php` | `widget{Component}{Name}` | `widgetShopCart` |

**Важно:** В названиях компонентов в каталогах используются строчные буквы с подчеркиваниями, а в названиях классов — `CamelCase`:
- **Каталог:** `/system/controllers/purchase_requisition/`
- **Frontend-класс:** `controllerPurchaseRequisition`
- **Класс модели:** `modelPurchaseRequisition`

### 35.5.2. Соглашение об именовании файлов шаблонов

Файлы шаблонов используют расширение `.tpl.php`. Шаблон именования зависит от типа:

| Тип шаблона | Расположение | Шаблон именования | Пример |
|-------------|--------------|-------------------|--------|
| Основной макет | `/templates/{theme}/` | `main.tpl.php` | `main.tpl.php` |
| Макет административной панели | `/templates/{theme}/` | `admin.tpl.php` | `admin.tpl.php` |
| Представление компонента | `/templates/{theme}/controllers/{component}/` | `{action}.tpl.php` | `item_view.tpl.php` |
| Шаблон виджета | `/templates/{theme}/widgets/` | `{widget_name}.tpl.php` | `menu.tpl.php` |
| Виджет компонента | `/templates/{theme}/controllers/{component}/widgets/` | `{widget_name}.tpl.php` | `cart.tpl.php` |
| Представление в бэкенде | `/templates/{theme}/controllers/{component}/backend/` | `{action}.tpl.php` | `form.tpl.php` |
| Элемент интерфейса | `/templates/{theme}/assets/ui/` | `{element}.tpl.php` | `breadcrumbs.tpl.php` |
| Страница ошибки | `/templates/{theme}/assets/errors/` | `{error}.tpl.php` | `404.tpl.php` |

### 35.5.3. Механизм наследования шаблонов

<img src="https://github.com/DSTGlobal/DST-Platform/blob/main/images/218.png" alt="Наследование шаблонов DST Platform">

*Диаграмма: Последовательность разрешения наследования шаблонов.*

Для включения наследования создайте файл `/templates/{custom_theme}/inherit.php`:

```php
<?php
// Указывает родительскую тему для наследования
return 'default';
```

**Принцип работы:**
Когда запрашивается файл шаблона:
1. Система проверяет каталог активной темы
2. Если файл не найден, проверяется родительская тема (определенная в `inherit.php`)
3. Если файл по-прежнему не найден, возвращается ошибка

Это относится к файлам `.tpl.php`, `.css`, `.js` и при загрузке с помощью методов `cmsTemplate`.

### Автозагрузка классов
Composer генерирует автозагрузчик, который регистрирует все зависимости:


## 35.7. Каталоги данных и кэширования

### 35.7.1. Каталог `/cache/`

Хранит временные файлы кэширования для оптимизации производительности.

```plaintext
/cache/
├── pages/                    # Кэш готовых HTML-страниц
│   ├── home_*.html
│   ├── category_*.html
│   └── ...
├── data/                     # Кэш данных (массивы, объекты)
│   ├── popular_products_*.php
│   ├── category_tree_*.php
│   └── ...
├── assets/                   # Объединённые и минифицированные ресурсы
│   ├── main_*.css
│   ├── main_*.js
│   └── ...
├── sql.log                   # Лог SQL-запросов (отладка)
└── .htaccess                 # Запрет прямого доступа
```

**Файл `.htaccess` в `/cache/`:**
```apache
# Запрет доступа ко всем файлам
Deny from all

# Разрешить доступ к .htaccess
<Files ".htaccess">
    Allow from all
</Files>
```

```apache
# Разрешить доступ к изображениям и документам
<FilesMatch "\.(jpg|jpeg|png|gif|pdf|doc|docx|xls|xlsx)$">
    Allow from all
```
