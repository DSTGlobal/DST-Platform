# 38. Создание запланированных задач

Данное руководство описывает создание и настройку запланированных задач (cron-задач) в DST Platform. Рассматриваются два подхода: универсальный планировщик на основе базы данных (`cron.php`) и специализированные автономные скрипты. Материал ориентирован на практическую реализацию для разработчиков.

Для понимания архитектуры системы см. раздел *«Архитектура планировщика Cron»*. Информацию о существующих задачах (экспорт товаров, генерация YML и др.) см. в соответствующих разделах документации.

---

## 38.1. Обзор подходов

В платформе реализованы два механизма выполнения задач по расписанию:

| Подход | Файл | Сценарий применения | Хранение конфигурации |
|--------|------|---------------------|----------------------|
| **Универсальный планировщик** | `cron.php` | Множество низкоприоритетных задач с настраиваемой частотой | БД (`scheduler_tasks`) |
| **Специализированный скрипт** | `cron_*.php` | Критически важные для производительности задачи | Жёстко закодировано в скрипте |

Оба подхода используют общую базовую модель:
- Блокировка на основе файлов для предотвращения параллельного выполнения
- Инициализация системы через `bootstrap.php`
- Выполнение бизнес-логики через хуки контроллеров

## 38.3. Создание задачи в универсальном планировщике

Универсальный планировщик управляет задачами через таблицу `scheduler_tasks`, предоставляя административный интерфейс для настройки.

### 38.3.1. Реализация обработчика хука

Создайте метод в файле `hooks.php` контроллера компонента. Имя метода должно соответствовать шаблону `cron_{hook_name}`:

```php
// Файл: /system/controllers/shop/hooks.php
class shop extends cmsAction {
    
    /**
     * Пример: обновление цен на товары
     * Вызывается через cron.php по расписанию
     */
    public function cron_update_product_prices() {
        // Получение настроек компонента
        $options = $this->model->getComponentOptions('shop');
        
        // Логирование начала выполнения
        error_log('[CRON] Начало обновления цен: ' . date('Y-m-d H:i:s'));
        
        // Получение товаров для обновления
        $products = $this->model->getProductsForPriceUpdate([
            'limit' => 1000,
            'batch_size' => 100
        ]);
        
        $updated_count = 0;
        foreach ($products as $product) {
            // Применение бизнес-логики обновления цены
            $new_price = $this->calculateNewPrice($product, $options);
            
            if ($new_price !== $product['price']) {
                $this->model->updateProductPrice($product['id'], $new_price);
                $updated_count++;
            }
        }
        
        // Логирование результата
        error_log(sprintf(
            '[CRON] Обновление цен завершено: %d товаров обновлено',
            $updated_count
        ));
        
        return $updated_count;
    }
    
    /**
     * Расчёт новой цены на основе правил
     */
    private function calculateNewPrice($product, $options) {
        // Пример бизнес-логики
        $markup = $options['default_markup'] ?? 1.1;
        return round($product['cost_price'] * $markup, 2);
    }
}
```

### 38.3.2. Регистрация задачи в базе данных

Добавьте запись в таблицу `scheduler_tasks` через административный интерфейс или напрямую в БД:

| Поле | Тип | Описание | Пример значения |
|------|-----|----------|-----------------|
| `title` | VARCHAR(255) | Человекочитаемое название | "Ежедневное обновление цен" |
| `controller` | VARCHAR(50) | Имя контроллера компонента | "shop" |
| `hook` | VARCHAR(100) | Название хука (без префикса `cron_`) | "update_product_prices" |
| `period` | INT | Интервал выполнения (минуты) | 1440 |
| `is_enabled` | TINYINT(1) | Флаг активности | 1 |
| `next_run` | DATETIME | Время следующего запуска | `NOW() + INTERVAL period MINUTE` |
| `date_last_run` | DATETIME | Время последнего выполнения | NULL |

**SQL-пример добавления задачи:**
```sql
INSERT INTO scheduler_tasks (
    title, 
    controller, 
    hook, 
    period, 
    is_enabled, 
    next_run,
    date_last_run
) VALUES (
    'Ежедневное обновление цен',
    'shop',
    'update_product_prices',
    1440,
    1,
    DATE_ADD(NOW(), INTERVAL 1440 MINUTE),
    NULL
);
```

### 38.3.3. Настройка системного cron

Добавьте запись в системный планировщик (через `crontab -e` или `/etc/crontab`):

```bash
# Запуск универсального планировщика каждые 5 минут
*/5 * * * * /usr/bin/php /var/www/site/cron.php >> /var/log/dst_cron.log 2>&1
```

Планировщик проверяет `period` и `next_run` каждой задачи и выполняет те, для которых наступило время.

### 38.3.4. Алгоритм выполнения задачи

При каждом запуске `cron.php` система:

1. **Проверяет доступ через CLI**:
   ```php
   if (PHP_SAPI !== 'cli') {
       die('Access denied. CLI only.');
   }
   ```

2. **Получает файловую блокировку**:
   ```php
   $lock_file = cmsConfig::get('cache_path') . 'cron_lock';
   $lockfp = fopen($lock_file, 'w');
   if (!$lockfp || !flock($lockfp, LOCK_EX | LOCK_NB)) {
       error_log('[CRON] Another instance is running. Exiting.');
       exit(1);
   }
   ```

3. **Инициализирует ядро**:
   ```php
   require_once PATH . '/bootstrap.php';
   ```

4. **Загружает модель админки**:
   ```php
   $model = cmsCore::getModel('admin');
   ```

5. **Получает ожидающие задачи**:
   ```php
   $tasks = $model->getPendingSchedulerTasks();
   ```

6. **Для каждой задачи**:
   - Проверяет существование контроллера: `cmsCore::isControllerExists($task['controller'])`
   - Загружает контроллер: `cmsCore::getController($task['controller'])`
   - Проверяет активность: `$controller->isEnabled()`
   - Выполняет хук: `$controller->runHook("cron_{$task['hook']}")`
   - Обновляет время следующего запуска: `$model->updateSchedulerTaskDate($task)`
   - При ошибке отключает задачу: `$model->toggleSchedulerPublication($task['id'], 0)`

### 38.3.5. Выполнение конкретной задачи

Для тестирования можно запустить отдельную задачу, передав её ID:

```bash
# Запуск задачи с ID=123
php /var/www/site/cron.php yourdomain.com 123
```

Скрипт проверяет второй аргумент командной строки (`$argv[2]`) на наличие ID задачи.

## 38.4. Создание специализированного cron-скрипта

Специализированные скрипты используются для высокоприоритетных или ресурсоёмких задач, требующих выделенного контроля. Примеры: `cron_export.php`, `cron_partner_import.php`, `cron_yml_create.php`.

### 38.4.1. Структура скрипта

```php
#!/usr/bin/env php
<?php
/**
 * cron_your_task.php
 * Специализированный скрипт для выполнения задачи по расписанию
 */

// Настройка DOCUMENT_ROOT для CLI-совместимости
if (!isset($_SERVER['DOCUMENT_ROOT']) || empty($_SERVER['DOCUMENT_ROOT'])) {
    $_SERVER['DOCUMENT_ROOT'] = getenv('DOCUMENT_ROOT') ?: dirname(__DIR__);
}
define('PATH', dirname(__FILE__));
define('NO_SESSION', true); // Отключение сессии для CLI

// 1. Проверка: только CLI-доступ
if (PHP_SAPI !== 'cli') {
    http_response_code(403);
    die('Access denied. CLI only.');
}

// 2. Инициализация системы
require_once PATH . '/bootstrap.php';

// 3. Блокировка файла для предотвращения параллельного запуска
$lock_file = cmsConfig::get('cache_path') . 'cron_your_task_lock';
$lockfp = fopen($lock_file, 'w');

if (!$lockfp || !flock($lockfp, LOCK_EX | LOCK_NB)) {
    error_log('[YOUR_TASK] Another process is already running. Exiting.');
    exit(1);
}

// Гарантированная очистка блокировки при завершении
register_shutdown_function(function() use ($lockfp, $lock_file) {
    if ($lockfp) {
        flock($lockfp, LOCK_UN);
        fclose($lockfp);
        @unlink($lock_file);
    }
});

// 4. Установка лимита времени выполнения (для долгих задач)
set_time_limit(0); // Без ограничения
ini_set('memory_limit', '512M'); // Увеличение лимита памяти

// 5. Загрузка контроллера
$controller = cmsCore::getController('your_controller');

if (!$controller || !$controller->isEnabled()) {
    error_log('[YOUR_TASK] Controller not available or disabled');
    exit(1);
}

// 6. Выполнение хука
try {
    error_log('[YOUR_TASK] Starting execution at ' . date('Y-m-d H:i:s'));
    
    $result = $controller->runHook('cron_your_task_job');
    
    error_log(sprintf(
        '[YOUR_TASK] Completed successfully at %s. Result: %s',
        date('Y-m-d H:i:s'),
        json_encode($result)
    ));
    
    exit(0);
    
} catch (Exception $e) {
    error_log(sprintf(
        '[YOUR_TASK] ERROR: %s at %s:%d',
        $e->getMessage(),
        $e->getFile(),
        $e->getLine()
    ));
    
    // Логирование стека вызовов для отладки
    error_log($e->getTraceAsString());
    
    exit(1);
}
```

### 38.4.2. Реализация обработчика в контроллере

```php
// Файл: /system/controllers/your_controller/hooks.php
class your_controller extends cmsAction {
    
    /**
     * Основной хук для специализированной задачи
     * @return array Статистика выполнения
     */
    public function cron_your_task_job() {
        $start_time = microtime(true);
        
        // Получение настроек компонента
        $options = $this->model->getComponentOptions('your_controller');
        
        // Инициализация счётчиков
        $stats = [
            'processed' => 0,
            'success' => 0,
            'failed' => 0,
            'skipped' => 0
        ];
        
        // Обработка данных порциями (чанкирование)
        $batch_size = $options['batch_size'] ?? 100;
        $offset = 0;
        $total_processed = 0;
        
        do {
            // Получение порции данных
            $items = $this->model->getItemsForProcessing([
                'limit' => $batch_size,
                'offset' => $offset
            ]);
            
            if (empty($items)) {
                break;
            }
            
            // Обработка каждой записи
            foreach ($items as $item) {
                try {
                    if ($this->shouldProcessItem($item)) {
                        $this->processItem($item);
                        $stats['success']++;
                    } else {
                        $stats['skipped']++;
                    }
                    
                    $stats['processed']++;
                    
                } catch (Exception $e) {
                    error_log(sprintf(
                        '[YOUR_TASK] Error processing item %d: %s',
                        $item['id'],
                        $e->getMessage()
                    ));
                    
                    $stats['failed']++;
                    // Продолжаем обработку остальных записей
                }
            }
            
            $offset += $batch_size;
            $total_processed += count($items);
            
            // Логирование прогресса каждые 1000 записей
            if ($total_processed % 1000 === 0) {
                error_log(sprintf(
                    '[YOUR_TASK] Progress: %d items processed (%d success, %d failed, %d skipped)',
                    $total_processed,
                    $stats['success'],
                    $stats['failed'],
                    $stats['skipped']
                ));
            }
            
            // Небольшая пауза между порциями для снижения нагрузки
            usleep(10000); // 10 мс
            
        } while (count($items) === $batch_size);
        
        // Финальное логирование
        $execution_time = microtime(true) - $start_time;
        error_log(sprintf(
            '[YOUR_TASK] Completed: %d processed, %d success, %d failed, %d skipped. Time: %.2f sec',
            $stats['processed'],
            $stats['success'],
            $stats['failed'],
            $stats['skipped'],
            $execution_time
        ));
        
        // Возврат статистики для внешнего мониторинга
        $stats['execution_time'] = round($execution_time, 2);
        $stats['memory_peak'] = memory_get_peak_usage(true);
        
        return $stats;
    }
    
    /**
     * Проверка необходимости обработки записи
     */
    private function shouldProcessItem($item) {
        // Пример бизнес-логики
        return !empty($item['needs_processing']) && 
               $item['status'] === 'pending';
    }
    
    /**
     * Обработка отдельной записи
     */
    private function processItem($item) {
        // Бизнес-логика обработки
        // ...
        
        // Обновление статуса
        $this->model->updateItemStatus($item['id'], 'processed');
    }
}
```

## 38.5. Механизм файловой блокировки

Оба подхода используют файловую блокировку для предотвращения состояний гонки:

<img src="https://github.com/DSTGlobal/DST-Platform/blob/main/images/234.png" alt="DST Platform">

### 38.5.1. Карта файлов блокировки

| Скрипт | Файл блокировки | Расположение |
|--------|-----------------|--------------|
| `cron.php` | `cron_lock` | `{cache_path}/cron_lock` |
| `cron_export.php` | `cron_export_lock` | `{cache_path}/cron_export_lock` |
| `cron_partner_import.php` | `cron_partner_import_lock` | `{cache_path}/cron_partner_import_lock` |
| `cron_yml_create.php` | `cron_lock_yml` | `{cache_path}/cron_lock_yml` |
| Пользовательский скрипт | `cron_{task}_lock` | `{cache_path}/cron_{task}_lock` |

### 38.5.2. Реализация блокировки

```php
// Создание файла блокировки
$lock_file = cmsConfig::get('cache_path') . 'cron_your_task_lock';
$lockfp = fopen($lock_file, 'w');

if (!$lockfp) {
    error_log('[TASK] Cannot create lock file');
    exit(1);
}

// Попытка получения эксклюзивной неблокирующей блокировки
if (!flock($lockfp, LOCK_EX | LOCK_NB)) {
    error_log('[TASK] Another instance is running. Exiting.');
    fclose($lockfp);
    exit(1);
}

// Гарантированная очистка при завершении (даже при ошибке)
register_shutdown_function(function() use ($lockfp, $lock_file) {
    if ($lockfp) {
        flock($lockfp, LOCK_UN); // Снятие блокировки
        fclose($lockfp);         // Закрытие файла
        @unlink($lock_file);     // Удаление файла
    }
});
```

### 38.5.3. Флаги блокировки

| Флаг | Описание |
|------|----------|
| `LOCK_EX` | Эксклюзивная блокировка (никакой другой процесс не может её получить) |
| `LOCK_NB` | Неблокирующий режим (возвращает управление немедленно, если блокировка недоступна) |

Если `flock()` возвращает `false`, скрипт немедленно завершает работу.

## 38.6. Обработка ошибок и отключение задач

Универсальный планировщик автоматически обрабатывает сбои задач:

### Схема обработки исключений

<img src="https://github.com/DSTGlobal/DST-Platform/blob/main/images/235.png" alt="DST Platform">

### 38.6.1. Универсальный планировщик

При возникновении исключения в обработчике хука:

1. Исключение перехватывается планировщиком
2. Задача автоматически отключается: `$model->toggleSchedulerPublication($task['id'], 0)`
3. Задача остаётся отключённой до ручного включения в админке
4. Ошибка логируется для диагностики

```php
try {
    $controller->runHook("cron_{$task['hook']}");
    
    // Обновление времени следующего запуска
    $model->updateSchedulerTaskDate($task, [
        'next_run' => date('Y-m-d H:i:s', strtotime("+{$task['period']} minutes")),
        'date_last_run' => date('Y-m-d H:i:s')
    ]);
    
} catch (Exception $e) {
    // Автоматическое отключение задачи при ошибке
    $model->toggleSchedulerPublication($task['id'], 0);
    
    // Логирование ошибки
    error_log(sprintf(
        "[CRON] Task %d (%s) failed: %s at %s:%d",
        $task['id'],
        $task['title'],
        $e->getMessage(),
        $e->getFile(),
        $e->getLine()
    ));
}
```

### 38.6.2. Стратегии обработки ошибок в хуках

**Для задач, которые должны оставаться активными при ошибках:**

```php
public function cron_resilient_task() {
    $items = $this->model->getItems();
    
    foreach ($items as $item) {
        try {
            $this->processItem($item);
        } catch (Exception $e) {
            // Логируем ошибку, но продолжаем обработку
            error_log(sprintf(
                '[TASK] Error processing item %d: %s',
                $item['id'],
                $e->getMessage()
            ));
            
            // Можно добавить запись в таблицу ошибок для последующего анализа
            $this->logProcessingError($item['id'], $e->getMessage());
        }
    }
}
```

**Для критически важных задач, которые должны отключаться при ошибке:**

```php
public function cron_critical_task() {
    // Исключение будет перехвачено планировщиком и задача отключится
    $this->validateCriticalConditions();
    $this->performCriticalOperation();
}
```

**Для специализированных скриптов (нет автоматического отключения):**

```php
try {
    $result = $controller->runHook('cron_your_task_job');
    exit(0); // Успешное завершение
} catch (Exception $e) {
    error_log('[TASK] Critical error: ' . $e->getMessage());
    exit(1); // Неудачное завершение (код ошибки)
}
```

## 38.8. Рекомендации по выбору подхода

### ✅ Используйте универсальный планировщик, когда:

| Критерий | Обоснование |
|----------|-------------|
| **Частота настраивается** | Ежечасно, ежедневно, еженедельно через интерфейс |
| **Требуется административный интерфейс** | Настройка параметров без изменения кода |
| **Задача не критична** | Отключение при ошибке не влияет на бизнес |
| **Много похожих задач** | Централизованное управление и мониторинг |
| **Автоматическое отключение при ошибке** | Предотвращение повторных сбоев |

**Примеры:** Ежедневные отчёты, очистка временных файлов, синхронизация данных.

### ✅ Используйте специализированный скрипт, когда:

| Критерий | Обоснование |
|----------|-------------|
| **Критична для производительности** | Передача данных в реальном времени |
| **Требуется точная частота** | Каждые 2 минуты (меньше 5 минут стандартного интервала) |
| **Выделенные ресурсы** | Отдельные настройки памяти, времени выполнения |
| **Нельзя отключать при ошибке** | Задача должна продолжать работу с пропуском ошибок |
| **Специальная инициализация** | Уникальные требования к окружению |

**Примеры:** Экспорт товаров, генерация YML-фидов, высокочастотное обновление цен.

### 💡 Гибридный подход

Для одной логической задачи можно использовать оба подхода:
- Универсальная запись в планировщике для регулярного выполнения
- Специализированный скрипт для ручного/аварийного запуска

## 38.10. Лучшие практики

### ✅ Рекомендуется

| Практика | Обоснование |
|----------|-------------|
| **Чанкирование больших объёмов данных** | Предотвращение переполнения памяти |
| **Детальное логирование** | Легко отследить прогресс и ошибки |
| **Обработка исключений на уровне записей** | Продолжение работы при частичных сбоях |
| **Использование файловой блокировки** | Предотвращение параллельного выполнения |
| **Настройка лимитов памяти** | `ini_set('memory_limit', '512M')` для больших задач |
| **Тестирование вручную перед добавлением в cron** | Выявление проблем до автоматизации |

### ❌ Избегайте

| Антипаттерн | Риск |
|-------------|------|
| **Отсутствие блокировки** | Параллельное выполнение → конфликты данных |
| **Жёсткое кодирование путей** | Проблемы при развёртывании на разных серверах |
| **Отсутствие обработки ошибок** | Полное прерывание задачи при первой ошибке |
| **Слишком частые запуски** | Нагрузка на сервер, конфликты с предыдущими запусками |
| **Хранение учётных данных в коде** | Риски безопасности |

## 38.11. Примеры шаблонов реализации

### Шаблон 1: Пакетная обработка с чанкированием

```php
public function cron_batch_processing() {
    $batch_size = 100;
    $offset = $this->getLastProcessedOffset();
    $total_processed = 0;
    
    do {
        $items = $this->model->getBatch($offset, $batch_size);
        
        if (empty($items)) {
            break;
        }
        
        foreach ($items as $item) {
            $this->processItem($item);
            $total_processed++;
        }
        
        $offset += count($items);
        $this->saveLastProcessedOffset($offset);
        
        // Пауза между порциями
        usleep(10000);
        
    } while (count($items) === $batch_size);
    
    return ['processed' => $total_processed];
}
```

### Шаблон 2: Инкрементальная обработка с маркером

```php
public function cron_incremental_sync() {
    $last_sync_id = $this->model->getLastSyncMarker('external_system');
    
    $new_records = $this->model->getRecordsSinceId($last_sync_id);
    
    foreach ($new_records as $record) {
        $this->syncRecord($record);
    }
    
    if (!empty($new_records)) {
        $this->model->updateSyncMarker('external_system', end($new_records)['id']);
    }
    
    return ['synced' => count($new_records)];
}
```

### Шаблон 3: Задача с прогресс-баром (для админки)

```php
public function cron_long_running_task() {
    $total = $this->model->getTotalItemsToProcess();
    $processed = 0;
    
    $items = $this->model->getAllItems();
    
    foreach ($items as $item) {
        $this->processItem($item);
        $processed++;
        
        // Обновление прогресса в БД для отображения в админке
        if ($processed % 10 === 0) {
            $progress = round(($processed / $total) * 100, 2);
            $this->model->updateTaskProgress('long_task', $progress);
        }
    }
    
    // Сброс прогресса по завершении
    $this->model->updateTaskProgress('long_task', 100);
    
    return ['total' => $total, 'processed' => $processed];
}
```

## 38.12. Заключение

DST Platform предоставляет гибкие механизмы для автоматизации задач:

- **Универсальный планировщик** (`cron.php`) — для множества настраиваемых задач с административным интерфейсом
- **Специализированные скрипты** (`cron_*.php`) — для критически важных и высокочастотных операций

Ключевые принципы:
1. Все задачи выполняются только через CLI
2. Файловая блокировка предотвращает параллельное выполнение
3. Бизнес-логика реализуется через хуки контроллеров
4. Универсальный планировщик автоматически отключает задачи при ошибках
5. Специализированные скрипты требуют ручной обработки ошибок

Для углублённого изучения:
- *«Архитектура планировщика Cron»* — детали реализации системы
- *«Работа с хуками»* — создание обработчиков событий
- *«Экспорт данных о товарах»* — пример реализации специализированного скрипта
- *«Генерация YML-канала»* — интеграция с внешними системами
