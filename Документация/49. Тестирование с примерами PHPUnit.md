# Часть I. Основы

## 49.1. Зачем тестировать на DST Platform

DST Platform — модульный монолит с двойственной архитектурой (социальная + бизнес-часть). Даже небольшое изменение в ядре или компоненте может затронуть:

- десятки компонентов, использующих общие абстракции (`cmsModel`, `cmsEventsManager`);
- готовые коробочные решения (Маркетплейс, LMS, CRM и др.), собранные из одних и тех же модулей;
- интеграции с внешними сервисами (ЮKassa, CDEK, СБИС, 1С), где ошибка стоит денег.

**Что даёт тестирование:**

| Проблема без тестов | Решение с тестами |
|---|---|
| Регрессии после обновления ядра | Быстрый прогон — 5 минут вместо 5 дней ручного тестирования |
| Неожиданные поломки в чужих компонентах | Изоляция через моки и контрактные тесты |
| Ошибки в интеграциях (платежи, доставка) | Тесты с моками SDK + контрактные тесты на staging |
| Рост сложности при кастомизации под клиента | Регрессионная сетка для форков |
| Долгая диагностика инцидентов | Воспроизведение бага в тесте за минуты |

> 💡 **Правило DST.** Любой баг, найденный в продакшене, должен превращаться в тест, который его воспроизводит и предотвращает повторение. Это дешевле, чем повторный инцидент.

## 49.2. Пирамида тестов и уровни покрытия

```
                    ┌──────────────────┐
                    │   E2E / UI       │  ← 5–10 %, Playwright, Selenium
                    │   (медленные)    │     только критичные сценарии
                    └──────────────────┘
                  ┌──────────────────────┐
                  │  Интеграционные      │  ← 15–25 %, API + БД + кэш
                  │  (средние)           │     реальные компоненты
                  └──────────────────────┘
              ┌────────────────────────────┐
              │  Unit-тесты                │  ← 65–80 %, без БД и сети
              │  (быстрые)                 │     модели, формы, хелперы
              └────────────────────────────┘
```

**Уровни в терминах DST Platform:**

| Уровень | Что тестируем | Инструменты | Скорость |
|---|---|---|---|
| **Unit** | Модели, формы, хелперы, `api_actions` (с моками) | PHPUnit + Mockery | мс |
| **Интеграционные** | API + БД + кэш + события | PHPUnit + тестовая БД + Redis | сек |
| **Контрактные** | Внешние SDK (ЮKassa, CDEK) | PHPUnit + staging-стенд | сек–мин |
| **E2E** | Полные пользовательские сценарии | Playwright / Selenium | мин |

**Целевые метрики:**

| Компонент | Минимальное покрытие | Рекомендуемое |
|---|---|---|
| Ядро (`/system/core/`) | 80 % | 90 % |
| Бизнес-компоненты (`shop`, `partner`, `payment`) | 70 % | 85 % |
| Социальные компоненты (`content`, `comments`) | 60 % | 80 % |
| API-методы | 90 % | 95 % (write-методы — 100 %) |

> ⚠️ **Не гонитесь за 100 %.** Покрытие — индикатор, а не цель. Непокрытые ветки должны быть осознанным решением (например, обработка экзотического ответа внешнего сервиса), а не забывчивостью.

## 49.3. Архитектура тестового окружения

```
┌──────────────────────────────────────────────────────────────┐
│                  ТЕСТОВОЕ ОКРУЖЕНИЕ DST                      │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  ┌────────────────────────────────────────────────────────┐  │
│  │  PHPUnit 9.6 / 10.x                                    │  │
│  │  • Тест-раннер, ассерты, data providers                │  │
│  └──────┬─────────────────────────────────────────────────┘  │
│         │                                                    │
│         ▼                                                    │
│  ┌────────────────────────────────────────────────────────┐  │
│  │  Bootstrap: инициализация платформы                    │  │
│  │  • /system/config/config.php (тестовый)                │  │
│  │  • cmsCore::getInstance()                              │  │
│  │  • Автозагрузка классов                                │  │
│  └──────┬─────────────────────────────────────────────────┘  │
│         │                                                    │
│         ▼                                                    │
│  ┌────────────────────────────────────────────────────────┐  │
│  │  Базовый TestCase                                      │  │
│  │  • setUp(): транзакция, фикстуры                       │  │
│  │  • tearDown(): откат, очистка кэша                     │  │
│  │  • Хелперы: createUser(), loginAs(), ...               │  │
│  └──────┬─────────────────────────────────────────────────┘  │
│         │                                                    │
│         ▼                                                    │
│  ┌──────────────┬──────────────┬──────────────┬───────────┐  │
│  │ Unit-тесты   │ API-тесты    │ Интеграционные│ E2E      │  │
│  │ (моки)       │ (HTTP)       │ (полный стек) │ (вне PHP)│  │
│  └──────┬───────┴──────┬───────┴──────┬───────┴────┬──────┘  │
│         │              │              │            │         │
│         ▼              ▼              ▼            ▼         │
│  ┌────────────────────────────────────────────────────────┐  │
│  │  Зависимости                                           │  │
│  │  • MySQL/MariaDB (тестовая БД, транзакции)             │  │
│  │  • Redis (тестовый namespace)                          │  │
│  │  • Mockery (моки классов)                              │  │
│  │  • Guzzle MockHandler (моки HTTP)                      │  │
│  └────────────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────────┘
```

**Ключевые принципы:**

1. **Изоляция.** Каждый тест не зависит от предыдущего. Достигается транзакциями в БД и уникальными namespace в Redis.
2. **Детерминизм.** Никаких `sleep()`, `rand()`, реального времени. Всё, что зависит от времени/случайности — мокается.
3. **Скорость.** Unit-тесты — миллисекунды. Интеграционные — секунды. E2E — минуты (и только на CI, не локально).
4. **Повторяемость.** Один и тот же результат при каждом запуске на любой машине.

# Часть II. Настройка

## 49.4. Установка PHPUnit

### 49.4.1. Требования

| Компонент | Минимум | Рекомендуется |
|---|---|---|
| PHP | 7.4 | 8.1+ |
| Composer | 2.0 | 2.5+ |
| PHPUnit | 9.6 | 10.x (для PHP 8.1+) |
| Mockery | 1.5 | 1.6+ |
| Расширения PHP | `pdo`, `pdo_mysql`, `mbstring`, `json` | + `xdebug` или `pcov` (для coverage) |

### 49.4.2. Установка через Composer

```bash
composer require --dev phpunit/phpunit:^9.6
composer require --dev mockery/mockery:^1.5
composer require --dev guzzlehttp/mockhandler:^1.4  # для моков HTTP
```

**`composer.json` — фрагмент:**

```json
{
  "require-dev": {
    "phpunit/phpunit": "^9.6",
    "mockery/mockery": "^1.5",
    "guzzlehttp/mockhandler": "^1.4",
    "spatie/phpunit-snapshot-assertions": "^4.2"
  },
  "autoload-dev": {
    "psr-4": {
      "DST\\Tests\\": "tests/"
    }
  },
  "scripts": {
    "test": "phpunit",
    "test:unit": "phpunit --testsuite unit",
    "test:integration": "phpunit --testsuite integration",
    "test:api": "phpunit --testsuite api",
    "test:coverage": "phpunit --coverage-html coverage"
  }
}
```

## 49.5. Конфигурация `phpunit.xml`

### 49.5.1. Базовая конфигурация

**Файл:** `/phpunit.xml`

```xml
<?xml version="1.0" encoding="UTF-8"?>
<phpunit xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:noNamespaceSchemaLocation="vendor/phpunit/phpunit/phpunit.xsd"
         bootstrap="tests/bootstrap.php"
         colors="true"
         cacheResultFile=".phpunit.cache"
         executionOrder="depends,defects"
         beStrictAboutOutputDuringTests="true"
         beStrictAboutTodoAnnotatedTests="true"
         failOnRisky="true"
         failOnWarning="true"
         convertDeprecationsToExceptions="true">

    <!-- ─────────────────────────────────────────────
         Наборы тестов (test suites)
         ───────────────────────────────────────────── -->
    <testsuites>
        <!-- Unit-тесты: без БД, без сети, быстрые -->
        <testsuite name="unit">
            <directory>tests/Unit</directory>
        </testsuite>

        <!-- Интеграционные: с БД, кэшем, событиями -->
        <testsuite name="integration">
            <directory>tests/Integration</directory>
        </testsuite>

        <!-- API-тесты: HTTP-запросы к локальному стенду -->
        <testsuite name="api">
            <directory>tests/Api</directory>
        </testsuite>

        <!-- Контрактные: с реальными внешними SDK (staging) -->
        <testsuite name="contract">
            <directory>tests/Contract</directory>
        </testsuite>
    </testsuites>

    <!-- ─────────────────────────────────────────────
         Покрытие кода
         ───────────────────────────────────────────── -->
    <coverage includeUncoveredFiles="true"
              processUncoveredFiles="false"
              ignoreDeprecatedCodeUnits="true">
        <include>
            <directory suffix=".php">system/core</directory>
            <directory suffix=".php">system/controllers</directory>
            <directory suffix=".php">system/fields</directory>
        </include>
        <exclude>
            <directory>system/libs</directory>
            <directory>system/controllers/*/assets</directory>
            <file>system/config/config.php</file>
        </exclude>
        <report>
            <html outputDirectory="coverage/html"/>
            <clover outputFile="coverage/clover.xml"/>
            <text outputFile="coverage/coverage.txt" showUncoveredFiles="true"/>
        </report>
    </coverage>

    <!-- ─────────────────────────────────────────────
         Переменные окружения (переопределяются .env.test)
         ───────────────────────────────────────────── -->
    <php>
        <env name="APP_ENV" value="test"/>
        <env name="DB_DSN" value="mysql:host=127.0.0.1;dbname=dst_test;charset=utf8mb4"/>
        <env name="DB_USER" value="root"/>
        <env name="DB_PASS" value=""/>
        <env name="REDIS_HOST" value="127.0.0.1"/>
        <env name="REDIS_PORT" value="6379"/>
        <env name="REDIS_DB" value="15"/>
        <env name="CACHE_DRIVER" value="redis"/>
        <env name="API_URL" value="http://localhost:8080"/>
        <env name="API_KEY" value="test_api_key_0123456789abcdef"/>
        <env name="ENCRYPTION_KEY" value="test_encryption_key_for_phpunit_only"/>
        <ini name="error_reporting" value="E_ALL"/>
        <ini name="memory_limit" value="512M"/>
    </php>

    <!-- ─────────────────────────────────────────────
         Расширения и listeners
         ───────────────────────────────────────────── -->
    <extensions>
        <!-- Позволяет откатывать транзакции после каждого теста -->
        <extension class="DST\Tests\Extensions\TransactionPerTestExtension"/>
    </extensions>
</phpunit>
```

## 49.6. Bootstrap и инициализация платформы в тестах

### 49.6.1. Bootstrap-файл

**Файл:** `/tests/bootstrap.php`

```php
<?php
/**
 * Bootstrap для PHPUnit-тестов DST Platform.
 *
 * Инициализирует:
 *  - Composer autoloader
 *  - Константы путей
 *  - Тестовую конфигурацию (config.php)
 *  - Ядро платформы
 *  - Mockery
 */

declare(strict_types=1);

// ─────────────────────────────────────────────
// 1. Composer autoloader
// ─────────────────────────────────────────────
require_once __DIR__ . '/../vendor/autoload.php';

// ─────────────────────────────────────────────
// 2. Определение путей
// ─────────────────────────────────────────────
define('PATH', dirname(__DIR__));
define('SYSTEM_PATH', PATH . '/system');
define('TEST_PATH', __DIR__);
define('NO_SESSION', true);

// ─────────────────────────────────────────────
// 3. Тестовая конфигурация (подменяет config.php)
//    Используем отдельный config.test.php
// ─────────────────────────────────────────────
$configPath = SYSTEM_PATH . '/config/config.php';
$testConfigPath = __DIR__ . '/config/config.test.php';

if (file_exists($testConfigPath)) {
    // Симлинк или копия тестового конфига
    if (!file_exists($configPath) || md5_file($configPath) !== md5_file($testConfigPath)) {
        // Сохраняем оригинал и подменяем
        if (file_exists($configPath) && !file_exists($configPath . '.bak')) {
            copy($configPath, $configPath . '.bak');
        }
        copy($testConfigPath, $configPath);
    }
}

// ─────────────────────────────────────────────
// 4. Инициализация ядра платформы
// ─────────────────────────────────────────────
require_once SYSTEM_PATH . '/core/core.php';

// Тестовая среда
cmsConfig::getInstance()->set('debug', true);
cmsConfig::getInstance()->set('is_test', true);

// ─────────────────────────────────────────────
// 5. Mockery shutdown (закрывает моки после теста)
// ─────────────────────────────────────────────
if (class_exists(\Mockery::class)) {
    register_shutdown_function(function () {
        if (class_exists(\Mockery::class)) {
            \Mockery::close();
        }
    });
}

// ─────────────────────────────────────────────
// 6. Подавление вывода нотисов PHP в тестах
//    (кроме случаев, когда они ожидаются)
// ─────────────────────────────────────────────
error_reporting(E_ALL & ~E_DEPRECATED & ~E_USER_DEPRECATED);
ini_set('display_errors', '1');
```

### 49.6.3. Тестовая миграция БД

**Файл:** `/tests/config/schema.sql`

Схема создаётся один раз при первом запуске. Содержит минимальный набор таблиц, необходимых для тестов (полная схема не нужна — это ускоряет прогон).

```sql
-- Основные таблицы для тестов
CREATE TABLE IF NOT EXISTS `cms_users` (
    `id` INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    `email` VARCHAR(255) NOT NULL UNIQUE,
    `password` VARCHAR(255) NOT NULL,
    `nickname` VARCHAR(100) NOT NULL,
    `is_admin` TINYINT(1) DEFAULT 0,
    `is_locked` TINYINT(1) DEFAULT 0,
    `date_reg` DATETIME NOT NULL,
    `groups` TEXT,
    INDEX `idx_email` (`email`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE IF NOT EXISTS `cms_users_groups` (
    `id` INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    `title` VARCHAR(100) NOT NULL,
    `description` TEXT,
    `is_default` TINYINT(1) DEFAULT 0
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE IF NOT EXISTS `cms_users_groups_members` (
    `user_id` INT UNSIGNED NOT NULL,
    `group_id` INT UNSIGNED NOT NULL,
    PRIMARY KEY (`user_id`, `group_id`),
    INDEX `idx_group` (`group_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE IF NOT EXISTS `cms_api_keys` (
    `id` INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    `description` VARCHAR(255),
    `api_key` VARCHAR(32) NOT NULL UNIQUE,
    `ip_addresses` TEXT,
    `allowed_methods` TEXT,
    `is_active` TINYINT(1) DEFAULT 1,
    `created_at` DATETIME NOT NULL
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE IF NOT EXISTS `cms_api_logs` (
    `id` BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    `api_key_id` INT UNSIGNED,
    `method` VARCHAR(100),
    `params` TEXT,
    `ip` VARCHAR(45),
    `user_agent` VARCHAR(255),
    `response` TEXT,
    `error_code` INT,
    `execution_time` FLOAT,
    `created_at` DATETIME NOT NULL,
    INDEX `idx_method` (`method`),
    INDEX `idx_date` (`created_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- Таблицы для тестового компонента mycomp
CREATE TABLE IF NOT EXISTS `cms_mycomp_items` (
    `id` INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    `title` VARCHAR(255) NOT NULL,
    `content` TEXT,
    `category_id` INT UNSIGNED DEFAULT 0,
    `is_published` TINYINT(1) DEFAULT 0,
    `user_id` INT UNSIGNED NOT NULL,
    `created_at` DATETIME NOT NULL,
    `updated_at` DATETIME DEFAULT NULL,
    INDEX `idx_user` (`user_id`),
    INDEX `idx_category` (`category_id`)
```

### 49.7.2. Базовый `TestCase`

**Файл:** `/tests/TestCase.php`

```php
<?php
declare(strict_types=1);

namespace DST\Tests;

use PHPUnit\Framework\TestCase as PHPUnitTestCase;
use Mockery;
use Mockery\MockInterface;

/**
 * Базовый TestCase для DST Platform.
 *
 * Предоставляет:
 *  - Транзакционную изоляцию БД (rollback после каждого теста)
 *  - Очистку кэша
 *  - Хелперы для создания пользователей, авторизации
 *  - Фабрику моков для cmsModel, cmsCache, cmsUser, cmsConfig
 *  - Очистку Mockery
 */
abstract class TestCase extends PHPUnitTestCase
{
    /** @var \cmsCore|null */
    protected ?\cmsCore $core = null;

    /** @var \PDO|null PDO-соединение для прямой работы с тестовой БД */
    protected ?\PDO $pdo = null;

    /** @var bool Флаг активной транзакции */
    protected bool $inTransaction = false;

    protected function setUp(): void
    {
        parent::setUp();

        // Инициализация ядра
        $this->core = \cmsCore::getInstance();

        // Прямое PDO-соединение для манипуляций с БД в тестах
        $this->initPdo();

        // Стартуем транзакцию для изоляции
        $this->beginTransaction();

        // Чистим кэш
        $this->clearCache();

        // Фикстуры по умолчанию (можно переопределить в дочерних классах)
        $this->setUpFixtures();
    }

    protected function tearDown(): void
    {
        // Откатываем транзакцию БД
        $this->rollbackTransaction();

        // Закрываем Mockery
        Mockery::close();

        // Очищаем статические синглтоны (на случай, если тест их менял)
        $this->resetSingletons();

        parent::tearDown();
    }

    // ─────────────────────────────────────────────
    // Транзакции
    // ─────────────────────────────────────────────

    protected function beginTransaction(): void
    {
        if ($this->pdo && !$this->inTransaction) {
            $this->pdo->beginTransaction();
            $this->inTransaction = true;
        }
    }

    protected function rollbackTransaction(): void
    {
        if ($this->pdo && $this->inTransaction) {
            try {
                $this->pdo->rollBack();
            } catch (\PDOException $e) {
                // Транзакция могла быть уже откачена вручную
            }
            $this->inTransaction = false;
        }
    }

    // ─────────────────────────────────────────────
    // Инициализация
    // ─────────────────────────────────────────────

    private function initPdo(): void
    {
        $config = \cmsConfig::getInstance();

        $dsn = sprintf(
            'mysql:host=%s;dbname=%s;charset=utf8mb4',
            $config->get('db_host'),
            $config->get('db_base')
        );

        $this->pdo = new \PDO(
            $dsn,
            $config->get('db_user'),
            $config->get('db_pass'),
            [
                \PDO::ATTR_ERRMODE => \PDO::ERRMODE_EXCEPTION,
                \PDO::ATTR_DEFAULT_FETCH_MODE => \PDO::FETCH_ASSOC,
                \PDO::ATTR_EMULATE_PREPARES => false,
            ]
        );

        // Создаём схему, если её нет
        $this->ensureSchema();
    }

    private function ensureSchema(): void
    {
        $schemaFile = __DIR__ . '/config/schema.sql';
        if (!file_exists($schemaFile)) {
            return;
        }

        // Проверяем наличие основной таблицы
        $stmt = $this->pdo->query("SHOW TABLES LIKE 'cms_users'");
        if ($stmt->fetch()) {
            return; // Схема уже создана
        }

        $sql = file_get_contents($schemaFile);
        $this->pdo->exec($sql);
    }

    private function clearCache(): void
    {
        try {
            \cmsCache::getInstance()->clean();
        } catch (\Throwable $e) {
            // Кэш может быть не сконфигурирован — не падаем
        }
    }

    private function resetSingletons(): void
    {
        // Сброс синглтона cmsConfig через Reflection
        // (чтобы изменения в тесте не протекали в другие тесты)
        if (class_exists(\cmsConfig::class)) {
            $ref = new \ReflectionClass(\cmsConfig::class);
            if ($ref->hasProperty('instance')) {
                $prop = $ref->getProperty('instance');
                $prop->setAccessible(true);
                $prop->setValue(null, null);
            }
        }
    }

    // ─────────────────────────────────────────────
    // Фикстуры
    // ─────────────────────────────────────────────

    /**
     * Переопределяется в дочерних классах для настройки данных.
     */
    protected function setUpFixtures(): void
    {
        // По умолчанию — ничего
    }

    /**
     * Создание тестового пользователя.
     */
    protected function createUser(array $overrides = []): array
    {
        $defaults = [
            'email'      => 'user_' . uniqid() . '@test.local',
            'password'   => password_hash('password123', PASSWORD_BCRYPT, ['cost' => 4]),
            'nickname'   => 'Test User ' . uniqid(),
            'is_admin'   => 0,
            'is_locked'  => 0,
            'date_reg'   => date('Y-m-d H:i:s'),
            'groups'     => json_encode([1]),
        ];

        $data = array_merge($defaults, $overrides);

        $stmt = $this->pdo->prepare(
            "INSERT INTO cms_users (email, password, nickname, is_admin, is_locked, date_reg, groups)
             VALUES (:email, :password, :nickname, :is_admin, :is_locked, :date_reg, :groups)"
        );
        $stmt->execute($data);

        $data['id'] = (int)$this->pdo->lastInsertId();

        return $data;
    }

    /**
     * Создание тестового API-ключа.
     */
    protected function createApiKey(array $overrides = []): array
    {
        $defaults = [
            'description'     => 'Test key ' . uniqid(),
            'api_key'         => bin2hex(random_bytes(16)),
            'ip_addresses'    => '',
            'allowed_methods' => '',
            'is_active'       => 1,
            'created_at'      => date('Y-m-d H:i:s'),
        ];

        $data = array_merge($defaults, $overrides);

        $stmt = $this->pdo->prepare(
            "INSERT INTO cms_api_keys (description, api_key, ip_addresses, allowed_methods, is_active, created_at)
             VALUES (:description, :api_key, :ip_addresses, :allowed_methods, :is_active, :created_at)"
        );
        $stmt->execute($data);

        $data['id'] = (int)$this->pdo->lastInsertId();

        return $data;
    }

    /**
     * Авторизация через cmsUser (эмуляция залогиненного пользователя).
     */
    protected function loginAs(array $user): void
    {
        $cmsUser = \cmsUser::getInstance();
        $cmsUser->id = (int)$user['id'];
        $cmsUser->email = $user['email'];
        $cmsUser->nickname = $user['nickname'];

    }

    // ─────────────────────────────────────────────
    // Фабрика моков
    // ─────────────────────────────────────────────

    /**
     * Создание мока cmsModel (для unit-тестов без БД).
     */

    {
        $mock = Mockery::mock(\cmsModel::class);

        foreach ($methods as $method => $returnValue) {
            $mock->shouldReceive($method)->andReturn($returnValue);
        }

        return $mock;
    }

    /**
     * Мок cmsCache.
     */
    protected function mockCache(): MockInterface
    {
        $mock = Mockery::mock(\cmsCache::class);

        // Дефолтное поведение: пустой кэш
        $mock->shouldReceive('get')->andReturn(false)->byDefault();

    }
```

### 49.7.3. Хелпер для работы с БД

**Файл:** `/tests/Support/Database.php`

```php
<?php
declare(strict_types=1);

namespace DST\Tests\Support;

/**
 * Хелперы для работы с тестовой БД.
 */
class Database
{
    private \PDO $pdo;

    public function __construct(\PDO $pdo)
    {
        $this->pdo = $pdo;
    }

    /**
     * Вставка строки в таблицу.
     */
    public function insert(string $table, array $data): int
    {
        $columns = implode(', ', array_keys($data));
        $placeholders = implode(', ', array_map(fn($k) => ':' . $k, array_keys($data)));

        $stmt = $this->pdo->prepare("INSERT INTO {$table} ({$columns}) VALUES ({$placeholders})");
        $stmt->execute($data);

        return (int)$this->pdo->lastInsertId();
    }

    /**
     * Массовая вставка.
     */
    public function bulkInsert(string $table, array $rows): int
    {
        if (empty($rows)) {
            return 0;
        }

        $columns = implode(', ', array_keys($rows[0]));
        $placeholders = '(' . implode(', ', array_fill(0, count($rows[0]), '?')) . ')';
        $allPlaceholders = implode(', ', array_fill(0, count($rows), $placeholders));

        $values = [];
        foreach ($rows as $row) {
            foreach ($row as $value) {
                $values[] = $value;
            }
        }

        $stmt = $this->pdo->prepare("INSERT INTO {$table} ({$columns}) VALUES {$allPlaceholders}");
        $stmt->execute($values);

        return $stmt->rowCount();
    }

    /**
     * Поиск одной строки.
     */
    public function find(string $table, array $where): ?array
    {
        $conditions = implode(' AND ', array_map(fn($k) => "{$k} = :{$k}", array_keys($where)));
        $stmt = $this->pdo->prepare("SELECT * FROM {$table} WHERE {$conditions} LIMIT 1");
        $stmt->execute($where);
        $result = $stmt->fetch();

        return $result ?: null;
    }

    /**
     * Поиск всех строк.
     */
    public function findAll(string $table, array $where = []): array
    {
        $sql = "SELECT * FROM {$table}";
        if (!empty($where)) {
            $conditions = implode(' AND ', array_map(fn($k) => "{$k} = :{$k}", array_keys($where)));
            $sql .= " WHERE {$conditions}";
        }

        $stmt = $this->pdo->prepare($sql);
        $stmt->execute($where);

        return $stmt->fetchAll();
    }

    /**
     * Подсчёт строк.
     */
    public function count(string $table, array $where = []): int
    {
        $sql = "SELECT COUNT(*) FROM {$table}";
        if (!empty($where)) {
            $conditions = implode(' AND ', array_map(fn($k) => "{$k} = :{$k}", array_keys($where)));
            $sql .= " WHERE {$conditions}";
        }

        $stmt = $this->pdo->prepare($sql);
        $stmt->execute($where);

        return (int)$stmt->fetchColumn();
    }

    /**
     * Полная очистка таблицы (используется редко — обычно транзакции достаточно).
     */
    public function truncate(string $table): void
    {
        $this->pdo->exec("TRUNCATE TABLE {$table}");
    }
}
```

### 49.17.3. Транзакции и изоляция

**Правило:** каждая тестовая транзакция откатывается в `tearDown()`. Это гарантирует, что:

- данные одного теста не видны в другом;
- тестовая БД не «загрязняется»;
- параллельный запуск (например, `--parallel`) работает без конфликтов.

**Ограничения:**

- DDL-операции (`CREATE TABLE`, `ALTER TABLE`) не откатываются в MySQL. Избегайте их в тестах — создавайте схему один раз.
- Транзакции не работают с MyISAM. Используйте только InnoDB.
- Если тест сам вызывает `beginTransaction()` (например, тестирует транзакционную логику `api_actions`), возникает вложенность. Решение: **savepoints** (`SAVEPOINT`, `ROLLBACK TO SAVEPOINT`).

**Savepoints для тестов транзакций:**

```php
public function testAddItemRollsBackOnError(): void
{
    // Arrange
    $this->pdo->exec("SAVEPOINT test_nested");

    try {
        // Act — вызываем метод, который должен откатиться
        $this->model->addItemWithRollback(['title' => 'X'], 1);
    } catch (\Throwable $e) {
        // ожидаемо
    }

    // Assert — откатываемся к savepoint
    $this->pdo->exec("ROLLBACK TO SAVEPOINT test_nested");
    $this->assertSame(0, $this->db->count('cms_mycomp_items'));
}
```

### 49.17.4. Тест-кейс с нетранзакционной логикой

Если тест проверяет именно транзакции (например, `api_actions::add_item` с `beginTransaction` / `commit`), базовый `TestCase` создаст **внешнюю** транзакцию, а тестируемый код — **внутреннюю**. MySQL не поддерживает вложенные транзакции, только savepoints. Решение:

```php
class AddItemTransactionTest extends TestCase
{
    protected function setUp(): void
    {
        // Не вызываем parent::setUp() — нам не нужна внешняя транзакция
        // Но нужна инициализация PDO
        $this->pdo = new \PDO(...);
        $this->inTransaction = false;
    }

    public function testTransactionCommits(): void
    {
        $this->model->addItem(['title' => 'A'], 1);
        $this->assertSame(1, $this->db->count('cms_mycomp_items'));

        // Убираем за собой
        $this->db->truncate('cms_mycomp_items');
    }
}
```

## 49.21. Лучшие практики и антипаттерны

### 49.21.1. ✅ Рекомендуется

| Практика | Обоснование |
|---|---|
| **Один тест — одна проверка** | Легче диагностировать падение |
| **AAA-паттерн** (Arrange-Act-Assert) | Читаемость и структура |
| **`dataProvider` для вариаций** | Компактность и покрытие |
| **Моки только внешних зависимостей** | Реальные БД/кэш ловят больше багов |
| **Транзакции для изоляции** | Скорость и отсутствие «загрязнения» |
| **Имена тестов описывают поведение** | `testAddItemRollsBackOnError()` лучше `test1()` |
| **Фикстуры в `setUp()`** | Готовое окружение для каждого теста |
| **Тесты на найденные баги** | Регрессионная защита |
| **CI с матрицей PHP** | Совместимость с 7.4–8.2 (см. раздел *«Поддержка PHP и миграция»*) |
| **Покрытие — индикатор, не цель** | Фокус на критичных путях |

### 49.21.2. ❌ Антипаттерны

| Антипаттерн | Проблема | Как исправить |
|---|---|---|
| **Тест зависит от другого теста** | Нельзя запускать по отдельности | Изоляция через `setUp()` |
| **`sleep()` в тестах** | Медленно и нестабильно | Моки времени / событий |
| **Мок `cmsModel` в интеграционных тестах** | Не ловит SQL-ошибки | Реальная тестовая БД |
| **Тест реального `rand()`/`time()`** | Не детерминирован | Мок / фиксированный сид |
| **Проверка `===` на float** | Плавающая точка | `assertEqualsWithDelta` |
| **Тест выводит в `echo`/`var_dump`** | Ломает PHPUnit-вывод | Использовать ассерты |
| **Продовые ключи в тестах** | Риск утечки | Только тестовые env-переменные |
| **Тест без ассертов** | Покрытие есть, пользы нет | Хотя бы один ассерт |
| **Мок всего подряд** | Тестирование моков, не кода | Мокать только внешнее |
| **Гигантские тесты (200+ строк)** | Сложно диагностировать | Разбить на несколько |
| **Комментарии вместо имён** | `// проверяем, что...` | Имя теста уже говорит |

### 49.21.3. Пример: «плохой» vs «хороший» тест

**❌ Плохо:**

```php
public function testSomething()
{
    $result = $this->model->calculate(100);
    $this->assertTrue($result > 0);
}
```

Проблемы: непонятное имя, нет конкретики, нет данных, нет изоляции.

**✅ Хорошо:**

```php
/**
 * @dataProvider calculateProvider
 */
public function testCalculateReturnsExpectedTotal(float $input, float $expected): void
{
    $result = $this->model->calculate($input);
    $this->assertEqualsWithDelta($expected, $result, 0.01);
}

public function calculateProvider(): array
{
    return [
        'нулевой вход'     => [0.0, 0.0],
        'положительный'    => [100.0, 120.0],
        'дробный'          => [33.33, 40.0],
    ];
}
```

- [ ] Транзакция откатывается в `tearDown()`
- [ ] Есть ассерты (не «пустой» тест)
- [ ] Для вариаций используется `dataProvider`
- [ ] Для float — `assertEqualsWithDelta`
- [ ] Нет вывода в `echo`/`print_r`/`var_dump`
- [ ] Тест не зависит от порядка запуска
- [ ] Тест изолирован от продакшен-БД и продакшен-ключей

### 49.22.3. Справочник команд

| Команда | Назначение |
|---|---|
| `composer test` | Все тесты |
| `composer test:unit` | Только unit |
| `composer test:integration` | Только интеграционные |
| `composer test:api` | Только API |
| `composer test:coverage` | С покрытием (HTML) |
| `vendor/bin/phpunit --filter testAddItem` | Один тест по имени |
| `vendor/bin/phpunit --testsuite unit --filter ShopModelTest` | Один класс |
| `vendor/bin/phpunit --group integration` | По группе (`@group`) |
| `vendor/bin/phpunit --exclude-group external` | Исключить группу |
| `vendor/bin/phpunit --process-isolation` | Каждый тест — в отдельном процессе (медленно) |
| `vendor/bin/phpunit --parallel` | Параллельно (требует `paratest`) |
| `vendor/bin/phpunit --debug` | Подробный вывод |
| `vendor/bin/phpunit --stop-on-failure` | Остановиться на первом падении |

### 49.22.4. Полезные ассерты

| Ассерт | Когда использовать |
|---|---|
| `assertSame($expected, $actual)` | Строгое сравнение (типы важны) |
| `assertEquals($expected, $actual)` | Нестрогое сравнение |
| `assertEqualsWithDelta($expected, $actual, 0.01)` | Float |
| `assertCount($n, $array)` | Количество элементов |
| `assertArrayHasKey($key, $array)` | Наличие ключа |
| `assertArraySubset($subset, $array)` | Частичное совпадение (устар., лучше `assertArrayHasKey` + `assertSame`) |
| `assertStringContainsString($needle, $haystack)` | Подстрока |
| `assertMatchesRegularExpression($pattern, $string)` | Regex |
| `assertInstanceOf($class, $object)` | Тип объекта |
| `assertTrue` / `assertFalse` | Булевы |
| `assertNull` / `assertNotNull` | Null |
| `assertEmpty` / `assertNotEmpty` | Пустота |
| `assertGreaterThan` / `assertLessThan` | Сравнения |
| `expectException($class)` | Ожидание исключения |
| `expectExceptionMessage($msg)` | Ожидание сообщения |

## 49.23. Заключение

Тестирование на DST Platform строится на трёх принципах:

1. **Изоляция.** Транзакции в БД, отдельный Redis-namespace, моки только для внешних зависимостей.
2. **Скорость.** Unit-тесты — миллисекунды (без БД и сети), интеграционные — секунды.
3. **Детерминизм.** Никаких `sleep()`, реального времени и `rand()` — всё мокается.

**Ключевые компоненты:**

| Компонент | Назначение | Расположение |
