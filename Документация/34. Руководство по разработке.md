# 34. Руководство по разработке

В данном разделе представлено исчерпывающее руководство для разработчиков, работающих с DST Platform: основные этапы разработки, архитектурные паттерны, ключевые элементы кода и лучшие практики создания новой функциональности.

**Связанные разделы:**
- *«Структура проекта»* — организация файловой системы
- *«Создание компонентов»* — разработка пользовательских компонентов с нуля
- *«Работа с хуками»* — расширение функциональности через систему событий
- *«Создание запланированных задач»* — автоматизация фоновых процессов
- *«Система типов контента»* — декларативная разработка без кода
- *«Основная архитектура»* — ключевые архитектурные концепции
- *«Производительность и кэширование»* — оптимизация приложений

## 34.1. Обзор подходов к разработке

DST Platform поддерживает **гибридную модель разработки**, сочетающую декларативный подход для быстрого прототипирования и императивный для сложной бизнес-логики.

### Сравнение подходов
| Подход | Механизм | Лучшее применение | Временные затраты |
|--------|----------|-------------------|-------------------|
| **Декларативный** | Генератор типов контента через админ-панель | Стандартные CRUD-сущности, прототипы, контент-ориентированные функции | Минуты–часы |
| **Императивный** | Разработка кастомных компонентов (PHP-классы) | Сложная бизнес-логика, интеграции, уникальные рабочие процессы | Часы–дни |

### Рекомендованная стратегия
```
1. Начните с декларативного подхода (генератор типов контента)
2. Расширьте через хуки и наследование классов
3. Разработайте полноценный компонент при необходимости
4. Интегрируйте с существующими компонентами через события
```

## 34.2. Базовые классы и синглтоны

Все запросы в DST Platform опираются на набор базовых синглтон-классов, предоставляющих доступ к основным сервисам платформы.

## 34.3. Компонентная архитектура

Каждый функциональный блок в DST Platform реализован как **компонент** — независимый модуль с собственной моделью, контроллером и шаблонами.

### Структура типичного компонента
```
/system/controllers/{component}/
├── frontend.php              # Публичный контроллер (наследует cmsFrontend)
├── backend.php               # Админ-контроллер (наследует cmsBackend)
├── model.php                 # Модель данных (наследует cmsModel)
├── manifest.php              # Метаданные компонента
├── hooks.php                 # Обработчики событий
├── actions/                  # Методы действий
│   ├── index.php             # actionIndex()
│   ├── view.php              # actionView()
│   └── ...
└── utils/                    # Вспомогательные классы (опционально)
```

<img src="https://github.com/DSTGlobal/DST-Platform/blob/main/images/207.png" alt="Структура компонента">

### Соглашения об именовании
| Элемент | Формат | Пример |
|---------|--------|--------|
| Каталог компонента | строчные буквы, цифры, `_` (минимум 3 символа) | `shop`, `my_feature` |
| Класс контроллера | `{Name}` наследует `cmsFrontend` | `class shop extends cmsFrontend` |
| Класс бэкенда | `backend{Name}` наследует `cmsBackend` | `class backendShop extends cmsBackend` |
| Класс модели | `model{Name}` наследует `cmsModel` | `class modelShop extends cmsModel` |
| Метод действия | `action{ActionName}()` | `actionItemView()` |

## 34.4. Маршрутизация и структура контроллеров

Понимание связи между URL и методами контроллеров критично для разработки.

### Шаблон структуры URL
```
/{component}/{action}/{param1}/{param2}/...
```

### Примеры маршрутизации
| URL | Компонент | Метод | Параметры |
|-----|-----------|-------|-----------|
| `/shop` | `shop` | `actionIndex()` | `[]` |
| `/shop/item/laptop-dell-xps` | `shop` | `actionItem()` | `['laptop-dell-xps']` |
| `/users/profile/john` | `users` | `actionProfile()` | `['john']` |
| `/content/articles/read/123` | `content` | `actionRead()` | `['articles', 123]` |

<img src="https://github.com/DSTGlobal/DST-Platform/blob/main/images/208.png" alt="Маршрутизация запросов">

### Подпись метода действия
```php
// В /system/controllers/shop/frontend.php
class shop extends cmsFrontend {
    
    /**
     * Просмотр карточки товара
     * URL: /shop/item/{slug}
     */
    public function actionItem($slug) {
        // 1. Получение данных из модели
        $item = $this->model->getItemBySlug('shop_products', $slug);
        
        if (!$item) {
            return cmsCore::error404();
        }
        
        // 2. Подготовка данных для шаблона
        $this->cms_template->assign('item', $item);
        $this->cms_template->assign('related_items', 
            $this->model->getRelatedItems($item['id']));
        
        // 3. Регистрация ресурсов
        $this->cms_template->addControllerCSS('item.css', $this->name);
        $this->cms_template->addJS('controllers/shop/gallery.js');
        
        // 4. Возврат имени шаблона
        return 'item';
    }
}
```

## 34.5. Модели и работа с данными

DST Platform использует **Query Builder** вместо традиционного ORM, обеспечивая прозрачность SQL при сохранении преимуществ абстракции.

### Сравнение подходов
| Подход | Преимущества | Недостатки | Рекомендации |
|--------|--------------|------------|--------------|
| **Query Builder** | Прозрачность запросов, контроль над производительностью | Требует знания SQL | Основной подход для всех компонентов |
| **Прямой SQL** | Максимальная производительность, сложные запросы | Меньше абстракции | Для критичных по производительности операций |
| **ORM (Eloquent)** | Быстрая разработка, объектная модель | Накладные расходы, сложность отладки | Не рекомендуется |

<img src="https://github.com/DSTGlobal/DST-Platform/blob/main/images/209.png" alt="Шаблон работы с моделями">

### Типичный шаблон использования модели
```php
// В /system/controllers/shop/model.php
class modelShop extends cmsModel {
    
    /**
     * Получение популярных товаров
     */
    public function getPopularProducts($limit = 10) {
        return $this->select('shop_products')
            ->filterEqual('is_published', 1)
            ->filterGte('views_count', 100)
            ->orderBy('sales_count', 'DESC')
            ->limit($limit)
            ->getItems();
    }
    
    /**
     * Получение товаров с категориями и изображениями
     */
    public function getProductsFull($category_id) {
        $sql = "SELECT p.*, 
                       c.title as category_title,
                       GROUP_CONCAT(i.url) as images
                FROM shop_products p
                LEFT JOIN shop_categories c ON c.id = p.category_id
                LEFT JOIN product_images i ON i.product_id = p.id
                WHERE p.category_id = ? AND p.is_published = 1
                GROUP BY p.id
                ORDER BY p.date_pub DESC";
        
        return $this->db->query($sql, [$category_id], true);
    }
}
```

### Встроенные методы модели
| Метод | Назначение | Возвращает |
|-------|------------|------------|
| `getItemById($table, $id)` | Получить запись по первичному ключу | Массив или `false` |
| `getItems($table, $filters)` | Получить несколько записей | Массив массивов |
| `insert($table, $data)` | Вставить новую запись | ID вставленной записи |
| `update($table, $id, $data)` | Обновить существующую запись | `boolean` |
| `delete($table, $id)` | Удалить запись | `boolean` |
| `filterEqual($field, $value)` | Добавить условие `WHERE field = value` | `$this` (цепочка) |
| `filterLike($field, $value)` | Добавить условие `LIKE` | `$this` (цепочка) |
| `filterIn($field, $array)` | Добавить условие `IN` | `$this` (цепочка) |
| `filterGte($field, $value)` | Добавить условие `>=` | `$this` (цепочка) |
| `filterLte($field, $value)` | Добавить условие `<=` | `$this` (цепочка) |
| `orderBy($field, $direction)` | Сортировка | `$this` (цепочка) |
| `limit($limit)` | Ограничение количества | `$this` (цепочка) |
| `getItems()` | Выполнить запрос и получить результаты | Массив массивов |

## 34.6. Шаблоны и представления

Шаблоны используют **нативный PHP** с расширением `.tpl.php`. Механизм шаблонов предоставляет методы управления ресурсами с учётом наследования тем.

### Разрешение шаблонных файлов
```
Запрос шаблона: /templates/default/controllers/shop/item.tpl.php
    ↓
Проверка в текущей теме (например, /templates/dark/)
    ↓ (если не найден)
Поиск в родительской теме (указанной в inherit.php)
    ↓ (если не найден)
Поиск в базовой теме (/templates/default/)
    ↓
Возврат пути к файлу или ошибка 404
```

## 34.7. Система событий и хуки

Класс `cmsEventsManager` предоставляет систему хуков, позволяющую компонентам реагировать на события в других компонентах без изменения их кода.

### Архитектура системы событий

```
Издатель (Компонент А)
    ↓
Вызов события через cmsEventsManager::hook('event_name', $data)
    ↓
Поиск всех обработчиков в /system/controllers/*/hooks.php
    ↓
Последовательный вызов всех обработчиков
    ↓
Возврат модифицированных данных
```

<img src="https://github.com/DSTGlobal/DST-Platform/blob/main/images/211.png" alt="Система событий">


### Шаблон определения хука

```php
// В /system/controllers/shop/frontend.php
class shop extends cmsFrontend {
    
    public function actionCreateOrder() {
        // Подготовка данных заказа
        $order_data = [
            'user_id' => $this->cms_user->id,
            'items' => $this->getCartItems(),
            'total' => $this->calculateTotal()
        ];
        
        // Вызов события ДО создания заказа
        $order_data = cmsEventsManager::hook('shop_before_create_order', $order_data);
        
        if (empty($order_data['items'])) {
            return $this->cms_template->render('cart_empty');
        }
        
        // Создание заказа
        $order_id = $this->model->insert('shop_orders', $order_data);
        
        // Вызов события ПОСЛЕ создания заказа
        cmsEventsManager::hook('shop_after_create_order', $order_id, $order_data);
        
        return $this->redirectTo('order_success', ['id' => $order_id]);
    }
}
```

### Схема подключения хука

```php
// В /system/controllers/analytics/hooks.php
class analytics {
    
    /**
     * Отслеживание создания заказа
     */
    public function hookShopAfterCreateOrder($order_id, $order_data) {
        // Отправка данных в аналитическую систему
        $this->sendToAnalytics('order_created', [
            'order_id' => $order_id,
            'amount' => $order_data['total'],
            'items_count' => count($order_data['items']),
            'user_id' => $order_data['user_id']
        ]);
        
        // Логирование для внутреннего анализа
        $this->logOrderEvent($order_id, 'created');
        
        // Возврат не требуется для "после" событий
    }
    
    /**
     * Валидация заказа перед созданием
     */
    public function hookShopBeforeCreateOrder($order_data) {
        // Проверка наличия товаров
        foreach ($order_data['items'] as $item) {
            if (!$this->checkItemAvailability($item['id'], $item['quantity'])) {
                $order_data['errors'][] = "Товар {$item['title']} недоступен в количестве {$item['quantity']}";
            }
        }
        
        // Проверка минимальной суммы заказа
        if ($order_data['total'] < 500) {
            $order_data['errors'][] = "Минимальная сумма заказа: 500 ₽";
        }
        
        // Возврат модифицированных данных
        return $order_data;
    }
}
```

### Распространённые паттерны хуков
| Паттерн | Назначение | Пример |
|---------|------------|--------|
| `{component}_before_{action}` | Изменение входных данных | `content_before_save` |
| `{component}_after_{action}` | Постобработка результатов | `shop_after_order_create` |
| `{component}_validate_{action}` | Добавление правил валидации | `users_validate_registration` |
| `{component}_{entity}_view` | Расширение отображения данных | `shop_item_before_view` |
| `core_start` | Инициализация на старте системы | `analytics_on_core_start` |

## 34.8. Запланированные задачи (Cron)

DST Platform использует **CLI-скрипты**, запускаемые через системный планировщик cron, которые делегируют выполнение задач контроллерам.

### Структура CLI-скрипта
```php
#!/usr/bin/env php
<?php
/**
 * Автоматическое обновление цен
 * Запуск: php cron_price_update.php
 */

// 1. Блокировка доступа через HTTP
if (php_sapi_name() !== 'cli') {
    http_response_code(404);
    exit;
}

// 2. Определение констант
define('IS_CRON', true);
define('BASEPATH', dirname(__FILE__));

// 3. Инициализация системы
require_once BASEPATH . '/system/bootstrap.php';

// 4. Инициализация шаблона (для вспомогательных функций)
$template = cmsTemplate::getInstance();

// 5. Загрузка контроллера
$controller = cmsCore::getController('shop');

try {
    // 6. Выполнение хука обновления цен
    $result = $controller->runHook('cron_set_change_price');
    
    // 7. Вывод результата
    echo "Price update completed: " . ($result ? 'SUCCESS' : 'FAILURE') . PHP_EOL;
    
} catch (Exception $e) {
    // 8. Обработка ошибок
    error_log('[CRON] Price update failed: ' . $e->getMessage());
    echo "ERROR: " . $e->getMessage() . PHP_EOL;
    exit(1);
}
```

### Реализация Cron-хука
```php
// В /system/controllers/shop/hooks.php
class shop {
    
    /**
     * Автоматическое обновление цен
     * Хук: cron_set_change_price
     */
    public function hookCronSetChangePrice() {
        // Получение правил изменения цен
        $rules = $this->model->getPriceChangeRules();
        
        $updated_count = 0;
        $error_count = 0;
        
        foreach ($rules as $rule) {
            // Фильтрация товаров по правилу
            $products = $this->model->getProductsWithFilter($rule['filter']);
            
            foreach ($products as $product) {
                try {
                    $new_price = $this->calculateNewPrice($product, $rule);
                    
                    // Обновление цены
                    $this->model->update('shop_products', $product['id'], [
                        'price' => $new_price,
                        'price_changed_at' => date('Y-m-d H:i:s')
                    ]);
                    
                    // Логирование изменения
                    $this->model->logPriceChange(
                        $product['id'],
                        $product['price'],
                        $new_price,
                        $rule['id']
                    );
                    
                    $updated_count++;
                    
                } catch (Exception $e) {
                    error_log(sprintf(
                        '[PRICE_UPDATE] Error updating product #%d: %s',
                        $product['id'],
                        $e->getMessage()
                    ));
                    $error_count++;
                }
            }
        }
        
        // Финальное логирование
        error_log(sprintf(
            '[PRICE_UPDATE] Completed: %d updated, %d errors',
            $updated_count,
            $error_count
        ));
        
        return $updated_count > 0;
    }
    
    /**
     * Расчёт новой цены по правилу
     */
    private function calculateNewPrice($product, $rule) {
        $current_price = $product['price'];
        
        switch ($rule['type']) {
            case 'fixed':
                // Фиксированная цена
                return $rule['value'];
                
            case 'percent_increase':
                // Увеличение на процент
                return $current_price * (1 + $rule['value'] / 100);
                
            case 'percent_decrease':
                // Уменьшение на процент
                return $current_price * (1 - $rule['value'] / 100);
                
            case 'formula':
                // Расчёт по формуле
                return eval('return ' . $rule['formula'] . ';');
                
            default:
                return $current_price;
        }
    }
}
```

## 34.9. Общие паттерны разработки

### Паттерн 1: Операции CRUD
```php
// Создание
$item_id = $this->model->insert('my_table', [
    'title' => 'Новый элемент',
    'content' => 'Описание',
    'created_at' => date('Y-m-d H:i:s')
]);

// Чтение
$item = $this->model->getItemById('my_table', $item_id);

// Обновление
$this->model->update('my_table', $item_id, [
    'title' => 'Обновлённый заголовок',
    'updated_at' => date('Y-m-d H:i:s')
]);

// Удаление
$this->model->delete('my_table', $item_id);
```

### Паттерн 2: Валидация формы
```php
// В контроллере
public function actionSubmitForm() {
    // Получение данных из запроса
    $data = $this->request->get('form_data', []);
    
    // Валидация через хук
    $validation_result = cmsEventsManager::hook(
        'mycomponent_validate_form',
        $data
    );
    
    if (!empty($validation_result['errors'])) {
        // Возврат ошибок валидации
        $this->cms_template->assign('errors', $validation_result['errors']);
        $this->cms_template->assign('form_data', $data);
        return 'form';
    }
    
    // Сохранение данных
    $item_id = $this->model->insert('my_table', $data);
```

### Паттерн 3: Кэширование результатов
```php
public function getPopularProducts($limit = 10) {
    $cache_key = 'popular_products_' . $limit;
    
    // Попытка получения из кэша
    if (!$products = cmsCache::getInstance()->get($cache_key)) {
        // Запрос к базе данных
        $products = $this->select('shop_products')
            ->filterEqual('is_published', 1)
            ->orderBy('views_count', 'DESC')
            ->limit($limit)
            ->getItems();
        
        // Сохранение в кэш на 1 час
        cmsCache::getInstance()->set($cache_key, $products, 3600);
    }
    
    return $products;
}

// Инвалидация кэша при обновлении
public function updateProduct($id, $data) {
    $result = parent::update('shop_products', $id, $data);
    
    if ($result) {
        // Очистка всех кэшей, связанных с товарами
        cmsCache::getInstance()->delete('popular_products_*');
        cmsCache::getInstance()->delete('product_' . $id);
    }
    
    return $result;
}
```

## 34.14. Лучшие практики

### ✅ Рекомендуется
- **Использовать хуки** для расширения существующих компонентов (не изменяйте ядро!)
- **Переопределять шаблоны** в теме, а не в `/system/`
- **Валидировать и санитизировать** все входные данные через методы `cmsModel` или `cmsRequest`
- **Кэшировать тяжёлые запросы** через `cmsCache::getInstance()`
- **Документировать события**, которые генерирует ваш компонент
- **Использовать Query Builder** вместо прямого SQL для простых запросов
- **Тестировать на staging-среде** перед деплоем в продакшен

### ❌ Избегайте
- **Прямого изменения ядра** — используйте хуки и наследование
- **Жёсткого кодирования путей** — используйте `PATH` и `ROOT` константы
- **Отсутствия валидации** входных данных
- **Игнорирования ошибок** — всегда обрабатывайте исключения
- **Отсутствия кэширования** для часто запрашиваемых данных
- **Генерации исключений в хуках** — используйте флаги ошибок
- **Предположений о порядке выполнения** хуков

### Пример правильного подхода
```php
// ✅ Правильно: использование хуков
cmsEventsManager::hook('mycomponent_before_save', $data);

// ✅ Правильно: валидация входных данных
$data = $this->request->getFiltered('data', [
    'title' => 'str',
    'price' => 'float',
    'category_id' => 'int'
]);

// ✅ Правильно: кэширование
$cache_key = 'component_data_' . $id;
if (!$data = cmsCache::getInstance()->get($cache_key)) {
    $data = $this->model->getData($id);
    cmsCache::getInstance()->set($cache_key, $data, 3600);
}

// ❌ Неправильно: прямое изменение ядра
// Изменение файлов в /system/core/

// ❌ Неправильно: отсутствие валидации
$title = $_POST['title']; // НЕБЕЗОПАСНО!

// ❌ Неправильно: игнорирование ошибок
@file_get_contents($url); // Подавление ошибок
```

## 34.15. Заключение

Руководство по разработке DST Platform предоставляет основу для создания расширений и кастомизации платформы. Ключевые принципы:

1. **Гибридный подход**: сочетание декларативной и императивной разработки
2. **Расширяемость через хуки**: минимальное вмешательство в ядро
3. **Чёткие границы компонентов**: каждый компонент — независимый модуль
4. **Производительность через кэширование**: многоуровневая стратегия кэширования
5. **Безопасность через валидацию**: санитизация всех входных данных

**Рекомендация для разработчиков:** Начинайте с изучения существующих компонентов (например, `shop`, `users`) для понимания архитектурных паттернов. Используйте декларативный подход для быстрого прототипирования, переходя к императивной разработке по мере усложнения требований. Всегда документируйте созданные компоненты и события для облегчения поддержки.

Для углублённого изучения конкретных аспектов разработки обратитесь к связанным разделам документации, перечисленным в начале данного руководства.
