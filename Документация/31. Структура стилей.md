# 31. Структура стилей

В данном разделе описана архитектура и организация CSS-стилей в DST Platform: базовый фреймворк Bootstrap, пользовательские стили, механизмы загрузки, наследование тем и оптимизация производительности.

**Связанные разделы:**
- *«Конвейер обработки ресурсов»* — загрузка и кэширование CSS
- *«Типографика и шрифты»* — пользовательские веб-шрифты и определения типографики
- *«Система шаблонов»* — общая архитектура шаблонизации
- *«Работа с ресурсами (CSS/JS)»* — методы подключения стилей

---

## 31.1. Обзор архитектуры стилей

Система стилей DST Platform построена на многоуровневой архитектуре, обеспечивающей разделение ответственности и гибкость кастомизации:

```
Базовый уровень: Bootstrap 4 (кастомизированный)
    ↓
Глобальные стили темы (/templates/{theme}/css/)
    ↓
Изолированные стили компонентов (/templates/{theme}/controllers/{component}/)
    ↓
Динамические стили (options.css.php)
```

**Ключевые принципы:**
- **Изоляция**: Стили компонентов не влияют на глобальные стили и наоборот
- **Наследование**: Дочерние темы могут переопределять только необходимые файлы
- **Оптимизация**: Автоматическая минификация и объединение в production-режиме
- **Семантичность**: Использование вспомогательных классов Bootstrap вместо кастомных стилей

---

## 31.2. Базовый CSS-фреймворк: кастомизированный Bootstrap

DST Platform использует модифицированную версию **Bootstrap 4** в качестве основы системы стилей.

### Расположение и назначение
| Файл | Расположение | Назначение |
|------|--------------|------------|
| `css/bootstrap.css` | `/css/` | Кастомизированный фреймворк Bootstrap 4 |
| `css/fonts.css` | `/css/` | Объявления `@font-face` для веб-шрифтов |
| `css/style.css` | `/templates/{theme}/css/` | Глобальные стили темы |

### Ключевые модификации Bootstrap
- **Цветовая схема**: Переопределены переменные `--primary`, `--blue` и другие
- **Точки останова**: `xl` изменён с 1200px на **1400px**
- **Типографика**: Интеграция пользовательских шрифтов GT Eesti Pro и Styrene A Web
- **Компоненты**: Кастомизация кнопок, форм, таблиц под корпоративный стиль

### Вспомогательные классы Bootstrap

Рекомендуется использовать встроенные утилиты вместо написания кастомных стилей:

```html
<!-- Рекомендуется -->
<div class="d-flex justify-content-between align-items-center mb-3">
    <h3 class="text-primary">Заголовок</h3>
    <button class="btn btn-outline-primary">Кнопка</button>
</div>

<!-- Избегайте -->
<div class="custom-flex-container">
    <h3 class="custom-title">Заголовок</h3>
    <button class="custom-button">Кнопка</button>
</div>
```

## 31.3. Организация файлов стилей

### Структура каталогов темы

```
/templates/{theme_name}/
├── css/
│   ├── style.css              # Глобальные стили темы
│   ├── theme-content.css      # Типографика контента
│   ├── theme-gui.css          # Стили форм и элементов управления
│   └── fonts.css              # Объявления шрифтов
├── shop/
│   ├── bootstrap.css          # Изолированная сетка для маркетплейса
│   └── styles.css             # Стили интерфейса магазина
├── controllers/
│   ├── shop/
│   │   ├── styles.css         # Стили компонента "Магазин"
│   │   └── item.css           # Стили карточки товара
│   ├── users/
│   │   └── styles.css         # Стили профиля пользователя
│   ├── forum/
│   │   └── styles.css         # Стили форума
│   └── ...
├── widgets/
│   └── {widget_name}.css      # Стили виджетов
└── options.css.php            # Динамические стили из настроек темы
```

### Назначение каталогов
| Каталог | Содержимое | Область применения |
|---------|------------|---------------------|
| `/css/` | Глобальные стили, шрифты | Весь сайт |
| `/shop/` | Стили маркетплейса | Только компонент `shop` |
| `/controllers/{component}/` | Стили компонентов | Конкретный компонент |
| `/widgets/` | Стили виджетов | Экземпляры виджетов |
| `/assets/` | Системные UI-элементы | Фреймворк (формы, ошибки, пагинация) |

## 31.4. Стили компонентов

Каждый компонент может иметь собственную таблицу стилей, изолированную от глобальных стилей.

### Соглашение об именовании
Файлы стилей компонентов должны называться `styles.css` и располагаться в каталоге шаблонов компонента:

```
/templates/{theme_name}/controllers/{component_name}/styles.css
```

### Таблица компонентов и их стилей
| Компонент | Путь к стилям | Назначение |
|-----------|---------------|------------|
| `shop` | `/controllers/shop/styles.css` | Список товаров, корзина, оформление заказа |
| `users` | `/controllers/users/styles.css` | Профили пользователей, ЛК |
| `partner` | `/controllers/partner/styles.css` | Панель управления продавца |
| `forum` | `/controllers/forum/styles.css` | Темы и обсуждения |
| `photos` | `/controllers/photos/styles.css` | Фотоальбомы |
| `groups` | `/controllers/groups/styles.css` | Страницы сообществ |
| `comments` | `/controllers/comments/styles.css` | Система комментариев |

### Автоматическая загрузка стилей компонента
```php
// В контроллере компонента
public function index() {
    // Автоматически загружает /templates/{theme}/controllers/shop/styles.css
    $this->addControllerCSS('styles.css', $this->name);
    
    // Дополнительные стили для конкретного представления
    $this->addCSS('controllers/shop/item.css');
}
```

## 31.5. Изолированные стили маркетплейса

Компонент `shop` использует изолированное пространство имён для предотвращения конфликтов стилей с основной темой.

### Структура изолированных стилей
```
/templates/default/shop/
├── bootstrap.css    # Изолированная сетка Bootstrap
├── styles.css       # Основные стили маркетплейса
└── assets/
    ├── icons/       # Иконки магазина
    └── images/      # Изображения интерфейса
```

### Преимущества изоляции
- **Независимость**: Стили магазина не влияют на остальной сайт
- **Поддерживаемость**: Легко обновлять и тестировать
- **Безопасность**: Изменения в одном компоненте не ломают другой

### Подключение изолированных стилей
```php
// В контроллере компонента shop
$this->addCSS('shop/bootstrap.css');  // Изолированная сетка
$this->addCSS('shop/styles.css');     // Стили магазина
$this->addControllerCSS('styles.css', 'shop');  // Стили компонента
```

## 31.6. Методы подключения CSS

Класс `cmsTemplate` предоставляет унифицированный интерфейс для подключения стилей с автоматической обработкой наследования и оптимизации.

### Справочник методов
| Метод | Расположение в документе | Участвует в объединении | Назначение |
|-------|--------------------------|-------------------------|------------|
| `addMainCSS($path)` | `<head>`, начало стека | Да | Критические стили (рендеринг выше сгиба) |
| `addCSS($path)` | `<head>`, конец стека | Опционально | Дополнительные стили |
| `addControllerCSS($file, $component)` | `<head>` | Да | Автоматическая загрузка стилей компонента |

### Примеры использования
```php
// Критические стили для быстрой отрисовки
$this->addMainCSS('templates/default/css/custom-layout.css');

// Стили сторонних плагинов (загружаются после основных)
$this->addCSS('templates/default/css/plugin-styles.css');

// Автоматическая загрузка стилей компонента
$this->addControllerCSS('styles.css', 'shop');
```

### Механизм разрешения путей
Все методы используют внутренний механизм `getTplFilePath()`, который:
1. Проверяет наличие файла в текущей теме
2. При отсутствии ищет в родительской теме (указанной в `inherit.php`)
3. Возвращает найденный путь или `null`

## 31.7. Наследование тем и переопределение стилей

Дочерние темы могут выборочно переопределять стили родительской темы без дублирования всей структуры.

### Создание дочерней темы
1. Создайте каталог темы: `/templates/my_theme/`
2. Добавьте файл наследования: `inherit.php`
3. Переопределите только необходимые файлы

### Пример структуры дочерней темы
```
/templates/dark/
├── inherit.php              # return 'default';
├── css/
│   └── style.css            # Переопределяет только этот файл
└── controllers/
    └── shop/
        └── styles.css       # Переопределяет стили магазина
```

### Алгоритм поиска файлов
При запросе файла система ищет в порядке приоритета:
1. Текущая тема (`/templates/dark/...`)
2. Родительская тема (`/templates/default/...`)
3. Рекурсивно вверх по цепочке наследования
4. Фолбэк на `default` (если не в цепочке)

```
Текущая тема: dark
    ↓ (если файл не найден)
Родительская тема: default
    ↓ (если файл не найден)
Базовая тема: default
```

## 31.8. Динамическая генерация стилей

DST Platform поддерживает генерацию CSS на основе настроек темы через специальный файл `options.css.php`.

### Структура файла

```php
<?php
// /templates/{theme_name}/options.css.php

header('Content-Type: text/css; charset=utf-8');

// Получение настроек темы
$settings = cmsCore::getSettings('theme.' . cmsTemplate::getTemplateName());

// Генерация динамических стилей
?>
:root {
    --primary-color: <?= $settings['primary_color'] ?? '#5b88bd' ?>;
    --secondary-color: <?= $settings['secondary_color'] ?? '#0b1f35' ?>;
    --border-radius: <?= $settings['border_radius'] ?? '4px' ?>;
}

body {
    font-family: <?= $settings['font_family'] ?? '"GT Eesti Pro", sans-serif' ?>;
    font-size: <?= $settings['font_size'] ?? '16px' ?>;
}

.btn-primary {
    background-color: var(--primary-color);
    border-radius: var(--border-radius);
}
```

### Интеграция с формой настроек
Файл `options.form.php` определяет поля настроек, доступные в админ-панели:

```php
<?php
// /templates/{theme_name}/options.form.php

return [
    'primary_color' => [
        'title' => 'Основной цвет',
        'type' => 'color',
        'default' => '#5b88bd'
    ],
    'font_family' => [
        'title' => 'Семейство шрифтов',
        'type' => 'text',
        'default' => '"GT Eesti Pro", sans-serif'
    ],
    'border_radius' => [
        'title' => 'Скругление углов',
        'type' => 'text',
        'default' => '4px'
    ]
];
```

## 31.9. Рендеринг и вывод ресурсов

Зарегистрированные CSS-файлы выводятся в HTML через методы шаблона макета.

### Интеграция в макет
В файле `/templates/default/main.tpl.php`:
```php
<!DOCTYPE html>
<html>
<head>
    <?php $this->renderHead(); ?>
    <!-- или -->
    <?php $this->head(); ?>
</head>
<body>
    <!-- Контент страницы -->
</body>
</html>
```

### Порядок вывода CSS
1. **Основные стили** (`addMainCSS()`) — включены в пакет минификации
2. **Дополнительные стили** (`addCSS()`) — загружаются после основного пакета
3. **Стили компонентов** (`addControllerCSS()`) — загружаются при активации компонента

### Содержимое renderHead()
Метод выводит в следующем порядке:
- Метатеги (title, description, Open Graph)
- Зарегистрированные CSS-файлы
- Встроенные `<style>` блоки
- JavaScript-файлы, помеченные для загрузки в `<head>`

## 31.10. Оптимизация и кэширование CSS

Система автоматически оптимизирует загрузку стилей в production-режиме.

### Функции оптимизации
| Функция | Описание | Конфигурация |
|---------|----------|--------------|
| **Минификация** | Удаление пробелов, комментариев, сжатие | Включено в настройках |
| **Объединение** | Сборка всех `addMainCSS()` в один файл | Включено в настройках |
| **Версионирование** | Добавление `?v={timestamp}` к URL | Автоматически |
| **Кэширование** | Сохранение объединённых файлов в `/cache/` | Автоматически |

### Процесс оптимизации
```
Исходные CSS-файлы
    ↓
Объединение (concatenation)
    ↓
Минификация (удаление пробелов, комментариев)
    ↓
Сохранение в /cache/{hash}.css
    ↓
Добавление версионного параметра ?v={timestamp}
    ↓
Отдача браузеру
```

### Конфигурация оптимизации
Управляется через настройки в админ-панели:
- **Режим разработки**: Минификация отключена, файлы загружаются отдельно
- **Production-режим**: Минификация и объединение включены

## 31.11. Лучшие практики

### 1. Изоляция стилей компонентов
Всегда размещайте стили компонента в его каталоге, а не в глобальных файлах:

```css
/* ✅ Рекомендуется */
/templates/default/controllers/mycomponent/styles.css

/* ❌ Избегайте */
/templates/default/css/style.css  /* Добавление .mycomponent-* классов */
```

### 2. Используйте методы шаблона для подключения CSS
Всегда используйте `cmsTemplate` методы вместо прямых `<link>` тегов:

```php
// ✅ Рекомендуется
$this->addMainCSS('templates/default/css/custom.css');

// ❌ Избегайте
<link rel="stylesheet" href="/templates/default/css/custom.css">
```

**Почему:** Автоматическая обработка наследования, кэширование, минификация.

### 3. Соблюдайте изоляцию стилей маркетплейса
Никогда не смешивайте стили магазина со стилями основной темы:

```php
// ✅ Рекомендуется
$this->addCSS('shop/bootstrap.css');
$this->addCSS('shop/styles.css');
$this->addControllerCSS('styles.css', 'shop');

// ❌ Избегайте
$this->addCSS('css/style.css');  /* Глобальные стили в компоненте магазина */
```

### 4. Используйте утилиты Bootstrap
Для распространённых задач используйте встроенные классы вместо кастомных стилей:

```html
<!-- ✅ Рекомендуется -->
<div class="container">
    <div class="row">
        <div class="col-md-6 offset-md-3 text-center">
            <h2 class="mb-4">Заголовок</h2>
            <p class="text-muted">Описание</p>
        </div>
    </div>
</div>

<!-- ❌ Избегайте -->
<div class="custom-container">
    <div class="custom-row">
        <div class="custom-col custom-centered">
            <h2 class="custom-title">Заголовок</h2>
            <p class="custom-description">Описание</p>
        </div>
    </div>
</div>
```

### 5. Создавайте дочерние темы для кастомизации
Вместо изменения темы `default` создавайте дочернюю тему:

```php
// /templates/my_theme/inherit.php
<?php return 'default'; ?>
```

**Преимущества:**
- Сохранение возможности обновления базовой темы
- Чёткое разделение кастомных и стандартных стилей
- Упрощённое отслеживание изменений

### 6. Автоматическая загрузка стилей компонентов
Используйте `addControllerCSS()` для автоматической загрузки:

```php
// В контроллере компонента
public function index() {
    $this->addControllerCSS('styles.css', $this->name);
    // Автоматически загрузит /templates/{theme}/controllers/{component}/styles.css
}
```

### 7. Динамические стили через options.css.php
Для настроек на уровне темы используйте динамическую генерацию:

```php
// Вместо жёстко закодированных значений в CSS
:root {
    --primary-color: <?= $settings['primary_color'] ?>;
}
```

## 31.13. Заключение

Архитектура стилей DST Platform обеспечивает:

1. **Чёткое разделение ответственности** через многоуровневую структуру
2. **Гибкость кастомизации** через наследование тем и изоляцию компонентов
3. **Производительность** через автоматическую оптимизацию (минификация, объединение)
4. **Поддерживаемость** через семантические имена и стандартные соглашения
5. **Безопасность** через изоляцию стилей маркетплейса от основной темы

**Рекомендация для разработчиков:** При создании кастомных тем или расширении компонентов всегда следуйте описанной структуре и используйте методы `cmsTemplate` для подключения ресурсов. Это гарантирует совместимость с механизмами кэширования, обновлениями платформы и упростит поддержку проекта.
