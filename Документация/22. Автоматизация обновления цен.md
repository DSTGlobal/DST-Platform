# 22. Автоматизация обновления цен

Данный документ описывает систему автоматизированного обновления цен на платформе DST Platform. Система реализована в виде специализированного cron-скрипта, который периодически запускает бизнес-логику контроллера маркетплейса для применения запланированных изменений цен к товарам. Решение обеспечивает гибкое управление ценовой политикой без ручного вмешательства.

> **Важно**: Данный документ описывает систему автоматизированного обновления цен через специализированный cron-скрипт. Для общего описания архитектуры планировщика Cron см. раздел *«Архитектура планировщика Cron»*. Для других автоматизированных операций (экспорт продукции, генерация фидов) см. разделы *«Задания экспорта продукции»* и *«Генерация фидов для маркетплейсов»*.

---

## 22.1. Обзор системы

Система автоматизации обновления цен реализована через специализированный cron-скрипт `cron_test_run_set_change_price.php`, который делегирует обработку изменений цен контроллеру маркетплейса через систему хуков. В отличие от задач, управляемых базой данных (`cron.php`), этот скрипт предназначен для прямого вызова из системного демона cron.

### Ключевые характеристики

| Характеристика | Реализация |
|----------------|------------|
| **Точка входа** | `cron_test_run_set_change_price.php` |
| **Контроллер** | `shop` (маркетплейс) |
| **Название хука** | `cron_set_change_price` |
| **Модель параллелизма** | Отсутствует файловая блокировка (идемпотентные операции) |
| **Требования к окружению** | Только командная строка (HTTP-доступ запрещён) |
| **Типичная частота** | Ежечасно или по расписанию правил |
| **Контекст выполнения** | Без сессии, только инициализация ядра |

### Типичные сценарии использования

| Сценарий | Описание | Частота |
|----------|----------|---------|
| **Сезонные распродажи** | Автоматическое снижение цен на определённые категории товаров | Раз в сезон |
| **Динамическое ценообразование** | Корректировка цен на основе спроса, конкуренции | Ежедневно/ежечасно |
| **Оптовые скидки** | Применение скидок для оптовых покупателей по расписанию | Еженедельно |
| **Валютные колебания** | Автоматическая корректировка цен при изменении курса валют | Ежедневно |
| **Акции и промо** | Временные скидки с автоматическим восстановлением базовой цены | По расписанию |

/**
 * Автоматизированное обновление цен
 * Запускается по расписанию через системный cron
 * 
 * Пример использования:
 *   php cron_test_run_set_change_price.php
 * 
 * Типичная запись в crontab:
 *   0 * * * * /usr/bin/php /var/www/site/cron_test_run_set_change_price.php >> /var/log/dst_price_update.log 2>&1
 */

// 1. Проверка: только для CLI (защита от HTTP-вызова)
if (PHP_SAPI !== 'cli') {
    http_response_code(404);
    die('404');
}

// 2. Инициализация ядра
require_once __DIR__ . '/bootstrap.php';

// 3. Изменение рабочего каталога (если доступно)
if (function_exists('chdir') && defined('PATH')) {
    chdir(PATH);
}

// 4. Инициализация системы шаблонов (для вспомогательных функций)
$template = cmsTemplate::getInstance();

// 5. Загрузка модели (опционально, для будущего использования)

$controller = cmsCore::getController('shop');

try {
    // 7. Выполнение хука обновления цен
    $result = $controller->runHook("cron_set_change_price");
    
    // 8. Вывод результата в стандартный поток
    echo $result;
    
} catch (Exception $e) {
    // 9. Обработка исключений с подробной отладочной информацией

}

## 22.7. Бизнес-логика хука обновления цен

### Структура метода хука

```php
// /system/controllers/shop/hooks.php
class shop {
    /**
     * Хук: автоматизированное обновление цен
     * Вызывается из cron_test_run_set_change_price.php
     * 
     * @return string Результат выполнения (лог, статистика)
     */
    public function cron_set_change_price() {
        $start_time = microtime(true);
        $log = [];
        
        try {
            // 1. Получение активных правил изменения цен
            $rules = $this->model->getActivePriceChangeRules();
            $log[] = sprintf('[PRICE UPDATE] Found %d active rules', count($rules));
            
            if (empty($rules)) {
                $log[] = '[PRICE UPDATE] No active rules. Skipping update.';
                return implode("\n", $log);
            }
            
            $total_updated = 0;
            $total_skipped = 0;
            
            // 2. Обработка каждого правила
            foreach ($rules as $rule) {
                $log[] = sprintf(
                    '[PRICE UPDATE] Processing rule #%d: %s',
                    $rule['id'],
                    $rule['name']
                );
                
                // 3. Получение товаров, соответствующих правилу
                $products = $this->model->getProductsWithFilter($rule['filter']);
                $log[] = sprintf(
                    '[PRICE UPDATE] Rule #%d matches %d products',
                    $rule['id'],
                    count($products)
                );
                
                if (empty($products)) {
                    $total_skipped += count($products);
                    continue;
                }
                
                // 4. Применение правила к каждому товару
                $updated_count = 0;
                foreach ($products as $product) {
                    try {
                        // Расчёт новой цены
                        $new_price = $this->calculateNewPrice($product, $rule);
                        
                        // Проверка: цена изменилась?
                        if ($new_price === $product['price']) {
                            $total_skipped++;
                            continue;
                        }
                        
                        // Обновление цены в БД
                        $this->model->update('shop_products', $product['id'], [
                            'price' => $new_price,
                            'price_changed_at' => date('Y-m-d H:i:s'),
                            'price_changed_by_rule' => $rule['id']
                        ]);
                        
                        // Логирование изменения
                        $this->model->logPriceChange(
                            $product['id'],
                            $product['price'],
                            $new_price,
                            $rule['id']
                        );
                        
                        $updated_count++;
                        $total_updated++;
                        
                    } catch (Exception $e) {
                        $log[] = sprintf(
                            '[PRICE UPDATE] ERROR updating product #%d: %s',
                            $product['id'],
                            $e->getMessage()
                        );
                        // Продолжаем обработку остальных товаров
                    }
                }
                
                $log[] = sprintf(
                    '[PRICE UPDATE] Rule #%d: updated %d products, skipped %d',
                    $rule['id'],
                    $updated_count,
                    count($products) - $updated_count
                );
            }
            
            // 5. Инвалидация кэша
            $this->invalidatePriceCache();
            $log[] = '[PRICE UPDATE] Cache invalidated';
            
            // 6. Обновление поискового индекса
            $this->updateSearchIndex();
            $log[] = '[PRICE UPDATE] Search index updated';
            
            // 7. Финальное логирование
            $duration = round(microtime(true) - $start_time, 2);
            $log[] = sprintf(
                '[PRICE UPDATE] Completed: %d prices updated, %d skipped in %.2f seconds',
                $total_updated,
                $total_skipped,
                $duration
            );
            
            return implode("\n", $log);
            
        } catch (Exception $e) {
            $log[] = sprintf('[PRICE UPDATE] CRITICAL ERROR: %s', $e->getMessage());
            $log[] = $e->getTraceAsString();
            return implode("\n", $log);
        }
    }
    
    /**
     * Расчёт новой цены по правилу
     * 
     * @param array $product Данные товара
     * @param array $rule Правило изменения цены
     * @return float Новая цена
     */
    private function calculateNewPrice($product, $rule) {
        $current_price = $product['price'];
        
        switch ($rule['type']) {
            case 'fixed':
                // Фиксированная цена
                return (float)$rule['value'];
                
            case 'percent_increase':
                // Увеличение на процент
                return $current_price * (1 + $rule['value'] / 100);
                
            case 'percent_decrease':
                // Уменьшение на процент
                return $current_price * (1 - $rule['value'] / 100);
                
            case 'formula':
                // Расчёт по формуле (опасно, требует валидации)
                // Пример: "price * 1.1 + 100"
                $formula = str_replace('price', $current_price, $rule['formula']);
                return eval('return ' . $formula . ';');
                
            case 'round_to':
                // Округление до заданного значения
                // Пример: округление до 999: 1234 → 1999
                $round_to = $rule['value'];
                return ceil($current_price / $round_to) * $round_to;
                
            default:
                // По умолчанию — текущая цена без изменений
                return $current_price;
        }
    }
    
    /**
     * Инвалидация кэша цен
     */
    private function invalidatePriceCache() {
        // Очистка кэша всех товаров
        cmsCache::getInstance()->deleteByTag('shop_products');
        
        // Очистка кэша цен
        cmsCache::getInstance()->deleteByTag('product_prices');
    }
    
    /**
     * Обновление поискового индекса
     */
    private function updateSearchIndex() {
        // Интеграция с компонентом поиска
        // Обычно вызывает событие для обновления индекса
        cmsEventsManager::hook('shop_prices_updated');
    }
}
```

### Типы правил изменения цен

| Тип правила | Описание | Пример | Формула |
|-------------|----------|--------|---------|
| **Фиксированная цена** | Установка конкретной цены | 1999.00 | `value` |
| **Процентное увеличение** | Повышение цены на % | +10% | `price * (1 + value/100)` |
| **Процентное уменьшение** | Снижение цены на % | -15% | `price * (1 - value/100)` |
| **Округление** | Округление до заданного значения | до 999 | `ceil(price / value) * value` |
| **Формула** | Произвольная формула | `price * 1.2 + 50` | `eval(formula)` |

### Структура таблицы правил

```sql
CREATE TABLE `shop_price_change_rules` (
    `id` INT(11) NOT NULL AUTO_INCREMENT,
    `name` VARCHAR(255) NOT NULL,
    `type` ENUM('fixed', 'percent_increase', 'percent_decrease', 'round_to', 'formula') NOT NULL,
    `value` DECIMAL(10,2) DEFAULT NULL,
    `formula` TEXT DEFAULT NULL,
    `filter` TEXT NOT NULL COMMENT 'JSON с условиями фильтрации товаров',
    `is_active` TINYINT(1) DEFAULT 1,
    `start_date` DATETIME DEFAULT NULL,
    `end_date` DATETIME DEFAULT NULL,
    `created_at` DATETIME DEFAULT CURRENT_TIMESTAMP,
    `updated_at` DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (`id`),
    KEY `is_active` (`is_active`),
    KEY `start_date` (`start_date`),
    KEY `end_date` (`end_date`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

Автоматизация обновления цен тесно связана с модулем маркетплейса, который предоставляет следующие возможности:

- Модели изменения цен — схемы баз данных для запланированных изменений цен.

- Логика проверки — бизнес-правила для изменения цен.
- Отслеживание истории — журнал аудита изменений цен.
- Аннулирование кэша — очистка кэшированных цен на товары.
- Обновление поискового индекса — синхронизация данных о ценах с результатами поиска.

Контроллер цеха cron_set_change_price управляет этими операциями в транзакционном режиме.

Подробную информацию об архитектуре модуля маркетплейса см. в разделе «Модуль маркетплейса и электронной коммерции».

## 22.12. Безопасность и контроль доступа

### Механизмы безопасности

| Механизм | Реализация | Цель |
|----------|------------|------|
| **CLI-only** | `PHP_SAPI !== 'cli'` → 404 | Предотвращение веб-доступа |
| **Проверка правил** | Валидация `filter` перед применением | Предотвращение некорректных изменений |
| **Логирование** | Запись всех изменений цен | Аудит и откат при ошибках |
| **Транзакции** | Использование транзакций БД | Атомарность операций |
| **Резервное копирование** | Автоматическое бэкапирование перед массовыми изменениями | Восстановление при сбоях |

### Пример безопасного применения правил

```php
/**
 * Применение правила изменения цен с защитой
 */
private function applyPriceRuleSafely($rule, $products) {
    // 1. Валидация правила
    if (!$this->validatePriceRule($rule)) {
        throw new Exception('Invalid price rule');
    }
    
    // 2. Проверка лимитов
    if (count($products) > 10000) {
        throw new Exception('Too many products to update at once');
    }
    
    // 3. Создание резервной копии (для массовых изменений)
    if (count($products) > 1000) {
        $this->createPriceBackup($products);
    }
    
    // 4. Применение в транзакции
    $this->db->startTransaction();
    
    try {
        $updated = 0;
        foreach ($products as $product) {
            $new_price = $this->calculateNewPrice($product, $rule);
            
            // Защита от слишком больших изменений
            $change_percent = abs(($new_price - $product['price']) / $product['price'] * 100);
            if ($change_percent > 50) {
                error_log(sprintf(
                    '[PRICE UPDATE] WARNING: Large price change for product #%d: %.2f%%',
                    $product['id'],
                    $change_percent
                ));
                // Пропускаем слишком большие изменения для ручной проверки
                continue;
            }
            
            $this->model->update('shop_products', $product['id'], [
                'price' => $new_price,
                'price_changed_at' => date('Y-m-d H:i:s'),
                'price_changed_by_rule' => $rule['id']
            ]);
            
            $updated++;
        }
        
        $this->db->commitTransaction();
        return $updated;
        
    } catch (Exception $e) {
        $this->db->rollbackTransaction();
        throw $e;
    }
}

/**
 * Валидация правила изменения цен
 */
private function validatePriceRule($rule) {
    // Проверка типа правила
    $valid_types = ['fixed', 'percent_increase', 'percent_decrease', 'round_to', 'formula'];
    if (!in_array($rule['type'], $valid_types)) {
        return false;
    }
    
    // Проверка значения
    if ($rule['type'] !== 'formula' && (!isset($rule['value']) || $rule['value'] === '')) {
        return false;
    }
    
    // Проверка формулы (если применимо)
    if ($rule['type'] === 'formula' && empty($rule['formula'])) {
        return false;
    }
    
    // Проверка фильтра
    $filter = json_decode($rule['filter'], true);
    if (json_last_error() !== JSON_ERROR_NONE || !is_array($filter)) {
        return false;
    }
    
    return true;
}

/**
 * Создание резервной копии цен
 */
private function createPriceBackup($products) {
    $backup_data = [
        'timestamp' => date('Y-m-d H:i:s'),
        'product_count' => count($products),
        'products' => array_map(function($p) {
            return [
                'id' => $p['id'],
                'price' => $p['price'],
                'sku' => $p['sku']
            ];
        }, $products)
    ];
    
    $backup_file = PATH . '/cache/price_backups/' . date('Y-m-d_H-i-s') . '.json';
    file_put_contents($backup_file, json_encode($backup_data, JSON_PRETTY_PRINT));
    
    // Очистка старых бэкапов (> 7 дней)
    $this->cleanupOldBackups(7);
}
```

### Анализ отсутствия блокировки файлов

**Потенциальные причины**:
1. **Идемпотентность операций**: Обновление цен разработано так, чтобы повторное выполнение не приводило к ошибкам
2. **Короткое время выполнения**: Скрипт выполняется достаточно быстро, чтобы избежать наложений
3. **Транзакционная безопасность**: Использование транзакций БД предотвращает частичные обновления
4. **Умышленное разрешение параллелизма**: Возможность одновременного выполнения для распределённых систем

if ($rule['type'] === 'formula' && $product['quantity'] < 10) {

## 22.16. Диагностика и устранение неполадок

### Типичные проблемы и решения

| Проблема | Симптом | Причина | Решение |
|----------|---------|---------|---------|
| **Скрипт не запускается** | Нет записей в логе | Неправильный crontab | Проверить `crontab -l`, права на скрипт |
| **Ошибки подключения к БД** | `Connection refused` | Неверные параметры в `config.php` | Проверить конфигурацию БД |
| **Правила не применяются** | "No active rules" в логе | Правила отключены или вне периода действия | Проверить `is_active`, `start_date`, `end_date` |
| **Цены не обновляются** | "0 prices updated" | Фильтры не находят товары | Проверить условия фильтрации |
| **Слишком большие изменения** | Предупреждения о >50% | Некорректные правила | Проверить формулы и проценты |
| **Таймаут скрипта** | Процесс завершается без результата | Большой каталог без оптимизации | Увеличить `max_execution_time`, добавить чанкирование |

### Пример кастомного алгоритма ценообразования

```php
// /system/controllers/custom_pricing/hooks.php
class custom_pricing {
    /**
     * Динамическое ценообразование на основе спроса
     */
    public function hookShopPriceChanged($product_id, $old_price, $new_price, $rule_id) {
        // Получение данных о спросе
        $demand_data = $this->getDemandMetrics($product_id);
        
        // Расчёт коэффициента спроса (0.8 - 1.5)
        $demand_factor = $this->calculateDemandFactor($demand_data);
        
        // Корректировка цены на основе спроса
        $adjusted_price = $new_price * $demand_factor;
        
        // Обновление цены
        $shop_model = cmsCore::getModel('shop');
        $shop_model->update('shop_products', $product_id, [
            'price' => $adjusted_price,
            'price_adjusted_for_demand' => 1,
            'demand_factor' => $demand_factor
        ]);
        
        error_log(sprintf(
            '[DEMAND PRICING] Product #%d: adjusted price from %.2f to %.2f (factor: %.2f)',
            $product_id,
            $new_price,
            $adjusted_price,
            $demand_factor
        ));
        
        return [$product_id, $old_price, $adjusted_price, $rule_id];
    }
    
    private function getDemandMetrics($product_id) {
        // Анализ просмотров, добавлений в корзину, покупок
        $views = $this->model->getProductViews($product_id, 7); // за 7 дней
        $cart_adds = $this->model->getCartAdds($product_id, 7);
        $purchases = $this->model->getPurchases($product_id, 7);
        
        return [
            'views' => $views,
            'cart_adds' => $cart_adds,
            'purchases' => $purchases,
            'conversion_rate' => $purchases > 0 ? ($purchases / $views * 100) : 0
        ];
    }
    
    private function calculateDemandFactor($metrics) {
        // Базовый коэффициент
        $factor = 1.0;
        
        // Увеличение цены при высоком спросе
        if ($metrics['conversion_rate'] > 5) {
            $factor += 0.1; // +10%
        }
        
        if ($metrics['cart_adds'] > $metrics['purchases'] * 2) {
            $factor += 0.05; // +5% (много добавлений в корзину)
        }
        
        // Снижение цены при низком спросе
        if ($metrics['conversion_rate'] < 1) {
            $factor -= 0.1; // -10%
        }
        
        if ($metrics['views'] < 10) {
            $factor -= 0.05; // -5% (мало просмотров)
        }
        
        // Ограничение в разумных пределах
        $factor = max(0.8, min(1.5, $factor));
        
        return $factor;
    }
}
```
