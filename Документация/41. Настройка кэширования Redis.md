# 41. Настройка кэширования Redis

Данный раздел описывает детальную настройку кэширования с использованием сервера Redis в среде производства (production). Redis обеспечивает высокопроизводительное кэширование в оперативной памяти, что критически важно для высоконагруженных проектов.

---

## 41.1. Архитектурный обзор

### Почему выбирать Redis?

Redis (Remote Dictionary Server) — это высокопроизводительная система кэширования в оперативной памяти с поддержкой различных структур данных. Для платформы DST Platform преимущества очевидны:

| Критерий | Файловое кэширование | Redis |
|----------|---------------------|-------|
| **Скорость** | Миллисекунды | Микросекунды |
| **Масштабируемость** | Ограниченная | Горизонтальное масштабирование |
| **Поддержка кластеров** | Нет | Да |
| **Постоянство данных** | Нет | RDB/AOF |
| **Распределённое кэширование** | Нет | Да |
| **Истечение срока действия (TTL)** | Ограниченное | Гибкое |
| **Транзакции** | Нет | Да |
| **Публикация/подписка** | Нет | Да |
| **Мониторинг** | Базовый | Расширенный |

### Сценарии использования

Redis рекомендуется для:
- **Высоконагруженных проектов** (> 100 запросов в секунду)
- **Распределённых систем** (несколько серверов приложений)
- **Проектов с большим объёмом кэшируемых данных** (> 1 ГБ)
- **Систем, требующих минимальной задержки** (< 10 мс)
- **Проектов с требованиями к отказоустойчивости**

## 41.2. Установка и настройка сервера Redis

### Установка на Ubuntu/Debian

```bash
# Обновление пакетов
sudo apt update

# Установка Redis
sudo apt install redis-server

# Проверка статуса
sudo systemctl status redis-server

# Запуск/остановка
sudo systemctl start redis-server
sudo systemctl stop redis-server
sudo systemctl restart redis-server

# Включение автозапуска
sudo systemctl enable redis-server
```

### Установка на CentOS/RHEL

```bash
# Установка EPEL репозитория
sudo yum install epel-release

# Установка Redis
sudo yum install redis

# Запуск и включение автозапуска
sudo systemctl start redis
sudo systemctl enable redis
```

### Базовая конфигурация Redis

Файл конфигурации: `/etc/redis/redis.conf`

```conf
# Порт (по умолчанию 6379)
port 6379

# Привязка к интерфейсу
bind 127.0.0.1

# Защита от атак (требует пароль для команд)
protected-mode yes

# Пароль для подключения (рекомендуется для продакшена)
requirepass "your_strong_password_here"

# Максимальный объём памяти (пример: 2 ГБ)
maxmemory 2gb

# Политика удаления при достижении лимита
maxmemory-policy allkeys-lru

# Сохранение на диск (RDB)
save 900 1
save 300 10
save 60 10000

# Включение журналирования (AOF)
appendonly yes
appendfsync everysec

# Количество баз данных (по умолчанию 16)
databases 16

# Время жизни соединения (секунды)
timeout 300

# Включение кластерного режима (опционально)
# cluster-enabled yes
# cluster-config-file nodes.conf
# cluster-node-timeout 5000
```

### Рекомендуемые настройки для разных сценариев

| Сценарий | `maxmemory` | `maxmemory-policy` | `appendonly` | `appendfsync` |
|----------|-------------|-------------------|--------------|---------------|
| **Разработка** | 512мб | `volatile-lru` | `no` | — |
| **Тестирование** | 1гб | `allkeys-lru` | `yes` | `everysec` |
| **Production (малый)** | 2гб | `allkeys-lru` | `yes` | `everysec` |
| **Production (средний)** | 4гб | `allkeys-lru` | `yes` | `everysec` |
| **Production (крупный)** | 8гб+ | `allkeys-lru` | `yes` | `everysec` |

### Политики удаления данных

| Политика | Описание | Рекомендуется для |
|----------|----------|-------------------|
| `noeviction` | Возвращает ошибку при достижении лимита | Не рекомендуется |
| `allkeys-lru` | Удаляет наименее используемые ключи | Большинство сценариев |
| `volatile-lru` | Удаляет наименее используемые ключи с TTL | Смешанное кэширование |
| `allkeys-random` | Случайное удаление ключей | Редко |
| `volatile-random` | Случайное удаление ключей с TTL | Редко |
| `volatile-ttl` | Удаляет ключи с ближайшим истечением | Специфические случаи |

## 41.5. Использование кэширования в компонентах

### Базовые операции

```php
// Получение экземпляра кэша
$cache = cmsCache::getInstance();

// Сохранение данных
$cache->set('my_key', 'my_value', 3600); // TTL 1 час

// Получение данных
$value = $cache->get('my_key');

// Проверка существования ключа
if ($cache->has('my_key')) {
    // Ключ существует
}

// Удаление ключа
$cache->delete('my_key');

// Очистка всего кэша
$cache->clear();

// Увеличение значения
$cache->increment('counter', 1);

// Уменьшение значения
$cache->decrement('counter', 1);
```

### Кэширование с использованием тегов

```php
// Сохранение с тегами
$item = $cache->getItem('user_profile_123');
$item->set($profile_data);
$item->expiresAfter(3600);
$item->addTag('user_123');
$item->addTag('profiles');
$cache->save($item);

// Удаление по тегу
$cache->deleteByTag('user_123');
$cache->deleteByTag('profiles');

// Удаление по нескольким тегам
$cache->deleteByTags(['user_123', 'admin']);
```

### Условное кэширование

```php
// Проверка наличия кэша перед вычислениями
if (!$cache->has('expensive_calculation')) {
    $result = $this->performExpensiveCalculation();
    $cache->set('expensive_calculation', $result, 86400); // 24 часа
} else {
    $result = $cache->get('expensive_calculation');
}

// Альтернативный подход с проверкой
$result = $cache->get('expensive_calculation');
if ($result === false) {
    $result = $this->performExpensiveCalculation();
    $cache->set('expensive_calculation', $result, 86400);
}
```

### Кэширование в моделях

```php
// /system/controllers/shop/model.php
class modelShop extends cmsModel {
    
    /**
     * Получение товаров с кэшированием
     */
    public function getProducts($category_id, $limit = 20) {
        // Генерация ключа кэша
        $cache_key = 'shop_products_' . $category_id . '_' . $limit;
        
        // Попытка получить из кэша
        $cached = cmsCache::getInstance()->get($cache_key);
        if ($cached !== false) {
            return $cached;
        }
        
        // Запрос к БД
        $products = $this->select('shop_products')
            ->filterEqual('category_id', $category_id)
            ->filterEqual('is_published', 1)
            ->orderBy('date_pub', 'DESC')
            ->limit($limit)
            ->getItems();
        
        // Сохранение в кэш (1 час)
        cmsCache::getInstance()->set($cache_key, $products, 3600);
        
        return $products;
    }
    
    /**
     * Инвалидация кэша при обновлении товара
     */
    public function updateProduct($id, $data) {
        $result = parent::update('shop_products', $id, $data);
        
        if ($result) {
            // Очистка кэша
            $cache = cmsCache::getInstance();
            $cache->delete('shop_product_' . $id);
            $cache->deleteByPattern('shop_products_*');
        }
        
        return $result;
    }
}
```

## 41.6. Мониторинг и диагностика

### Проверка подключения к Redis

```php
// Тестовый скрипт: test_redis.php
<?php
require_once 'bootstrap.php';

try {
    $cache = cmsCache::getInstance();
    
    // Тестовая запись
    $test_key = 'redis_test_' . time();
    $cache->set($test_key, 'test_value', 60);
    
    // Тестовое чтение
    $value = $cache->get($test_key);
    
    if ($value === 'test_value') {
        echo "✓ Redis подключен и работает корректно\n";
        
        // Информация о сервере
        $info = $cache->getStats();
        if ($info) {
            echo "\nСтатистика сервера Redis:\n";
```

### Интеграция с системой мониторинга

```php
// /system/controllers/monitoring/hooks.php
class monitoring extends cmsAction {
    
    /**
     * Хук для сбора метрик Redis
     */
    public function hookSystemMetricsCollect($metrics) {
        try {
            $cache = cmsCache::getInstance();
            $info = $cache->getStats();
            
            if ($info) {
                $metrics['redis'] = [
                    'status' => 'ok',
                    'version' => $info['redis_version'],
                    'memory_used' => $info['used_memory_human'],
                    'keys_count' => $info['db0']['keys'] ?? 0,
                    'connected_clients' => $info['connected_clients'],
                    'hits' => $info['keyspace_hits'] ?? 0,
                    'misses' => $info['keyspace_misses'] ?? 0,
                    'hit_rate' => $this->calculateHitRate($info)
                ];
            }
        } catch (Exception $e) {
            $metrics['redis'] = [
                'status' => 'error',
                'error' => $e->getMessage()
            ];
        }
        
        return $metrics;
    }
    
    /**
     * Расчёт процента попаданий в кэш
     */
    private function calculateHitRate($info) {
        $hits = $info['keyspace_hits'] ?? 0;
        $misses = $info['keyspace_misses'] ?? 0;
        $total = $hits + $misses;
        
        return $total > 0 ? round(($hits / $total) * 100, 2) : 0;
    }
}
```

## 41.7. Оптимизация производительности

### Стратегии кэширования

| Тип данных | Рекомендуемый TTL | Стратегия |
|------------|-------------------|-----------|
| **Статическая конфигурация** | 1-24 часа | Долгосрочное кэширование |
| **Данные о продуктах** | 5-30 минут | Среднесрочное кэширование |
| **Списки категорий** | 10-60 минут | Среднесрочное кэширование |
| **Пользовательские сессии** | Срок действия сессии | Привязано к аутентификации |
| **Результаты поиска** | 1-10 минут | Краткосрочное кэширование |
| **Страницы (полный HTML)** | 5-15 минут | Для анонимных пользователей |

### Пакетное кэширование

```php
// Пакетное получение данных
$keys = ['key1', 'key2', 'key3', 'key4'];
$items = cmsCache::getInstance()->getMultiple($keys);

foreach ($items as $key => $value) {
    if ($value === null) {
        // Кэш промахнулся, нужно загрузить данные
        $data = $this->loadData($key);
        cmsCache::getInstance()->set($key, $data, 3600);
    }
}

// Пакетное сохранение
$data_to_cache = [
    'key1' => $value1,
    'key2' => $value2,
    'key3' => $value3
];
cmsCache::getInstance()->setMultiple($data_to_cache, 3600);
```

### Кэширование с фрагментацией

```php
/**
 * Кэширование больших данных с фрагментацией
 */
class FragmentedCache {
    private $cache;
    private $fragment_size = 1024 * 1024; // 1 МБ
    
    public function __construct($cache) {
        $this->cache = $cache;
    }
    
    /**
     * Сохранение большого объекта с фрагментацией
     */
    public function set($key, $data, $ttl = 3600) {
        $serialized = serialize($data);
        $total_size = strlen($serialized);
        $num_fragments = ceil($total_size / $this->fragment_size);
        
        // Сохранение метаданных
        $this->cache->set($key . '_meta', [
            'size' => $total_size,
            'fragments' => $num_fragments,
            'ttl' => $ttl
        ], $ttl);
        
        // Сохранение фрагментов
        for ($i = 0; $i < $num_fragments; $i++) {
            $start = $i * $this->fragment_size;
            $fragment = substr($serialized, $start, $this->fragment_size);
            $this->cache->set($key . '_frag_' . $i, $fragment, $ttl);
        }
    }
    
    /**
     * Получение большого объекта
     */
    public function get($key) {
        $meta = $this->cache->get($key . '_meta');
        if (!$meta) {
            return false;
        }
        
        $fragments = [];
        for ($i = 0; $i < $meta['fragments']; $i++) {
            $fragment = $this->cache->get($key . '_frag_' . $i);
            if ($fragment === false) {
                return false;
            }
            $fragments[] = $fragment;
        }
        
        $serialized = implode('', $fragments);
        return unserialize($serialized);
    }
}
```

## 41.8. Решение распространённых проблем

### Проблема: "Не удаётся подключиться к Redis"

**Симптомы:**
```
Connection refused
Connection timeout
```

**Решение:**
```bash
# 1. Проверка статуса сервиса
sudo systemctl status redis-server

# 2. Проверка порта
sudo netstat -tlnp | grep 6379

# 3. Проверка конфигурации
sudo redis-cli ping  # Должен вернуть "PONG"

# 4. Проверка брандмауэра
sudo ufw status
sudo ufw allow 6379/tcp

# 5. Проверка конфигурации Redis
sudo grep "bind" /etc/redis/redis.conf
sudo grep "protected-mode" /etc/redis/redis.conf
```

### Проблема: "Недостаточно памяти"

**Симптомы:**
```
OOM command not allowed when used memory > 'maxmemory'
```

**Решение:**
```bash
# 1. Проверка использования памяти
redis-cli info memory

# 2. Увеличение лимита памяти в /etc/redis/redis.conf
maxmemory 4gb

# 3. Оптимизация политики удаления
maxmemory-policy allkeys-lru

# 4. Перезапуск Redis
sudo systemctl restart redis-server

# 5. Очистка кэша (временное решение)
redis-cli flushdb
```

### Проблема: "Низкий процент попаданий в кэш"

**Симптомы:**
- Процент попаданий < 70%
- Высокая нагрузка на БД

**Решение:**
```php
// 1. Анализ ключей кэша
$cache = cmsCache::getInstance();
$stats = $cache->getStats();

echo "Попаданий: " . ($stats['keyspace_hits'] ?? 0) . "\n";
echo "Промахов: " . ($stats['keyspace_misses'] ?? 0) . "\n";

// 2. Оптимизация стратегии кэширования
// Увеличение TTL для часто используемых данных
// Добавление кэширования для тяжёлых запросов

// 3. Мониторинг ключей
redis-cli --bigkeys  # Поиск больших ключей
redis-cli monitor     # Анализ запросов в реальном времени
```

### Проблема: "Утечка памяти"

**Симптомы:**
- Постоянное увеличение использования памяти
- Redis использует всю доступную память

**Решение:**
```bash
# 1. Анализ ключей
redis-cli --bigkeys

# 2. Поиск ключей без TTL
redis-cli keys "*" | while read key; do
    ttl=$(redis-cli ttl "$key")
    if [ "$ttl" = "-1" ]; then
        echo "Ключ без TTL: $key"
    fi
done

# 3. Установка TTL для всех ключей
redis-cli keys "*" | while read key; do
    redis-cli expire "$key" 3600
done

# 4. Настройка автоматического удаления
# В /etc/redis/redis.conf:
maxmemory-policy allkeys-lru
```

## 41.9. Безопасность Redis

### Рекомендуемые меры безопасности

```conf
# /etc/redis/redis.conf

# 1. Требование пароля
requirepass "your_strong_password_here"

# 2. Ограничение привязки к интерфейсу
bind 127.0.0.1

# 3. Включение защищённого режима
protected-mode yes

# 4. Ограничение команд (опционально)
rename-command FLUSHDB ""
rename-command FLUSHALL ""
rename-command CONFIG ""

# 5. Настройка SSL/TLS (для удалённых подключений)
tls-port 6380
tls-cert-file /etc/redis/redis.crt
tls-key-file /etc/redis/redis.key
tls-ca-cert-file /etc/redis/ca.crt
```

## 41.10. Резервное копирование и восстановление

### Автоматическое резервное копирование

```bash
#!/bin/bash
# backup_redis.sh

BACKUP_DIR="/var/backups/redis"
DATE=$(date +%Y%m%d_%H%M%S)
BACKUP_FILE="$BACKUP_DIR/redis_backup_$DATE.rdb"

# Создание директории для бэкапов
mkdir -p $BACKUP_DIR

# Создание бэкапа
redis-cli BGSAVE
cp /var/lib/redis/dump.rdb $BACKUP_FILE

# Сжатие бэкапа
gzip $BACKUP_FILE

# Удаление старых бэкапов (старше 7 дней)
find $BACKUP_DIR -name "redis_backup_*.rdb.gz" -mtime +7 -delete

echo "Backup created: $BACKUP_FILE.gz"
```

### Настройка cron для автоматического бэкапа

```bash
# Ежедневный бэкап в 3:00
0 3 * * * /path/to/backup_redis.sh

# Еженедельный бэкап в воскресенье в 2:00
0 2 * * 0 /path/to/backup_redis.sh
```

### Восстановление из бэкапа

```bash
#!/bin/bash
# restore_redis.sh

BACKUP_FILE="/var/backups/redis/redis_backup_20240115_030000.rdb.gz"
REDIS_DATA_DIR="/var/lib/redis"

# Остановка Redis
sudo systemctl stop redis-server

# Распаковка бэкапа
gunzip -c $BACKUP_FILE > $REDIS_DATA_DIR/dump.rdb

# Изменение владельца
sudo chown redis:redis $REDIS_DATA_DIR/dump.rdb

# Запуск Redis
sudo systemctl start redis-server

echo "Redis restored from $BACKUP_FILE"
```

## 41.11. Миграция с файлового кэширования на Redis

### Пошаговая миграция

```bash
# 1. Установка Redis (см. раздел 41.13.2)
sudo apt install redis-server

# 2. Настройка Redis (см. раздел 41.13.2)
sudo nano /etc/redis/redis.conf

# 3. Запуск и проверка Redis
sudo systemctl start redis-server
redis-cli ping  # Должен вернуть "PONG"

# 4. Установка PHP расширения
sudo apt install php-redis

# 5. Обновление конфигурации платформы
# Изменить /system/config/config.php:
# 'driver' => 'redis' вместо 'files'

# 6. Тестирование подключения
php test_redis.php

# 7. Очистка старого кэша
rm -rf /path/to/cache/*

# 8. Мониторинг после миграции
redis-cli monitor
```

### Скрипт миграции данных (опционально)

```php
<?php
/**
 * migrate_cache.php
 * Миграция данных из файлового кэша в Redis
 */

require_once 'bootstrap.php';

$old_cache_path = PATH . '/cache';
$new_cache = cmsCache::getInstance();

// Сканирование файлов кэша
$files = glob($old_cache_path . '/*.{php,json,txt}', GLOB_BRACE);

$migrated = 0;
$failed = 0;

foreach ($files as $file) {
    $key = basename($file);
    
    try {
        // Чтение данных из файла
        $data = file_get_contents($file);
        
        // Определение формата
        $ext = pathinfo($file, PATHINFO_EXTENSION);
        if ($ext === 'php') {
            $value = include $file;
        } elseif ($ext === 'json') {
            $value = json_decode($data, true);
        } else {
            $value = $data;
        }
        
        // Сохранение в Redis
        if ($value !== false) {
            $new_cache->set($key, $value, 3600);
            $migrated++;
        }
    } catch (Exception $e) {
        error_log("Ошибка миграции $key: " . $e->getMessage());
        $failed++;
    }
}

echo "Миграция завершена:\n";
echo "Успешно: $migrated\n";
echo "Ошибок: $failed\n";
?>
```
