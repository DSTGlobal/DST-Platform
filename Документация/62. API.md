# Часть I. Введение и обзор

## 62.1. Назначение и область применения

Компонент `api` реализует лёгкий REST-интерфейс между DST Platform и внешними потребителями: мобильными приложениями, сторонними сайтами, сервисами синхронизации (1С, CRM), микросервисами и внутренними фоновыми задачами.

API **не дублирует** бизнес-логику компонентов, а выступает тонким адаптером: он принимает HTTP-запрос, валидирует его, вызывает действие (action) соответствующего компонента и формирует JSON-ответ. Это следует принципам, заложенным в архитектуре платформы (см. раздел *«Базовая архитектура»*): компонент владеет своей логикой, API — лишь точка входа.

| Характеристика | Реализация |
|---|---|
| Формат ответа | **Только JSON** (UTF-8, RFC 8259) |
| Протокол | HTTP/1.1 и HTTP/2, только через HTTPS в продакшене |
| Методы | GET, POST (для операций чтения и записи соответственно) |
| Точки входа | `/api/method/{METHOD_NAME}` и `/api/execute` |
| Аутентификация | API-ключ (`api_key`), опционально — подпись (`sig`), IP-фильтр, CSRF |
| Логирование | Встроенное, с фильтрацией по методу, ключу, IP, коду ошибки |

> ⚠️ **Только JSON.** Даже при ошибке 404 или 500 ответ формируется в JSON — это упрощает обработку на клиенте. Партнёры, ожидающие HTML-ошибки, должны быть предупреждены.

## 62.2. Ключевые преимущества

| Преимущество | Что это даёт интегратору |
|---|---|
| **Единая точка входа** | Один базовый URL для всех методов — упрощает конфигурацию клиента |
| **Универсальный `execute`** | Пакетная отправка до N методов за один HTTP-запрос — снижает round-trip latency |
| **Удобная обработка ошибок** | Всегда HTTP 200, ошибка в теле — детерминированная обработка на клиенте |
| **Логирование из коробки** | Прозрачная диагностика на стороне платформы (см. 62.6) |
| **Автоматическая валидация** | Параметры проверяются ядром (`cmsRequest`, `cmsForm`) до бизнес-логики |
| **Модульность** | Метод принадлежит компоненту — границы ответственности очевидны |
| **Совместимость с платформенной моделью** | Права доступа, события, кэш работают так же, как в вебе |

## 62.4. Терминология и соглашения

| Термин | Значение |
|---|---|
| **Метод API** | Идентификатор вида `content.get.news` |
| **Контроллер** | Компонент платформы (первая часть имени метода) |
| **Действие (action)** | Вторая часть имени метода |
| **CTYPE** | Тип контента (третья, опциональная часть) |
| **Ключ API** | `api_key` — 32-символьный идентификатор клиента |
| **Подпись** | `sig` — HMAC-подпись запроса (опционально) |
| **`execute`** | Универсальный метод пакетного вызова |
| **`paging`** | Блок метаданных пагинации в ответе |

**Соглашения по именованию параметров:** `snake_case` (`per_page`, `date_from`, `show_all`). Временные метки — `Y-m-d H:i:s` (UTC) либо UNIX timestamp, если явно указано в описании метода.

# Часть II. Руководство для внешних разработчиков

## 62.5. Быстрый старт

**Шаг 1. Получите ключ.** Админка → **Компоненты** → **API** → **Ключи доступа** → **Создать**. Ключ генерируется автоматически (32 символа), его можно изменить и ограничить по IP и методам.

**Шаг 2. Выполните тестовый запрос.**

```bash
curl -s "https://example.com/api/method/content.get.news?api_key=ВАШ_КЛЮЧ&per_page=3"
```

**Шаг 3. Разберите ответ.**

```json
{
  "success": true,
  "result": {
    "count": 42,
    "items": [
      { "id": 101, "title": "Новость 1", "date_pub": "2024-01-15 14:30:00" }
    ]
  },
  "paging": { "page": 1, "per_page": 3, "has_next": true }
}
```

**Шаг 4. Проверьте ошибку.**

```bash
curl -s "https://example.com/api/method/content.get.news?api_key=INVALID"
```

```json
{ "error": { "error_code": 101, "error_msg": "Неверный ключ доступа", "request_params": [] } }
```

> 💡 **Совет.** Настройте логирование успешных и ошибочных запросов (см. 62.6), прежде чем передавать ключ мобильной команде — это сократит цикл диагностики с часов до минут.

## 62.6. Настройка и конфигурация

**Установка:** Админка → **Компоненты** → **Установить** → **API** → **Установить**.

**Настройки компонента** (`/system/controllers/api/options.form.php`):

| Параметр | Назначение | Рекомендация для продакшена |
|---|---|---|
| `enable_logging` | Логировать запросы | **вкл** |
| `log_errors` | Логировать только ошибки | выкл (если включено полное) |
| `log_success` | Логировать успешные | вкл на старте, далее — по необходимости |
| `log_retention_days` | Хранить логи (дней) | 30 |
| `max_log_size` | Максимум записей | 100 000 |
| `enable_sig_check` | Требовать `sig` | **вкл** для write-методов |
| `rate_limit_per_minute` | Лимит запросов/мин с одного ключа | 100–300 |
| `allowed_origins` | CORS-allowlist | Только доверенные домены |

| Поле | Назначение |

## 62.7. Аутентификация и безопасность

### 62.7.1. Механизмы и уровни защиты

| Механизм | Обязательность | Уровень | Где задаётся |
|---|---|---|---|
| **API-ключ** | всегда | базовый | Админка → API → Ключи |
| **IP-фильтр** | опционально | средний | Поле ключа |
| **HMAC-подпись (`sig`)** | рекомендуется для write | высокий | `enable_sig_check` |
| **CSRF-токен** | для write-методов | высокий | Автоматически |
| **HTTPS** | обязательно в продакшене | критический | Веб-сервер |

### 62.7.2. Передача ключа

Ключ может передаваться **тремя способами** (в порядке убывания предпочтения):

1. **Заголовок** `Authorization: Bearer <api_key>` — **рекомендуется** (не попадает в логи прокси и access-log).
2. **Заголовок** `X-API-Key: <api_key>` — альтернатива.
3. **Параметр запроса** `?api_key=...` — допустимо только для read-методов по HTTPS.

```bash
# Предпочтительно
curl -H "Authorization: Bearer a1b2c3d4e5f6..." \
     "https://example.com/api/method/content.get.news"

# Допустимо
curl -H "X-API-Key: a1b2c3d4e5f6..." \
     "https://example.com/api/method/content.get.news"

# Не рекомендуется (но поддерживается)
curl "https://example.com/api/method/content.get.news?api_key=a1b2c3d4e5f6..."
```

> ❌ **Никогда** не передавайте ключ в URL без HTTPS: он попадёт в access-log веб-сервера, логи прокси и историю браузера.

### 62.7.3. IP-фильтрация

Если в ключе задан список IP, платформа принимает запрос только с этих адресов. Для определения реального IP за прокси/балансировщиком передавайте параметр `ip` (см. 62.15) **или** настройте доверенные прокси на веб-сервере.

### 62.7.4. HMAC-подпись (`sig`)

Для критичных методов (платежи, изменение данных, выдача персональных данных) используйте подпись. Механизм построен на **HMAC-SHA256** и сравнении за постоянное время (`hash_equals`) — см. раздел *«Вопросы безопасности»*.

**Формула:**

```
sig = HMAC_SHA256(secret, METHOD_NAME + "\n" + canonical_query + "\n" + timestamp)
```

где `canonical_query` — отсортированные по имени параметры `name=value`, склеенные через `&`, **без** `api_key` и `sig`.

**Пример на PHP:**

```php
function buildSig(string $secret, string $method, array $params, int $ts): string {
    unset($params['api_key'], $params['sig']);
    ksort($params);
    $pairs = [];
    foreach ($params as $k => $v) {
        $pairs[] = rawurlencode($k) . '=' . rawurlencode((string)$v);
    }
    $canonical = $method . "\n" . implode('&', $pairs) . "\n" . $ts;
    return hash_hmac('sha256', $canonical, $secret);
}

$ts  = time();
$sig = buildSig($secret, 'content.add_item.news', ['title' => 'Привет'], $ts);
// В запросе передайте: sig=$sig&ts=$ts
```

**Пример на JavaScript (Node.js):**

```js
const crypto = require('crypto');

function buildSig(secret, method, params, ts) {
  const { api_key, sig, ...rest } = params;
  const canonical = Object.keys(rest).sort()
    .map(k => encodeURIComponent(k) + '=' + encodeURIComponent(rest[k]))
    .join('&');
  const payload = `${method}\n${canonical}\n${ts}`;
  return crypto.createHmac('sha256', secret).update(payload).digest('hex');
}
```

**Проверка на сервере** (в `api_actions`):

```php
if ($this->check_sig) {
    $ts = (int)$this->request->get('ts', 0);
    if (abs(time() - $ts) > 300) { // окно 5 минут
        return $this->error(115, 'Просроченная подпись (ts)');
    }
    $expected = buildSig($this->api_secret, $this->method_name, $this->request->getAll(), $ts);
    if (!hash_equals($expected, (string)$this->request->get('sig', ''))) {
        return $this->error(115, 'Неверная подпись');
    }
}
```

### 62.7.5. CSRF-токен

Для методов, изменяющих состояние (`*.add_*`, `*.update_*`, `*.delete_*`), платформа может требовать CSRF-токен. Получите его через метод `users.get_sig` или из ответа метода, возвращающего форму. Передавайте в заголовке `X-CSRF-Token` **или** параметром `csrf_token`.

Валидация выполняется через `hash_equals`, как описано в разделе *«Вопросы безопасности»* (62.7 → CSRF).

## 62.8. Синтаксис запросов

### 62.8.1. Базовый URL

```
https://<host>/api/method/<METHOD_NAME>?<PARAMS>
https://<host>/api/execute?<PARAMS>
```

### 62.8.2. Структура `METHOD_NAME`

```
<component>.<action>[.<ctype>]
```

| Часть | Обязательность | Пример |
|---|---|---|
| `component` | да | `content`, `shop`, `users` |
| `action` | да | `get`, `add_item`, `update_item` |
| `ctype` | опционально | `news`, `articles`, `products` |

**Пример:** `content.get_datasets.articles` — компонент `content`, действие `get_datasets`, тип контента `articles`.

### 62.8.3. Параметры

| Группа | Где | Пример |
|---|---|---|
| Параметры метода | query / body | `page=2&per_page=10` |
| Ключ | header / query / body | `api_key=...` |
| Подпись | query / body | `sig=...&ts=...` |
| IP клиента | query / body | `ip=8.8.8.8` |

**Правила:**

- Значения — **UTF-8**.
- GET — до ~2 КБ; при больших данных — **POST** с `Content-Type: application/json` или `application/x-www-form-urlencoded`.
- Вложенные структуры передаются JSON-сериализованно (`items=[{...}]`).
- Булевы значения: `1/0`, `true/false`, `yes/no`.

### 62.8.4. Примеры

**GET (чтение):**

```bash
curl -s "https://example.com/api/method/content.get_datasets.articles?api_key=KEY&show_all=1"
```

**POST (запись, JSON):**

```bash
curl -s -X POST "https://example.com/api/method/shop.add_order" \
  -H "Authorization: Bearer KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotence-Key: $(uuidgen)" \
  -d '{
    "user_id": 123,
    "items": [
      {"product_id": 456, "quantity": 2},
      {"product_id": 789, "quantity": 1}
    ]
  }'
```

**POST (запись, form-urlencoded):**

```bash
curl -s -X POST "https://example.com/api/method/content.add_item.news" \
  -H "Authorization: Bearer KEY" \
  -d "title=Заголовок&content=Текст&is_published=1"
```

### 62.8.5. Идемпотентность

Для `*.add_*` используйте заголовок `Idempotence-Key` (по аналогии с YooKassa, см. раздел *«Интеграция платежного шлюза»*). Повторный запрос с тем же ключом вернёт тот же результат без создания дубликата.

```bash
curl -X POST "https://example.com/api/method/shop.add_order" \
  -H "Authorization: Bearer KEY" \
  -H "Idempotence-Key: order-2024-01-15-001" \
  -d '{...}'
```

## 62.9. Формат ответов

### 62.9.1. Успешный ответ

```json
{
  "success": true,
  "result": { ... },
  "paging": { "page": 1, "per_page": 20, "has_next": true }
}
```

| Поле | Наличие | Описание |
|---|---|---|
| `success` | всегда | `true` |
| `result` | всегда | Данные метода (объект/массив/скаляр) |
| `paging` | при списках | Метаданные пагинации |
| `meta` | опционально | Доп. данные (время генерации, версия API) |

### 62.9.2. Ответ с ошибкой

```json
{
  "error": {
    "error_code": 101,
    "error_msg": "Неверный ключ доступа",
    "request_params": [
      { "key": "method", "value": "content.get.news" }
    ]
  }
}
```

**Всегда HTTP 200.** Клиент обязан проверять наличие поля `error` в теле — это отличает ошибку от успеха. Такой подход выбран осознанно: он упрощает обработку на мобильных клиентах, где перехват HTTP-кодов не всегда удобен.

| Поле | Описание |
|---|---|

## 62.14. Универсальный метод `execute`

Позволяет выполнить несколько методов за один HTTP-запрос, сохраняя промежуточные результаты.

**Формат:** `GET /api/execute?code=<JSON-encoded-array>&api_key=...`

**Структура `code`:**

```json
[
  { "method": "content.get.news", "params": { "page": 1 } },
  { "method": "shop.get_cart", "params": {} }
]
```

**Пример:**

```bash
curl -G "https://example.com/api/execute" \
  --data-urlencode 'code=[{"method":"content.get.news","params":{"page":1}},{"method":"shop.get_cart"}]' \
  --data-urlencode 'api_key=KEY'
```

**Ответ:**

```json
{
  "success": true,
  "result": [
    { "method": "content.get.news", "result": { "count": 10, "items": [ ... ] } },
    { "method": "shop.get_cart", "result": { "items_count": 3, "total": 4500 } }
  ]
}
```

**Ограничения и правила:**

| Параметр | Значение |
|---|---|
| Максимум методов в пакете | 20 |
| Общий таймаут | 30 секунд |
| Вложенный `execute` | **запрещён** |
| Write-методы в пакете | разрешены (каждый получает свой CSRF/sig) |
| Частичная ошибка | если один метод упал, остальные выполняются; в `result` будет `error` для упавшего |

**Пример с частичной ошибкой:**

```json
{
  "success": true,
  "result": [
    { "method": "content.get.news", "result": { ... } },
    { "method": "shop.get_cart", "error": { "error_code": 71, "error_msg": "Требуется авторизация" } }
  ]
}
```

> ⚠️ **JSON должен быть валидным по RFC 8259.** Никаких одинарных кавычек, завершающих запятых, комментариев. Это частая причина ошибки `8` («Неверный запрос»).

## 62.15. Определение IP посетителя

Если запросы к API идут с одного сервера (например, backend-скрипт), но нужно, чтобы платформа видела **реальный IP конечного пользователя** (для геолокации, антифрода, rate limiting), передайте его параметром `ip`:

```bash
curl "https://example.com/api/method/geo.get_current_country?api_key=KEY&ip=8.8.8.8"
```

**Правила:**

- Параметр `ip` **учитывается только** если запрос пришёл с IP, входящего в белый список «доверенных прокси» (настраивается в компоненте).
- Значение валидируется (`filter_var(..., FILTER_VALIDATE_IP)`).
- Неверный IP → код `777`.

## 62.16. Версионирование и обратная совместимость

### 62.16.1. Стратегия версионирования

API DST Platform **не использует URL-версионирование** (`/v1/`, `/v2/`). Вместо этого применяется **эволюционное версионирование методов**:

- Новые поля добавляются в ответы — **без** ломания существующих клиентов.
- Удаление полей и изменение типов — **только** через новую версию метода (`content.get.news_v2`) при сохранении старого.
- Изменение поведения — через флаг (`deprecated=true` в ответе + HTTP-заголовок `Warning: 299 - "Deprecated method"`).

### 62.16.2. Гарантии обратной совместимости

| Изменение | Совместимо | Комментарий |
|---|---|---|
| Добавление поля в `result` | ✅ | Клиенты должны игнорировать незнакомые поля |
| Добавление нового метода | ✅ | Не влияет на существующие |
| Добавление необязательного параметра | ✅ | — |
| Удаление поля | ❌ | Только через `_v2` |
| Изменение типа поля | ❌ | Только через `_v2` |
| Изменение кода ошибки | ⚠️ | Считается breaking change |
| Изменение семантики параметра | ❌ | Только через `_v2` |

### 62.16.3. Политика deprecated

Метод помечается как `deprecated` минимум за **6 месяцев** до удаления. В ответе появляется:

```json
{
  "success": true,
  "result": { ... },
  "meta": { "deprecated": true, "sunset": "2025-12-31" }
}
```

Заголовок: `Warning: 299 - "This method is deprecated and will be removed on 2025-12-31"`.

### 62.16.4. Рекомендации клиентам

1. **Всегда** игнорируйте неизвестные поля в ответе.
2. Не полагайтесь на порядок полей в JSON.
3. Обрабатывайте `meta.deprecated` и переключайтесь на новую версию заранее.
4. Логируйте `Warning`-заголовки — они сигнализируют о скором breaking change.

## 62.17. Rate limiting

### 62.17.1. Механизм

Ограничение частоты реализовано через `cmsCache` (Redis/Memcached) — см. раздел *«Вопросы безопасности»*. Лимит задаётся на ключ и на IP.

| Уровень | По умолчанию | Настраивается |
|---|---|---|
| На ключ | 100 запросов/мин | `rate_limit_per_minute` |
| На IP | 300 запросов/мин | Глобально |
| На `execute` | 20 методов/запрос | Жёстко |
| На метод (индивидуально) | — | В `api_docs/*.json` |

### 62.17.2. Заголовки ответа

При каждом запросе платформа возвращает:

```
X-RateLimit-Limit: 100
X-RateLimit-Remaining: 47
X-RateLimit-Reset: 1700000060
Retry-After: 30          (только при 429)
```

### 62.17.3. Обработка на клиенте

При получении `error_code: 429`:

1. Прочитайте `Retry-After`.
2. Подождите указанное время **или** примените **экспоненциальный backoff** (как в разделе *«Интеграция платежного шлюза»*).

```php
function callWithRetry(callable $fn, int $maxRetries = 5): mixed {
    $attempt = 0;
    while (true) {
        try {
            $result = $fn();
            if (isset($result['error']) && $result['error']['error_code'] === 429) {
                throw new RateLimitException($result['error']['error_msg']);
            }
            return $result;
        } catch (RateLimitException $e) {
            if (++$attempt > $maxRetries) throw $e;
            $delay = min(60, 2 ** $attempt); // 2, 4, 8, 16, 32 сек
            sleep($delay);
        }
    }
}
```

### 62.17.4. Лучшие практики

- **Не ретрайте** на `4xx`, кроме `429`.
- Ретрайте на `5xx` и сетевые ошибки — с backoff.
- Ограничивайте общий бюджет ретраев (например, 5 минут).
- Используйте идемпотентные ключи (`Idempotence-Key`) для write-методов при ретраях.

## 62.18. Кэширование ответов

### 62.18.1. Серверное кэширование

Для тяжёлых list-методов (`content.get.*`, `shop.get_products`) платформа кэширует ответы через `cmsCache`. Управление — в `api_docs/*.json`:

```json
{
  "method": "content.get.news",
  "cache_ttl": 300,
  "cache_key_params": ["page", "per_page", "filter"]
}
```

`cache_ttl` — время жизни в секундах. При изменении контента кэш инвалидируется через хуки (см. 62.24).

### 62.18.2. HTTP-кэширование

Платформа возвращает заголовки:

```
Cache-Control: private, max-age=60
ETag: "abc123"
Last-Modified: Mon, 15 Jan 2024 14:30:00 GMT
```

Клиент может использовать **условные запросы**:

```bash
curl -H "If-None-Match: \"abc123\"" \
     "https://example.com/api/method/content.get.news?api_key=KEY"
# → 304 Not Modified, тело пустое
```

### 62.18.3. Рекомендации клиентам

- Для справочников (страны, регионы, категории) — кэшируйте на клиенте надолго (часы/дни).
- Для списков товаров — 1–5 минут.
- Для карточек — до 1 часа.
- Для корзины/заказов — **не кэшируйте**.

## 62.19. Асинхронные операции и очереди

### 62.19.1. Долгие операции

Ряд методов (экспорт каталога, массовое обновление цен, генерация YML) не могут выполняться синхронно за разумное время. Для них используется **асинхронный паттерн** (тот же, что в вебхуках YooKassa, см. раздел *«Интеграция платежного шлюза»*):

1. Клиент вызывает метод (`shop.export_start`).
2. Платформа создаёт задачу в очереди и **немедленно** возвращает `task_id`.
3. Клиент периодически опрашивает `shop.export_status?task_id=...` **или** получает вебхук по завершении.

**Пример:**

```bash
# 1. Запуск
curl -X POST "https://example.com/api/method/shop.export_start" \
  -H "Authorization: Bearer KEY" \
  -d '{"type":"products","format":"xlsx"}'
```

```json
{ "success": true, "result": { "task_id": "task_a1b2c3d4", "status": "queued" } }
```

```bash
# 2. Опрос
curl "https://example.com/api/method/shop.export_status?task_id=task_a1b2c3d4&api_key=KEY"
```

```json
{
  "success": true,
  "result": {
    "task_id": "task_a1b2c3d4",
    "status": "completed",
    "progress": 100,
    "file_url": "/upload/exports/products_2024-01-15.xlsx",
    "created_at": "2024-01-15 14:30:00",
    "completed_at": "2024-01-15 14:32:11"
  }
}
```

**Статусы:** `queued` → `running` → `completed` / `failed`. При `failed` — поле `error`.

### 62.19.2. Исходящие вебхуки: готовые модули и паттерн для собственных методов

**Что уже есть в платформе.** Исходящие уведомления (вебхуки) реализованы в готовых модулях интеграции:

| Модуль | Тип уведомлений | Механизм проверки |
|---|---|---|
| **ЮKassa** | `payment.succeeded`, `payment.canceled`, `refund.succeeded` | IP-фильтр + `Idempotence-Key` |
| **Robokassa** | `ResultURL` (успех/неудача) | `SignatureValue` (MD5) |
| **Т-Банк** | `payment`, `refund` | `Token` (SHA-256 от параметров + пароль) |
| **CDEK** | `ORDER_STATUS`, `DELIVERY_STATUS` | `X-Cdek-Signature` |
| **Деловые Линии** | `StatusChange` | Проверка по IP + токен |
| **5Post** | `order.status` | HMAC |
| **DeepSeek** | Синхронный API (вебхуки не используются) | — |

**Чего нет в платформе «из коробки».** Универсального метода `webhooks.register` для клиентских интеграций пока нет. Если ваш проект требует собственных исходящих уведомлений (например, «уведомить внешнюю систему о новом заказе»), реализуйте их **по образцу готовых модулей**.

### Паттерн для собственных методов

**Шаг 1. Таблица подписок** (`my_webhooks`):

| Поле | Тип | Назначение |
|---|---|---|
| `id` | INT | PK |
| `api_key_id` | INT | Кто подписан |
| `url` | VARCHAR(500) | Endpoint клиента |
| `secret` | VARCHAR(64) | HMAC-секрет (генерируется `random_bytes(32)`) |
| `events` | TEXT (JSON) | Список событий |
| `is_active` | TINYINT | Вкл/выкл |
| `created_at` | DATETIME | — |

**Шаг 2. Отправка** (вызывается из хука, см. 62.24):

```php
class modelMyWebhooks extends cmsModel {

    private const MAX_ATTEMPTS = 5;
    private const TIMEOUT = 10;

    public function dispatch(string $event, array $payload): void {
        $subs = $this->filterEqual('is_active', 1)
            ->get('my_webhooks');

        foreach ($subs as $sub) {
            $events = json_decode($sub['events'], true) ?: [];
            if (!in_array($event, $events, true)) {
                continue;
            }

            $body      = json_encode(['event' => $event, 'data' => $payload], JSON_UNESCAPED_UNICODE);
            $signature = hash_hmac('sha256', $body, $sub['secret']);

            $this->enqueueDelivery($sub['id'], $event, $body, $signature);
        }
    }

    private function enqueueDelivery(int $subId, string $event, string $body, string $signature): void {
        $this->insert('my_webhook_queue', [
            'webhook_id'   => $subId,
            'event'        => $event,
            'payload'      => $body,
            'signature'    => $signature,
            'attempts'     => 0,
            'next_attempt' => date('Y-m-d H:i:s'),
            'status'       => 'pending',
            'created_at'   => date('Y-m-d H:i:s'),
        ]);
    }
}
```

**Шаг 3. Воркер** (запускается по cron, см. раздел *«Архитектура планировщика Cron»*):

```php
class modelMyWebhooks extends cmsModel {

    public function processQueue(int $batch = 50): array {
        $stats = ['sent' => 0, 'failed' => 0, 'retried' => 0];

        $items = $this->filterEqual('status', 'pending')
            ->filterLte('next_attempt', date('Y-m-d H:i:s'))
            ->limit($batch)
            ->get('my_webhook_queue');

        $http = new \GuzzleHttp\Client(['timeout' => 10, 'connect_timeout' => 3]);

        foreach ($items as $item) {
            $sub = $this->getItem('my_webhooks', $item['webhook_id']);
            if (!$sub || !$sub['is_active']) {
                $this->update('my_webhook_queue', $item['id'], ['status' => 'canceled']);
                continue;
            }

            try {
                $resp = $http->post($sub['url'], [
                    'body'    => $item['payload'],
                    'headers' => [
                        'Content-Type'     => 'application/json',
                        'X-DST-Event'      => $item['event'],
                        'X-DST-Signature'  => $item['signature'],
                        'X-DST-Delivery'   => (string)$item['id'],
                        'User-Agent'       => 'DST-Webhook/1.0',
                    ],
                ]);

                if ($resp->getStatusCode() >= 200 && $resp->getStatusCode() < 300) {
                    $this->update('my_webhook_queue', $item['id'], [
                        'status' => 'sent', 'sent_at' => date('Y-m-d H:i:s')
                    ]);
                    $stats['sent']++;
                } else {
                    $this->retryOrFail($item, 'HTTP ' . $resp->getStatusCode());
                    $stats['retried']++;
                }
            } catch (\GuzzleHttp\Exception\GuzzleException $e) {
                $this->retryOrFail($item, $e->getMessage());
                $stats['retried']++;
            }
        }

        return $stats;
    }

    private function retryOrFail(array $item, string $reason): void {
        $attempts = (int)$item['attempts'] + 1;

        if ($attempts >= self::MAX_ATTEMPTS) {
            $this->update('my_webhook_queue', $item['id'], [
                'status' => 'failed',
                'attempts' => $attempts,
                'last_error' => $reason,
            ]);
            return;
        }

        $delay = min(3600, 2 ** $attempts * 30); // 60, 120, 240... до 1 часа
        $this->update('my_webhook_queue', $item['id'], [
            'attempts'     => $attempts,
            'next_attempt' => date('Y-m-d H:i:s', time() + $delay),
            'last_error'   => $reason,
        ]);
    }
}
```

**Шаг 4. Проверка подписи на клиенте:**

```php
$payload = file_get_contents('php://input');
$expected = hash_hmac('sha256', $payload, $webhookSecret);
if (!hash_equals($expected, $_SERVER['HTTP_X_DST_SIGNATURE'] ?? '')) {
    http_response_code(403); exit;
}
```

**Требования к клиентскому endpoint:**

- Отвечать HTTP 2xx за < 5 сек (иначе — ретрай).
- Быть **идемпотентным** (события могут дублироваться) — используйте `X-DST-Delivery` как ключ дедупликации.
- Отвечать 2xx только после **успешной обработки**; при ошибке — 5xx (вызовет ретрай).
- Логировать все входящие события.

### 62.20.1. Postman-коллекция

Импорт: **API → Экспорт коллекции Postman** (в админке). Коллекция содержит:

- Переменные окружения (`base_url`, `api_key`, `user_id`, `csrf_token`).
- Pre-request скрипты для автогенерации `sig` и `ts`.
- Тесты на коды ошибок.

**Пример pre-request script (Postman):**

```js
const crypto = require('crypto-js');
const ts = Math.floor(Date.now() / 1000).toString();
const method = pm.request.url.getPath().replace('/api/method/', '');
const params = pm.request.url.query.all()
    .filter(p => !['api_key','sig','ts'].includes(p.key))
    .sort((a,b) => a.key.localeCompare(b.key))
    .map(p => encodeURIComponent(p.key) + '=' + encodeURIComponent(p.value))
    .join('&');
const payload = `${method}\n${params}\n${ts}`;
const sig = crypto.HmacSHA256(payload, pm.environment.get('api_secret')).toString();
pm.request.addQueryParams([{key:'ts',value:ts},{key:'sig',value:sig}]);
```

## 62.21. Диагностика типовых ошибок

| Симптом | Вероятная причина | Что делать |
|---|---|---|
| `error_code: 101` | Неверный/устаревший ключ | Проверить `api_key`, перевыпустить |
| `error_code: 8` | Невалидный JSON в `code` | Проверить RFC 8259, убрать trailing comma |
| `error_code: 115` | Подпись не сходится | Пересчитать `sig`, проверить `ts`, `canonical_query` |
| `error_code: 777` | Неверный `ip` | Проверить валидность IPv4/IPv6 |
| `error_code: 429` | Rate limit | Backoff + `Retry-After` |
| `success:true`, но пустой `items` | Фильтры слишком узкие | Убрать `filter`, увеличить `per_page` |
| `error:0`, но нет данных | Нет прав у пользователя (`user_id`) | Проверить группы пользователя |
| `Warning: 299` | Метод deprecated | Перейти на новую версию |
| Тело — HTML вместо JSON | Запрос ушёл не на `/api/*` | Проверить URL и `.htaccess` |
| 0-байтный ответ на POST | CORS preflight не настроен | Настроить `allowed_origins` |

# Часть III. Руководство для внутренних разработчиков

## 62.22. Как устроен роутинг API внутри платформы

Точка входа `/api/method/{METHOD_NAME}` обрабатывается frontend-контроллером `api` (`/system/controllers/api/frontend.php`). Последовательность:

```
1. Парсинг URL → извлечение METHOD_NAME
2. Разбор METHOD_NAME → [component, action, ctype?]
3. Проверка: компонент существует и включён (cmsCore::isControllerExists)
4. Аутентификация:
   a. Извлечение api_key (header → query → body)
   b. Поиск ключа в БД, проверка is_active
   c. IP-фильтр (если задан)
   d. sig (если check_sig)
   e. csrf_token (если check_csrf)
5. Определение класса действия:
   - api_actions/{action}.php → api{Component}{Action}
   - либо hooks/api_{component}_{action}.php
6. Проверка прав:
   - require_user → пользователь авторизован?
   - require_admin → is_admin?
7. Выполнение run()
8. Формирование JSON-ответа (success/result | error)
9. Запись в api_logs
```

**Файлы компонента `api`:**

```
/system/controllers/api/
├── frontend.php          # Точка входа /api/method и /api/execute
├── model.php             # Работа с ключами, логами
├── backend/              # Админка (управление ключами, логи, статистика)
├── options.form.php      # Настройки компонента
└── api_docs/             # JSON-описания методов (см. 62.25)
```

**Файлы конкретного компонента (например, `shop`):**

```
/system/controllers/shop/
├── api_actions/
│   ├── get_products.php       # shop.get_products
│   ├── add_order.php          # shop.add_order
│   └── get_cart.php           # shop.get_cart
├── api_docs/
│   ├── get_products.json
│   ├── add_order.json
│   └── get_cart.json
└── hooks/
    └── api_shop_get_stats.php # Альтернатива api_actions (см. 62.24)
```

> ⚠️ **Именование файлов.** `api_actions/{action_name}.php` → действие `shop.{action_name}`. Регистр — только `snake_case`, латиница, цифры, `_`. Действие не может быть `execute` (зарезервировано).

## 62.23. Создание собственного метода через `api_actions`

### 62.23.1. Структура класса действия

Любой `api_actions/*.php` — это класс, наследующий `cmsAction` (см. раздел *«Ядро системы»*). Обязательные и опциональные свойства:

| Свойство | Тип | По умолчанию | Назначение |
|---|---|---|---|
| `$check_sig` | bool | `false` | Требовать HMAC-подпись |
| `$check_csrf` | bool | `false` | Требовать CSRF-токен (для write) |
| `$require_user` | bool | `false` | Требовать авторизованного пользователя |
| `$require_admin` | bool | `false` | Требовать админ-доступ |
| `$allowed_methods` | array\|null | `null` | Доп. ограничение по HTTP-методам (`['GET','POST']`) |
| `$idempotent` | bool | `false` | Поддержка `Idempotence-Key` |

Метод `run()` — единственная обязательная точка входа. Возвращает `true` при успехе (результат кладётся в `$this->controller->output_success`), либо вызывает `$this->error($code, $message)`.

### 62.23.2. Пример 1: read-метод `mycomp.get_stats` (полный листинг)

**Файл:** `/system/controllers/mycomp/api_actions/get_stats.php`

```php
<?php
/**
 * API-метод: mycomp.get_stats
 *
 * Возвращает агрегированную статистику по компоненту за период.
 *
 * @package    DST Platform
 * @subpackage mycomp
 * @category   API
 */

class apiMycompGetStats extends cmsAction {

    /** @var bool Подпись не требуется — метод только для чтения */
    public $check_sig = false;

    /** @var bool CSRF не требуется — нет изменений состояния */
    public $check_csrf = false;

    /** @var bool Авторизация не требуется — данные публичные */
    public $require_user = false;

    /** @var bool Админ-права не нужны */
    public $require_admin = false;

    /** @var array Ограничение HTTP-методов */
    public $allowed_methods = ['GET'];

    /** @var bool Не идемпотентный метод */
    public $idempotent = false;

    /**
     * Допустимые значения параметра period.
     *
     * @var array
     */
    private const ALLOWED_PERIODS = ['day', 'week', 'month', 'year'];

    /**
     * Точка входа метода.
     *
     * @return bool
     */
    public function run() {

        // ─────────────────────────────────────────────
        // 1. Получение и валидация параметров
        // ─────────────────────────────────────────────
        $period = (string)$this->request->get('period', 'day');

        if (!in_array($period, self::ALLOWED_PERIODS, true)) {
            return $this->error(100, 'Параметр period должен быть одним из: '
                . implode(', ', self::ALLOWED_PERIODS));
        }

        $dateFrom = (string)$this->request->get('date_from', '');
        if ($dateFrom !== '' && !$this->isValidDate($dateFrom)) {
            return $this->error(100, 'Параметр date_from должен быть в формате Y-m-d H:i:s');
        }

        $entityId = (int)$this->request->get('entity_id', 0);
        if ($entityId < 0) {
            return $this->error(100, 'Параметр entity_id должен быть неотрицательным');
        }

        // ─────────────────────────────────────────────
        // 2. Получение данных через модель
        // ─────────────────────────────────────────────
        $model = cmsCore::getModel('mycomp');

        try {
            $stats = $model->getStatistics($period, [
                'date_from' => $dateFrom,
                'entity_id' => $entityId,
            ]);
        } catch (\Throwable $e) {
            // Не светим внутренние детали клиенту
            error_log('[API mycomp.get_stats] ' . $e->getMessage());
            return $this->error(1, 'Не удалось получить статистику');
        }

        // ─────────────────────────────────────────────
        // 3. Формирование ответа
        // ─────────────────────────────────────────────
        $this->controller->output_success = [
            'period'       => $period,
            'date_from'    => $dateFrom ?: null,
            'entity_id'    => $entityId ?: null,
            'generated_at' => date('Y-m-d H:i:s'),
            'data'         => $stats,
        ];

        return true;
    }

    /**
     * Проверка формата даты.
     *
     * @param string $value
     * @return bool
     */
    private function isValidDate(string $value): bool {
        $dt = \DateTime::createFromFormat('Y-m-d H:i:s', $value);
        return $dt !== false && $dt->format('Y-m-d H:i:s') === $value;
    }
}
```

### 62.23.3. Пример 2: write-метод `mycomp.add_item` (полный листинг)

**Файл:** `/system/controllers/mycomp/api_actions/add_item.php`

```php
<?php
/**
 * API-метод: mycomp.add_item
 *
 * Создаёт запись в компоненте mycomp.
 * Требует: авторизацию пользователя, подпись, CSRF, идемпотентный ключ.
 *
 * @package    DST Platform
 * @subpackage mycomp
 * @category   API
 */

class apiMycompAddItem extends cmsAction {

    /** @var bool Подпись обязательна (write-метод) */
    public $check_sig = true;

    /** @var bool CSRF обязателен (write-метод) */
    public $check_csrf = true;

    /** @var bool Требуется авторизация пользователя */
    public $require_user = true;

    /** @var bool Админ-права не нужны */
    public $require_admin = false;

    /** @var array Только POST */
    public $allowed_methods = ['POST'];

    /** @var bool Поддержка Idempotence-Key */
    public $idempotent = true;

    /**
     * Обязательные поля для создания.
     *
     * @var array
     */
    private const REQUIRED_FIELDS = ['title', 'content'];

    /**
     * Точка входа метода.
     *
     * @return bool
     */
    public function run() {

        // ─────────────────────────────────────────────
        // 1. Идемпотентность: если ключ уже использован
        //    — возвращаем сохранённый результат
        // ─────────────────────────────────────────────
        $idempotenceKey = (string)$this->request->getHeader('Idempotence-Key');
        if ($idempotenceKey === '') {
            return $this->error(100, 'Заголовок Idempotence-Key обязателен для этого метода');
        }

        $existing = $this->model->getIdempotentResult($idempotenceKey);
        if ($existing !== null) {
            $this->controller->output_success = $existing;
            return true;
        }

        // ─────────────────────────────────────────────
        // 2. Сбор и валидация данных
        // ─────────────────────────────────────────────
        $data = [];
        $errors = [];

        foreach (self::REQUIRED_FIELDS as $field) {
            $value = trim((string)$this->request->get($field, ''));
            if ($value === '') {
                $errors[] = ['key' => $field, 'message' => 'Поле обязательно'];
            } else {
                $data[$field] = $value;
            }
        }

        if (!empty($errors)) {
            return $this->error(100, 'Одно или несколько обязательных полей не заполнены', $errors);
        }

        // Валидация длины
        if (mb_strlen($data['title']) > 255) {
            return $this->error(100, 'Поле title не должно превышать 255 символов');
        }
        if (mb_strlen($data['content']) > 100000) {
            return $this->error(100, 'Поле content не должно превышать 100000 символов');
        }

        // Дополнительные поля (опциональные)
        $data['category_id'] = (int)$this->request->get('category_id', 0);
        $data['is_published'] = (int)(bool)$this->request->get('is_published', 0);
        $data['tags'] = (array)$this->request->get('tags', []);

        // ─────────────────────────────────────────────
        // 3. Права: пользователь может писать только в свои объекты
        // ─────────────────────────────────────────────
        $user = $this->cms_user;
        if (!$user->isAllowed('mycomp', 'add')) {
            return $this->error(7, 'Нет прав на добавление записей в this компоеннт');
        }

        // ─────────────────────────────────────────────
        // 4. Сохранение через модель (транзакция)
        // ─────────────────────────────────────────────
        try {
            $this->model->beginTransaction();

            $itemId = $this->model->addItem($data, (int)$user->id);

            if (!$itemId) {
                throw new \RuntimeException('addItem вернул пустой ID');
            }

            $item = $this->model->getItem($itemId);
            if (!$item) {
                throw new \RuntimeException('Не удалось прочитать созданную запись');
            }

            // Хук — другие компоненты могут отреагировать
            $item = cmsEventsManager::hook('mycomp_after_add', $item);

            $this->model->commit();

        } catch (\Throwable $e) {
            $this->model->rollback();
            error_log('[API mycomp.add_item] ' . $e->getMessage());
            return $this->error(1, 'Не удалось создать запись');
        }

        // ─────────────────────────────────────────────
        // 5. Формирование ответа и сохранение для идемпотентности
        // ─────────────────────────────────────────────
        $result = [
            'id'         => (int)$item['id'],
            'title'      => $item['title'],
            'created_at' => $item['created_at'] ?? date('Y-m-d H:i:s'),
            'created_by' => (int)$item['user_id'],
        ];

        $this->model->saveIdempotentResult(
            $idempotenceKey,
            $result,
            (int)$user->id,
            86400 // TTL — сутки
        );

        $this->controller->output_success = $result;

        return true;
    }
}
```

**Пояснения к примеру 2:**

| Механизм | Где реализован |
|---|---|
| Идемпотентность | `$idempotent = true` + `getIdempotentResult` / `saveIdempotentResult` |
| Подпись | `$check_sig = true` — платформа проверит `sig` автоматически |
| CSRF | `$check_csrf = true` — платформа проверит `csrf_token` автоматически |
| Авторизация | `$require_user = true` — без `user_id` вернёт 71 |
| Права RBAC | `$user->isAllowed('mycomp', 'add')` — стандартная проверка (см. раздел *«Вопросы безопасности»*) |
| Транзакция | `beginTransaction` / `commit` / `rollback` в `cmsModel` |
| События | `cmsEventsManager::hook('mycomp_after_add', ...)` — см. 62.24 |

### 62.23.4. Пример 3: админский метод `mycomp.admin_reset_stats` (полный листинг)

**Файл:** `/system/controllers/mycomp/api_actions/admin_reset_stats.php`

```php
<?php
/**
 * API-метод: mycomp.admin_reset_stats
 *
 * Сбрасывает статистику. Только для администраторов.
 *
 * @package    DST Platform
 * @subpackage mycomp
 * @category   API
 */

class apiMycompAdminResetStats extends cmsAction {

    public $check_sig    = true;
    public $check_csrf   = true;
    public $require_user = true;
    public $require_admin = true; // ← ключевое отличие

    public $allowed_methods = ['POST'];

    public function run() {

        // Подтверждение через параметр (защита от случайного вызова)
        $confirm = (string)$this->request->get('confirm', '');
        if ($confirm !== 'YES') {
            return $this->error(100, 'Передайте confirm=YES для подтверждения сброса');
        }

        $period = (string)$this->request->get('period', 'all');
        $allowedPeriods = ['day', 'week', 'month', 'all'];
        if (!in_array($period, $allowedPeriods, true)) {
            return $this->error(100, 'Параметр period должен быть одним из: '
                . implode(', ', $allowedPeriods));
        }

        try {
            $deleted = $this->model->resetStatistics($period);

            // Логирование действия администратора
            cmsEventsManager::hook('security_event', [
                'type'      => 'admin_action',
                'action'    => 'mycomp.admin_reset_stats',
                'admin_id'  => (int)$this->cms_user->id,
                'period'    => $period,
                'deleted'   => $deleted,
                'ip'        => $_SERVER['REMOTE_ADDR'] ?? 'cli',
                'timestamp' => time(),
            ]);

            $this->controller->output_success = [
                'period'  => $period,
                'deleted' => $deleted,
                'reset_at' => date('Y-m-d H:i:s'),
            ];

            return true;

        } catch (\Throwable $e) {
            error_log('[API mycomp.admin_reset_stats] ' . $e->getMessage());
            return $this->error(1, 'Не удалось сбросить статистику');
        }
    }
}
```

### 62.23.5. Методы ответа в `api_actions`

| Метод | Назначение | Что делает |
|---|---|---|
| `$this->controller->output_success = [...]` | Успех | Платформа обернёт в `{success: true, result: ...}` |
| `$this->error($code, $msg)` | Ошибка | Возвращает `false`, платформа сформирует `{error: ...}` |
| `$this->error($code, $msg, $params)` | Ошибка с параметрами | `request_params` заполняется массивом `[{key, value}]` |

> ⚠️ **Никогда** не выводите через `echo`, `print_r`, `var_dump` внутри `api_actions` — это сломает JSON-ответ. Только `output_success` и `error`.

## 62.24. Создание метода через хуки (полный листинг)

Альтернатива `api_actions` — **хук**. Используется, когда:

- метод — тонкая обёртка над существующим хуком компонента;
- логика уже есть в `hooks.php` и нужно лишь «пробросить» её в API;
- нужно встроиться в цепочку хуков других компонентов.

**Файл:** `/system/controllers/mycomp/hooks/api_mycomp_get_stats.php`

```php
<?php
/**
 * API-метод через хук: mycomp.get_stats
 *
 * Регистрируется автоматически при наличии файла
 * /system/controllers/{component}/hooks/api_{component}_{action}.php
 *
 * @package    DST Platform
 * @subpackage mycomp
 * @category   API
 */

class onMycompApiMycompGetStats extends cmsAction {

    public $check_sig     = false;
    public $check_csrf    = false;
    public $require_user  = false;
    public $require_admin = false;
    public $allowed_methods = ['GET'];

    /**
     * Точка входа хука.
     *
     * @return bool
     */
    public function run() {

        // ─────────────────────────────────────────────
        // 1. Параметры
        // ─────────────────────────────────────────────
        $period = (string)$this->request->get('period', 'day');
        if (!in_array($period, ['day', 'week', 'month'], true)) {
            return $this->error(100, 'Неверный period');
        }

        // ─────────────────────────────────────────────
        // 2. Проверка существования основного хука
        //    и вызов, если он определён
        // ─────────────────────────────────────────────
        $stats = [];

        if (method_exists($this, 'hookMycompGetStats')) {
            $stats = $this->hookMycompGetStats($period);
        } else {
            // fallback — прямое обращение к модели
            $stats = $this->model->getStatistics($period);
        }

        // ─────────────────────────────────────────────
        // 3. Ответ
        // ─────────────────────────────────────────────
        $this->controller->output_success = [
            'period' => $period,
            'data'   => $stats,
        ];

        return true;
    }
}
```

**Когда что использовать:**

| Критерий | `api_actions` | `hooks/api_*` |
|---|---|---|
| Метод полностью новый | ✅ | — |
| Тонкая обёртка над существующим хуком | — | ✅ |
| Нужен полный контроль над `run()` | ✅ | — |
| Нужна интеграция в цепочку хуков других компонентов | — | ✅ |
| Требуется идемпотентность `Idempotence-Key` | ✅ | — (только через модель) |

> ⚠️ **Не дублируйте.** Если один и тот же метод реализован и в `api_actions`, и в `hooks/api_*` — приоритет у `api_actions` (см. 62.22, шаг 5). Второй файл будет проигнорирован, но лучше его не создавать.

Формат **не пересекается** с OpenAPI намеренно: он проще, расширяем и позволяет генерировать OpenAPI 3.1 через отдельный скрипт (см. 47.10). Универсальные поля:

| Поле | Обязательность | Назначение |
|---|---|---|
| `method` | ✅ | Полное имя метода (`component.action[.ctype]`) |
| `title` | ✅ | Человекочитаемое название |
| `description` | ✅ | Подробное описание |
| `since` | ✅ | Версия платформы, с которой доступен метод |
| `deprecated` | ❌ | `true` — метод устарел |
| `sunset` | ❌ | Дата удаления (`Y-m-d`) |
| `category` | ❌ | Для группировки в админке |
| `auth` | ✅ | `{api_key, sig, csrf, user, admin}` — все bool |
| `allowed_methods` | ❌ | HTTP-методы (`["GET","POST"]`) |
| `idempotent` | ❌ | Поддержка `Idempotence-Key` |
| `cache` | ❌ | `{ttl, key_params}` — серверное кэширование |
| `params` | ✅ | Массив параметров |
| `returns` | ✅ | Схема ответа (JSON Schema-подобная) |
| `errors` | ✅ | Массив `{code, when}` |
| `examples` | ❌ | Массив `{title, request, response}` |
| `schemas` | ❌ | Именованные схемы для `$ref` |

**Поля параметра (`params[]`):**

| Поле | Обязательность | Пример |
|---|---|---|
| `name` | ✅ | `period` |
| `in` | ✅ | `query`, `body`, `header`, `path` |
| `type` | ✅ | `string`, `integer`, `boolean`, `array`, `object` |
| `required` | ✅ | `true` / `false` |
| `default` | ❌ | `"day"` |
| `enum` | ❌ | `["day","week"]` |
| `format` | ❌ | `date-time`, `email`, `uri` |
| `min` / `max` | ❌ | `0` / `100` |
| `description` | ✅ | Текстовое описание |

## 62.26. Соглашения по именованию, версионированию и совместимости

### 62.26.1. Именование методов

```
{component}.{action}[.{ctype}]
```

| Правило | Пример |
|---|---|
| `component` — имя директории компонента | `shop`, `content`, `mycomp` |
| `action` — `snake_case`, начинается с глагола | `get_products`, `add_order`, `update_item` |
| `ctype` — имя типа контента (только для `content`) | `news`, `articles` |
| Длина | 3–100 символов |
| Символы | `a-z`, `0-9`, `_`, `.` |
| Зарезервировано | `execute`, `method`, `api` |

**Глаголы (единый словарь):**

| Глагол | Назначение |
|---|---|
| `get` / `get_item` / `get_list` | Чтение |
| `add` / `add_item` / `create` | Создание |
| `update` / `update_item` | Изменение |
| `delete` / `remove` | Удаление |
| `search` | Поиск |
| `export` / `import` | Массовые операции |
| `_status` / `_start` / `_cancel` | Async-операции (см. 62.19) |

### 62.26.2. Версионирование

| Изменение | Действие |
|---|---|
| Добавление опционального параметра | В той же версии метода |
| Добавление поля в ответ | В той же версии метода |
| Новый метод | С `since` = текущая версия платформы |
| Изменение типа поля | Новый метод `{action}_v2` |
| Удаление метода | `deprecated=true` + `sunset` за 6 мес. |
| Изменение кода ошибки | Новый метод `{action}_v2` |

### 62.26.3. Правила для `ctype`

- `content.*.CTYPE` — если `CTYPE` не указан, возвращаются данные по всем типам контента (см. 62.11).
- При добавлении нового типа контента — переиспользуйте существующие методы `content.*.CTYPE` без создания новых.
- Не создавайте «обёртки» вида `content.get_news` — это нарушает соглашение.

## 62.27. Логирование и мониторинг собственных методов

### 62.27.1. Что уже логируется автоматически

Компонент `api` пишет в `api_logs`:

- `api_key_id`, `method`, `params`, `ip`, `user_agent`, `response`, `error_code`, `execution_time`, `created_at`.

Этого **достаточно** для диагностики большинства проблем. Дополнительное логирование требуется, только если:

- метод выполняет внешние вызовы (нужны трейсы);
- есть бизнес-события, которые не отражаются в `error_code`;
- нужны метрики для дашборда.

```php
class mycomp extends cmsAction {

    /**
     * Запись бизнес-события API в отдельную таблицу.
     */
    public function hookMycompApiEvent(array $event): void {
        if (empty($event['method'])) {
            return;
        }

        $this->model->insert('mycomp_api_events', [
            'method'    => $event['method'],
            'event'     => $event['event'],
            'item_id'   => $event['item_id'] ?? null,
            'user_id'   => $event['user_id'] ?? null,
            'api_key_id'=> $event['api_key'] ?? null,
            'duration'  => $event['duration'] ?? null,
            'created_at'=> date('Y-m-d H:i:s', $event['timestamp'] ?? time()),
        ]);
    }
}
```

### 62.27.3. Метрики

Для сбора метрик (Prometheus/Grafana — см. раздел *«Мониторинг и алертинг»*) настройте регулярный экспорт:

```php
class modelMycomp extends cmsModel {

    /**
     * Метрики API для Prometheus.
     */
    public function getApiMetrics(): array {
        $sql = "SELECT method, COUNT(*) AS cnt,
                       AVG(execution_time) AS avg_time,
                       SUM(CASE WHEN error_code IS NULL THEN 1 ELSE 0 END) AS ok_cnt
                FROM api_logs
                WHERE method LIKE 'mycomp.%'
                  AND created_at > (NOW() - INTERVAL 1 DAY)
                GROUP BY method";

        return $this->db->query($sql)->getRows();
    }
}
```

### 62.27.4. Алерты

Настройте алерты на:

| Метрика | Порог | Действие |
|---|---|---|
| Доля ошибок 5xx | > 1% за 5 мин | Уведомление дежурному |
| `error_code: 1` | > 10 за 5 мин | Уведомление разработчику |
| `execution_time` p95 | > 2 сек | Дашборд, алерт |
| `error_code: 429` | > 20% запросов | Алерт: клиент не соблюдает backoff |
| Rate limit одного ключа | > 90% лимита | Алерт клиенту (письмо) |

```php
use PHPUnit\Framework\TestCase;

class ApiGetStatsTest extends TestCase {

            'query'   => ['period' => 'week'],

        $this->assertTrue($data['success']);
        $this->assertSame('week', $data['result']['period']);
        $this->assertArrayHasKey('data', $data['result']);
```

## 62.29. Безопасность при разработке собственных методов

Сводный чек-лист (детали — в разделе *«Вопросы безопасности»*):

- [ ] **Таймауты** для внешних вызовов внутри метода (Guzzle `timeout`, см. раздел 28)
- [ ] **Тесты** на все коды ошибок из `api_docs/*.json`
- [ ] **`api_docs/*.json`** заполнен и валиден
- [ ] **Метод не дублирует** существующий (`api_actions` vs `hooks/api_*`)
- [ ] **`allowed_methods`** ограничен необходимыми HTTP-методами

- [ ] Настроены IP-фильтр и `allowed_methods` ключа
- [ ] Для write-методов включён `check_sig` и настроен `sig`
- [ ] Для write-методов реализован `Idempotence-Key`
- [ ] Обрабатываются все коды ошибок из `api_docs/*.json`
- [ ] Реализован backoff на `429` и `5xx`
- [ ] Настроены таймауты HTTP-клиента (см. раздел 28)
- [ ] Проверены `paging` и граничные значения `page` / `per_page`
- [ ] Проверены `execute` и частичные ошибки
- [ ] Настроено логирование ошибок на клиенте
- [ ] Импортирована Postman-коллекция, пройдены все тесты
- [ ] Настроен мониторинг ошибок (алерты на 5xx, 429, `error_code: 1`)

### 62.32.2. Чек-лист готовности метода (для внутренних разработчиков)

- [ ] Создан `api_actions/{action}.php` (или `hooks/api_{c}_{a}.php`)
- [ ] Настроены `$check_sig`, `$check_csrf`, `$require_user`, `$require_admin`, `$allowed_methods`
- [ ] Валидированы все входные параметры
- [ ] Реализована RBAC-проверка (`$this->cms_user->isAllowed()`)
- [ ] Использованы транзакции для многошаговых операций
- [ ] Реализована идемпотентность (для `add_*`)
- [ ] Сформирован `output_success` (без `echo` / `print_r`)
- [ ] Создан `api_docs/{action}.json` (валидный)
- [ ] Написаны PHPUnit-тесты (позитив + все ошибки)
- [ ] Настроено логирование бизнес-событий (через хук)
- [ ] Настроены метрики и алерты
- [ ] Проверено, что метод не дублирует существующий
- [ ] Пройдена проверка безопасности (см. 62.29)

### 62.32.3. Чек-лист развёртывания API в продакшене

- [ ] `enable_logging = true`
- [ ] `log_retention_days` ≥ 30
- [ ] `enable_sig_check = true`
- [ ] `rate_limit_per_minute` настроен
- [ ] `allowed_origins` — только доверенные домены
- [ ] HTTPS включён, редирект с HTTP
- [ ] Ключи в переменных окружения (см. 42.5)
- [ ] Мониторинг `api_logs` и алерты
- [ ] Резервное копирование БД (см. раздел *«Резервное копирование»*)
- [ ] Ротация ключей клиентов (политика)
- [ ] Документация методов актуальна (все `api_docs/*.json` валидны)
