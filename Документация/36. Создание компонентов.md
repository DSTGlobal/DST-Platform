# 36. Создание компонентов

В данном разделе представлено практическое руководство по созданию новых компонентов в DST Platform: структура файлов, соглашения об именовании, реализация контроллеров, моделей и шаблонов.

**Связанные разделы:**
- *«Система компонентов»* — архитектура компонентной системы
- *«Система типов контента»* — декларативный подход к созданию функциональности
- *«Работа с хуками»* — расширение существующих компонентов
- *«Руководство по разработке»* — общие принципы разработки

---

## 36.1. Архитектура компонента

Компонент в DST Platform представляет собой **самодостаточный функциональный модуль**, расположенный в каталоге `/system/controllers/{component_name}/`. Компоненты следуют шаблону MVC и могут включать любую комбинацию фронтенд-контроллера, бэкенд-контроллера, модели, шаблонов и обработчиков событий.

### Структура типичного компонента

```
/system/controllers/{component_name}/
├── frontend.php              # Фронтенд-контроллер (класс {componentName})
├── backend.php               # Бэкенд-контроллер (класс backend{ComponentName})
├── model.php                 # Модель данных (класс model{ComponentName})
├── manifest.php              # Метаданные компонента
├── hooks.php                 # Обработчики событий (опционально)
├── actions/                  # Методы действий (опционально)
│   ├── index.php            # actionIndex()
│   ├── view.php             # actionView()
│   └── ...
├── backend/
│   ├── controller.php       # Бэкенд-контроллер (альтернативное расположение)
│   ├── model.php            # Расширенная модель бэкенда
│   └── forms/               # Формы административной панели
└── utils/                    # Вспомогательные классы (опционально)
```

## 36.2. Требования к именованию компонентов

Имя каталога компонента должно строго соответствовать правилам системы маршрутизации и автозагрузки.

### Правила именования
| Требование | Ограничение | Примеры |
|------------|-------------|---------|
| **Набор символов** | Строчные латинские буквы, цифры, нижнее подчеркивание | `shop`, `my_feature`, `blog3` |
| **Первый символ** | Обязательно буква | ✅ `news` ❌ `3news` |
| **Минимальная длина** | 3 символа | ✅ `geo` ❌ `io` |
| **Уникальность** | Не должен конфликтовать с существующими компонентами | Проверять `/system/controllers/` |
| **Семантичность** | Должно отражать назначение компонента | ✅ `product_catalog` ❌ `comp1` |

### Соглашения об именовании классов
| Элемент | Формат | Пример |
|---------|--------|--------|
| **Каталог компонента** | `snake_case` | `product_catalog` |
| **Класс фронтенд-контроллера** | `{Name}` наследует `cmsFrontend` | `class productCatalog extends cmsFrontend` |
| **Класс бэкенд-контроллера** | `backend{Name}` наследует `cmsBackend` | `class backendProductCatalog extends cmsBackend` |
| **Класс модели** | `model{Name}` наследует `cmsModel` | `class modelProductCatalog extends cmsModel` |
| **Класс модели бэкенда** | `modelBackend{Name}` наследует `model{Name}` | `class modelBackendProductCatalog extends modelProductCatalog` |

## 36.3. Создание фронтенд-контроллера

Фронтенд-контроллер обрабатывает все публичные запросы к компоненту. Он расширяет `cmsFrontend` и определяет методы действий.

### Базовая структура

```php
// /system/controllers/my_component/frontend.php
<?php
class myComponent extends cmsFrontend {
    
    /**
     * Действие по умолчанию - отображается при доступе к /my_component
     */
    public function actionIndex() {
        // Подготовка данных
        $data = [
            'title' => 'My Component',
            'items' => $this->model->getItems()
        ];
        
        // Установка заголовка страницы
        $this->setPageTitle('My Component');
        
        // Рендеринг шаблона
        return $this->render('index', $data);
    }
    
    /**
     * Просмотр отдельного элемента - доступ через /my_component/view/{id}
     */
    public function actionView($id) {
        // Получение элемента из модели
        $item = $this->model->getItem($id);
        
        if (!$item) {
            return $this->error404();
        }
        
        // Подготовка данных для шаблона
        $data = [
            'item' => $item,
            'related_items' => $this->model->getRelatedItems($item['id'])
        ];
        
        // Регистрация ресурсов
        $this->template->addControllerCSS('view.css', 'my_component');
        $this->template->addControllerJS('view.js', 'my_component');
        
        // Рендеринг шаблона
        return $this->render('view', $data);
    }
    
    /**
     * Действие с параметрами из URL
     * URL: /my_component/category/{category_id}/{page}
     */
    public function actionCategory($category_id, $page = 1) {
        // Валидация параметров
        $category_id = (int)$category_id;
        $page = max(1, (int)$page);
        
        // Получение данных
        $items = $this->model->getItemsByCategory($category_id, $page);
        $total = $this->model->getTotalItemsByCategory($category_id);
        
        // Пагинация
        $per_page = 20;
        $pages_count = ceil($total / $per_page);
        
        return $this->render('category', [
            'items' => $items,
            'category_id' => $category_id,
            'page' => $page,
            'pages_count' => $pages_count
        ]);
    }
}
```

### Доступные методы контроллера
| Метод | Назначение | Пример |
|-------|------------|--------|
| `$this->model` | Доступ к модели компонента | `$this->model->getItems()` |
| `$this->request->get($key, $default)` | Получение GET-параметра | `$this->request->get('id', 0)` |
| `$this->request->post($key, $default)` | Получение POST-параметра | `$this->request->post('title', '')` |
| `$this->render($template, $data)` | Рендеринг шаблона | `$this->render('view', ['item' => $item])` |
| `$this->redirect($url)` | HTTP-редирект | `$this->redirect('/my_component')` |
| `$this->error404()` | Показать страницу 404 | `return $this->error404()` |
| `$this->setPageTitle($title)` | Установить заголовок страницы | `$this->setPageTitle('Item View')` |
| `$this->addBreadcrumb($title, $url)` | Добавить хлебную крошку | `$this->addBreadcrumb('Home', '/')` |
| `$this->halt()` | Остановить выполнение | `return $this->halt()` |

## 36.4. Создание бэкенд-контроллера

Бэкенд-контроллер предоставляет административный интерфейс для управления данными компонента. Он расширяет `cmsBackend` и интегрируется с админ-панелью.

### Базовая структура

```php
// /system/controllers/my_component/backend.php
<?php
class backendMyComponent extends cmsBackend {
    
    /**
     * Требуемые права доступа для этого компонента
     */
    public $usePermissions = ['admin', 'my_component'];
    
    /**
     * Действие по умолчанию - показывает список элементов
     */
    public function actionIndex() {
        $model = $this->model;
        
        // Получение элементов из базы данных
        $items = $model->getItems();
        
        return $this->render('index', [
            'items' => $items
        ]);
    }
    
    /**
     * Добавить новый элемент
     */
    public function actionAdd() {
        return $this->actionEdit();
    }
    
    /**
     * Редактировать элемент
     */
    public function actionEdit() {
        $id = $this->request->get('id', 0);
        
        // Определение формы
        $form = $this->getItemForm();
        
        // Загрузка существующего элемента при редактировании
        if ($id) {
            $item = $this->model->getItem($id);
            if (!$item) {
                return $this->error404();
            }
        } else {
            $item = [];
        }
        
        // Обработка отправки формы
        if ($this->request->has('submit')) {
            $form_data = $form->parse($this->request);
            $errors = $form->validate();
            
            if (!$errors) {
                $item_data = array_merge($item, $form_data);
                
                if ($id) {
                    $this->model->updateItem($id, $item_data);
                } else {
                    $id = $this->model->addItem($item_data);
                }
                
                $this->redirectToAction('index');
            }
        }
        
        return $this->render('edit', [
            'form' => $form,
            'item' => $item,
            'errors' => $errors ?? []
        ]);
    }
    
    /**
     * Удалить элемент
     */
    public function actionDelete() {
        $id = $this->request->get('id', 0);
        
        if ($id) {
            $this->model->deleteItem($id);
        }
        
        $this->redirectToAction('index');
    }
    
    /**
     * Определение структуры формы элемента
     */
    private function getItemForm() {
        $form = new cmsForm();
        
        $form->addField('title', [
            'type' => 'text',
            'title' => 'Title',
            'rules' => [
                ['required']
            ]
        ]);
        
        $form->addField('content', [
            'type' => 'html',
            'title' => 'Content'
        ]);
        
        $form->addField('is_published', [
            'type' => 'checkbox',
            'title' => 'Published',
            'default' => true
        ]);
        
        return $form;
    }
}
```

## 36.5. Создание модели данных

Класс модели обеспечивает абстракцию доступа к данным. Он расширяет `cmsModel`, который предлагает методы построения запросов и автоматическую фильтрацию входных данных.

### Базовая реализация

```php
// /system/controllers/my_component/model.php
<?php
class modelMyComponent extends cmsModel {
    
    /**
     * Получить отдельный элемент по ID
     */
    public function getItem($id) {
        return $this->db->getItem(
            'my_component_items',
            $id,
            function($item, $db) {
                // Дополнительная обработка при необходимости
                return $item;
            }
        );
    }
    
    /**
     * Получить все элементы с фильтрацией
     */
    public function getItems($filter = []) {
        // Начало построения запроса
        $this->db->select('i.*');
        $this->db->from('my_component_items', 'i');
        
        // Применение фильтров
        if (!empty($filter['is_published'])) {
            $this->db->where('i.is_published', 1);
        }
        
        if (!empty($filter['search'])) {
            $this->db->whereLike('i.title', $filter['search']);
        }
        
        // Сортировка
        $this->db->orderBy('i.date_created', 'DESC');
        
        // Выполнение запроса
        return $this->db->get();
    }
    
    /**
     * Добавить новый элемент
     */
    public function addItem($item) {
        // Вызов события ДО добавления
        $item = cmsEventsManager::hook('my_component_before_add', $item);
        
        // Вставка в базу данных
        $id = $this->db->insert('my_component_items', $item);
        
        // Вызов события ПОСЛЕ добавления
        cmsEventsManager::hook('my_component_after_add', $id, $item);
        
        return $id;
    }
    
    /**
     * Обновить существующий элемент
     */
    public function updateItem($id, $item) {
        // Вызов события ДО обновления
        $item = cmsEventsManager::hook('my_component_before_update', $item);
        
        // Обновление в базе данных
        $this->db->update('my_component_items', $id, $item);
        
        // Вызов события ПОСЛЕ обновления
        cmsEventsManager::hook('my_component_after_update', $id, $item);
        
        return true;
    }
    
    /**
     * Удалить элемент
     */
    public function deleteItem($id) {
        // Вызов события ДО удаления
        cmsEventsManager::hook('my_component_before_delete', $id);
        
        // Удаление из базы данных
        $this->db->delete('my_component_items', $id);
        
        // Вызов события ПОСЛЕ удаления
        cmsEventsManager::hook('my_component_after_delete', $id);
        
        return true;
    }
    
    /**
     * Пример сложного запроса с JOIN
     */
    public function getItemsWithAuthor() {
        $this->db->select('i.*, u.nickname as author_name');
        $this->db->from('my_component_items', 'i');
        $this->db->join('users', 'u', 'u.id = i.user_id', 'LEFT');
        $this->db->where('i.is_published', 1);
        
        return $this->db->get();
    }
}
```

### Методы базы данных
| Метод | Назначение | Пример |
|-------|------------|--------|
| `select($fields)` | Предложение SELECT | `$this->db->select('id, title')` |
| `from($table, $alias)` | Предложение FROM | `$this->db->from('items', 'i')` |
| `join($table, $alias, $on, $type)` | Предложение JOIN | `$this->db->join('users', 'u', 'u.id = i.user_id')` |
| `where($field, $value)` | Условие WHERE | `$this->db->where('is_active', 1)` |
| `whereLike($field, $value)` | Условие LIKE | `$this->db->whereLike('title', '%search%')` |
| `whereIn($field, $array)` | Условие IN | `$this->db->whereIn('status', [1,2,3])` |
| `orderBy($field, $dir)` | ORDER BY | `$this->db->orderBy('date_created', 'DESC')` |
| `limit($limit, $offset)` | LIMIT | `$this->db->limit(10, 0)` |
| `get()` | Выполнить запрос | `return $this->db->get()` |
| `getItem($table, $id, $callback)` | Получить одну строку | `$this->db->getItem('items', 5)` |
| `insert($table, $data)` | Вставить строку | `$this->db->insert('items', ['title' => 'New'])` |
| `update($table, $id, $data)` | Обновить строку | `$this->db->update('items', 5, ['title' => 'Updated'])` |
| `delete($table, $id)` | Удалить строку | `$this->db->delete('items', 5)` |

## 36.6. Создание шаблонов

Шаблоны — это PHP-файлы с расширением `.tpl.php`, расположенные в каталоге `/templates/{theme}/controllers/{component_name}/`. Они получают данные от контроллеров и генерируют HTML-код.

### Расположение файлов шаблонов

<img src="https://github.com/DSTGlobal/DST-Platform/blob/main/images/223.png" alt="Расположение шаблонов">

### Шаблон списка

```php
<!-- /templates/default/controllers/my_component/index.tpl.php -->
<?php
/**
 * @var array $items - Список элементов от контроллера
 * @var string $title - Заголовок страницы
 */
?>
<?php $this->addControllerCSS('styles.css', 'my_component'); ?>

<div class="my-component">
    <h1><?= html_escape($title) ?></h1>
    
    <?php if ($items): ?>
        <div class="items-list">
            <?php foreach ($items as $item): ?>
                <div class="item">
                    <h2>
                        <a href="<?= href_to('my_component', 'view', $item['id']) ?>">
                            <?= html_escape($item['title']) ?>
                        </a>
                    </h2>
                    
                    <div class="item-date">
                        <?= html_date_time($item['date_created']) ?>
                    </div>
                    
                    <div class="item-excerpt">
                        <?= string_short($item['content'], 200) ?>
                    </div>
                </div>
            <?php endforeach; ?>
        </div>
    <?php else: ?>
        <p class="no-items">Элементы не найдены.</p>
    <?php endif; ?>
</div>
```

### Шаблон отдельного элемента

```php
<!-- /templates/default/controllers/my_component/view.tpl.php -->
<?php
/**
 * @var array $item - Данные элемента от контроллера
 */
?>
<?php
$this->addControllerCSS('view.css', 'my_component');
$this->addControllerJS('view.js', 'my_component');
?>

<article class="my-component-item">
    <header>
        <h1><?= html_escape($item['title']) ?></h1>
        
        <div class="meta">
            <time datetime="<?= $item['date_created'] ?>">
                <?= html_date_time($item['date_created']) ?>
            </time>
        </div>
    </header>
    
    <div class="content">
        <?= $item['content'] ?>
    </div>
    
    <footer>
        <a href="<?= href_to('my_component') ?>" class="btn btn-back">
            Назад к списку
        </a>
    </footer>
</article>
```

### Вспомогательные функции шаблонов
| Функция | Назначение | Пример |
|---------|------------|--------|
| `html_escape($text)` | Экранирование HTML-сущностей | `<?= html_escape($item['title']) ?>` |
| `href_to($component, $action, ...)` | Сгенерировать URL компонента | `href_to('my_component', 'view', 5)` |
| `html_date_time($datetime)` | Формат даты и времени | `html_date_time($item['date_created'])` |
| `string_short($text, $length)` | Сокращение текста | `string_short($item['content'], 200)` |
| `$this->user->is_logged` | Проверка авторизации | `<?php if ($this->user->is_logged): ?>` |
| `$this->renderChild($tpl, $data)` | Рендеринг частичного шаблона | `$this->renderChild('_item', ['item' => $item])` |

## 36.7. Файл манифеста компонента

## 36.8. Полный рабочий процесс создания компонента

### Пошаговый процесс

1. **Создание структуры каталогов**
   ```bash
   mkdir -p /system/controllers/my_component/
   mkdir -p /system/controllers/my_component/actions
   mkdir -p /templates/default/controllers/my_component
   ```

2. **Создание базовых файлов**
   - `frontend.php` — фронтенд-контроллер
   - `backend.php` — бэкенд-контроллер
   - `model.php` — модель данных
   - `manifest.php` — метаданные компонента

3. **Создание шаблонов**
   - `index.tpl.php` — список элементов
   - `view.tpl.php` — просмотр элемента
   - `edit.tpl.php` — форма редактирования

4. **Регистрация компонента**
   - Через админ-панель: **Компоненты → Установить компонент**
   - Или вручную в базе данных

5. **Тестирование**
   - Фронтенд: `/my_component`
   - Бэкенд: `/admin/my_component`

## 36.9. Расширенные сценарии

### Наследование моделей

Компоненты могут наследовать модели от других компонентов для расширения функциональности:

```php
// /system/controllers/partner/model.php
class modelPartner extends modelShop {
    
    /**
     * Переопределение или расширение методов магазина
     */
    public function getPartnerProducts($partner_id) {
        return $this->db->from($this->table_prefix . 'shop_items')
            ->where('partner_id', $partner_id)
            ->get();
    }
}
```

### Расширенная модель бэкенда

Для реализации сложных административных функций создайте отдельную модель бэкенда:

```php
// /system/controllers/blog/backend/model.php
class modelBackendBlog extends modelBlog {
    
    /**
     * Получение постов с дополнительной статистикой
     */
    public function getPostsWithStats() {
        $this->db->select('p.*, COUNT(c.id) as comment_count');
        $this->db->from('blog_posts', 'p');
        $this->db->join('comments', 'c', 'c.target_id = p.id', 'LEFT');
        $this->db->groupBy('p.id');
        
        return $this->db->get();
    }
}
```

### Компонент-слушатель событий

Некоторые компоненты существуют исключительно для обработки событий от других компонентов:

```php
// /system/controllers/my_listener/hooks.php
<?php
class myListener extends cmsController {
    
    /**
     * Вызывается перед сохранением элемента магазина
     */
    public function hookShopBeforeSave($item) {
        // Модификация данных элемента
        $item['custom_field'] = $this->calculateCustomValue($item);
        return $item;
    }
    
    /**
     * Вызывается после регистрации пользователя
     */
    public function hookUsersAfterRegister($user) {
        // Отправка приветственного письма или создание начальных данных
        $this->sendWelcomeEmail($user);
    }
}
```

### Структура каталогов для компонента-слушателя

```
/system/controllers/my_listener/
├── manifest.php
└── hooks.php
```

## 36.10. Регистрация и состояние компонентов

### Процесс регистрации

При установке компонента система создает:
- **Таблицы базы данных** — определены в `manifest.php`
- **Запись в реестре** — таблица `components`

### Состояния компонента

| Состояние | Значение | Доступ |
|-----------|----------|--------|
| **Установлен** | Файлы присутствуют, запись в БД существует | Полный доступ, если включен |
| **Включен** | Активен и доступен | Работа фронтенд/бэкенд |
| **Отключен** | Установлен, но не активирован | Нет доступа к действиям |
| **Удален** | Файлы существуют, но отсутствуют в БД | Недоступен |

## 36.11. Загрузка ресурсов (CSS/JS)

Контроллеры должны использовать шаблонные методы для корректной загрузки ресурсов:

```php
// В методе действия фронтенд-контроллера
public function actionView() {
    // Загрузка CSS, специфичного для компонента
    $this->template->addControllerCSS('styles.css', 'my_component');
    
    // Загрузка JavaScript, специфичного для компонента
    $this->template->addControllerJS('script.js', 'my_component');
    
    // Передача языковых строк в JavaScript
    $this->template->getLangJS([
        'LANG_CONFIRM_DELETE',
        'LANG_ERROR_REQUIRED'
    ]);
    
    // ... остальная логика действия
}
```

### Расположение файлов ресурсов

- **CSS**: `/templates/default/controllers/my_component/styles.css`
- **JS**: `/templates/default/controllers/my_component/script.js`

## 36.12. Проверочный список создания компонента

| Шаг | Файл/Действие | Обязательно |
|-----|---------------|-------------|
| 1 | Создать каталог `/system/controllers/{name}/` | ✅ |
| 2 | Создать `manifest.php` с метаданными | ✅ |
| 3 | Создать `model.php` расширяющий `cmsModel` | Рекомендуется |
| 4 | Создать `frontend.php` расширяющий `cmsFrontend` | Если есть публичные страницы |
| 5 | Создать `backend.php` расширяющий `cmsBackend` | Если есть админка |
| 6 | Создать шаблоны в `/templates/default/controllers/{name}/` | Если есть фронтенд |
| 7 | Создать шаблоны бэкенда в `/templates/default/controllers/{name}/backend/` | Если есть бэкенд |
| 8 | Определить таблицы БД в манифесте | Если хранит данные |
| 9 | Определить права доступа в манифесте | Если есть бэкенд |
| 10 | Создать `hooks.php` для событий | Если расширяет другие компоненты |
| 11 | Установить через админ-панель → Компоненты | ✅ |
| 12 | Протестировать интерфейс на `/{component_name}` | ✅ |
| 13 | Протестировать бэкенд на `/admin/{component_name}` | Если применимо |

## 36.13. Пример: Создание блога

### Структура каталогов

```
/system/controllers/blog/
├── manifest.php
├── model.php
├── frontend.php
└── backend.php
```

### Модель

```php
// /system/controllers/blog/model.php
<?php
class modelBlog extends cmsModel {
    public function getPosts() {
        return $this->db->from('blog_posts')
            ->where('is_published', 1)
            ->orderBy('date_created', 'DESC')
            ->get();
    }
}
```

### Фронтенд-контроллер

```php
// /system/controllers/blog/frontend.php
<?php
class blog extends cmsFrontend {
    public function actionIndex() {
        $posts = $this->model->getPosts();
        return $this->render('index', ['posts' => $posts]);
    }
}
```

### Шаблон

```php
<!-- /templates/default/controllers/blog/index.tpl.php -->
<?php foreach ($posts as $post): ?>
    <article>
        <h2><?= html_escape($post['title']) ?></h2>
        <p><?= $post['content'] ?></p>
    </article>
<?php endforeach; ?>
```

## 36.14. Лучшие практики

### ✅ Рекомендуется
- **Следовать соглашениям об именовании** для автоматической загрузки классов
- **Использовать события** для расширения функциональности без изменения ядра
- **Валидировать все входные данные** через методы модели или формы
- **Документировать методы** с помощью PHPDoc
- **Использовать кэширование** для тяжелых запросов
- **Тестировать на staging-среде** перед деплоем в продакшен

### ❌ Избегайте
- **Прямого изменения ядра** — используйте хуки и наследование
- **Жесткого кодирования путей** — используйте константы `PATH` и `ROOT`
- **Отсутствия валидации** входных данных
- **Игнорирования ошибок** — всегда обрабатывайте исключения
- **Отсутствия кэширования** для часто запрашиваемых данных

## 36.15. Заключение

Создание компонентов в DST Platform обеспечивает:

1. **Четкую структуру** через разделение на контроллеры, модели и шаблоны
2. **Гибкость** через наследование и события
3. **Безопасность** через валидацию и санитизацию данных
4. **Производительность** через кэширование и оптимизированные запросы
5. **Поддерживаемость** через документирование и стандарты кодирования

**Рекомендация для разработчиков:** Начинайте с изучения существующих компонентов (например, `shop`, `users`) для понимания архитектурных паттернов. Следуйте проверочному списку при создании новых компонентов и всегда тестируйте функциональность в изолированной среде перед интеграцией в основной проект.

Для углубленного изучения конкретных аспектов создания компонентов обратитесь к связанным разделам документации, перечисленным в начале данного руководства.
